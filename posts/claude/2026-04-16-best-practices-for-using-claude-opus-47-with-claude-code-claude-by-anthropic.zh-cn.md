---

[Opus 4.7](https://www.anthropic.com/news/claude-opus-4-7) 是我们迄今为止在编程、企业工作流以及长时间运行的智能代理任务中最强大的通用模型。它在处理模糊性方面优于 Opus 4.6，在发现错误和审查代码方面能力更强，能在会话之间更可靠地传递上下文，并且能在更少指导的情况下推理模糊任务。

在我们的[发布公告](https://www.anthropic.com/news/claude-opus-4-7)中，我们指出两项变化——更新的分词器以及在更高投入度级别下（尤其在较长会话的后续轮次中）更倾向于进行更多思考——会影响令牌使用量。因此，当用 Opus 4.7 替换 Opus 4.6 时，需要一些调整才能达到最佳性能。对提示词和调用框架进行一些微调就能带来显著差异。

本文将介绍有哪些变化，以及如何在 Claude Code 中最有效地使用 Opus 4.7。

## 构建交互式编程会话

Opus 4.7 的令牌用量和行为可能有所不同，这取决于你是在部署单次用户回合的自主异步编程代理，还是多次用户回合的交互式同步编程代理。在交互式场景中，它会在用户回合后进行更多思考：这提高了其在长时间会话中的连贯性、指令遵循能力和编程质量，但也倾向于使用更多令牌。

为了在 Claude Code 中充分利用 Opus 4.7，我们发现最好将 Claude 视为一位你可以委派任务的能干工程师，而不是逐行指导你的结对编程伙伴：

* **在第一次回合中一次性指定任务。** 包含意图、约束条件、验收标准以及相关文件位置的任务描述，能为 Opus 4.7 提供所需的上下文，从而输出更强的结果。渐进式地在多个回合中传达模糊提示词通常会降低令牌效率，有时也会影响整体质量。
* **减少所需的用户交互次数。** 每次用户回合都会增加推理开销。将你的问题分批提出，并为模型提供持续推进所需的上下文。
* **在适当时使用**[**自动模式**](https://claude.com/blog/auto-mode)**。** 对于你信任模型无需频繁确认即可安全执行的任务，自动模式可缩短周期时间。它特别适用于你提前提供了完整上下文的长时间运行任务。自动模式现已在 Claude Code Max 用户的研究预览版中可用——你可以使用 Shift+Tab 切换开启。
* **设置任务完成通知。** 让 Claude 在任务完成时播放声音，它可以创建基于钩子的通知。

## Opus 4.7 推荐投入度设置

Opus 4.7 在 Claude Code 中的默认投入度级别现在是 `xhigh`。这是一个介于 `high` 和 `max` 之间的新投入度级别，能让用户在困难问题上更好地权衡推理与延迟。对于大多数代理式编程任务，我们推荐使用 xhigh，尤其是对智能性敏感的任务，如设计 API 和架构、迁移遗留代码以及审查大型代码库。

以下是每个投入度级别的进一步指导：

* **`medium` 和 `low`**：适用于对成本敏感、对延迟敏感或范围严格的任务。在较难的任务上，模型的能力会低于更高投入度级别，但它仍然优于运行在同一投入度级别的 Opus 4.6——有时使用的令牌更少。
* **`high`**：平衡智能性与成本。如果你在运行并发会话或希望在不显著降低质量的情况下减少开销，请选择 high。
* **`xhigh`（默认，推荐）**：适用于大多数编程和代理式使用的最佳设置。它具备强大的自主性和智能性，且不会产生 max 级别在长时间代理式运行时可能出现的失控令牌消耗。
* **`max`**：在真正困难的问题上挤出额外性能，但回报递减，并且更容易过度思考。请有选择地使用它，例如在评估中测试模型的最大上限，以及用于对智能性极其敏感且对成本不敏感的场景。

如果你正在升级到新模型，我们建议尝试调整投入度，而不是直接沿用旧设置。你可以在同一任务期间切换投入度级别，以更有效地管理令牌用量和推理。

我们将 Opus 4.7 的默认投入度级别设为 xhigh，因为我们相信这是大多数编程任务的最佳设置。如果你是现有 Claude Code 用户但尚未手动设置投入度级别，你将自动升级到 `xhigh`。你仍然可以手动调整投入度。

## 使用自适应思考

**Opus 4.7 不支持带有固定思考预算的扩展思考。** 相反，Opus 4.7 提供了自适应思考。这使得思考在每个步骤中成为*可选的*，并允许模型根据上下文决定何时使用更多思考。它可以快速响应简单查询，在某个步骤无需思考时跳过它，并将思考令牌投入到最可能有用之处。在一次代理式运行中，这可以累积起来实现更快的响应和更好的用户体验。

在此版本中，自适应思考有了明显的改进——特别是，Opus 4.7 不太容易过度思考。

如果你希望更精确地控制思考速率，可以直接在提示词中要求：

* **如果你希望更多思考，** 尝试类似这样的提示：“在回复前仔细思考并逐步推理；这个问题比看上去要难。”
* **如果你希望更少思考，** 尝试类似这样的提示：“优先快速回复，而非深入思考。如有疑问，直接回答。” 这样你会节省令牌，但可能在较难步骤上损失一些准确性。

## 值得了解的行为变化

Opus 4.6 和 4.7 之间有一些默认行为发生了变化，如果你已经为旧模型精心调整了提示词或调用框架，这些变化值得了解。

**回复长度会根据任务复杂度进行校准。** Opus 4.7 不像 Opus 4.6 那样默认冗长。你可以预期在简单查询上得到较短的答案，在开放式分析上得到较长的答案。如果你的用例依赖于特定的长度或风格，请在提示词中明确说明。我们发现，你想要的语气的正面示例比负面的“不要这样做”指令效果更好。

**模型调用工具次数减少，思考更多。** 这在许多情况下能产生更好的结果。如果你希望*更多*地使用工具（比如在代理式工作中进行更积极的搜索或文件读取），请提供明确描述何时以及为何使用工具的指导。

**默认情况下，它产生的子代理更少。** Opus 4.7 在决定何时将工作委派给子代理时往往更加谨慎。如果你的用例受益于并行子代理（例如，分散处理文件或独立项目），我们建议明确说明。例如：

对于你可以在一次回复中直接完成的工作（例如，重构你已经看到的函数），不要生成子代理。当需要分散处理项目或读取多个文件时，在同一回合中生成多个子代理。

## 接下来可以尝试什么

Opus 4.7 在长时间运行任务上的表现优于之前的模型。这使得它非常适合那些原本监督是瓶颈的任务，例如复杂的多文件修改、模糊调试、跨服务代码审查以及多步骤代理式工作。

我们建议将投入度保持在 `xhigh`，并看看你的第一次回合能走多远。
