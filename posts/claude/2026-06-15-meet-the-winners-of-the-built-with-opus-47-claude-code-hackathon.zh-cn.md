# 认识 Built with Opus 4.7 Claude Code 黑客马拉松获奖者

            **日期：** 2026-06-15 00:00 UTC

            上周，我们举办了 [Claude 构建日](https://cerebralvalley.ai/e/claude-startups-build-day)，这是最新一届黑客马拉松，开发者们齐聚旧金山，利用 Claude Opus 4.8 将他们的想法付诸实践。

            在等待他们成果的同时，我们与 Built with Opus 4.7 黑客马拉松的获奖者聊了聊他们的项目。他们的项目涉及医疗培训、电子维修、计算机科学教育、互动游戏、家庭维修和工厂维护。

            祝贺所有获奖者和参与者！希望他们的想法能给您带来启发。

## 一等奖：[Medkit](https://bedirhankeskin.com/)，贝迪尔汉·凯斯金

            贝迪尔汉·凯斯金是一位来自伊斯坦布尔的医生转软件工程师，他使用 Claude Managed Agents 构建了 Medkit：这是一个面向住院医师或初级医生的学习工具，在游戏化的医疗诊所中模拟真实的患者就诊场景。

            "当你独自一人在急诊科面对 50 位等待的患者，却意识到医学院从未教过你如何处理某些病例时，你最终只能在真实患者身上实时练习这些技能，"贝迪尔汉说。

            借助 Medkit，医学生可以练习诊断和治疗模拟患者，使用该工具采集病史、开具化验单、读取影像、诊断并制定治疗方案。最后，一个智能评分代理会根据与考官使用的相同临床指南对整个诊疗过程进行评估。

            贝迪尔汉在四个独立的 Claude Code 会话中构建了 Medkit（语音引擎、内容生成、3D 游戏层和核心应用），保持每个上下文的清晰，并同时推进所有部分。他采用了"说，不打字"的方法，几乎完全通过语音工作。

            Medkit 已经获得关注，三家位于伊斯坦布尔的医学院和一家制药公司将在未来几周内开始试点运行。

            **给其他开发者的建议：** 将 Claude 视为思维伙伴，而不仅仅是编码代理。

            贝迪尔汉最初想自行托管语音引擎，但 Claude 建议使用云提供商来加快进度。"我最看重 Claude 的是，它不仅仅是一个代码生成器，更是一个思维伙伴，帮助我看到原本可能错过的选择，"他说。

            [*GitHub 上的 Medkit*](https://github.com/bedriyan/medkit-app)

## 二等奖：[Wrench Board](https://wrenchboard.cloud/)，亚历克西斯·沙佩利耶

            来自法国雷涅埃塞里的亚历克西斯·沙佩利耶在创建 [RepairMind](https://repairmind.io/)（一个面向维修店的人工智能管理平台）之前，花了多年时间修理电子产品。他在 Opus 4.7 黑客马拉松上的项目 [Wrench Board](https://wrenchboard.cloud/) 帮助独立技术人员解决复杂维修问题。用户上传原理图和电路板视图并描述故障症状，代理会创建一个统一的电气图，进行推理，指出需要探测的确切焊盘，读取测量值，并更新其假设，直到诊断出问题。

            亚历克西斯在 Claude Design 中制作了 Wrench Board 的原型，将应用的责任分开（设计、原理图导入、电路板视图、诊断代理），并为每个部分先生成规范，然后制定计划。他在 Claude Code 的多代理模式下执行，在调试过程中每一步都进行基准测试，同时运行五到六个代理，每个领域有一个专用代理。

            亚历克西斯的大胆押注是 Opus 4.7 理解视觉原理图的新能力；他说，当他让模型追踪主板上的电源路径时，他就知道这行得通了。

            "我看到 Wrench Board 的电路板视图一步步亮起，箭头出现，组件被指向，名称浮现。那一刻，我明白这个想法是成立的，"他说。

            Wrench Board 的下一阶段是建立一个对尝试该应用感兴趣的电子维修人员社区，以及能够用他们的现场经验丰富该工具的专家。他的 Claude 积分将用于 RepairMind、首批用户以及所有正在运行的基础设施。

            "这次黑客马拉松证明，一个自学成才、从维修店走出来的人可以在五天内交付一个雄心勃勃的系统，"亚历克西斯说，他参赛时正在申请"生存工作"。"Claude Code 放大了任何有想法并有毅力去执行的人，无论他们的起点如何。"

            **给其他开发者的建议：** 深入头脑风暴，并对模型提出质疑。

            亚历克西斯使用 [Superpowers](https://claude.com/plugins/superpowers)，这是一个集成到 Claude 中的技能框架，用于构建头脑风暴和规划步骤，有时并行进行头脑风暴以在不同方面取得进展。他从 Claude Design 开始，然后使用内置按钮将项目直接共享到 Claude Code，并在模型说"不行"时推动它。

            "在黑客马拉松期间，Claude 好几次告诉我这个或那个在时间上不可行。实际上，我有充足的时间，"他说。"你必须知道如何告诉它，*我还是要试试。*"

            [*GitHub 上的 Wrench Board*](https://github.com/Junkz3/wrench-board)

## 三等奖：[Maieutic](https://maieutic.dev/)，保拉·瓦斯克斯-恩里克斯

            在智利康塞普西翁的德尔萨罗约大学教授计算机科学的保拉·瓦斯克斯-恩里克斯说，过去两年她看到越来越多的学生通过了考试，却不理解自己写的代码。

            "学生们现在用人工智能制造代码，但他们完全不知道代码在做什么，"她说。"他们从未学会精确地陈述问题，在编码前起草计划，或者批判性地阅读自己的代码并注意到它偏离了原本的意图。自动补全在他们还没问完问题之前就提供了可运行的代码，所以元认知循环——即真正造就程序员的思考过程——从未闭合。他们毕业时能够生成代码，但无法推理代码。"

            保拉目前正在攻读人工智能博士学位，研究学生与人工智能的交互模式，她参加黑客马拉松是为了从学生和教师两个角度解决这个问题。

            Maieutic 是一个 IDE，旨在让学生在关键时刻放慢速度。学生在编写任何代码之前，必须用通俗语言描述他们的程序应该做什么；Claude 会提出有针对性的澄清问题，并保持编辑器锁定，直到规范足够详细，以至于一个称职的程序员无需猜测就能实现它。

            然后学生可以开始编写 Python，但自动补全已关闭；一个聊天面板直接回答参考性问题，但对推理问题则以反问而非修正来回应，拒绝替学生思考。

            该工具的核心是 Intent-Diff 审查，它让 Claude 将规范与最终代码进行比较，将每个差异分类为漂移、修订或错误，然后提出中立、非指责性的问题，促使学生自己解释问题。

            对于教师，一个实时仪表板显示每个学生一行，附有一句认知摘要（例如，"写了三遍规范，仍未考虑空输入"）。教师可以点击单个学生，监控他们与 Claude 的具体交互，该工具还会分析整个班级，识别并呈现全班共有的误解，以便教师弥补这一差距。

            黑客马拉松结束后，休斯顿大学的研究人员联系了保拉，希望合著一篇论文，她将把获奖积分用于进一步开发该工具。她说，黑客马拉松那一周让她看到，理解问题与交付工具之间的差距已经消失。

            "我是智利康塞普西翁的一名教育工作者，不是硅谷的人，"她说。"我在一周内交付了一个可运行的全栈产品，因为这些工具让我能够专注于我真正擅长的角色，而它们处理其余部分。最接近真实问题的人现在可以直接为他们构建解决方案。"

            **给其他开发者的建议：** 先思考，再构建。

            这个项目是保拉践行自己的理念：先明确规范，再开始构建。"Maieutic 之所以存在，是因为学生们直接跳入代码，而我能够很好地构建它的唯一方法就是拒绝自己这样做，"她说。她花了整整两天进行纯粹的思考工作，在写一行代码之前先创建设计规范和技术规范。

            "那两天的规范制定在当时感觉很慢——黑客马拉松中确实有立即开始交付的压力——但它们让接下来的一周能够快速推进，"她说。

## Opus 4.7 最具创意应用奖：虚拟木偶剧场，雷内·汉斯特鲁普·穆勒

            全栈开发者雷内·汉斯特鲁普·穆勒对 Opus 4.7 的空间推理能力很感兴趣，他构建了虚拟木偶剧场，这是一个基于浏览器的应用，将网络摄像头视频和语音转化为动态的互动木偶表演。一个实时动画木偶模仿用户的动作，而另一个由人工智能驱动的同伴木偶与用户聊天；语音提示可以即时变换场景并生成 3D 道具。

            雷内在整个流程中使用了 Claude：概念讨论、规划和代码编写，而他负责方向、架构、审查和决策。该应用基于 Bun、Vite 和 TypeScript，使用 MediaPipe 手部追踪（在 WASM 中运行）和 Three.js 以 60 fps 渲染 3D 木偶舞台。一个小型 WebSocket 服务器通过 Anthropic SDK 连接到 Claude Opus 4.7，驱动人工智能木偶的对话并即时生成 3D 道具，而语音则由 Web Speech API 处理输入，ElevenLabs 处理输出（浏览器语音合成作为后备）。Opus 的空间推理能力通过基于截图的反馈循环进行优化，处理视觉输出。

            虚拟木偶剧场没有明确的目标，只是开放式的游戏，雷内说她没有为她的获奖项目制定产品计划。对她来说，这关乎学习和乐趣。"我和我最小的儿子一起测试了它，他玩得很开心，"雷内说。"看到他互动木偶、描述场景、对回应咯咯笑，这就是我需要的所有用户验证。"

            虚拟木偶剧场的源代码在 GitHub 上以 MIT 许可证提供，她补充道，"如果有人想进一步开发它。"

            **给其他开发者的建议：** 如果你参加黑客马拉松，一定要留出时间制作演示视频。

            "制作一个 3 分钟的视频所需的时间比你想象的要长得多，"雷内说，她提到她在黑客马拉松截止日期前使用 Claude 和 Hyperframes 创建和编辑了她的虚拟木偶剧场视频。"黑客马拉松 Discord 中的很多人都提醒过这一点，他们是对的。下次，我会把最后一天全部留出来制作演示。"

            [*GitHub 上的虚拟木偶剧场*](https://github.com/rhmoller/virtual-puppet-theater)

## "持续思考"奖：[MaestrIA](https://www.youtube.com/watch?v=rkH4AjoTL5Q)，本杰明·托拉尔博

            本杰明·托拉尔博从小在智利奇洛埃跟随父亲胡安·罗德里戈·托拉尔博（一位认证的 *Maestro Mayor* 木匠）做学徒。"我父亲有 30 年的手艺，修复过联合国教科文组织列名的教堂，但在智利的体系中仍然默默无闻，就像成千上万的其他手艺人一样，"本杰明说。"与此同时，需要家庭维修的人不知道哪里出了问题，不知道费用，不知道该找谁，也不知道自己是否被公平收费。"

            他的 [MaestrIA](https://maestriachile.cl/) 黑客马拉松项目从两方面解决了这个问题：它是一个网络应用，既为普通人提供大师级的家庭维修诊断，又为熟练手艺人提供展示专业知识的途径。

            使用 MaestrIA，用户拍摄问题照片，用语音或文字描述，并分享位置。Claude 实时流式输出推理过程，在照片上显示动画边界框，然后提供结构化诊断：损坏了什么、材料、严重程度 1-5 级、项目预算和时间估算。然后，代理渲染附近按行业筛选的师傅地图，同时另一个代理起草一条 WhatsApp 消息发送。

            MaestrIA 的技术核心是一个 JSON 文件，注入到每次诊断中，包含 17 条诊断规则、7 种本地奇洛埃木材、16 个当地行业术语、19 个基准价格和 9 个常见工艺错误——所有这些都来自本杰明与父亲数小时的访谈。无需触及系统提示，仅这一个文件就将他的评估分数提升了 7 个百分点（从 74% 到 81%，与人类大师的判断相比），这就是 MaestrIA 能够诊断"阿莱尔塞木墙板上的上升潮气"而非泛泛的"木材损坏"的原因。

            没有任何编程经验的本杰明说，他的角色是现场主管，监督 Claude 的技术执行。"在编写任何功能之前，我要求 Claude Code 设计规范、分阶段行动计划和安全模型：针对提示注入的输入清理、速率限制、来源验证和 Zod 模式作为唯一真实来源，"他说。"然后我逐个差异审查每个功能。"

            本杰明希望 MaestrIA 能够扩展到新的建筑项目、五金店集成、正式预算、合同、评论和认证系统。最终，每个行业都将内置自己的 Maestro Mayor，包括木匠、建筑师、水管工、电工和泥瓦匠。

            他的获奖积分将用于开发应用、将其父亲的公司数字化作为实时试点，以及他自己的技术成长。"Claude Code 让一个来自奇洛埃、没有编程经验的 20 岁年轻人能够构建他父亲也能使用的软件，并且能够帮助智利像他一样的 28 万名师傅，"他说。"它为数百万一直有宝贵想法但无法实现的人打开了大门。"

            **给其他开发者的建议：** 先评估，再开发功能。

            "我做的最重要的一件事是构建了一个可审计的 9 维度评估，针对 12 个真实案例，以我父亲记录的真实情况为基准，"本杰明说。"那个评估，而不是我的直觉，告诉我什么有效、什么无效。如果我参加下一次黑客马拉松，评估将是第一个提交的内容。"

## Claude Managed Agents 最佳应用奖：[ARIA](https://www.youtube.com/watch?v=Hen24w2Jyz4&t=28s)，伊德里斯·本格佐 & 亚当·奈恩

            大多数工厂都有那么一位资深技师，仅凭机器发出的声音就能判断它是否即将发生故障。获得 Claude Managed Agents 最佳应用奖的项目 ARIA（自适应运行时智能）将经验丰富的维护工程师的本能转化为一个价格合理、快速部署的人工智能系统，持续监控工厂机器，并在问题出现时立即生成定制诊断和维修计划。

            使用 ARIA，维护工程师上传制造商的 PDF，回答四个简单的校准问题，15 分钟内即可完成工厂配置。此后，五个代理实时监控信号。如果某个代理检测到故障或预测故障即将发生，它会生成一份工单，分析组件、故障模式、紧急程度、零件和干预窗口。

            该项目的两位构建者都有一线工业经验，他们在黑客马拉松的队友寻找 Discord 频道中相识。伊德里斯·本格佐是一位法国工业软件工程师，拥有数据/人工智能硕士学位，他之前已经构思了这个想法及其大部分架构。亚当·奈恩是一位自学成才的工程专业学生，对 Claude Code 和多代理工作流有丰富经验，他立即认识到 ARIA 是工业维护的一个有价值的解决方案。

            伊德里斯和亚当将黑客马拉松的第二天全部用于规划模式，使用 GitHub 项目面板，在编写第一行代码之前确定每个里程碑、问题和验收标准。"我们希望从第二天开始就以 200% 的速度推进，"亚当说。"一天的规划让我们能够在一周剩余的时间里执行，而不是即兴发挥。"

            两人估计 Claude Code 编写了约 80% 的原始代码行，而他们手动处理领域逻辑和设计决策。伊德里斯负责阈值评估、知识库模式和异常检测，因为他说"你不能通过提示来了解维护技师实际关注什么。"亚当负责用户体验、视觉语言和 ARIA 的星座概念，因为他说"你不能通过提示来获得品味。"

            Managed Agents 处理了代理基础设施。"如果没有 Claude Managed Agents，我们就会花一周时间构建 Anthropic 已经托管的基础设施：沙盒 Python 环境、安全执行、会话持久化、MCP 调度，"亚当说。"相反，我们把那一周花在了围绕该基础设施构建产品上。这就是在五天内交付 ARIA 与在五周内交付 ARIA 的区别。"

            黑客马拉松结果公布后，从事这一领域工作的公司联系了该项目。伊德里斯将把 ARIA 的代理架构、知识库模式和信号管道整合到他自己的工业物联网平台中；他的积分将用于更多的构建和实验。至于亚当，他的计划是继续探索工业代理人工智能的机会，并使用 API 积分继续构建和实验。

            **给其他开发者的建议：** 让 Claude 进行审计。伊德里斯说，在构建下一个功能之前，让 Claude 找出你已经构建的内容中是否存在任何问题。"这个循环被低估了。"
