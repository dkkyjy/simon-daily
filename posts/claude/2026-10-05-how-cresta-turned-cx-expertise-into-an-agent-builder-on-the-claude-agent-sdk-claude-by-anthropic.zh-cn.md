为客户体验用例构建企业级 AI 代理需要理解嵌入在各种客户交互中的上下文。例如，客户可能会：

* 在不指明具体购买项目的情况下要求退款，
* 在同一条消息中报告账单问题和登录问题，或者
* 在退货窗口关闭后要求退款。

为了正确回应，代理可能需要检查客户购买的内容、退款政策、他们的账户历史记录或支付状态。

Cresta 大规模地观察到这些交互。其平台为 AI 代理提供动力，这些代理可以自行处理对话，为与它们协同工作的人工代理提供实时指导，并展示对话智能，让业务了解需要改进的地方。

构建和维护客户体验代理需要组织在运营要求方面做出关键决策：代理需要知道什么、必须访问哪些系统，以及其行为应该在哪些方面灵活、哪些方面确定。Cresta 希望让更多团队能够做出这些判断，而无需每个团队都从零开始。

Conductor 就是由此产生的：一个自然语言代理构建器，帮助团队将复杂的业务上下文转化为生产就绪的代理。用户描述他们想要构建的内容，Conductor 引导工作从有依据的蓝图到实现、评估和优化。

Cresta 最初使用 Claude Sonnet 和 Claude Opus 构建了 Conductor 的早期版本，以帮助内部团队支持客户部署。悬而未决的问题是，Cresta 能否将那个系统转化为一个产品，让客户能够直接在平台*内*构建代理。

为了执行开放式开发工作，Conductor 使用 Claude Agent SDK 作为通用工具来收集上下文、使用工具、编写和运行代码，并根据结果进行调整。

“我们在内部使用 Claude Code 作为开发工具，因为它在构建代理的软件开发方面非常有效，”Cresta Conductor 的工程负责人 Renjie Li 说。“Claude Agent SDK 让我们能够以编程方式使用同样的代理开发工具。通过 Conductor，我们将它与 Cresta 的深度对话智能、CX 专业知识、评估和运行时连接起来，为用户提供我们一直希望从第一天就拥有的代理构建体验。”

Cresta 报告说，在 Cresta 及其合作伙伴的早期用例中，Conductor 将初始部署时间减少了大约一半。

## **一个帮助构建下一个代理的元代理**

Conductor 是一个自我改进的元代理，建立在 CX 代理开发的既定最佳实践之上。随着团队使用它构建和完善更多代理，他们捕获自己经过验证的模式、工作流和专业判断。这创造了一个知识飞轮，使未来的开发更快、更一致。

发布后，生产交互、工作流结果和反馈成为下一次改进的新信号。

Conductor 帮助构建者将从代理构建中所学到的转化为可重用的记忆工件，捕获模式、业务规则和评估方法。然后他们可以将它作为技能分享给团队的其他成员，让其他人也能从同样的经过验证的实践出发构建。

### **让重要决策更容易**

编写第一个提示只是构建有用代理的一部分。更难的决定之一是对话应该在哪些方面保持灵活，哪些方面需要明确业务规则和受控的工具行为。

“你不想过于确定化，否则你会创建一个巨大的决策树，试图映射出每个可能的分支……但有一些企业关键的工作流，你需要确保它们始终有效，特别是在风险承受能力低的强监管行业，”Renjie 说。“Conductor 帮助发现和强化这些确定性要求以及实现，同时保持改进整体体验的灵活性。”

Conductor 利用历史对话帮助团队确定哪些地方应该让人类保持参与，哪些地方可以给予模型适应的空间。一旦这些边界设定好，开发人员仍然需要针对它们应该强制执行的要求测试确定性部分，并在底层业务规则发生变化时修订这些测试。

## **Cresta 如何评估 Conductor**

Conductor 的衡量标准是它构建代理的能力。为此，Cresta 让 Conductor 通过一组构建任务：

* 构建新代理
* 为其编写测试用例
* 更改已存在的代理
* 执行根本原因分析

完成任务不是唯一的衡量标准。团队还关注结果、Conductor 如何到达那里以及它沿途使用了什么。

| 评估 | 回答的问题 |
| --- | --- |
| 结果 | Conductor 是否产生了所请求的、可用的工件？ |
| 执行路径 | 它是否使用了适当的工具和必需的上下文？ |
| 质量 | 结果与精心准备的参考相比如何？ |
| 资源使用 | 该任务需要多少时间和模型使用量？ |

同样的任务也充当安全网。当新的 Claude 模型发布或 Conductor 框架更新时，Cresta 重新运行其评估。它使用相同的任务和相同的评分来识别哪些得到了改进，哪些在任何人承诺更改之前仍然需要工作。

同样的评估纪律也内置于 Conductor 中，允许其用户检查他们的代理是否按预期执行。Conductor 将在构建阶段捕获的需求和边缘情况转化为其评估模块中的测试。

团队然后可以监控那些必须每次都能正常工作的流程，因为策略、连接系统和对话模式都在变化。这为他们提供了一种实用的方法，可以在业务变化时更新代理，同时保持他们已经强化的工作流的可靠性。

## **基于 Claude Agent SDK 构建 Conductor**

Cresta 将 Conductor 设计为代理开发的 CX 特定控制平面。它将对话数据、领域专业知识和开发实践结合在一起，然后通过策略、可观察性、验证和反馈驱动的改进来治理每个代理运行。

Claude Agent SDK 位于 Conductor 之下，作为通用执行工具。它管理收集上下文、调用工具以及编写和运行代码的工作；Conductor 在其上层叠加 Cresta 的 CX 工作流、工具和领域上下文。

团队评估了 SDK 与 Conductor 需要执行的工作：具有多个步骤、大量上下文和重复工具使用的任务。其审查涵盖了数据隐私、租户架构、组织级别的密钥分发、控制和实现中的可观察性。

“Anthropic 为我们提供了强大的通用代理软件开发基础。这让我们能够将工程投资放在 Cresta 创造最持久客户价值的地方，”Cresta 工程副总裁 Xiangru Chen 说。

## **将 Cresta 的工程专业知识直接交到客户手中**

Conductor 始于 Cresta 内部，帮助其自身的前线部署团队了解哪些开发任务可以变得可重复，哪些地方的上下文最重要，以及构建者在沿途需要检查什么。它在内部工作中的成功让团队有信心将同样的能力带给客户和合作伙伴。

对于任何产品的定制代理部署速度超过其工程师手动构建速度的团队来说，Cresta 的方法是一个有用的参考点：对于代理或元代理，初始构建后的工作往往是最难的部分。
