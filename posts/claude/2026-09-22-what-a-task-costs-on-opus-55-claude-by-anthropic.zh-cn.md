## 任务成本与重试成本

你并不是为了购买数百万个 token 而开始工作。你的目标是构建一个功能、完成一次迁移或执行一项任务。token 数量只是模型完成工作所需的量。

两个每 token 价格相同的模型，在执行同一任务时，成本可能截然不同。一个模型只阅读一次代码。另一个模型阅读代码，尝试修复，然后再次阅读。每一步都是一个回合，每个回合都会重新发送迄今为止的对话内容。因此，即使价格相同，需要更多回合的模型成本也更高。

读完本文后，你应该能够回答关于你自己工作的三个问题：

* 我的典型任务在 Opus 5.5 上的成本是多少？
* 哪些设置会影响这个成本，影响程度如何？
* 如何检查自己的会话使用情况？

我想首先分享的权衡是，每一种节省 token 的方法都可能让你失去一个完成的任务。更低的努力程度、更小的模型或更少的上下文都可以节省 token。但重试的成本会超过这些节省。本文试图为每种权衡定价。

这里的一些数字是列表价格，另一些是基于这些价格构建的示例。这些图表是交互式的，你可以在阅读时更改输入值。这些只是尽力而为的示例，请务必查阅我们的文档并自行计算。

## 任务的成本是多少？

在 Claude Code 中，一个任务是一个循环。模型阅读对话，调用工具，阅读结果，然后再次循环，直到完成。循环的每一圈都是一个请求。有四件事决定了循环的成本。

**回合数。** 每个回合都会重新发送迄今为止的对话内容。回合数越少，处理的输入就越少。

**缓存读取。** 一个回合重新发送的内容大部分是模型在前一个回合已经见过的文本。它按缓存读取计费，价格仅为输入价格的一小部分。

**输出 token 类型。** 这是最昂贵的 token，价格是输入价格的五倍。[思考](https://platform.claude.com/docs/en/build-with-claude/extended-thinking)按输出计费，因此一个在得出答案前思考较少的模型成本更低。

**模型。** 每个模型都有自己的价格，列在定价页面上，因此你选择的模型决定了每个 token 的价格。

我们的示例使用 Opus 5.5 API 列表价格：每百万输入 token 4 美元，每百万输出 token 20 美元，每百万缓存读取 0.20 美元。与下面的计算器一样，示例按读取价格对缓存输入计费，对其他所有输入按输入价格计费，并不计算缓存写入。token 数量仅为示例。

### 回合数

假设一个任务以 20K 的上下文 token 开始，随着模型阅读文件和工具结果，增长到 120K。在 40 个回合中，平均每个回合发送约 70K token。这意味着该任务的输入 token 约为 280 万，尽管对话从未超过 120K。如果有 90% 从缓存读取，输入成本约为 1.62 美元。同样的任务在 25 个回合中处理约 175 万 token，输入成本约为 1.02 美元。

一个回合的成本超过它新增的 token，因为它会重新发送之前的所有内容。因此，最便宜的回合是你不需要的那个。

一种可以减少回合数的习惯是赋予模型检查其工作的方法。例如，运行一个测试、构建或调用端点的脚本。能够检查自己工作的模型会更早发现错误。

一个模型如果在一次通过中收集所需的一切，并批量调用工具，也会减少重新发送的次数。

### 缓存读取

同样的 280 万输入 token，如果都不来自缓存，成本为 11.20 美元。在 90% 命中率下，成本为 1.62 美元，在 96% 命中率下约为 0.99 美元。没有其他设置能对输入成本产生如此大的影响。一个稳定的会话自然会保持高命中率。我将在本文后面介绍一些避免破坏缓存的操作。

### 输出 token

在 Opus 5.5 上，一个输出 token 的成本是缓存读取的 100 倍。一个典型任务的 60K 输出 token 成本为 1.20 美元，相当于从缓存读取 600 万 token。输出包括思考。你需要为所有这些付费，即使 Claude Code 只向你显示摘要。这就是为什么努力程度（主要改变模型的思考量）会对账单产生如此大的影响。

### 模型

缓存读取更便宜的模型主要对长会话有帮助。输出更便宜的模型主要对需要大量推理的任务有帮助。

## Opus 5.5 的变化

有两件事发生了变化：价格，以及模型完成的工作量。

**所有价格线都降低了。** 输入和输出 token 比 Opus 5 便宜 20%。缓存读取便宜 60%。输入价格下降，读取价格也随之下降，从输入价格的十分之一降至二十分之一。图 A 比较了两个模型每百万 token 的价格。这些是 API 列表价格。在 Pro、Max 或 Team 计划上，更低的 Opus 5.5 价格会传递到你的使用限额中，包括缓存上下文，因此你的使用量比在 Opus 5 上多约 25%。缓存读取的额外折扣是 API 价格变化。

## 最大化会话价值的技巧

Opus 5.5 的更低价格使每个 token 成本更低。你如何运行会话决定了你使用多少 token，以下步骤会有帮助。

### **在更换模型之前先提高努力程度**

努力程度设定了模型在每个回合上花费多少 token 的总体倾向：它的思考、它编写的文本以及它的工具调用。在较低的努力程度下，它进行更少的工具调用，并且保持调用更简短。Opus 5.5 有四个级别（低、中、高和 xhigh），加上单次会话的 max。选择一个级别以查看何时使用以及设置它的命令。

级别从每回合最少到最多思考排列。

Claude Code 为每个模型设置默认级别，/effort status 显示你的级别。对于范围明确、日常的工作，尝试**中等**。当中等停滞时，尝试**高**。它每回合花费比中等多，但比升级到更大的模型少。对于机械性工作，如重命名或在文件间应用已知模式，使用**低**。

粗略地思考努力程度的定价：假设高在一项任务中增加了 2 万思考 token。在 Opus 5.5 上，这是 0.40 美元。一个十回合的重试循环，有 10 万缓存上下文和总共 1 万输出 token，成本大约相同。因此，高在一个它节省一次重试的任务上就回本了。在一个中等第一次就能完成的任务上，它是浪费的。

#### **当中等只修复一层时**

你需要更多努力程度的最明显标志是修复只停留在一层。

假设 API 处理器中的一个字段被重命名。在中等级别，模型更新处理器，处理器的测试通过，但客户端仍然发送旧字段。它完成了被要求的事情。它只是没有阅读得足够远以找到第二个调用者。在高级别，它在编写之前花费更多回合阅读调用位置，并在一次通过中改变两层。

一个检查可以捕获同样的 bug。如果模型可以运行一个通过客户端的测试，旧字段会在它被编写的那个回合上导致测试失败，即使是在中等级别。因此，在提高努力程度之前，检查模型是否有办法检查其工作。运行一次测试的成本是一个回合及其输出。更高的努力程度给每个回合增加思考。

如果升级努力程度和添加检查都不起作用，那么切换到更大的模型。

#### **在会话中途改变努力程度**

在 Claude Code 中，运行 /effort 加上级别，例如 /effort high。/effort status 打印当前级别。你可以在任务中途改变它，新级别适用于下一个请求。

改变努力程度或思考设置会清除缓存的对话，因为这些设置是缓存匹配的提示的一部分。下一个请求将对整个对话支付缓存写入价格。

### **为你的工作选择合适的模型**

模型选择决定了会话中每个 token 的价格，因此它对账单的影响比努力程度更大。它也影响更远。继承主模型的每个子代理也会继承其价格。大多数日子需要三个模型：一个用于查找的小模型，一个用于你密切监督的工作的 Opus 5.5，以及一个用于最难任务的更大模型。

#### **将 Opus 5.5 作为日常主力**

将 Opus 5.5 用于你监督的工作：跨几个文件的功能开发、调试以及带有后续编辑的代码审查。你阅读它做的事情，并在它偏离时介入，因此循环保持简短。升级到 Fable 5.1

**当结果比 token 价格更重要时，升级到 Fable 5.1。例如**你不会监督的长运行、代码库中没有现有模式的问题，以及协调许多子代理的大型变更。不要等到第三次失败。如果 Opus 5.5 在高努力程度上两次遇到同样的问题，就切换，并在问题解决后切换回来。对于交互式工作，Opus 5.5 是更好的选择，因为它延迟更低且成本更少。

Fable 5.1 的列表价格为每百万输入 token 10 美元，每百万输出 50 美元，是 Opus 5.5 价格的两倍半。它的缓存读取成本为每百万 0.25 美元，仅为 Opus 5.5 速率的 1.25 倍，因为它们按其输入价格的 0.025 倍计费。因此，差距在长而缓存密集的运行上最小，在编写大量内容的任务上最大。

在自然断点处切换。缓存属于前一个模型，因此预期新模型上的第一个回合将对整个对话支付写入价格。先运行 /compact，或用一个简短的书面计划开始一个新会话，以使那个回合更小。运行 [/model](https://code.claude.com/docs/en/model-config) 加上别名或模型名称来切换。/model 还会将你的选择保存为新会话的默认值，因此在困难部分完成后切换回来。

#### **为查找降级**

**为查找降级到 Sonnet 或 Haiku，而不是为编写代码：**搜索和总结的子代理、阅读日志和测试输出，以及"这在哪里定义"的问题。对于跨许多文件的机械性编辑，保留 Opus 5.5 并将努力程度设置为低。编辑保留在编写你其余代码的模型上，每回合成本更低。

要将[子代理](https://code.claude.com/docs/en/sub-agents)放在更小的模型上，在其定义中设置 model: haiku 或 model: sonnet。要将每个子代理放在一个模型上，设置 CLAUDE\_CODE\_SUBAGENT\_MODEL 环境变量。子代理定义中命名的模型覆盖变量。没有模型设置的子代理在你的主模型上运行，除非设置了变量。

每个子代理在自己的上下文窗口中运行并返回摘要，因此它的文件读取不会进入你的主对话。它仍然为自己的 token 付费，因此模型设置决定了该花费的成本。

权衡：一个误读搜索结果的小模型会将主模型引向错误的文件，主模型为绕路付费。将小模型保留在错误容易被发现的工作上，如查找文件、运行测试和阅读日志。

将判断性调用保留在主模型上。opusplan 别名以不同方式分割工作：Opus 在计划模式下计划，Sonnet 执行计划。这将代码编辑放在 Sonnet 上，与上述建议相反。在将其设为默认值之前，在你自己的任务上衡量它。

### **迁移时检查你的提示**

为旧模型编写的指令可能使 Opus 5.5 编写更多并重复工具调用。在 Claude Code 中运行 /claude-api prompt-audit 以检查你的 Claude Code 设置，如你的技能和 CLAUDE.md 文件，是否存在这些[提示反模式](https://claude.com/blog/reducing-cost-and-improving-performance-with-claude-platform)。它还会检查你在 Claude 平台上构建的应用的代码。

我们在从 Opus 4.8 到 Opus 5.5 的迁移上测试了这一点，使用了一个内部客户支持基准，包含 44 个提示中有几个这些模式的工单。迁移到 Opus 5.5，在低努力程度下，将基准成本降低了约 18%。运行 prompt-audit 进一步降低了 9%，降至 Opus 4.8 起点以下约 25%。审计移除了使模型编写更多并重复工具调用的仪式性指令：一个强制的六步程序、一个草稿规则、一个双重验证规则，以及相互矛盾的指令。

这个结果来自一个基准，因此将其视为一个示例，而非预期的数字。运行审计，然后在实际任务上比较运行前后的 /usage（见自行衡量）。

### **缓存与压缩**

Claude Code 为你处理缓存和压缩。你如何运行会话决定了它们节省多少。

#### **缓存如何工作**

Claude Code 缓存请求中重复的部分，如系统提示、工具定义和迄今为止的对话。

在 Opus 5.5 上，缓存读取的成本是新鲜输入 token 的 5%。写入缓存的成本高于新鲜读取，五分钟缓存为输入价格的 1.25 倍，一小时缓存为输入价格的两倍，按今日价格。每次命中都会免费重置生命周期。

在 Claude Code 中，生命周期取决于你的付费方式。在 Claude 订阅上，它是一小时。在 API 密钥或云提供商上，默认是五分钟，一旦订阅开始使用使用积分，就降至五分钟。

在 120K 上下文 token 时，Opus 5.5 上的五分钟写入成本约为 0.60 美元，读取约为 0.02 美元。一次写入的成本相当于 25 次读取。在 API 密钥上，六分钟的咖啡休息时间会将下一次 0.02 美元的读取变成 0.60 美元的写入。同样大小的一小时写入成本约为 0.96 美元，在 API 上，你可以支付这个溢价以覆盖你一天中的间隙。

#### **会话形状与命中率**

缓存存储前缀，因此它只能重用请求中与上一个请求从开头匹配的部分。

一个稳定的会话在每个回合上附加到对话的末尾，并保持高命中率。任何改变请求较早部分的内容都会降低它。改变工具定义会清除整个缓存，对系统提示的更改会从那个点开始清除它，这几乎是所有内容。

在实践中，预期在以下情况下会发生缓存写入：

* 你暂停的时间超过缓存生命周期；
* 你改变努力程度或思考设置（见努力程度部分），这可能清除缓存的对话；
* 你连接或断开 MCP 服务器，这可能改变每个请求开始时加载的内容；
* 你切换模型，因为新模型从空缓存开始；以及
* 对话被压缩，这重写了缓存匹配的歷史。

因此，在会话开始时设置这些，并在它工作时不要碰它们。

#### **为什么长会话每回合成本更高**

每个回合重新发送整个上下文，因此随着上下文增长，回合成本增加，即使缓存是热的。在 20K 上下文 token 时，Opus 5.5 上一个回合的缓存读取成本约为 0.004 美元。在 150K 时，成本约为 0.03 美元，30 个该大小的回合仅在读取上就花费 0.90 美元。同样 30 个回合在 20K 时成本约为 0.12 美元。在 Claude 4.6 及以后的模型上，更大的上下文窗口不会改变每 token 价格，因此成本完全来自重新发送对话。

这些上下文的大部分是早期工作的残留物：一个小时前的一次堆栈跟踪、一个你已完成阅读的文件、一个你后来修复的测试运行输出。它们在每个回合上仍然被发送。

#### **压缩、/compact 和 /clear**

当会话接近其上下文限制时，Claude Code 会总结较旧的歷史，使后续回合发送更少的内容。运行 /autocompact 加上 token 数量以改变上下文在该发生之前变得多满。

两个命令让你自行完成此操作。/clear 清空对话且成本为零，因此在你转向不相关的工作时使用它。/compact 保持连续性且成本为一个请求。它读取它总结的对话，你可以指定要保留什么，例如 /compact keep the failing test names and the schema change。

在 150K token 时压缩的大致价格是约 0.25 美元。这是读取、几千个输出 token 的摘要，以及对更短上下文的新缓存写入。每个后续回合在读取上节省约 0.025 美元，因此压缩在大约十个回合内回本。在你即将完成时进行的压缩成本超过其节省。

摘要也会丢失细节。在调试会话中途进行的压缩可能会丢弃那一条重要的日志行。在自然断点处压缩，当下一步依赖于特定内容时，在 /compact 指令中说明。

#### **在你键入之前加载的内容**

你的[CLAUDE.md 文件](https://code.claude.com/docs/en/memory)在每个会话开始时加载到上下文中，因此其中的每一行都是每个回合重新发送内容的一部分。[成本文档](https://code.claude.com/docs/en/costs)建议将其保持在 200 行以下。MCP 工具定义是延迟加载的。只有工具名称和服务器指令在开始时加载，完整定义在其工具被使用时加载。运行 /mcp 查看哪些服务器已连接，并关闭你不使用的那些。

## 自行衡量

本文中的数字是示例。你的代码库、提示和习惯不同，因此在你自己的任务上衡量成本。以下是检查方法。

1. **在会话中运行** [/usage](https://code.claude.com/docs/en/costs)**。** /cost 做同样的事情。会话块显示 token 使用和按列表价格估算的美元成本。提示缓存行显示你的输入中有多少来自缓存。在 Pro、Max、Team 或 Enterprise 计划上，同一屏幕显示你的计划使用条。美元数字是在你的机器上按列表价格计算的，因此在订阅上，它是你完成多少工作的指导，而非账单。
2. **运行相同任务两次。** 从你的待办事项中选择一些东西，而不是玩具示例。使用 /model 在 Opus 5 和 Opus 5.5 之间切换。记录每次运行的回合数、输出 token 和成本。在下结论之前做三四个任务。
3. **对于团队，使用使用和成本报告。** [Claude Code Analytics API](https://platform.claude.com/docs/en/manage-claude/claude-code-analytics-api) 提供每用户估算成本。[Usage and Cost API](https://platform.claude.com/docs/en/manage-claude/usage-cost-api) 按模型和缓存与非缓存 token 细分支出。
4. **尝试努力程度阶梯。** 在中等级别运行一个困难任务，然后在高级别运行。在低级别运行一个机械性任务。

### 阅读会话

在任务结束时检查 /usage 中的三件事。

* **缓存份额。** 对于长会话，它应该很高。如果很低，查找长时间暂停、努力程度或模型变化，或在会话中途连接的 MCP 服务器。
* **输出相对于输入。** 小变更的大量输出通常意味着努力程度对于任务太高，或者模型在重试。
* **总输入相对于对话大小。** 如果总数是对话大小的许多倍，会话进行了许多回合，值得阅读对话以找到循环重复的地方。

作为基线，Claude Code 成本文档给出企业部署的平均值约为每个活跃开发者每天 13 美元，90% 的用户低于每天 30 美元。一个成本远高于你自己正常水平的会话值得审查。

## 牢记要点

* 对范围明确的日常工作使用中等努力程度。
* 给模型检查其工作的方法，并在计划模式下开始跨文件的变更。
* 当中等停滞时，将努力程度提高到高。在断点处改变它，因为改变可能导致缓存写入。
* 如果高两次遇到同样的问题，切换到 Fable 5.1。问题解决后切换回来。
* 将搜索和日志阅读子代理放在 Sonnet 或 Haiku 上。将代码编辑保留在 Opus 5.5 上。
* 保持长会话持续进行，使其缓存保持热。
* 在不相关任务之间使用 /clear，在断点处使用 /compact 并注明要保留什么。
* **最重要的一点：**在每个模型上运行一个真实任务，比较 /usage 报告的内容。你自己的数字才是你应该信任的。
