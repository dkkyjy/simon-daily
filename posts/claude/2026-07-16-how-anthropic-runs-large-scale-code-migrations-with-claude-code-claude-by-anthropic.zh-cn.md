代码迁移——将生产代码库移植到新语言的项目——直到最近还是需要数年才能完成的工作。

在过去一个月里，Anthropic 的独立开发者使用 Claude Fable 5、Claude Opus 4.8 和[动态工作流](https://claude.com/blog/introducing-dynamic-workflows-in-claude-code)迁移了 10 个代码包，每个包含数万至数十万行代码。本文将介绍其中两个案例，并总结这些项目的最佳实践。

Bun 联合创始人兼 Anthropic 技术员工 Jarred Sumner 使用 Claude Code 将 [Bun 从 Zig 迁移到 Rust](https://bun.com/blog/bun-in-rust)。不到两周内生成了百万行代码，合并前 Bun 现有测试套件在 CI 中全部通过。合并后出现了 19 个回归问题，现已全部修复。Rust 移植版已于 6 月在 Claude Code 中发布。

Anthropic Labs 联合负责人 Mike Krieger 在一个周末内将 Python 代码库迁移到了 165,000 行 TypeScript。其中包括数百个代理、八个阶段门控、三轮对抗性审查，以及一次最终一致性检查，将每个命令的输出与 Python 原版进行差异对比。

Claude Code 的新功能改变了这些长期搁置项目的成本核算。以下是我们现在使用的六步流程，源自这些迁移带给我们的经验。

核心见解是：你不修复代码。**你修复产生代码的流程（循环）。**

## **为什么要迁移以及何时迁移语言**

在直接进入“如何做”之前，有必要先讨论“何时”和“为什么”，因为这些项目的假设已经发生了变化。

团队启动迁移是因为初始构建与当前项目之间的环境发生了变化。要么是已知的权衡变得限制性，要么是出现了更好的方法，要么是原始生态系统正在萎缩。

例如，Jarred 最初选择 Zig 是因为它在提供 C 级性能的同时具有极简性，适合一位独立创始人“在 LLM 时代之前，在一间狭小的奥克兰公寓里用 1 年写出 Bun”。这种简洁性伴随着已知的权衡，[他在这里写道](https://bun.com/blog/bun-in-rust#just-be-really-smart-and-don-t-make-mistakes)。

快进到 2026 年。Bun 的 CLI 每月下载量超过 1000 万次，并在 Claude Code 中被广泛使用。

就在上个季度，这些权衡还不足以成为冻结路线图并将资源投入到跨季度项目的理由。语言迁移可以带来更小、更快、更安全的系统，但没有人愿意为此买单。

软件工程师还不得不面对这些以往巨型项目中固有的职业风险。你可能需要在几个季度甚至几年内维护两个并行代码库，如果最终结果只达到 90% 的一致性，那你的麻烦比开始时要大得多。

现在，最坏的情况是删除分支，重新尝试。

不过，仍然需要有一个合理的商业理由。虽然百万行迁移不再需要在一个四年项目中花费 300 到 400 万美元的工程资源，但执行它们仍然需要数万到数十万美元甚至更多。例如，Bun 的迁移消耗了 59 亿个未缓存输入令牌和 6.9 亿个输出令牌——按 API 定价约为 16.5 万美元。Mike 移植的主要部分消耗了 2700 万个令牌。

*Jarred 的百万行 PR。*

**然而，迁移的理由不再需要是生死攸关的。** 变更日志中一年的内存错误修补，或一个长期瓶颈，现在就可以证明迁移的合理性。

编译步骤是 Mike 项目的推动力。他团队开发的内部工具以单个二进制文件的形式交付给用户。使用 Python 工具链生成该二进制文件每个平台大约需要 8 分钟，每次发布时在整个构建矩阵中总计需要等待 30 分钟。移植后，同样的编译现在只需要大约两秒钟，二进制文件启动速度提高了 6 倍，团队还退休了一个独立的部署流水线。

## **为什么 AI 改变了代码迁移的成本核算**

Claude Fable 5 是我们最强大、普遍可用的模型。Fable 和 Opus 4.8 特别擅长委托、指导、验证与子代理的并行工作流，同时寻找多条路径以达到既定目标。

大型代码迁移是这些高级模型的特别有效用例，因为：

* **工作是并行的**。工作可以在数千个独立单元（如文件和 crate）上并行执行，因此代理可以同时工作，而不是一个等待另一个。
* **上下文清晰且全面**。旧代码为模型提供了很好的规格说明。它也是构建翻译代理指南的核心参考。
* **有内置的裁判**。许多大型代码库都包含测试套件，代理可以用它来验证工作。当验证是客观的时候，代理表现最佳，因为模型可以连续多天与地面实况进行磨合，而无需人工仲裁质量。
* **队列自动生成**。当编译器或测试运行时失败，该失败项就成为代理要修复的下一个任务。
* **需要一致性和边缘情况处理**：流程的设计使得偏差无处藏身：审查者引用每条发现背后的规则，因此违规行为变成队列项，而不是悄然偏离。当代理遇到边缘情况时，修复方案会成为每个后续代理遵循的规则。
