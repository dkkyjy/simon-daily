# Anthropic 一位销售如何用 Claude Code 重建团队工作流程 | Claude by Anthropic

**日期：** 2026-06-05 00:00 UTC  
**链接：** https://claude.com/blog/how-anthropic-uses-claude-gtm-engineering

---

在 2024 年加入 Anthropic 之前，Jared Sires 从未写过一行代码。他也没理由要写——他是一名初创公司的客户经理。

在快速成长的公司里，这种情况很常见：Jared 的客户簿很快就增长到 600 到 700 个账户。每天要打 10 到 15 通客户电话，再加上不断扩大的客户名单，Jared 每天都要坐在办公桌前，回复客户邮件直到晚上 9 点或 10 点。

“管理收件箱几乎是不可能的，”他说，“而且还要做外呼，你根本不知道该把精力放在哪儿。”

Jared 向 Claude Code 求助。没有任何编程经验，他创建了 CLAFTS（即 *Claude Drafts* 的缩写）：一个运行在 Gmail 内部的应用程序，它利用 Claude API 来起草客户邮件的回复。这个过程经历了多次迭代，但最终 Jared 估计 CLAFTS 每天为他节省了两到三个小时。第二天早上他在 Slack 上分享了它，24 小时内，销售组织的其他人也开始使用，并取得了类似的效果。

这导致了 Jared 在 Anthropic 角色的转变：如今，他是市场推广团队的产品经理，专门负责识别 Anthropic 销售组织在运作中的问题，并构建基于 Claude 的解决方案来修复它们。在这个新角色中，Jared 构建了能够自动化客户沟通、在通话前研究客户背景、以及从会议记录中生成跟进邮件的工具。然后，他将这些工具打包成 [Claude Cowork](https://claude.com/product/cowork) 中的一个插件，使整个销售团队都能使用它们。

他将自己职业生涯的这一转变描述为“我经历过的最具赋能感的事”。

以下是 Jared 如何运用 Claude 大规模处理他的收件箱、他接下来在构建什么，以及 GTM 团队可以从他的方法中学到的最佳实践。

## **一个深陷行政事务的销售代表**

邮件量并不是 Jared 作为客户经理面临的唯一挑战。Anthropic 每 24 到 48 小时就会发布一次产品变更，而客户的问题往往集中在最新的细节上：批量 API 的 SLA、提示缓存折扣、模型定价、SDK 行为。要想回答好这些问题，意味着要在 Slack、Google 文档、内部知识库和开发者文档中搜索——而且日复一日，每次都要面对一组略有不同的事实。

“将技术文档传达给客户相当困难，尤其是在 Anthropic，产品变化如此之快，”Jared 说。

他最早用 Claude 做的实验之一既狭窄又实用。通过 Apps Script（Google 的轻量级开发平台）和 Claude，Jared 从内部系统中拉取产品使用数据，然后让 Claude 每天早上根据账户的增长速度对其进行排序。

“每天 Claude 都会给我一份简报，告诉我根据客户的使用情况，我需要重点关注谁，”他说。面对 700 个账户，每日简报帮助他确定该把外呼时间花在哪儿。

## **开发 CLAFTS**

更大的挑战是 Jared 的收件箱以及他需要花在回复邮件上的深夜时间。

借助 Claude Code，他开始开发一个系统，能够以他的语气起草客户邮件的回复。“Claude Code，名字里带着‘Code’这个词，一开始让我有点不敢上手，”他说，“但过了一段时间，我理解了它的能力——它可以连接到我的电脑，并回答关于文件的问题。”

CLAFTS 建立在大约 4300 行代码之上，几乎全部由 Claude Code 编写。它从一个共享的 Google Drive 文件夹和其他第三方工具中提取上下文，通过网络搜索引用 Anthropic 的公开文档，并匹配 Jared 的写作风格。等到他一天结束时打开草稿文件夹，回复已经准备好等待审核。

每当 Anthropic 发布产品变更，文档会随之更新，Claude 会在下一次起草时捕捉到这一变化。“Claude 能够通过网络搜索了解我们网站上最新的文档，并在生成邮件时引用这些材料，”Jared 说，“我不需要把所有信息都记在脑子里。”

开箱即用时，Claude 的写作往往更长，并且有较多的缓和语气短语，因此 Jared 重新调整了系统提示，直到草稿匹配他自己的写作风格。“我可能已经对 CLAFTS 的系统提示进行了数百次迭代，以生成不同风格的文案，”他说。

接下来，他开发了 CLAFTS 语气功能，该功能使用模式匹配来模仿他在不同关系中的语气。客户、同事和家人之间的通信读起来各不相同，草稿会根据不同对象进行调整。

Jared 通过用自己的个人账户给自己写一系列越来越愤怒的邮件来测试这个功能。Claude 捕捉到了这种语气，然后拒绝继续。

“Claude 开始模仿那种语气，然后某个时刻开始出现拒绝响应，因为 Claude 不想生成对客户生气的邮件，”他说，“那时我就知道 CLAFTS 语气功能奏效了。”

### **衡量 CLAFTS 的影响**

虽然 CLAFTS 每周为 Jared 节省 10 到 15 个小时，但他最在意的变化是工作的准确性。由于 Claude 在每次起草时都会从文档中获取最新的产品细节，客户收到的答案总是关联到最近发布的内容，而不是 Jared 碰巧记住的内容。

“在 CLAFTS 之前，我觉得自己做的行政工作比实际花在客户身上的时间还多，”Jared 说，“有了 CLAFTS 之后，我才能真正做我想做的事——也就是销售。”

## **扩展 Anthropic 的 GTM 工具包**

除了 Jared 之外，一位经常工作到午夜之后还在给客户发邮件的 BDR——John Albert，也帮助共同构建了 Clafts。当业务开发团队的其他成员看到他们的同事每天多出了几个小时之后，他们也开始加入。之后，他们自己完成了大部分的推广工作。

Jared 接下来构建的一套工具是为他的日历做“前包和后衬”的技能：每日简报和每日回顾。

每天早上，每日简报技能会阅读他的日历，对即将见面的人进行网络搜索，并在第一次通话前生成谈话要点。该技能通过 [MCP 服务器](https://www.anthropic.com/news/model-context-protocol)连接到 Google 日历和 CRM 数据，提取每个客户的相关信息。

而在一天结束时，每日回顾技能会从 Google 文档和会议记录中提取信息，起草跟进邮件，类似于 CLAFTS。

“把这两者结合起来，你就得到 Claude 管理你的日常任务，这本质上就成了一个智能体，”他说。

Jared 的工作现在进一步深入智能体领域，他正在尝试使用 [Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview) 并将工作流串联起来，使一次 Claude 运行的输出成为下一次运行的输入。

为了确保他使用 Claude Code 构建的工具能够在他所支持的更广泛团队中扩展，他通过 Claude Cowork 发布这些工具，将技能和 MCP 连接器打包成一个任何人都可以在几分钟内安装的插件。

在推出销售插件后的几个月内，Anthropic 大约 80% 的销售组织都在使用它。剩下的 20% 主要是新员工，Jared 认为这是下一个要解决的问题，因为这些技能正是为了帮助人们更快上手而构建的。

在插件之前，每个新员工都要花上几周时间摸索自己的工作流程。而现在，新员工在第一天就可以安装插件，并获得 20 多项已经连接到他们所用工具的技能：Salesforce、Intercom、Gong、Google 日历、Gmail、Google Drive 和 BigQuery。

销售团队插件中两个核心技能是：

1. `/customer-context`：在大约 90 秒内从所有这些来源提取 360 度账户视图。
2. `/pipeline-management`：显示有风险的交易、预测指导以及推进建议。

该包还与 Cowork 的调度功能集成，让代表可以安排技能自动运行。

“我们的销售人员可以回归到有意义的对话中，而不是去更新所有这些不同的应用程序，”他说。

## **架构下一步**

Jared 的角色随着工具的变化而改变。作为 GTM 架构师，他现在参与与产品工程师的设计讨论，并帮助塑造 Anthropic 销售团队的新工具。

“我觉得随着技术壁垒的消融，我几乎能够设计更多产品，并让高级工程师帮助我实现最后冲刺，”Jared 说，“我能够增强并做更多事情。”

对于那些想知道自己是否也能构建类似工具的销售人员，他的建议是：打开 Claude Code，找一个拖慢你速度的任务，然后问 Claude 如何为它构建一个解决方案。

“如果你一年前告诉我，我会成为 Anthropic 的市场推广产品经理，我会相当惊讶，”他说，“我从来不具备参与这些对话的技术能力。有了 Claude，我能够设计和构建不仅改善我自己日常工作流程，也改善我整个团队工作流程的东西。我有空间进行更具创造性和战略性的工作，而且没有回头路了。”
