当 Andy Reed 两年前加入 [Brex](https://www.brex.com/) 担任内容设计师时，他从没想过自己会写代码、构建 Figma 插件。

“如果没有 [Claude Code](https://www.anthropic.com/claude-code)，过去一个月我连一半的工作都完不成。”Reed 说。

而这一切正是 Reed 拥抱 [Claude Code](https://www.anthropic.com/claude-code)（Anthropic 的智能体式编码解决方案）后发生的——他的故事只是这家智能金融平台如何改变其公司工作方式的众多例子之一。

为了解更多，我们采访了三位 Brex 团队成员，了解他们如何使用 Claude Code：

* Hércules Gimenes，产品 AI 团队软件工程主管
* Sumeet Marwaha，数据与分析主管
* Andy Reed，高级内容设计师

从这些对话中浮现的，不仅仅是关于效率提升的故事（尽管团队报告在特定任务上实现了 3-4 倍的改进）。更重要的是关于如何从根本上重新构想公司协同工作方式，以简化工作流程、激发创造性解决问题并推动大规模协作。

## 以智能体式编码实现思维转变

对于 Hércules Gimenes 和他的产品 AI 团队来说，Claude Code 代表的意义远不止是一个新工具。

“Claude Code 带来了一种思维转变，”他解释道，“你不是坐在驾驶位上，而是作为 Claude 所做更改的评审者。你在引导愿景和方向。”

这种转变重新定义了 Brex 中“编写代码”的含义——这反映了该公司 AI 优先原则的实际应用。工程师不再把时间花在实现细节上，而是专注于架构和问题解决。结果呢？更好的代码，而不仅仅是更快的代码。

“我并不觉得用 Claude Code 节省了时间，”Gimenes 说，“我反而更深入地打磨了问题本身。你可以在相同的时间内针对同一个问题尝试三种方法，而经过第三种方法后，你对问题有了更清晰的理解，接口也更加干净。”

## 打破技术与非技术角色之间的壁垒

在产品 AI 团队探索提高代码质量新方法的同时，Reed 也在经历自己的顿悟。

作为一名内容设计师，他在 Claude Code 中发现了意想不到的东西：独立。

过去，更新一个简单的字符串意味着提交一个工单，然后等待工程师处理。现在，Reed 可以直接创建 PR，但真正的变革发生在他着手处理一个长期积压的项目时：将全面的内容指南集成到 Brex 设计系统的每个组件中。

“如果手动操作，可能需要几周甚至几个月，”Reed 解释道。借助 Claude Code，他在几天内完成了这个项目，系统地将来自内部风格指南、无障碍标准和外部最佳实践的内容特定指南添加了进去。

其影响波及了整个团队。工程师和设计师现在可以直接在他们的工具中嵌入内容指南，省去了不断交叉参考的麻烦，并在错误发生前就减少了它们。这是一个虽小但有力的例子，展示了智能金融在系统后台运行，让人们能够专注于更有价值、更具创造性的工作。

## 让数据访问在整个组织内民主化

与此同时，Sumeet Marwaha 的数据与分析团队正在解决一个不同但同样重要的挑战：让 Brex 的每个人都能访问数据，而不仅仅是 SQL 专家。

该团队构建了 Brex Explorer——一个由 Claude Code 和 MCP 服务器驱动的文本到 SQL 界面。现在，一位销售经理可以用自然语言提问：“在佛罗里达州杰克逊维尔，有多少客户在 Brex 账户中拥有超过 1000 万美元且在过去一年内完成入账？”系统会翻译该查询，运行并汇总结果。

真正的乘数效应来自他们的 AI 数据工程代理。那些以前需要专业知识的任务，比如添加数据表并进行所有必要的文件编辑和测试配置，现在任何工程师都能完成。

“这就像速度提升了 4 倍，同时大约有 2 倍以上的人员在贡献，”Marwaha 指出。Claude Code 在组织内的采用率已达到 50%，Marwaha 希望到月底能达到 100%。

## 拥有“万能工具”带来的意外收获

随着 Brex 各个团队采用 Claude Code，一些令人惊讶的用例出现了。在一次公司黑客马拉松中，Gimenes 使用 Claude Code 的无头模式在短短几小时内构建了一个复杂的提交代理，而这通常需要几天的开发时间。

Reed 发现他现在可以构建自己从未想象过的工具，比如一个能自动根据 Brex 标准检查设计的 Figma 插件。“感觉就像我拥有了世界上最棒的实习生，”他说。

但也许最重大的意外收获是 Claude Code 作为组织知识库的角色。鉴于 Brex 使用 Kotlin 和 Bazel 构建的复杂单体仓库结构，理解不同系统如何连接一直是个难题。现在，Claude Code 充当了一个“神谕”，可以立即回答关于代码库功能的问题。

“传统上，设计会议会讨论某个功能应该如何工作，但没有人真正了解背后的实现细节，”Reed 解释道。“现在，我的另一台显示器上就坐着这个神谕。”

## 在整家公司推广 Claude Code 最佳实践

随着 Claude Code 在 Brex 的普及，各个团队形成了一系列最佳实践，并已成为标准：

* **结构化上下文管理**：单体仓库中的每个主要目录现在都有自己的 CLAUDE.md 文件，包含特定领域的上下文。新工程师无需依赖团队内部知识就能了解 Mastercard 集成细节或银行监管要求。
* **自动化文档**：产品 AI 团队实现了 CI/CD 检查，当代码变更可能导致文档过时时，会触发更新。“拥有可信任的最新文档——这非常强大，”Gimenes 强调。
* **上下文感知命令**：团队创建了自定义命令，可自动加载相关上下文。例如，`/submit-pr` 命令在执行前会获取 git 状态、近期变更以及相关的 PR 信息。
* **从探索开始**：“能够找到你需要的东西，不再只是某个资深工程师脑子里的东西了，”Marwaha 观察到。“它就在代码库中，每个人都能访问。”

## Brex 中 Claude Code 的未来

Brex 的团队已经在规划下一代应用：

* 数据团队正准备攻克以前无法触及的项目，比如分析数万亿条信用卡交易明细数据点——这些工作以前因为过于繁琐而无法开展，但 Claude Code 让这一切变得可行。他们还在开发针对不同角色的代理，包括一个用于支持 RevOps 任务的代理。
* 产品 AI 团队设想了更复杂的上下文管理方式，文档会自动更新，上下文保持去中心化但依然可访问。

从构建技术工具的内容设计师，到实现数据访问民主化的数据分析师，Claude Code 已成为 Gimenes 所说的“万能工具”——用于整合 Brex 的领域知识与外部最佳实践。

这也突显了一个强大的双重性：Brex 为客户提供的智能金融——帮助他们更明智地消费、更快速地行动——与 Brex 团队内部的工作方式如出一辙，即赋能每一位员工，无论其技术背景如何，都能以速度和信心进行构建。
