自[推出技能（Skills）](https://claude.com/blog/skills)以来，我们从客户那里听到的两个最大问题是：“技能和 MCP 如何协同工作？什么时候该用其中一个，而不是另一个？”

[模型上下文协议（MCP）](https://modelcontextprotocol.io/docs/getting-started/intro)将 Claude 连接到第三方工具，而技能则教会 Claude 如何很好地使用这些工具。当两者结合时，你可以构建遵循团队工作流程的智能体，而不是那些需要不断修正的通用流程。

例如，与 Notion 的 MCP 连接让 Claude 能够搜索你的工作空间。再添加一个用于会议准备的技能，Claude 就知道要提取*哪些*页面、*如何*格式化准备文档、以及*你团队*在交付会议记录方面的标准。这种连接变得有用，而不仅仅是可用。

在本文中，我们将详细分析技能与 MCP 之间的关系，如何将两者结合以构建遵循你工作流程并产生一致输出的智能体，并通过几个实际案例来说明它们在实践中如何协同工作。

## **理解技能与 MCP**

你走进一家五金店，想修一个坏掉的橱柜。店里应有尽有（木胶、夹具、替换铰链），但知道买什么以及如何使用它们，却是另一个问题。

MCP 就像是能够进入各个货架。而技能则好比店员的专业知识。如果你不知道需要哪些物品或如何使用它们，再多的库存也无济于事。技能就像一个乐于助人的店员，会向你讲解维修流程，指给你正确的材料，并展示正确的技巧。

更具体地说，MCP 服务器让 Claude 能够访问你的外部系统、服务和平台，而技能则提供 Claude 有效使用这些连接所需的上下文，教会 Claude 现在有了这种访问权限后该做什么。

如果没有技能提供的上下文，Claude 只能猜测你想要什么。有了技能，Claude 就能遵循你的剧本。

## **为什么技能与 MCP 能够很好地协同工作**

MCP 处理连接性：安全、标准化的外部系统访问。无论是连接到 GitHub、Salesforce、Notion 还是你自己的内部 API，MCP 服务器都能让 Claude 触及你的工具和数据。

技能处理专业知识：将原始工具访问转化为可靠结果的领域知识与工作流程逻辑。技能知道何时查询你的 CRM、在结果中寻找什么、如何格式化输出，以及哪些边缘情况需要不同的处理方式。

这种分离保持了架构的可组合性。一个技能可以协调多个 MCP 服务器，而一个 MCP 服务器可以支持数十种不同的技能。添加一个新连接，现有技能就能将其纳入其中。完善一个技能，它就能在你所有的连接工具中工作。

#### **当你结合技能与 MCP 时，你会得到：**

**清晰的发现**：Claude 不再需要猜测在哪里查找。一个会议准备技能可能会指定：先查看项目页面，然后是之前的会议记录，接着是利益相关者资料。一个研究技能可能会说：从共享驱动器开始，与 CRM 交叉对照，然后用网络搜索填补空缺。技能对哪些来源适用于哪些任务进行了制度化的知识编码。

**可靠的编排**：多步骤工作流程变得可预测。没有技能时，Claude 可能会在检查是否拥有所有必要数据之前就拉取数据并格式化。技能明确地定义了顺序，因此 Claude 每次都以相同的方式执行工作流程。

**一致的性能**：输出实际符合标准。通用结果需要编辑。技能为你的团队定义了“完成”的样子：正确的结构、正确的详细程度、适合受众的语调。

随着时间的推移，团队会积累起互相关联的技能和连接集合，使 Claude 在特定领域拥有专业知识。

**进一步阅读**：Tim O'Reilly 关于 [MCP 和技能对开源 AI 的意义](https://www.oreilly.com/radar/what-mcp-and-claude-skills-teach-us-about-open-source-for-ai/)

技能与 MCP 如何协同工作：MCP 提供工具访问，技能提供工作流程逻辑。

#### **技能与 MCP 可能重叠的地方**

MCP 服务器可能包含工具使用提示和常见任务提示形式的指令。这可以使工具特定的知识贴近工具本身。然而，这些指令在设计上应保持通用。

经验法则：MCP 指令涵盖如何正确使用服务器及其工具。技能指令涵盖如何针对特定流程或多服务器工作流程使用它们。

例如，一个 Salesforce MCP 服务器可能指定查询语法和 API 格式。一个技能则会指定首先检查哪些记录，如何将它们与 Slack 对话进行交叉对照以获取近期上下文，以及如何为团队的流水线审查构建输出。

在结合 MCP 服务器和技能时，请注意冲突的指令。如果你的 MCP 服务器要求返回 JSON，而你的技能要求格式化为 Markdown 表格，Claude 就必须猜测哪个是正确的。让 MCP 处理连接性，让技能处理呈现、顺序和工作流程逻辑。

## **技能与 MCP 结合使用的实际案例**

现在让我们看看技能和 MCP 如何在真实工作流程中结合。我们将介绍两个例子：金融分析师拉取实时市场数据进行公司估值，以及项目经理使用 Notion 的会议智能技能进行会议准备。

在这两种情况下，MCP 服务器提供对工具的访问，而技能则定义了如何利用这些访问。

#### **金融分析：公司估值自动化技能**

[Anthropic 发布了一套预构建技能](https://www.anthropic.com/news/advancing-claude-for-financial-services)，用于常见的金融工作流程，包括可比公司分析。可比公司分析是一种标准的估值方法。进行可比公司分析的分析师会花费数小时从多个来源拉取财务指标，应用相同的估值方法，并格式化输出以符合合规标准。这繁琐、容易出错，正是技能和 MCP 协同工作能带来好处的流程。

**技能**：[可比公司分析](https://www.anthropic.com/news/advancing-claude-for-financial-services)自动化了这种估值工作流程，从多个来源拉取数据，应用一致的方法，并按照特定标准格式化输出。

**MCP 服务器**：连接到 S&P Capital IQ、Daloopa 和 Morningstar 以获取实时市场数据。

**工作流程**：

1. 技能识别要查询哪些数据来源（发现）
2. MCP 连接拉取实时财务数据
3. 技能应用方法并格式化输出（编排）
4. 技能根据合规要求进行验证（性能）

#### **会议准备：Notion 的会议智能技能**

会议准备很繁琐。你需要从多个地方获取上下文，如项目文档、之前的会议记录和利益相关者信息，然后将其综合成预读材料和议程。这是一种多步骤流程，每次都需要重新解释。

**技能**：[会议智能](https://notiondevs.notion.site/notion-skills-for-claude)定义了要搜索哪些页面、如何构建输出、包含哪些部分。

**MCP 服务器**：Notion 连接，可搜索、读取和创建页面。

**工作流程**：

1. 技能识别要搜索的相关页面，包括项目、之前的会议、利益相关者信息（发现）
2. MCP 连接搜索并从 Notion 获取内容
3. 技能构建两份文档：内部预读材料和外部议程（编排）
4. MCP 连接将两份文档保存到 Notion，组织好并添加链接
5. 技能确保输出符合格式化标准（性能）

## **何时使用技能 vs. MCP**

技能和 MCP 解决不同的问题，但针对特定工作流程决定使用哪个并不总是显而易见的。

#### **技能用于什么场景**

技能捕捉那些原本存在于你脑海中的知识，或者每当有新成员加入团队时都需要重新解释的知识。它们最适合：

* **涉及工具的多步骤工作流程**：从多个来源提取信息，然后创建结构化文档的会议准备。
* **需要一致性的流程**：每次都必须遵循相同方法的季度财务分析，带有强制检查点的合规审查。
* **你想要捕获和分享的领域专业知识**：研究方法、代码审查标准、写作指南。
* **团队成员离开时仍应保留的工作流程**：编码为可重用指令的制度化知识。

#### **MCP 服务器用于什么场景**

MCP 扩展了 Claude 可以访问和使用的内容。当你需要以下功能时使用 MCP：

* **实时数据访问**：搜索 Notion 页面、读取 Slack 消息、查询数据库。
* **外部系统中的操作**：创建 GitHub Issue、更新项目管理工具、发送通知。
* **文件操作**：从 Google Drive 读取和写入、访问本地文件系统。
* **API 集成**：连接到没有原生 Claude 支持的服务。

如果你在解释*如何*做某事，那是一个技能。如果你需要 Claude *访问*某物，那是 MCP。

#### ***快速参考表：技能与 MCP 的区别***

| | 技能 | MCP |
| --- | --- | --- |
| **是什么** | 程序性知识 | 工具连接性 |
| **做什么** | 教 Claude *如何*做某事 | 让 Claude *访问*某物 |
| **何时加载** | 按需，相关时 | 连接后始终可用 |
| **包含** | 指令、脚本、模板、资产 | 工具、资源、提示 |
| **Token 行为** | 按需加载，节省上下文 | 定义预先加载 |
| **最适合** | 工作流程、标准、方法 | 数据访问、API 调用、外部操作 |

## **常见问题**

#### **技能会取代 MCP 吗？**

不会。技能和 MCP 解决不同的问题。MCP 提供对外部工具和数据的连接性。技能提供如何有效使用这种连接性的程序性知识。最强大的工作流程两者都会用到。

#### **一个技能可以使用多个 MCP 服务器吗？**

可以。一个技能可以同时协调多个 MCP 服务器。一个技术竞争分析技能可能搜索 Google Drive 获取内部研究，从 GitHub 拉取竞争对手仓库，并通过网络搜索收集市场数据。

#### **我可以为一个 MCP 服务器构建多个技能吗？**

可以。一个技能可以提升你从单个 MCP 连接中获得的价值。Notion 展示了这种模式，为会议准备、研究、知识捕获以及规格到实现设计了不同的技能——请[在此处](https://claude.com/connectors/notion)查看它们。

## **开始使用**

准备好了吗？以下是如何开始构建技能*和* MCP：

**使用技能：**

* 在 [claude.ai](https://claude.ai) 的设置 → 功能中启用技能
* 浏览[技能库](https://github.com/anthropics/skills)中的预构建示例
* 阅读[技能文档](https://docs.anthropic.com/en/docs/agents-and-tools/agent-skills)

**使用 MCP：**

* 浏览[MCP 服务器](https://github.com/modelcontextprotocol/servers)中的工具
* 阅读[MCP 文档](https://modelcontextprotocol.io/introduction)
* 通过 [MCP 快速入门](https://modelcontextprotocol.io/quickstart)构建你自己的服务器

**两者结合：**

* 连接一个 MCP 服务器，然后添加一个使用该服务器的技能
