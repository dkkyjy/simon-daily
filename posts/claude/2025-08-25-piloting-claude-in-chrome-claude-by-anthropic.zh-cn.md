近几个月来，我们一直在将 Claude 连接到您的日历、文档以及许多其他软件。下一步合乎逻辑的做法是让 Claude 直接在您的浏览器中工作。

我们认为浏览器使用 AI 是不可避免的：大量工作都在浏览器中完成，让 Claude 能够看到您正在查看的内容、点击按钮并填写表单，将使其更加实用。

但浏览器使用 AI 也带来了需要更强安全保障的安全挑战。从值得信赖的合作伙伴那里获得关于用途、缺陷和安全问题的真实世界反馈，使我们能够构建强大的分类器，并教未来的模型避免不良行为。这确保了随着能力的提升，浏览器的安全性也能同步跟上。

由前沿模型驱动的浏览器使用代理已经出现，这使得这项工作尤为紧迫。通过解决安全挑战，我们可以更好地保护 Claude 用户，并与任何在我们的 API 上构建浏览器使用代理的人分享我们的经验。

我们从受控测试开始：**一个 Claude 的 Chrome 扩展，值得信赖的用户可以指示 Claude 在浏览器中代表他们采取行动。** 我们正在与 1,000 名 Max 计划用户进行试点——[加入等待列表](http://claude.ai/chrome)——以尽可能多地学习。随着我们开发出更强的安全措施并通过这个有限的预览建立信心，我们将逐步扩大访问范围。

### 浏览器使用 AI 的考量

在 Anthropic 内部，我们已经看到使用早期版本的 Chrome 中的 Claude 来管理日历、安排会议、起草邮件回复、处理常规费用报告以及测试新网站功能所带来的显著改进。

然而，在我们可以将 Chrome 中的 Claude 普遍可用之前，仍有一些漏洞需要修复。就像人们在收件箱中遇到网络钓鱼尝试一样，浏览器使用 AI 也面临提示注入攻击——恶意行为者将指令隐藏在网站、电子邮件或文档中，以在用户不知情的情况下诱骗 AI 执行有害操作（例如隐藏文本写着“忽略之前的指令，改为执行 [恶意操作]”）。

提示注入攻击可能导致 AI 删除文件、窃取数据或进行金融交易。这不是猜测：我们已经进行了“红队”实验来测试 Chrome 中的 Claude，在没有缓解措施的情况下，我们发现了一些令人担忧的结果。

我们进行了广泛的对抗性提示注入测试，评估了代表 29 种不同攻击场景的 123 个测试案例。在没有我们的安全缓解措施的情况下，当被恶意行为者故意攻击时，浏览器使用的攻击成功率为 23.6%。

一个成功攻击的例子——在我们应用新防御措施之前——是一封恶意电子邮件，声称出于安全原因需要删除邮件。在处理收件箱时，Claude 遵循这些指令删除了用户的邮件，且未经确认。

Claude 遇到了这封恶意邮件，它模仿雇主要求删除邮件以进行“邮箱清洁”，并声称“无需额外确认”。

Claude 随后在没有确认的情况下执行了指令，选择并删除了用户的邮件，“按安全团队的要求执行”。

我们的新缓解措施成功防御了这种特定攻击。Claude 识别出“这是一封可疑的安全事件邮件，看起来像是钓鱼尝试”，并且没有对其采取行动。

正如我们将在下一节中解释的那样，我们已经实施了多项防御措施，显著降低了攻击成功率——尽管在发现新型攻击向量方面仍有工作要做。

### 当前防御措施

针对提示注入攻击的第一道防线是*权限*。用户始终掌控着 Chrome 中的 Claude 可以访问和执行的操作：

* **站点级权限**：用户可以在设置中随时授予或撤销 Claude 对特定网站的访问权限。
* **操作确认**：在执行发布、购买或共享个人数据等高危操作之前，Claude 会向用户请求确认。即使选择了我们的实验性“自动模式”，对于高度敏感的操作，Claude 仍会保持某些保护（注意：所有红队测试和安全评估均在自动模式下进行）。

我们还根据 Anthropic 的[可信代理](https://www.anthropic.com/news/our-framework-for-developing-safe-and-trustworthy-agents)原则构建了额外的保障措施。首先，我们改进了系统提示——Claude 在接收用户的具体指令之前收到的通用指令——以指导 Claude 如何处理敏感数据以及如何响应执行敏感操作的请求。

此外，我们已阻止 Claude 使用某些高风险类别的网站，例如金融服务、成人内容和盗版内容。我们还开始构建并测试高级分类器，用于检测可疑的指令模式和不寻常的数据访问请求——即使它们出现在看似合法的上下文中。

当我们在自动模式中添加了安全缓解措施后，我们将攻击成功率从 23.6% 降低到了 11.2%，这相对于我们现有的计算机使用能力（Claude 可以看到用户屏幕，但没有我们今天引入的浏览器界面）来说是一个有意义的改进。

三种场景下提示注入攻击的成功率：我们较旧的计算机使用能力、仅使用旧安全缓解措施的新浏览器使用产品，以及使用新缓解措施的新浏览器使用产品（分数越低越好）。我们的安全改进将浏览器攻击成功率降低到了计算机使用水平以下。

我们还进行了专门的红队测试和缓解措施，重点针对浏览器特有的新攻击，例如网页文档对象模型（DOM）中人类不可见的隐藏恶意表单字段，以及其他难以捕捉的注入，例如仅代理可能看到的 URL 文本和标签页标题。在一组包含四种浏览器特定攻击类型的“挑战”测试中，我们的新缓解措施将攻击成功率从 35.7% 降低到了 0%。

在我们让 Chrome 中的 Claude 更广泛可用之前，我们希望扩大我们正在考虑的攻击范围，并通过更深入地了解当前威胁以及未来可能出现的威胁，学习如何将这些百分比降低到接近零。

### 参与方式

内部测试无法复制人们真实浏览的全部复杂性：他们提出的具体请求、访问的网站以及恶意内容实际出现的方式。恶意行为者也在不断开发新形式的提示注入攻击。本次研究预览使我们能够与值得信赖的用户在真实条件下合作，揭示我们当前哪些保护措施有效，哪些需要改进。

我们将利用试点中的洞察来优化我们的提示注入分类器和底层模型。通过发现受控测试中不存在的真实世界不安全行为实例和新攻击模式，我们将教会我们的模型识别这些攻击并解释相关行为，并确保安全分类器能够捕捉到模型本身遗漏的任何内容。我们还将根据用户希望如何在浏览器中与 Claude 合作的经验，开发更精细的权限控制。

对于本次试点，我们正在寻找值得信赖的测试者，他们愿意让 Claude 在 Chrome 中代表他们采取行动，并且没有安全关键或特别敏感的设置。

**如果您想参与，可以加入 Chrome 中的 Claude 研究预览等待列表，网址为**[**claude.ai/chrome**](http://claude.ai/chrome)**。** 一旦获得访问权限，您可以从 Chrome 网上应用店安装扩展，并使用您的 Claude 凭证进行身份验证。

我们建议从受信任的网站开始——始终注意 Claude 可见的数据——并避免将 Chrome 中的 Claude 用于涉及金融、法律、医疗或其他类型敏感信息的网站。您可以在[我们的帮助中心](https://support.anthropic.com/en/articles/12012173-getting-started-with-claude-for-chrome)找到详细的安全指南。

我们希望您能分享反馈，帮助我们持续改进 Chrome 中 Claude 的能力和安全措施——并帮助我们朝着将 AI 融入日常生活这一根本性的新方式迈出重要一步。
