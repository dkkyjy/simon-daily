# 在 Claude Code 中选择 Claude 模型与努力程度

            **日期：** 2026-07-07 00:00 UTC
            **链接：** https://claude.com/blog/claude-model-and-effort-level-in-claude-code

            ---

            **关键要点**：

* Claude 模型选择决定了固定权重的集合，即模型的整体能力范围。虽然可以为模型提供上下文或引导，但模型的整体知识库和能力是固定的。
* 努力程度不仅仅意味着“思考时间”。它控制着 Claude 为你的请求所做的工作总量，包括读取的文件数量、使用的工具数量，以及在向你反馈之前所经历的步骤数。
* 对于更常规的任务选择较小的模型，对于更复杂或模糊的任务选择较大的模型。从每个模型的默认努力程度开始，并根据你所做工作的类型（而非逐个任务）将其调整为一个通用偏好。
* 如果 Claude 拥有所有相关上下文、明确尝试过但仍然出错，这表明需要选择一个能力更强的模型。如果 Claude 因跳过文件、未运行测试或中途放弃重构而出错，则应选择更高的努力程度。

## **Claude Code 努力程度与模型选择**

Claude Code 提供了两个看似能“让答案更好”的设置：模型设置和努力程度。你可能会认为，像 Claude Fable 5 这样的大型模型比 Claude Sonnet 能提供更智能的输出，而更高的努力程度意味着 Claude 在回答前会思考更久。

第一个假设是准确的。根据行业标准基准测试，我们最大的模型能力更强。

但努力程度不仅仅意味着“思考时间”。努力程度控制着 Claude 为你的请求所做的工作总量。这确实包括模型思考的时间，但也包括：

* 它读取了多少文件；
* 它验证了多少内容；
* 以及在向你反馈之前，它在多步骤任务中推进了多远。

在更高的努力程度下，Claude 会在向你反馈之前采取更多此类行动（例如，读取文件、运行测试和再次检查）。在较低的努力程度下，它宁愿向你询问更多上下文，也不愿花费 token 自行解决问题。

## **模型选择的工作原理**

当你按下回车键时，Claude Code 会将你的消息与系统提示、工具定义、你的 CLAUDE.md、对话历史以及上下文中的任何文件组合在一起。所有这些内容都作为一个请求发送到 API。

Claude Code 拥有的所有内容都被打包到一个 API 请求中。在服务器端，文本在到达模型之前会被进行**分词**处理。

不过，模型并不会将其视为纯文本。服务器上发生的第一件事是**分词**；文本被分割成片段，每个片段映射到模型训练时使用的固定词汇表中的一个整数。`const` 可能映射到 1978，`await` 可能映射到 4293。从这里开始，你的提示就是一个整数数组。

分词器将你的文本分割成片段，并将每个片段映射到固定词汇表中的一个整数。顶行的每个块都变成其 token ID（底行）；所示的 ID 仅供说明。

模型的工作是接收该数组并预测接下来会出现哪个 token。它通过计算词汇表中每个 token 的*概率*并从顶部进行选择来实现这一点。在 `const x = await` 之后，一个训练有素的模型会对 `fetch`（非常可能）赋予高概率，而对 `banana`（非常不可能）赋予接近零的概率。

模型的预测是其词汇表中每个 token 的概率。顶部猜测与不相关猜测之间的差距是巨大的。

将你的输入 token 转化为这些概率的是**权重**（也称为*参数*）。这些是组织成大型矩阵的数十亿个数字。为了预测一个 token，模型通过那些矩阵（一个长长的矩阵乘法链）运行你的输入，并在最后读取概率。权重是模型“知道”的一切所在。

**每个模型的权重在训练期间就已设定，当你发送请求时，它们是只读的。** 你的提示、你的 CLAUDE.md 或你的上下文中的任何内容都不会改变它们。（如果你遇到过“推理”这个词，这就是它的全部含义：在训练完成后使用模型，且权重是固定的。）

你的提示进入，概率输出。中间的权重不会改变。

Claude 所了解的关于 TypeScript、流行框架、惯用 Go 或任何其他通用编程知识的一切，都在训练时被编码到了这些权重中。

你的提示和上下文仍然可以*引导*预测（将你的真实代码放在 Claude 面前就是*引导*，效果很好），但它们不会向权重本身添加任何内容。

如果一个库在模型训练时还不存在，它就不在权重中。你可以将文档放在上下文中，Claude 会使用它们，但那是*引导*，而不是*教学*。Claude 的响应只会受该请求影响；底层模型并未保留该信息。

因此，当 Claude 自信地调用一个不存在的 API（即幻觉）时，那是权重在产生一个从训练模式来看*看似*合理的 token 序列，而不是一次失败的查找。

那么，更改模型实际上会做什么呢？它交换了**处理你请求的是哪一组冻结的权重**。

模型不会一次性生成整个答案。它预测一个 token，将其附加到序列中，然后再次运行整个计算以获取下一个 token。一个 200 个 token 的响应需要经过 200 次独立的权重传递。这个循环是你大部分等待时间和输出成本的来源。

序列每一步只增长一个 token。模型每次都会重新读取整个数组以预测接下来会发生什么。

因此，**模型设置**决定了*哪些权重*处理你的请求，同时也决定了每个输出 token 的成本。

它不决定的是会生成多少个 token。对于相同的提示，这个数字可能会有很大差异，具体取决于 Claude 决定做多少工作。

这就是**努力程度**所控制的：Claude 决定为每一轮交互做*多少工作*。

## **努力程度的工作原理**

当 Claude Code 处理任务时，它生成的 token 分为几类：

* **思考**：你在操作之前和操作之间看到的推理过程。
* **工具调用**：命名的结构化块，例如 `Read` 或 `Edit` 及其参数，Claude Code 随后会解析并执行这些块。
* **给你的文本**：计划、进度更新、最后的总结。

这些都是来自同一循环的普通输出 token，按相同费率计费。例如，思考 token 的生成方式与其他输出 token 完全相同，并且在该轮交互的剩余时间内保留在上下文中。

当 Claude 继续编写代码时，它之前的推理会成为输入的一部分，就像它读取过的文件一样。

Claude 的所有输出都是 token。思考、工具调用和给你的文本都来自同一个循环。

努力程度如何改变这一切？努力程度作为请求的一部分与你的提示一起发送给模型。模型经过训练，能够理解在每个努力程度下应该如何表现，并且这种习得的行为被固化在冻结的权重中。

当你的请求到达时，努力程度是模型响应的另一个输入，就像它响应你的提示文本一样。这设定了 Claude 在认为任务完成之前需要达到的彻底性和确定性程度。

**这在每一轮交互中都会被考虑**，并导致生成更多的 token 以产生更高置信度的答案。

相同的提示，两种努力程度。高努力路径生成的 token 数量大约是低努力路径的 7 倍，以达到更高置信度的答案。

在更高的努力程度下，Claude 通常从制定计划开始，努力程度会影响该计划的深度和广度。然而，计划并非一成不变。当 Claude 收到其行动的结果时，它会更新已取得的进展以及它对累积结果的确定程度。

因此，当一个包含三个假设的调试计划的步骤 1 发现了 bug 时，“调查假设 2 和 3”可能不再是必要的行动。Claude 通常会明确说明这一点，“第一次检查找到了，所以剩余的检查不需要了”，然后跳过。当任务列表在运行中被修改时，你可以在 Claude Code 中看到这种情况发生。

在更高的努力程度下，Claude 更倾向于再次检查额外的假设或验证正确性，但对于简单的任务，它通常不会人为地增加使用量。事实上，我们的团队在模型训练期间密切关注“过度思考”，因为它会降低效率。

## **选择努力程度**

我们的指导是，**对于大多数任务，你应该使用模型的默认努力程度**。默认水平是 Claude 会根据大多数人愿意在任务上花费的 token 数量来调整其 token 使用量的水平。

将努力程度视为一个手动覆盖选项，用于调整 Claude 工作的努力程度和时长。当你基于你的领域或所做的工作类型，对彻底性或速度有强烈偏好时，有意识地选择它。更多地将其视为一个通用偏好，而不是一个逐任务的决定。

一些可能有助于指导你的实用见解，继 [Claude Opus 4.8 发布](https://www.anthropic.com/news/claude-opus-4-8)之后：在我们的测试中，我们发现，当你在 Opus 4.8 上使用默认努力设置时，与在同一任务上使用 Opus 4.7 的默认努力设置相比，它会在大约相同数量的 token 下产生更好的结果。

## **当 Claude 出错时该更改什么**

当 Claude 出错时，你的第一反应不应该是调整旋钮，而是检查你提供的上下文。你的提示是否太模糊？Claude 是否连接了正确的工具？是否配备了正确的技能？

如果你在增加一个*不应该*需要它的任务的努力程度，那么修复通常在上游，在你的上下文、你的 CLAUDE.md 或任务的范围界定中。

但假设你提供了清晰的上下文，而 Claude 仍然出错，那么要问自己的问题是：它是没有*足够努力*，还是它*知识不够*？

两个问题，一个后备方案。使用启发式方法来选择一个起点，而不是一条硬性规则。

### **模型：问题太难了**

当问题确实很难时，选择更大的模型。例如，像微妙的 bug、不熟悉的领域或架构决策这样的问题。对于较小的模型无论你提供多少上下文都会自信地出错的情况，更大的模型会有所帮助。

更大的模型也更擅长处理模糊性，而具体的执行指令则更适合在较小的模型上取得成功。

当工作是常规性的时，选择较小的模型。例如，你可以精确描述的编辑、机械性的更改，或者关于已在上下文中的代码的问题。没有理由为任务不需要的能力付费。

如果 Claude 拥有所有相关上下文，并且明确尝试过但仍然出错，这表明需要选择更大的模型。如果你正在使用更大的模型，并且工作已经常规了一段时间，降低模型等级通常会提高速度并通常降低成本，而不会影响输出质量。

### **努力程度：Claude 不够努力**

如果 Claude 因跳过文件、未运行测试或未再次检查其工作而出错，则选择更高的努力程度。如果你选择的努力程度低于模型的默认值，这最为相关。

## **Fable vs. Opus vs. Sonnet：专家、行家与通才**

我喜欢思考这两个设置如何关联的一种方式：Fable 是见过几乎无人见过的问题的专家，Opus 是行家，而 Sonnet 是非常优秀的通才。努力程度决定了他们中任何一个人在你的任务上花费多少时间。

**低努力程度的 Opus** 就像与一位对你这类问题有深厚经验的行家交谈五分钟。他们带来了你的代码库中不存在的知识：他们以前见过的模式、他们知道要检查的陷阱，只有解决过大量类似问题才能获得的那种东西。但只给他们五分钟意味着快速阅读你的代码，而不是仔细阅读。

**高努力程度的 Sonnet** 就像给一位非常优秀的通才整个下午的时间。他们会阅读所有内容，运行程序，再次检查他们的工作，最终彻底理解*你的特定代码*。他们较少带来的是那种“我确切地见过这个”的识别能力。

**即使是低努力程度的 Fable**，也是那位专家瞥一眼其他人都卡住的问题，仍然能发现别人发现不了的东西。这种识别能力正是你付出最高代价所获得的，所以值得将其保留给真正需要它的任务。

这些都不是普遍更好的。模型设置大致是*能力有多强*；努力程度大致是*有多彻底*。大多数实际任务需要两者兼备。

## **努力程度、模型与 token 消耗**

那么，模型选择、努力程度和 token 消耗之间如何相互作用？这取决于任务。

在相同努力程度下的常规工作中，两个模型通常都能正确完成。较大的模型会消耗更多的 token，用于额外的验证步骤，且每个 token 的价格更高。这就是为什么在常规工作期间切换到较小的模型可以在不牺牲质量的情况下节省实际费用。

曲线仅供说明，显示的是单个足够简单、两个模型都能快速完成的任务。它们不代表真实的基准数据。

在更困难、多步骤的工作中，情况则不同。较小的模型必须在其能力极限附近挣扎，消耗大量迭代次数，而较大的模型可以用更少的步骤达到相同的质量水平。

你为较大的模型每个 token 支付更多费用，但在那些真正考验较小模型的任务上，每个任务的总成本可能会更低。而且，更重要的是，较大的模型可以完成较小的模型即使在最高努力程度设置下也无法完成的任务。

这在 Fable 上最为明显。在长期、多步骤的工作中，它领先最多。在我们的测试中，它完成了 Opus 和 Sonnet 在任何努力程度下都无法达到的工作。它的每个 token 成本也最高，这是将其保留给需要它的工作的另一个原因。

曲线仅供说明，显示的是单个足够困难、足以考验两个模型的任务。它们不代表真实的基准数据。

上图中的关键点是，努力程度决定了 Claude **愿意沿着曲线走多远**，但同样，这并不意味着 Claude **需要走那么远**才能完成任务。

另一个细微差别是：努力程度塑造了 token 消耗，但并不限制它。系统中唯一的硬性上限是 [max\_tokens](https://platform.claude.com/docs/en/build-with-claude/extended-thinking#max-tokens-and-context-window-size-with-extended-thinking)，当达到该上限时，它会截断正在进行的响应。这是一个生硬的工具，主要与 API 开发者相关。更柔和的控件，例如[任务预算](https://platform.claude.com/docs/en/build-with-claude/task-budgets#task-budgets-are-advisory-not-enforced)或在提示中要求 Claude 保持简洁，是更有用的工具。它们作为模型经过训练要遵循的指导（如果接近限制，它会寻求结束其任务）而不是它撞上的墙。

## **从默认值开始，然后调整旋钮**

大多数时候，你不应该考虑这两个设置中的任何一个。当结果未达预期时，问自己“Claude 是知识不够还是不够努力？”然后根据需要调整。
