智能体、机械化和工业化

所有 Datadog 工程师都在生产代码中使用 AI 编码工具，而 Claude Code 至少驱动了其中的三分之二。借助 Claude Code，他们在软件开发生命周期中生成个性化流程，涵盖四个不同的类别：

* **定向修改：** 数十个棘手的 bug 修复、性能优化以及与现有服务的桥接。
* **大型重构：** 在三天内重构自定义 protobuf 解析器，以及在不到三个月内将指标控制从 FoundationDB 重写为 Postgres。
* **替换大规模组件：** 新的分片算法和自动扩缩容重新设计。
* **构建整个系统：** 将 MongoDB 替换为 Postgres、BYOC 控制平面以及从头构建的数据采集管道。

然而，随着工作流在这张地图上推进，他们发现：在一端生成变得更加复杂，在另一端验证也变得更加模糊。

## 流程问题

对工程师而言，“流程”曾经意味着意图与代码之间的直接关系。你理解问题、编写代码、测试、审查、发布、运维，然后重复。而有了智能体，这种抽象正在迅速变化。

“你不再编写代码；你是在塑造工作。你决定智能体应该看到什么、拥有哪些工具、成功的定义是什么、如何检测失败……这就像每个人都向上晋升了三级，进入了管理层，而这并不是他们想要的，因为他们是工程师。”——Datadog 工程副总裁 Sesh Nalla。

通过 [Claude Managed Agents](https://platform.claude.com/docs/en/managed-agents/overview) 这类方法，Datadog 的会话运行时间更长，有时长达数天。每个智能体都会自行发明自己的工具、自己的胶水代码以及自己的约定。这些智能体变得更有用，但需要人类来弥合智能体执行与为人类设计的工具之间的差距。

机床是你在制造业中看到的夹具、治具、量具和铣床。它们可以生产出精确、可重复的零件，然后组装成更大型、更复杂的机器，如发动机、飞机、核反应堆和登月舱。它们是工业化的突破——因为零件变得可组合、可检验、可更换。

Temper 就是 Sesh 所说的 Datadog 为智能体系统构建万能机床的尝试。换句话说，它是智能体以安全、精确的方式构建所需内容所需的最小核心。

“这就是我觉得需要更结构化方案的时刻，” Sesh 说道，“如果智能体要构建和运维我们系统、数据库（这些都是关键任务）的很大一部分，它们就需要等同于这个机床概念的东西。Temper 就是 Datadog 的这台机床。”
