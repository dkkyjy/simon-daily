## 何时使用提示缓存

提示缓存在您希望一次性发送大量提示上下文，然后在后续请求中重复引用该信息的情况下非常有效，包括：

* **对话代理：** 减少长时间对话（尤其是带有长指令或上传文档的对话）的成本和延迟。
* **编码助手：** 通过在提示中保留代码库的摘要版本来改进自动补全和代码库问答。
* **大型文档处理：** 在提示中纳入完整的长期材料（包括图像），而不会增加响应延迟。
* **详细指令集：** 共享广泛的指令、程序和示例列表，以微调Claude的响应。开发者通常会在提示中包含几个示例，但借助提示缓存，您可以通过包含数十个高质量输出的多样化示例来获得更好的性能。
* **代理搜索和工具使用：** 增强涉及多轮工具调用和迭代更改的场景的性能，其中每个步骤通常需要新的API调用。
* **与书籍、论文、文档、播客转录和其他长期内容对话：** 通过将整个文档嵌入提示中，并让用户提问，使任何知识库变得生动。

早期客户已在各种用例中看到了提示缓存带来的显著速度和成本改进——从包含完整知识库到100次示例，再到将对话的每一轮都包含在提示中。

| **用例** | **无缓存的延迟（到第一个令牌的时间）** | **有缓存的延迟（到第一个令牌的时间）** | **成本降低** |
| --- | --- | --- | --- |
| 与书籍聊天（100,000令牌缓存提示）[1] | 11.5秒 | 2.4秒（-79%） | -90% |
| 多示例提示（10,000令牌提示）[1] | 1.6秒 | 1.1秒（-31%） | -86% |
| 多轮对话（带有长系统提示的10轮对话）[2] | ~10秒 | ~2.5秒（-75%） | -53% |

### 我们如何为缓存的提示定价

缓存的提示根据您缓存的输入令牌数量以及您使用该内容的频率来定价。写入缓存的成本比任何给定模型的基础输入令牌价格高出25%，而使用缓存内容则便宜得多，仅为基础输入令牌价格的10%。

|  |  |  |  |
| --- | --- | --- | --- |
| **Claude 3.5 Sonnet**  * 我们迄今为止最智能的模型 * 200K上下文窗口 | **输入**  * $3 / MTok | **提示缓存**  * $3.75 / MTok -   缓存写入 * $0.30 / MTok - 缓存读取 | **输出**   * $15 / MTok |
| **Claude 3 Opus**  * 适用于复杂任务的强大模型 * 200K上下文窗口 | **输入**  * $15 / MTok | **提示缓存**  * $18.75 / MTok -   缓存写入 * $1.50 / MTok - 缓存读取 | **输出**  * $75 / MTok |
| **Claude 3 Haiku**  * 最快、最具成本效益的模型 * 200K上下文窗口 | **输入**  * $0.25 / MTok | **提示缓存**  * $0.30 / MTok   -   缓存写入 * $0.03 / MTok - 缓存读取 | **输出**  * $1.25 / MTok |
