**关键要点：**

* Claude 模型选择决定的是固定的权重集，即模型的整体能力范围。虽然可以为模型提供上下文或进行引导，但模型的整体知识库和能力是固定的。
* 努力不仅仅意味着“思考时间”。它控制着 Claude 为你的请求所做工作的总量，包括读取的文件数量、使用的工具数量，以及在向你汇报之前所经历的步骤数量。
* 对于更常规的任务选择较小的模型，对于更复杂或更模糊的任务选择较大的模型。从每个模型的默认努力程度开始，然后根据你从事的工作类型（而非逐任务地）将其调整为你的一般偏好。
* 如果 Claude 拥有所有相关上下文、明确尝试了但仍然出错，这就是需要选择能力更强模型的信号。如果 Claude 因跳过文件、未运行测试或中途放弃重构而出错，则应选择更高的努力程度。

## **Claude Code 努力程度与模型选择**

Claude Code 提供了两个看起来能让“答案变得更好”的设置：模型设置和努力程度。你可能会认为，像 Claude Fable 5 这样更大的模型比 Claude Sonnet 能提供更智能的输出，而更高的努力程度意味着 Claude 在回答之前会思考更长时间。

第一个假设是正确的。根据行业标准基准测试，我们最大的模型能力更强。

但努力不仅仅意味着“思考时间”。努力程度控制着 Claude 为你的请求所做工作的总量。这确实包括模型思考的时间，但也包括：

* 读取了多少个文件；
* 进行了多少验证；以及
* 在向你汇报之前，它在多步骤任务中推进了多远。

在更高的努力程度下，Claude 会在返回结果之前采取更多此类行动（例如读取文件、运行测试和双重检查）。在较低的努力程度下，它宁愿向你询问更多上下文，也不愿自己花 token 去解决问题。
