在我们期待他们成果的同时，我们与 Built with Opus 4.7 黑客松的获奖者聊了聊他们的项目。他们的项目涉及医疗培训、电子维修、计算机科学教育、互动游戏、家居维修和工厂维护。

恭喜所有获奖者和参与者！我们希望他们的想法能给你带来启发。

## 第一名：[Medkit](https://bedirhankeskin.com/)，Bedirhan Keskin

来自伊斯坦布尔的 Bedirhan Keskin 是一位从医生转行的软件工程师，他使用 Claude Managed Agents 构建了 Medkit：一个面向住院医师和初级医生的学习工具，以游戏化的医疗诊所形式模拟真实患者诊疗场景。

“当你独自在急诊室面对 50 位等待的患者，却发现自己遇到了一些医学院从未教过的病例时，你只能直接在真实患者身上实时练习。”Bedirhan 说。

借助 Medkit，医学生可以练习诊断和治疗模拟患者，使用该工具采集病史、开具化验、阅读影像、做出诊断并制定治疗方案。最后，一个智能评分代理会根据与考官使用的相同公开临床指南对整个过程进行评估。

Bedirhan 在四个独立的 Claude Code 会话中构建了 Medkit（语音引擎、内容生成、3D 游戏层和核心应用），保持每个上下文清晰，并同时推进所有部分。他采用了“多说少打字”的方式，几乎全程通过语音工作。

Medkit 已经获得了初步关注，三家位于伊斯坦布尔的医学院和一家制药公司将在未来几周内启动试点项目。

**给其他开发者的建议：** 将 Claude 视为思考伙伴，而不仅仅是编码代理。

Bedirhan 的第一反应是自行托管语音引擎，但 Claude 建议使用云服务提供商来加快进度。“我最看重 Claude 的一点是，它不仅仅是代码生成器，更是一个思考伙伴，能帮我看到原本会错过的选项。”他说。

## 第二名：[Wrench Board](https://wrenchboard.cloud/)，Alexis Chapellier

来自法国 Reignier-Ésery 的 Alexis Chapellier 在创建 [RepairMind](https://repairmind.io/)（一个面向维修店的 AI 驱动管理平台）之前，花了多年时间维修电子产品。他的 Opus 4.7 黑客松项目 [Wrench Board](https://wrenchboard.cloud/) 帮助独立技术人员解决复杂的维修问题。用户上传原理图和板图并描述故障症状，代理会创建一个统一的电气图，在其上进行推理，指出需要探测的确切焊盘，读取测量值，并不断更新假设，直到诊断出问题。

Alexis 在 Claude Design 中制作了 Wrench Board 原型，将应用的不同职责（设计、原理图解析、板图、诊断代理）分开，并先为每个部分生成规格说明，再制定计划。他在 Claude Code 的多代理模式下执行，在调试过程中并行运行五到六个代理，每个领域配备一个专用代理，并在每一步进行基准测试。

Alexis 最大的赌注是 Opus 4.7 理解视觉原理图的新能力；他说当他让模型追踪主板上的电源路径时，他知道这个想法奏效了。

“我看着 Wrench Board 的板图一步步亮起来，箭头出现，元件被指向，名称浮现。那一刻，我明白这个想法是成立的。”他说。

Wrench Board 的下一阶段是建立一个由对试用该应用感兴趣的电子维修人员和能用现场经验丰富该工具的专家组成的社区。他的 Claude 积分将用于 RepairMind、那些首批用户以及所有正在推进的基础设施。

“这次黑客松证明，一个从维修店走出来的自学成才的人可以在五天内交付一个雄心勃勃的系统。”Alexis 说，他参赛时还在申请“维持生计的工作”。“Claude Code 能放大任何有想法并有毅力去执行的人的能力，无论他们的起点如何。”

**给其他开发者的建议：** 在头脑风暴中深入挖掘，并敢于反驳模型。

Alexis 使用 [Superpowers](https://claude.com/plugins/superpowers)，一个集成到 Claude 中的技能框架，用于结构化头脑风暴-然后-计划的步骤，有时并行运行头脑风暴以在不同方向取得进展。他从 Claude Design 开始，然后通过内置按钮直接分享项目给 Claude Code，并在模型说“不”时推动它。

“在黑客松期间，Claude 多次告诉我这个或那个在可用时间内无法完成。实际上，我的时间很充裕。”他说。“你必须知道如何告诉它，*我无论如何都要试试。*”

[*Wrench Board 在 GitHub 上*](https://github.com/Junkz3/wrench-board)

## 第三名：[Maieutic](https://maieutic.dev/)，Paula Vásquez-Henríquez

在智利康塞普西翁的 Universidad del Desarrollo 教授计算机科学的 Paula Vásquez-Henríquez 表示，过去两年她看到越来越多的学生通过了考试，却不理解自己的代码。

“学生现在用 AI 制造代码，但他们完全不知道代码在做什么。”她说。“他们从未学会精确地陈述问题、在编码前制定计划，或批判性地阅读自己的代码并发现它偏离了原本意图的地方。自动补全在他们还没完整表达问题之前就给出了可运行的代码，所以元认知循环——那种真正造就程序员的‘对思考的思考’——从未闭合。他们毕业时能生成代码，却不能推理代码。”

Paula 目前正在攻读人工智能博士学位，研究学生与 AI 的互动模式。她参加黑客松是为了从学生和教师两个角度解决这个问题。

Maieutic 是一个 IDE，旨在让学生在关键时刻放慢脚步。学生在编写任何代码之前，必须用自然语言描述他们的程序应该做什么；Claude 会提出有针对性的澄清问题，并保持编辑器锁定，直到规格详细到一位称职的程序员无需猜测就能实现为止。

学生随后可以开始编写 Python，但自动补全已关闭；聊天面板直接回答参考性问题，但对推理性问题则以反问回应而非直接修复，拒绝替学生思考。

该工具的核心是 Intent-Diff Review（意图差异审查），它让 Claude 将规格与最终代码进行比较，将每个偏差分类为漂移、修改或错误，然后提出一个中立、非指责性的问题，促使学生自己解释问题。

对于教师，一个实时仪表板显示每个学生一行，附有一句话的认知摘要（例如，“写了三次规格，仍未考虑空输入”）。教师可以点击单个学生来监控他们与 Claude 的具体互动，Claude 还会分析整个群体，识别并呈现全班共有的误解，以便教师弥补这一差距。

黑客松结束后，休斯顿大学的研究人员已联系 Paula 合作撰写论文，她将把奖金积分用于进一步开发该工具。她说黑客松那一周让她看到，理解一个问题与交付一个解决该问题的工具之间的鸿沟已经消失了。

“我是智利康塞普西翁的一名教育工作者，不是硅谷人。”她说。“我在一周内交付了一个可用的全栈产品，因为这些工具让我能留在自己真正擅长的角色中，而它们处理其余部分。最接近真实问题的人现在可以直接为这些问题构建解决方案了。”

**给其他开发者的建议：** 先思考，再构建。

这个项目是 Paula 践行自己理念的体现：先规格，后构建。“Maieutic 的存在是因为学生直接跳到代码，而我把它建好的唯一方式就是拒绝自己这样做。”她说。她花了整整两天做纯思考工作，在写一行代码之前先创建设计规格和技术规格。

“那两天的规格工作当时感觉很慢，黑客松中确实有立即开始交付的压力，但正是这两天让接下来的一周进展神速。”她说。

## Opus 4.7 最具创意使用奖：虚拟木偶剧场，Rene Hangstrup Møller

被 Opus 4.7 的空间推理能力所吸引，全栈开发者 Rene Hangstrup Møller 构建了虚拟木偶剧场，一个基于浏览器的应用，将网络摄像头视频和语音转化为动态的互动木偶表演。一个实时动画木偶模仿用户的动作，而另一个 AI 驱动的伙伴木偶与用户聊天；语音指令可以即时变换场景并生成 3D 道具。

Rene 在整个流程中都使用了 Claude：概念讨论、规划和代码编写，而他负责方向、架构、审查和决策。该应用基于 Bun、Vite 和 TypeScript，使用 MediaPipe 手部追踪（在 WASM 中运行）和 Three.js 以 60 fps 渲染 3D 木偶舞台。一个小型 WebSocket 服务器通过 Anthropic SDK 连接到 Claude Opus 4.7，驱动 AI 木偶的对话并即时生成 3D 道具，而语音输入由 Web Speech API 处理，输出由 ElevenLabs 处理（以浏览器语音合成为后备方案）。Opus 的空间推理能力通过基于截图的反馈循环进行优化，负责处理视觉输出。

虚拟木偶剧场没有目标，纯粹是开放式游戏，Rene 表示他对这个获奖项目没有产品规划。对他来说，这关乎学习和乐趣。“我和小儿子一起测试了它，他玩得非常开心。”Rene 说。“看着他与木偶互动、描述场景、对回应咯咯笑，这真的是我唯一需要的用户验证。”

虚拟木偶剧场的源代码在 GitHub 上以 MIT 许可证发布，他补充道，“如果有人想进一步开发的话。”

**给其他开发者的建议：** 如果你参加黑客松，一定要预留时间制作演示视频。

“制作一个 3 分钟的视频花费的时间远超你的想象。”Rene 说，他提到自己在黑客松截止日期前使用 Claude 和 Hyperframes 创建和编辑了他的虚拟木偶剧场视频。“黑客松 Discord 里的很多人警告过这一点，他们是对的。下次我会把最后整整一天留出来专门制作演示视频。”

[*虚拟木偶剧场在 Github 上*](https://github.com/rhmoller/virtual-puppet-theater)

## “持续思考”奖：[MaestrIA](https://www.youtube.com/watch?v=rkH4AjoTL5Q)，本杰明·托拉尔博

本杰明·托拉尔博从小跟随父亲胡安·罗德里戈·托拉尔博学徒，其父是智利奇洛埃岛一名持证的*大师级*木匠。“我父亲有30年的手艺，修复过联合国教科文组织名录中的教堂，但在智利体制内仍然默默无闻，就像成千上万的其他手艺人一样，”本杰明说。“与此同时，需要房屋维修的人不知道哪里出了问题、费用多少、该找谁，以及是否被公平收费。”

他的[MaestrIA](https://maestriachile.cl/)黑客松项目同时解决了这两方面的问题：作为一个网页应用，它既为普通人提供大师级的房屋维修诊断，也为熟练手艺人提供展示专业技能的方式。

使用MaestrIA时，用户拍摄问题照片，用语音或文字描述，并分享位置。Claude实时流式输出推理过程，在照片上叠加动态边界框，然后给出结构化诊断：哪里坏了、材料、严重程度1–5级、项目预算和工期估算。随后，智能体会按工种筛选并渲染附近师傅的地图，同时另一个智能体起草一条WhatsApp消息以便发送。

MaestrIA的技术核心是一个JSON文件，注入到每次诊断中，其中包含17条诊断规则、7种智利本土木材、16个当地行业方言术语、19个基准价格，以及9种常见工艺错误——全部提炼自本杰明与父亲数小时的访谈。在不触碰系统提示词的情况下，这一个文件就让他的评估分数提升了七个百分点（对照人类大师的判断，从74%升至81%），也正是它让MaestrIA能诊断出“落叶松木墙板的上升潮气”，而非笼统的“木材损坏”。

本杰明此前没有任何编程经验，他说自己的角色是现场工长，监督Claude的技术执行。“在编写任何功能之前，我让Claude Code设计规格、分阶段行动计划和安全模型：针对提示注入的输入净化、速率限制、来源验证，以及作为唯一事实来源的Zod模式，”他说。“然后我逐个差异地审查每个功能。”

本杰明希望MaestrIA能扩展到新的建筑类型、五金店集成、正式预算、合同、评价和认证体系。最终，每个工种都将内置自己的大师级知识库，包括木匠、建筑师、水管工、电工和泥瓦匠。

他的奖金将用于开发应用、将其父亲的公司数字化作为实时试点，以及自身的技术成长。“Claude Code让一个来自奇洛埃、毫无编程经验的20岁年轻人，能开发出自己父亲都能使用的软件，并帮助智利28万多名像他一样的师傅，”他说。“它也为数百万一直有宝贵想法却无法实现的人打开了大门。”

**给其他开发者的建议：** 先做评估，再做功能。

“我做的最重要的一件事，就是针对12个真实案例构建了一个可审计的9维度评估体系，基准真相由我父亲记录，”本杰明说。“是那个评估，而不是我的直觉，告诉我什么有效、什么无效。如果再参加一次黑客松，评估会是第一个提交。”

## Claude 托管代理最佳应用：[ARIA](https://www.youtube.com/watch?v=Hen24w2Jyz4&t=28s)，Idriss Benguezzou 与 Adam Hnaien

大多数工厂里都有这样一位资深技师，仅凭机器发出的声音就能判断它是否即将故障。荣获“Claude 托管代理最佳应用”奖项的项目 ARIA（自适应运行时智能）将经验丰富的维护工程师的直觉，转化为一套价格亲民、部署迅速的人工智能系统。该系统持续监控工厂机器，一旦出现异常，便会立即生成定制化诊断和维修方案。

借助 ARIA，维护工程师上传制造商的 PDF 文件，回答四个通俗易懂的校准问题，15 分钟内即可完成工厂画像。此后，五个代理实时监控信号。若某个代理检测到故障或预测故障即将发生，它便会生成一份工单，分析组件、故障模式、紧急程度、所需零件和干预窗口。

该项目的两位构建者均拥有一线工业经验，他们在黑客松的队友招募 Discord 频道中相识。Idriss Benguezzou 是法国工业软件工程师，拥有数据/人工智能硕士学位，此前已构思该想法及其大部分架构一段时间。Adam Hnaien 是自学成才的工程专业学生，熟悉 Claude Code 和多代理工作流，他立刻意识到 ARIA 是工业维护领域的宝贵解决方案。

Idriss 和 Adam 将黑客松第二天全部用于规划阶段，使用 GitHub Project 看板，在编写第一行代码之前就界定了每个里程碑、问题和验收标准。“我们希望从 M2 开始就以 200% 的状态投入，”Adam 表示，“一天的规划让我们在接下来的一周里专注于执行，而不是临场发挥。”

两人估计，Claude Code 编写了约 80% 的原始代码行，而他们则手动做出领域逻辑和设计决策。Idriss 负责阈值评估、知识库架构和异常检测，因为正如他所说，“你无法通过提示词来了解维护技师实际关注什么。”Adam 负责用户体验、视觉语言和 ARIA 的星座概念，因为正如他所说，“你无法通过提示词来获得审美品味。”

托管代理负责代理基础设施。“如果没有 Claude 托管代理，我们就会花一整周去构建 Anthropic 已经托管的那些基础设施：沙盒 Python 环境、安全执行、会话持久化、MCP 调度，”Adam 表示，“相反，我们把那一周用来围绕这些基础设施打造产品。这就是五天交付 ARIA 和五周交付 ARIA 之间的区别。”

黑客松结果公布后，正致力于解决同类问题的公司纷纷联系了他们。Idriss 将把 ARIA 的代理架构、知识库架构和信号管道整合到他自己的工业物联网平台中；他的 API 额度将用于更多构建和实验。至于 Adam，他计划继续探索工业代理式人工智能领域的机遇，并利用 API 额度继续构建和实验。

**给其他构建者的建议：让 Claude 进行审查。** Idriss 建议，在构建下一个功能之前，先让 Claude 检查你已构建的内容是否存在问题。“这个循环被低估了。”
