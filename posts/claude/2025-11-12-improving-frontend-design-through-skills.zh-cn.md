# 通过技能提升前端设计

**日期：** 2025-11-12 00:00 UTC  
**链接：** https://claude.com/blog/improving-frontend-design-through-skills  

---

你可能注意到，当你在没有指导的情况下让大语言模型构建一个落地页时，它几乎总是会使用Inter字体、白色背景上的紫色渐变以及极简动画。

问题在于？[分布收敛。](https://en.wikipedia.org/wiki/Convergence_of_random_variables)在采样过程中，模型基于训练数据中的统计模式预测token。那些普遍适用且不冒犯任何人的安全设计选择主导了网络训练数据。如果没有方向指引，Claude会从这个高概率中心进行采样。

对于构建面向客户产品的开发者来说，这种通用美学损害了品牌标识，并使AI生成的界面一眼就能被识别出来——进而被轻视。

### 可引导性挑战

好消息是，通过正确的提示，Claude具有很强的可引导性。告诉Claude"避免使用Inter和Roboto"或"使用氛围背景而非纯色"，结果会立即改善。这种对指导的敏感性是一个特性；这意味着Claude能够适应不同的设计语境、约束和审美偏好。

但这带来了一个实际挑战：任务越专业，你需要提供的上下文就越多。对于前端设计，有效的指导涵盖排版原理、色彩理论、动画模式和背景处理。你需要指定要避免哪些默认设置以及在多个维度上偏好哪些替代方案。

你可以将所有内容塞进系统提示中，但这样一来，每个请求——调试Python、分析数据、写邮件——都会携带前端设计上下文。问题就变成了：如何在不需要无关任务的永久上下文开销的情况下，在需要时向Claude提供领域特定的指导？

## 技能：动态上下文加载

这正是[技能](https://www.anthropic.com/news/skills)的设计目的：按需提供专业上下文，无需永久开销。技能是一个文档（通常是markdown格式），包含指令、约束和领域知识，存储在指定目录中，Claude可以通过简单的文件读取工具访问。Claude可以利用这些技能在运行时动态加载所需信息，逐步增强其上下文，而不是一次性加载所有内容。

当配备这些技能以及必要的读取工具时，Claude能够根据手头的任务自主识别并加载相关技能。例如，当被要求构建落地页或创建React组件时，Claude可以加载前端设计技能并即时应用其指令。这是关键的思维模型：技能是按需激活的提示和上下文资源，为特定任务类型提供专业指导，而不会产生永久上下文开销。

这使得开发者能够从Claude的可引导性中获益，而无需通过将跨多个任务的零散指令塞入系统提示来使上下文窗口过载。正如我们[之前解释过的](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)，上下文窗口中的token过多可能导致性能下降，因此保持上下文窗口内容精简且聚焦对于激发模型的最佳性能至关重要。技能通过使有效提示可重用且具有上下文相关性来解决这一问题。

## 为更好的前端输出进行提示

通过创建一个前端设计技能，我们可以在没有永久上下文开销的情况下，解锁Claude显著更好的UI生成能力。核心见解是像前端工程师那样思考前端设计。你越能将美学改进映射到可实现的前端代码上，Claude就能执行得越好。

利用这一见解，我们确定了几个有针对性的提示效果良好的领域：排版、动画、背景效果和主题。这些都能清晰地转化为Claude可以编写的代码。在提示中实现这一点并不需要详细的技术指令，只需使用有针对性的语言，引导模型更批判性地思考这些设计轴，就足以激发更强的输出。这与我们在[上下文工程](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)博客文章中提供的指导密切相关，即在适当的高度提示模型，避免两个极端：低层次的硬编码逻辑（如指定精确的十六进制颜色代码）和假设共享上下文的模糊高层次指导。

### 排版

为了看到实际效果，让我们首先将排版视为我们可以通过提示影响的一个维度。下面的提示专门引导Claude使用更有趣的字体：

```
<use_interesting_fonts>
排版瞬间传达品质。避免使用无聊、通用的字体。

绝不使用：Inter、Roboto、Open Sans、Lato、默认系统字体

以下是一些优秀、有影响力的选择的示例：
- 代码美学：JetBrains Mono、Fira Code、Space Grotesk
- 编辑风格：Playfair Display、Crimson Pro
- 技术风格：IBM Plex系列、Source Sans 3
- 独特风格：Bricolage Grotesque、Newsreader

配对原则：高对比度=有趣。展示字体+等宽字体、衬线字体+几何无衬线字体、可变字体跨字重使用。

使用极端值：100/200字重对比800/900字重，而不是400对比600。字号跳跃3倍以上，而不是1.5倍。

选择一个有特色的字体，果断使用。从Google Fonts加载。
</use_interesting_fonts>
```

### 主题

我们可以提示的另一个维度是受知名主题和美学启发的设计。Claude对流行主题有丰富的理解；我们可以利用这一点来传达我们希望前端体现的特定美学。以下是一个示例：

```
<always_use_rpg_theme>
始终以RPG美学进行设计：
- 受奇幻启发的调色板，采用丰富、戏剧性的色调
- 华丽的边框和装饰性框架元素
- 羊皮纸纹理、皮革装订风格和风化材料
- 史诗般的冒险氛围，配以戏剧性的光影
- 中世纪风格的衬线字体，配以装饰性标题
</always_use_rpg_theme>
```

### 通用提示

同样的原则也适用于其他设计维度：提示动效（动画和微交互）为静态设计增添了精致感，而引导模型选择更有趣的背景则创造了深度和视觉趣味。这正是综合技能的优势所在。

综合所有这些，我们开发了一个约400 token的提示——足够紧凑，不会使上下文臃肿（即使作为技能加载）——它在排版、色彩、动效和背景方面显著改善了前端输出：

```
<frontend_aesthetics>
你倾向于收敛到通用的、"符合分布"的输出。在前端设计中，这造成了用户所说的"AI垃圾"美学。避免这种情况：做出有创意、独特、令人惊喜和愉悦的前端。

重点关注：
- 排版：选择美观、独特且有趣的字体。避免使用Arial和Inter等通用字体；选择能够提升前端美学的特色字体。
- 色彩与主题：坚持连贯的美学。使用CSS变量保持一致性。主色调搭配锐利强调色优于胆小、均匀分布的调色板。从IDE主题和文化美学中汲取灵感。
- 动效：使用动画实现效果和微交互。优先使用纯CSS解决方案处理HTML。在React中可用时使用Motion库。专注于高影响力的时刻：一次精心编排的页面加载，配合错开显示（animation-delay），比分散的微交互更能创造愉悦感。
- 背景：创造氛围和深度，而不是默认使用纯色。叠加CSS渐变，使用几何图案，或添加与整体美学相匹配的上下文效果。

避免通用的AI生成美学：
- 过度使用的字体系列（Inter、Roboto、Arial、系统字体）
- 陈旧的配色方案（特别是白色背景上的紫色渐变）
- 可预测的布局和组件模式
- 缺乏上下文特定特色的千篇一律的设计

创造性地诠释，做出真正为上下文设计的感觉的意外选择。在浅色和深色主题、不同字体、不同美学之间变化。你仍然倾向于在多次生成中收敛到常见选择（例如Space Grotesk）。避免这种情况：跳出框框思考至关重要！
</frontend_aesthetics>
```

在上面的例子中，我们首先给Claude提供关于问题以及我们试图解决什么的通用上下文。我们发现，给模型这种类型的高层上下文是一种有用的提示策略，可以校准输出。然后，我们识别出之前讨论过的改进设计的向量，并给出有针对性的建议，鼓励模型在所有维度上更创造性地思考。

我们还在末尾添加了额外指导，以防止Claude收敛到另一个局部最优。即使有明确的指令避免某些模式，模型也可能默认选择其他常见选择（如排版中的Space Grotesk）。最后的"跳出框框思考"提醒强化了创造性变化。

## 在claude.ai中使用技能提升工件质量

设计品味并非唯一的限制。Claude在构建工件时也面临架构约束。[工件](https://support.claude.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them)是Claude创建并显示在聊天旁边的交互式、可编辑内容（如代码或文档）。

除了上面探讨的设计品味问题外，Claude还有另一个默认行为限制了它在claude.ai中生成优秀前端工件的能力。目前，当被要求创建前端时，Claude只构建一个包含CSS和JS的单个HTML文件。这是因为Claude理解前端必须是单个HTML文件才能正确渲染为工件。

就像你期望人类开发者如果只能在一个文件中编写HTML/CSS/JS，就只能创建非常基础的前端一样，我们假设如果给Claude使用更丰富工具集的指令，它就能生成更令人印象深刻的前端工件。

这促使我们创建了一个[web-artifacts-builder技能](https://github.com/anthropics/skills/blob/main/web-artifacts-builder/SKILL.md)，该技能利用Claude的[使用计算机](https://www.claude.com/blog/create-files)能力，引导Claude使用多个文件和现代Web技术（如[React](https://react.dev/)、[Tailwind CSS](https://tailwindcss.com/)和[shadcn/ui](https://ui.shadcn.com/)）构建工件。在底层，该技能暴露了一些脚本，这些脚本(1)帮助Claude高效设置基本React仓库，(2)在编辑完成后使用[Parcel](https://parceljs.org/)将所有内容打包到单个文件中以满足单HTML文件要求。这是技能的核心优势之一——通过让Claude访问执行样板操作的脚本，Claude能够最小化token使用，同时提高可靠性和性能。

借助web-artifacts-builder技能，Claude可以利用shadcn/ui的表单组件和Tailwind的响应式网格系统创建更全面的工件。

## 使用技能优化Claude的前端设计能力

这个前端设计技能展示了一个关于语言模型能力的更广泛原则：模型通常具备比默认表达更多的能力。Claude有很强的设计理解能力，但分布收敛在没有指导的情况下掩盖了这一点。虽然你可以将这些指令添加到系统提示中，但这意味着每个请求都会携带前端设计上下文，即使这些知识与手头任务无关。相反，使用技能将Claude从一个需要持续指导的工具转变为一个为每个任务带来领域专业知识的工具。

技能也具有高度可定制性——你可以根据自己的特定需求创建自己的技能。这使你能够定义想要融入技能的确切原语，无论是你公司的设计系统、特定的组件模式，还是行业特定的UI约定。通过将这些决策编码到技能中，你将代理思维的组成部分转化为整个开发团队都可以利用的可重用资产。技能成为持久存在且可扩展的组织知识，确保跨项目的一致质量。

这种模式超越了前端工作。任何Claude尽管有更广泛的理解却产生通用输出的领域都是技能开发的候选对象。方法是一致的：识别收敛的默认设置，提供具体的替代方案，在适当的高度构建指导，并通过技能使其可重用。

对于前端开发来说，这意味着Claude可以在无需每次请求进行提示工程的情况下生成独特界面。要开始使用，请探索我们的[前端设计食谱](https://github.com/anthropics/claude-cookbooks/blob/main/coding/prompting_for_frontend_aesthetics.ipynb)或尝试我们在[Claude Code中的新前端设计插件](https://github.com/anthropics/claude-code/tree/main/plugins/frontend-design)。
