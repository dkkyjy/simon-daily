大多数 [智能编码](https://claude.com/blog/introduction-to-agentic-coding) 会话遵循一个循环：你要求一个更改，Claude 收集上下文，采取行动，验证结果，如果需要，则循环回去收集更多上下文。

验证是智能体在回应之前检查其工作的方式。Claude 已经通过观察代码库中的确定性信号（包括类型检查器、linter、测试和运行时错误）来做一些这样的事情。Claude 无法推断的部分则成为你手动检查某个功能的步骤。

然而，这些手动步骤可以转化为验证循环。在 [Claude Code](https://claude.com/product/claude-code) 中，验证循环是一个迭代过程，Claude 检查并尝试修复工作。

*智能体循环：1. 收集上下文，2. 采取行动，3. 验证结果。*

在本文中，我们将介绍最常见的验证循环类型，并展示我们在 Anthropic 内部使用的内容。然后，我们将展示如何将你已经做的手动检查编码为技能，这样 Claude 就能关闭自己的反馈循环，而在它迭代时你可以专注于其他事情。

## 内置验证循环

在深入设计自定义验证循环之前，了解 Claude 对多种不同验证循环的内置支持会很有帮助。常见的功能和方法包括：

* **/verify 技能**：构建、运行并观察你应用程序中的更改。
* **工具链**：Claude 旨在捕获并处理你提供的任何工具（例如 linter）的错误代码和警告。一个好的做法是将你的确切构建和测试命令列在 CLAUDE.md 中，这样 Claude 就不必推断它们。
* **代码审查（研究预览）**：一个托管的多智能体服务，在你启用的仓库中的 PR 上自动运行审查遍数。你可以手动修复发现的问题并推送，或者通过评论 @claude 来关闭循环（如果你已经设置并配置了 GitHub Actions，见下文）。
* **GitHub Actions**：定义一个任务，调用带有验证技能的 Claude，并且与你本地运行的相同检查会在每次推送或 PR 时触发。
* **规范验证**：一个技能，帮助根据仓库中的 markdown 规范验证每次更改，并尝试修复违规。
* **Claude 托管智能体中的评分标准（测试版）**：一个托管智能体服务，允许你使用单独的评分智能体根据评分标准验证结果。失败会自动循环回去进行返工。

## 编写验证循环

当你有一个现有项目，并且每次 Claude 为你实现新功能时，你发现自己都在做相同的小修正，那么是时候将这些步骤转化为你自己的自定义验证循环了。第一步是写下你每次都会做的所有事情

同样，如果你正在启动一个新项目，并且需要弄清楚项目应该如何表现，也是如此。用简单的英语写下最佳实践版本，就像你在第一天交给新团队成员那样。

如果你难以表述验证检查本身，先向 Claude 询问最佳实践，然后在此基础上进行编辑。你的版本可能在几个具体点上有所不同，而这些差异正是你想要捕捉的。

**专业提示**：检查不一定非得是定性的才能属于这里。“拒绝任何没有回填步骤就删除列的迁移”是一个确定性规则，没有通用的 linter 会捕获它，但特定于项目的 linter 可以。任何你不得不手动强制执行的检查都有资格作为循环来捕获。
