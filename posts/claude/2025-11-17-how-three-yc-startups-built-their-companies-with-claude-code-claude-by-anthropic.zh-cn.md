[Y Combinator](https://www.ycombinator.com/)，一家创业加速器，自 2005 年以来已孵化了超过 5000 家公司，这些公司的总估值超过 8000 亿美元，其中包括 Airbnb、Stripe 和 DoorDash 等家喻户晓的名字。

如今，像 [Claude Code](https://www.claude.com/product/claude-code) 这样的智能编码工具正在从根本上改变 YC 初创公司的构建和扩张方式。创始人现在可以直接从终端交付产品，将开发周期从数周压缩到数小时，甚至让非技术背景的创始人也能从第一天起与成熟玩家竞争。

我们采访了三家 YC 初创公司，它们展示了这种转变的实际效果：

* [HumanLayer](https://www.humanlayer.dev/)（F24）完全使用 Claude Code 构建了他们的平台，并开创了上下文工程实践
* [Ambral](https://www.ambral.com/)（W25）正在利用基于 Claude Code 和 Claude Agents SDK 构建的复杂子智能体驱动工作流，扩展 AI 驱动的客户管理
* [Vulcan Technologies](https://vulcan-tech.com/)（S25）正在使用 Claude Code 为政府和行业解决监管复杂性难题

让我们深入了解。

## **HumanLayer：从 SQL 智能体到规模化 AI 优先的工程团队**

Dexter Horthy 正在构建自主 AI 智能体来管理 SQL 数据仓库，这时他注意到智能体化应用面临一个根本性（但可以理解的）挑战：公司不愿意让 AI 应用无监督地访问敏感操作，比如删除数据库表。

### **开启一切的产品转向**

这一认识成为了 HumanLayer 的核心洞察：通常，任何软件中最有用的函数也是最危险的，尤其是对于由 LLM 驱动的非确定性系统而言。

"我们的 MVP 是一个智能体，它可以在 Slack 中与人类协调，并能执行基本的清理工作，比如删除任何超过 90 天未被查询的表，"Horthy 解释道。"我们不放心让 AI 应用无监督地运行原始 SQL，所以我们加入了一些基本的人工审批步骤。"

2024 年 8 月，Horthy 构建了 MVP，在旧金山的多家初创公司进行了演示，并获得了第一批付费客户。

这一进展使 HumanLayer 进入了 YC F24 批次，团队全力投入，提供 API 和 SDK，让 AI 智能体能够通过 Slack、电子邮件、短信及其他渠道联系人类，获取反馈、输入和审批。

到 2025 年第一季度，HumanLayer 团队进行了广泛的客户探索，与数十个正在构建 AI 智能体的工程团队交谈，并意识到他们在智能体化开发循环中存在一个未曾预料到的缺口。

"每个团队都自己打造了各自的智能体架构，"Horthy 解释道。"我们意识到我们不能仅仅构建一个更好的 API——我们需要帮助建立让整个生态系统成熟的模式和原则。"

这促使 Horthy 将他们的经验整理成《[12 因素智能体：可靠 LLM 应用的模式](https://github.com/humanlayer/12-factor-agents)》。该指南于 2025 年 4 月发布，迅速传播开来，综合了他们构建生产级智能体系统的经验，并强调了新兴的上下文工程领域的最佳实践。

### **用 Claude Code 构建一切**

掌握了这些经验后，HumanLayer 团队开始探索其他产品创意和转向角度。

当 Anthropic 发布 Claude Code 时，Horthy 和他的团队已经是 Claude 模型在编码方面的坚定支持者。他们立即开始使用它来构建这些实验。

"我们就是用 Claude Code 写所有东西，"Horthy 说。"当 Claude Agent SDK 随 Opus 4 和 Sonnet 4 推出，实现无头智能体执行时，我们就知道这将是一件大事。"

在内部经过数月的打磨后，Horthy 开始与亲密的朋友兼创始人分享他们的 Claude Code 工作流。

"那个告诉我我们必须全力投入这一方向的时刻，是来自 BoundaryML（YC W23）的 Vaibhav 的全天配对编程会话，"Horthy 回忆道。"Vaibhav 起初持怀疑态度，但当我们花了 7 个小时交付了通常需要 1-2 周的工作量后，他被说服了。我意识到这个工作流也可以适用于其他团队和其他代码库。"

### **构建 CodeLayer：规模化 AI 优先的工程**

如今，HumanLayer 的产品 CodeLayer 帮助团队使用工作树和远程云工作器并行运行多个 Claude 智能体会话。他们发现了一个关键模式：一旦工程师掌握了 Claude Code，他们的生产力提升如此显著，以至于真正的挑战变成了组织层面的——如何将这些工作流扩展到整个团队。

"一旦你团队中有多个人在交付 AI 编写的代码，你就会面临一个完全不同类型的问题，"Horthy 解释道。"这是沟通、协作、工具和管理的问题。你必须重新调整团队构建软件的每一个环节。"

自 2025 年第四季度开始以来，HumanLayer 已与各种规模的工程团队达成了多个大型试点项目，以部署这些工具和工作流，所有这些工具和工作流都是用 Claude Code 构建的。

## **Ambral：使用子智能体构建生产系统**

Jack Stettner 和 Sam Brickman 创立 Ambral 是为了解决每个 B2B 初创公司创始人和 CRO 都熟悉的问题：随着公司扩张，推动早期增长的创始人级别的客户亲密度变得无法维持。

### **使用 Claude Agent SDK 改造客户管理**

无论是在经历超高速增长的早期公司，还是在成熟的企业级公司，客户经理通常要同时管理 50 到 100 个客户账户。"你不可能用别人 1/50 的注意力来提供有效的客户管理体验，"Stettner 解释道。曾经装在创始人脑子里的客户上下文分散在系统、日志、Slack 消息、会议记录和产品使用数据中。

Ambral 将来自客户活动和互动的信号综合成 AI 驱动的每个账户模型。系统能够精确定位谁需要关注以及为什么需要关注，自主推动或推荐扩展，同时捕捉早期不满迹象以防止流失。

"我们试图提供每个客户都拥有一位专属客户经理的体验，"Stettner 说。

作为这家年轻初创公司的 CTO 和唯一工程师，Stettner 在开发中严重依赖 Claude Code，并使用 Claude 的 Agent SDK 来驱动产品本身。技术架构反映出对如何从不同 Claude 模型中提取最大价值的深刻理解。

### **委托式工作流：Opus 负责思考，Sonnet 负责构建，子智能体无处不在**

Stettner 采用了一种精确的工作流，充分利用了不同 Claude 模型与子智能体的优势：

"我使用 Opus 4.1 进行研究和规划。Sonnet 4.5 在执行我以 Markdown 形式创建的这些计划方面表现得非常出色，"Stettner 解释道。

他的开发过程遵循三个独立的阶段：

1. **研究阶段（Opus 4.1）**：对功能实现所需的任何背景知识进行深入研究。"我认为最重要的事情是在规划之前进行研究，"Stettner 强调。"让 Claude 为你进行研究，并创建一个大型、详细的研究文档。"他使用一系列子智能体并行研究代码库的多个领域。
2. **规划阶段（Opus 4.1）**：创建一个包含各个阶段的计划，说明如何实现该功能。"我会让 Opus 创建一个计划，包含分阶段步骤，说明如何实际实施，然后我会修改这个计划。也许我会与 Opus 讨论某些细节问题，或者我会手动更新这个 Markdown 文件。"
3. **实现阶段（Sonnet 4.5）**：系统地执行计划的每个阶段。"然后我会使用 Sonnet 4.5 来实现每个阶段。"

这种方法胜过了 Stettner 尝试过的其他工作流，并且受到 Horthy 在 HumanLayer 所做工作的影响："我尝试过每一种编码工具，并且基本上实验了每一个模型。我只是认为 Anthropic 的模型目前在工具使用方面是最好的，而这自然转化到编码中。"

### **构建强大的研究引擎**

产品本身也反映了这种多智能体方法。Stettner 使用 Claude Agent SDK 构建了 Ambral 的核心研究引擎，为每种数据类型配备了专门的子智能体。

"我花了大量时间使用 Claude Agent SDK 来构建一个非常强大的研究引擎，能够跨所有数据运行，"Stettner 解释道。"它基于 Claude 子智能体，对于每种数据类型，我们都有一个专门的子智能体，它是理解该数据的专家。"

无论是用户与系统聊天，还是 Ambral 为客户构建自动化，一切都由 [Claude Agent SDK](https://docs.claude.com/en/api/agent-sdk/overview) 和一系列子智能体支持，这些子智能体检索并推理使用数据、Slack 消息、会议记录和产品交互。

架构灵感直接来自 Stettner 的开发经验："我认为正是 Claude Code 子智能体在辅助我开发方面表现如此出色，这启发了我，让我想采用同样的子智能体，并将它们用于产品本身的研究引擎。"

## **Vulcan Technologies：赋能非技术创始人发布产品**

对于 Vulcan 的 CEO 兼联合创始人 Tanner Jones 来说，Claude Code 的影响远远超出了生产力——它代表着公司构建的民主化。在创办初创公司时，Vulcan 团队相信一定存在一种产品能让政府更好地为公民服务。如果没有 Claude Code，这一愿景将永远无法实现，因为两位创始人都不具备工程背景。

### **在没有专门工程师的情况下交付产品**

Vulcan 解决的是一个积累了几个世纪的问题：[监管法规](https://en.wikipedia.org/wiki/Code_of_Federal_Regulations)的复杂性。弗吉尼亚州下议院，世界上最古老的连续民主机构，就是这一挑战的典型例子。400 多年的监管积累创造了美国最细致、最复杂的法规之一。

当 Aleksander Mekhanik 和 Tanner Jones 于 2025 年 4 月共同创立 Vulcan 时，两人都没有传统的工程背景。Mekhanik 在大学学习机器学习和数学，而 Jones 上一次编程经历是在高中时用纸笔写代码的 AP JavaScript 课程。然而，两人在 5 月 1 日之前就为弗吉尼亚州长办公室构建了第一个产品的原型——并从老牌咨询公司手中赢得了合同。

"整个原型都是用 Claude 制作的，"Jones 解释道。"那是在 Claude Code 之前。基本上就是把脚本复制粘贴到网页应用中，然后替换方法。"构建完原型后，他们聘请了他们的 CTO Christopher Minge，他曾在 Google 参与 Gemini 和 Waymo 项目。然后，当 Claude Code 在 6 月发布时，三人组的速度再次倍增。

Vulcan 的 AI 驱动监管分析帮助将弗吉尼亚州新房的平均价格降低了 24,000 美元，通过识别冗余和重复的监管要求，每年为弗吉尼亚人节省了超过 10 亿美元。弗吉尼亚州长非常喜欢 Vulcan 的工作，以至于他签署了 [第 51 号行政令](https://www.govtech.com/artificial-intelligence/virginia-to-use-agentic-ai-to-power-review-of-regulations)，要求所有州机构使用“智能体 AI 监管审查”。

### **公司构建的民主化**

对于 Jones 来说，Claude Code 的影响超越了生产力指标。

"如果你理解语言并且理解批判性思维，你就能很好地使用 Claude Code，"他说。"我实际上认为，对于学习人文学科的人来说，可能会有一些额外的好处，因为与 AI 沟通的媒介就是语言。如果你对语言有很好的掌握，并且擅长构建组织良好的有序列表、嵌套要点以及深思熟虑的流程，你的提示词可能会执行得更好。"

Jones 称赞 Claude Code 是 Vulcan 成功的重要组成部分：“在四个月内，我们三位创始人，其中只有一位具备适当的技术背景，就获得了州和联邦政府合同，并从一些顶级风投那里筹集了 1100 万美元的种子轮。没有 Anthropic 这些不可思议的工具，这一切都不可能实现。”

Christopher Minge，Vulcan 的 CTO，拥有“适当技术”背景，也经历了自己对工程思考方式的转变。

"感觉有点像我在 Google 有一个同事，我把自己所有的想法和任务都交给他，他经常犯错，但我的角色是委托给多个 Claude Code 实例，并善于检查常见错误以及有效传达想法，"Minge 解释道。

## **来自 YC 创始人的最佳实践**

这三家初创公司已经开发出经过实战检验的方法，用于最大化 Claude Code 的影响力，包括：

### **1. 将研究、规划和实现分离到不同的会话中**

"不要让 Claude 在尝试规划的同时进行研究，同时还在尝试实现，"Stettner 建议道。"使用独立的提示词，并将它们作为独立的步骤。"

这种模式可以防止上下文污染，并允许每个阶段专注于其核心目标。为每个主要阶段启动一个新的 Claude Code 会话，只传递经过提炼的结论，而不是拖拽整个上下文历史。

### **2. 有意识地进行上下文管理**

Stettner 对其他创始人的建议集中于有意识的上下文管理：

"上下文至关重要。当我看到输出出乎意料或质量较低时，通常是由于提示词中某处存在矛盾，"他解释道。"在选择将哪些信息放入系统提示词，或者选择何时开始新对话时，要非常谨慎，因为你不想混淆你的上下文。如果提示词中存在任何矛盾，你将会收到质量较低的输出。"

### **3. 监控并打断思维链**

"尝试仔细审视思维链，观察它在做什么，"Jones 建议道。"时刻准备触发中断，打断任何不良行为。"

这在运行多个实例时尤为重要。尽早发现错误方向——在最初几次工具调用之内——比让 Claude Code 完成整个错误方法要节省更多时间。

## **新的构建者优势**

这三家初创公司展示了像 Claude Code 这样的工具如何根本性地改变了公司的构建方式。HumanLayer 在转向和规模化发展的同时，将上下文工程实践系统化，这些实践现在已在整个 YC 生态系统中使用。Ambral 正在以精益的创始团队大规模解决客户成功问题。Vulcan 则在非工程师身份下赢得了政府合同。

软件构建的传统障碍——技术专长、团队规模、开发时间——正在让位于新的竞争优势：清晰的思维、结构化的问题分解，以及有效与 AI 协作的能力。
