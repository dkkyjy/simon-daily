# 智能体编码简介

            **日期：** 2025-10-30 00:00 UTC
            **链接：** https://claude.com/blog/introduction-to-agentic-coding

            ---

            近年来，AI辅助编码发展迅速。曾经只能预测下一行代码的工具，如今已能通过分析代码模式预测整个函数。

最新的演进更进一步：这些系统不再预测你接下来会输入什么，而是通过读取代码库中的文件、运行测试并持续迭代，自主执行多步骤开发任务，直至目标完成。

## 什么是智能体编码？

智能体编码将AI从自动补全转变为自主任务执行者。传统的编码助手等待你逐行输入并提示后续内容。而智能体系统会接收高层次目标，将其分解为独立步骤，自主执行这些步骤，并根据环境反馈调整方法。

关键区别在于自主性和范围。传统AI工具分析编辑器中可见的代码并提示下一片段。智能体编码工具则读取整个代码库，理解跨目录的文件关系，执行命令以验证修改是否有效，并持续迭代直至测试通过且满足需求。这种自主性贯穿整个开发周期，每个步骤都无需你手动编排工作流程。

## AI编码工具的演进历程

### 代码预测与补全

IDE自动补全扩展等工具会分析编辑器中可见的代码，预测你接下来可能输入的内容。这些系统擅长处理重复性模式，例如生成REST端点样板代码、按既定约定创建测试结构以及实现常见算法。

预测模型会考虑你的即时上下文。当你编写函数签名时，工具会根据函数名称、参数类型和周围代码建议实现方案。当你开始输入导入语句时，它会根据已导入的内容和常见用法模式推荐包。

局限性在于范围。自动补全工具使用有限的上下文窗口，通常只分析当前文件或少量邻近文件。它们无法追踪整个应用架构中的数据流，也无法理解一个服务中的变更如何影响依赖服务。

### 对话式AI聊天界面

基于浏览器的编码助手（如Claude.ai）为AI编码工具增加了对话功能。这些工具不是在输入时建议代码，而是通过分析粘贴的代码片段、错误描述和优化问题，与你讨论代码问题。

这些界面擅长分析和指导。粘贴一个慢速数据库查询，即可获得优化建议。描述一个架构决策，即可收到权衡分析。分享一个错误信息，即可探索故障排除方法。

对话格式支持迭代优化。你提出一个通用问题，收到初步回复，基于该回复澄清需求，然后逐步缩小范围直至找到具体解决方案。这种来回交流在问题尚未完全定义或需要探索不同方法后再确定实现方案时效果很好。

但对于涉及多个文件的任务，这种方式变得不切实际。重构一个被其他三十个文件导入的模块，意味着需要将每个文件粘贴到聊天中，手动跟踪哪些文件需要更新，将建议的修改复制回每个文件，并确保所有修改的一致性。聊天界面提供指导，但实现编排仍需手动完成。这正是智能体编码系统旨在填补的空白。

## 智能体编码的工作原理

### 上下文收集与规划

智能体编码系统在项目层面而非文件层面运作。当你提供一个目标时，系统会通过读取配置文件来了解项目设置、检查测试文件以查看现有覆盖模式、追踪导入关系以映射模块间的依赖关系，从而分析完成目标所需的相关上下文。

然后，系统会制定完成目标的计划。这不是一个静态列表，而是一种自适应方法，会随着系统收集更多信息而不断演进。如果你的目标是"为API添加身份验证"，计划可能从分析现有路由定义开始，确定哪些端点需要保护，检查身份验证中间件是否已存在，并确定用户会话管理应在何处实现。

### 实现与协调

实现阶段涉及读取和写入代码库中的文件。与仅建议单个文件内变更的自动补全工具不同，智能体系统会修改多个相关文件以保持一致性。添加身份验证可能需要更新路由处理器、创建中间件函数、修改数据库模式、调整API客户端代码、更新文档，并为所有这些变更添加测试覆盖。

这种自主工作流将开发从"编写代码、运行测试、读取错误、修复代码、重复"转变为"定义目标、审查提议的变更、批准实现"。你通过审查计划和批准文件变更来保持控制，而系统则处理迭代调试周期、研究现有代码模式以及协调跨多个文件的变更。

## 使用Claude Code进行智能体编码

[**Claude Code**](https://claude.com/product/claude-code) 将智能体能力引入终端环境。与需要不断复制代码的基于浏览器的工具或仅分析可见文件的IDE扩展不同，Claude Code直接在项目目录中运行，拥有对代码库的完全访问权限。

### 安装与启动

在终端中安装Claude Code：

```
npm install -g @anthropic-ai/claude-code
```

然后在项目目录中启动它以开始编码：

```
claude
```

### Claude Code的工作原理

Claude Code在收到请求时会读取整个项目上下文。当你询问架构或请求变更时，它会分析文件结构，理解package.json或requirements.txt中声明的依赖关系，追踪模块间的交互方式，并识别代码库中已有的模式。

多文件操作变得简单直接。请求"将此基于回调的代码重构为使用async/await"，Claude Code会识别所有使用回调模式的文件，用async/await语法更新每个文件，修改错误处理以使用try/catch块，更新相关测试以处理异步模式，并验证整个测试套件仍然通过。

### 文件系统访问与权限

文件系统访问使基于Web的工具无法处理的工作流成为可能。Claude Code使用适当的命名约定创建新文件，将代码组织到逻辑目录结构中，在添加依赖项时更新配置文件，并与现有项目组织模式保持一致。

权限模型确保你保持控制。默认情况下，Claude Code在修改文件前请求批准，并精确显示它计划进行的变更。你审查提议的修改，批准你同意的变更，并对不符合要求的变更请求修订。

### 与开发工作流的集成

与开发工作流的集成意味着Claude Code可以与你已使用的工具交互。它运行npm命令安装依赖项，执行Jest或pytest等测试运行器，使用Git进行提交和分支操作，并启动开发服务器以验证变更在运行中的应用中是否有效。

你可以通过连接模型上下文协议（MCP）服务器进一步扩展这些能力，这些服务器为Claude Code提供来自开发环境中其他工具和系统的全面上下文。

最终实现与参考方法相比达到了99.9%的数值精度，证明了系统理解复杂多语言代码库、为复杂算法规划实现方法以及交付生产级结果的能力。

**乐天的转型指标：**

* 功能交付**提速79%**（24天 → 5天）
* **7小时**自主实现，人工干预极少
* 复杂算法重构**99.9%**准确率
* 工程团队**5倍**并行任务执行能力

正如乐天AI业务总经理加治佑介所解释的："你可以同时运行五个任务，将其中四个委托给Claude Code，同时专注于剩余的一个。"
