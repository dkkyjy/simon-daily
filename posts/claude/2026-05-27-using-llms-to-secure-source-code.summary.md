# 使用LLM保障源代码安全

**一句话总结：** 发现漏洞已可并行化，瓶颈转向验证、分类和修补，需建立威胁模型和沙箱环境。

**主要观点：**

1. 发现漏洞已可并行化，瓶颈转向验证、分类和修补。
2. 截至2026年5月22日，已披露1,596个漏洞，仅97个被修补。
3. 威胁模型需明确信任边界，避免误报和漏报。
4. 沙箱环境需隔离代理并验证漏洞的可利用性。
5. 发现阶段应提供丰富上下文，使用简短提示和有用工具。
6. 验证阶段需独立代理，假设发现为误报并尝试证伪。
7. 分类阶段按根因去重，根据可达性、攻击者控制等评估严重性。
8. 修补阶段需编写测试，验证补丁有效且无回归。
9. 模型可生成补丁，但人类仍需负责审核和决策。
10. 持续扫描应定期或在代码重大变更时进行。

**要点总结：**

1. 先建立威胁模型和沙箱，再启动发现-验证-分类-修补循环。
2. 发现阶段使用简短提示和工具，让模型自主探索漏洞。
3. 验证阶段使用独立代理，要求构建可复现的概念验证。
4. 分类时按根因去重，根据预条件和影响评估严重性。
5. 修补时编写测试验证补丁，并搜索同类漏洞变体。
