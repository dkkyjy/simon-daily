# 构建 Claude Code 的经验教训：我们如何使用技能

            **日期：** 2026-06-03 00:00 UTC
            **链接：** https://claude.com/blog/lessons-from-building-claude-code-how-we-use-skills

            ---

            技能已成为 Claude Code 中使用最广泛的扩展点之一。它们灵活、易于创建且易于分发。

但这种灵活性也使得难以确定什么最有效。什么样的技能值得制作？如何构建一个技能？何时与他人分享？

在 Anthropic，我们已在 Claude Code 中广泛使用技能，活跃使用的技能有数百个。以下是我们学到的关于利用技能加速开发的经验教训。

## 什么是技能？

技能是智能体可以发现并用于更准确、更高效地完成任务的指令、脚本和资源文件夹。这篇博文假设您已熟悉技能基础知识；如果您是新手，请从我们在 Skilljar 上的[智能体技能入门课程](https://anthropic.skilljar.com/introduction-to-agent-skills)开始。

我们经常听到的一个关于技能的误解是，它们"只是 Markdown 文件"。实际上，它们是包含脚本、资产、数据等的文件夹，智能体可以发现、探索和操作这些内容。

在 Claude Code 中，技能还具有[多种配置选项](https://code.claude.com/docs/en/skills#frontmatter-reference)，包括注册动态钩子。

我们发现，Claude Code 中一些最有效的技能充分利用了这些配置选项和文件夹结构。

## 技能类型

在整理 Anthropic 内部所有技能后，我们注意到它们可分为九类。最好的技能能干净地归入其中一类；而那些试图包罗万象的技能会横跨多个类别，让智能体感到困惑。这并非一个 definitive 列表，但它是一个有用的框架，可用于识别您自己的技能库中的缺口。

Claude Code 团队对我们内部技能进行了分类，发现它们可分为九个不同的类别。

### **1. 库和 API 参考**

这些技能解释了如何正确使用某个库、CLI 或 SDK。它们既适用于内部库，也适用于 Claude Code 有时难以处理的常见库。这些技能通常包含一个参考代码片段文件夹以及一份 Claude 在编写脚本时应避免的注意事项列表。

示例包括：

* `billing-lib` — 您的内部计费库：边缘情况、陷阱等。
* `internal-platform-cli` — 您的内部 CLI 包装器的每个子命令，附有使用示例。
* `sandbox-proxy` — 配置您组织的出口网关以进行开发工作：哪些主机可达、如何调试"连接被拒绝"错误、如何添加允许列表条目。

### **2. 产品验证**

这些技能描述了如何测试或验证您的代码是否正常工作。它们通常与 Playwright、tmux 或其他外部工具配对使用以进行验证。

验证技能在内部对 Claude 输出质量的影响最为显著。让一名工程师花一周时间专门优化您的验证技能可能是值得的。

考虑采用诸如让 Claude 录制其输出视频以便您确切看到它测试了哪些内容，或在每一步强制执行程序化状态断言等技术。这些通常通过在技能中包含各种脚本来实现。

示例包括：

* `signup-flow-driver` — 在无头浏览器中运行注册 → 邮箱验证 → 引导流程，并带有每一步断言状态的钩子。
* `checkout-verifier` — 使用 Stripe 测试卡驱动结账 UI，验证发票是否实际进入正确状态。
* `tmux-cli-driver` — 用于交互式 CLI 测试，其中需要 TTY 进行验证。

### **3. 数据获取与分析**

这些技能连接到您的数据和监控堆栈。这些技能可能包含用于获取数据的库（含凭证）、特定仪表板 ID 等，以及关于常见工作流程或数据获取方式的说明。

示例包括：

* `funnel-query` — "我需要连接哪些事件才能看到注册 → 激活 → 付费"，以及实际包含规范 user_id 的表。
* `cohort-compare` — 比较两个群组的留存率或转化率，标记统计显著的差异，链接到细分定义。
* `grafana` — 数据源 UID、集群名称、问题 → 仪表板查找表。
* `datadog` — 字段参考（@request_id 与 trace_id）、服务列表、指标前缀约定。

### **4. 业务流程与团队自动化**

这些技能将重复性工作流程自动化成一个命令。这些技能通常相当简单，但可能依赖于其他技能或 MCP，较为复杂。对于这些技能，将先前结果保存在日志文件中可以帮助模型保持一致，并反思先前工作流程的执行情况。

示例包括：

* `standup-post` — 汇总您的工单追踪器、GitHub 活动和之前的 Slack 消息 → 格式化的站会报告，仅包含增量内容。
* `create-<ticket-system>-ticket` — 强制执行模式（有效枚举值、必填字段）以及创建后工作流程（通知审查者、在 Slack 中分享链接）。
* `weekly-recap` — 合并的 PR + 关闭的工单 + 部署 → 格式化的周报。

### **5. 代码脚手架与模板**

这些技能为代码库中的特定功能生成框架样板。您可以将这些技能与可组合的脚本结合使用。当您的脚手架包含无法纯粹由代码覆盖的自然语言需求时，它们尤其有用。

示例包括：

* `new-<framework>-workflow` — 使用您的注解搭建新的服务/工作流/处理器。
* `new-migration` — 您的迁移文件模板以及常见注意事项。
* `create-app` — 新的内部应用，预先配置了您的认证、日志记录和部署配置。

### **6. 代码质量与审查**

这些技能在组织内部强制执行代码质量并帮助审查代码。它们可以包含确定性脚本或工具以实现最大稳健性。您可能希望将这些技能作为钩子的一部分或在 GitHub Action 中自动运行。

* `adversarial-review` — 生成一个具有全新视角的子智能体进行批评，实施修复，迭代直到发现的问题降级为细枝末节。
* `code-style` — 强制执行代码风格，特别是 Claude 默认情况下处理不佳的风格。
* `testing-practices` — 关于如何编写测试以及测试什么的说明。

### **7. CI/CD 与部署**

这些技能帮助您在代码库内获取、推送和部署代码。这些技能可能引用其他技能来收集数据。

示例包括：

* `babysit-pr` — 监控 PR → 重试不稳定的 CI → 解决合并冲突 → 启用自动合并。
* `deploy-<service>` — 构建 → 冒烟测试 → 逐步流量发布并比较错误率 → 出现回归时自动回滚。
* `cherry-pick-prod` — 隔离工作树 → 挑选提交 → 冲突解决 → 带模板的 PR。

### **8. 操作手册**

这些技能接收一个症状（例如 Slack 线程、警报或错误特征），进行多工具调查，并生成结构化报告。

示例包括：

* `<service>-debugging` — 为您流量最高的服务映射症状 → 工具 → 查询模式。
* `oncall-runner` — 获取警报 → 检查常见嫌疑 → 格式化发现结果。
* `log-correlator` — 给定一个请求 ID，从每个可能接触过它的系统中拉取匹配的日志。

### **9. 基础设施运维**

这些技能执行日常维护和操作流程，其中一些涉及可能受益于防护措施的破坏性操作。它们使工程师更容易在关键操作中遵循最佳实践。

示例包括：

* `<resource>-orphans` — 查找孤立的 Pod/卷 → 发布到 Slack → 等待期 → 用户确认 → 级联清理。
* `dependency-management` — 您组织的依赖审批工作流程。
* `cost-investigation` — "为什么我们的存储/出口费用激增"并附带具体的存储桶和查询模式。

## 制作技能的技巧

一旦决定了要制作什么技能，如何编写它？以下是 Claude Code 团队的一些最佳实践、技巧和诀窍。

### 不要陈述显而易见的内容

Claude 已经知道如何编码，并且可以读取您的代码库。一个重述 Claude 默认会做的事情的技能增加了上下文但没有增加价值。如果您要发布一个主要关于知识的技能，请专注于将 Claude 推出其常规思维方式的信息。

[前端设计技能](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md)是一个很好的例子；它由 Anthropic 的一位工程师通过与客户迭代来改进 Claude 的设计品味而构建，避免了诸如 Inter 字体和紫色渐变等经典模式。

### 构建一个注意事项部分

任何技能中信号最强的部分是"注意事项"部分。这些部分应该从 Claude 在使用您的技能时遇到的常见失败点构建而来。理想情况下，您会随着时间的推移更新您的技能以捕捉这些注意事项。

例如：

"`subscriptions` 表是仅追加的。您想要的行是具有最高版本号的行，而不是最近的 `created_at`。"
"此字段在 API 网关中称为 `@request_id`，在计费服务中称为 `trace_id`。它们是相同的值。"
"即使 Stripe webhook 实际上没有处理，Staging 也会返回 200。请检查 `payment_events` 以获取真实状态。"

### 利用文件系统和渐进式披露

SKILL.md 文件指向 Claude 可以在特定情况下参考的其他几个文件。例如，如果某个作业处于待处理状态，它应该引用 stuck-jobs.md。

正如我们之前所说，技能是一个文件夹，而不仅仅是一个 Markdown 文件。您应该将整个文件系统视为一种上下文工程和渐进式披露的形式。告诉 Claude 您的技能中有哪些文件，它会在适当的时候读取它们。

渐进式披露的最简单形式是指向其他 Markdown 文件供 Claude 使用。例如，您可以将详细的函数签名和使用示例拆分为 `references/api.md`。

另一个例子：如果您的最终输出是一个 Markdown 文件，您可以在 `assets/` 中包含一个模板文件供其复制和使用。

您可以拥有参考、脚本、示例等文件夹，这些有助于 Claude 更有效地工作。

### 为模型编写描述，而非为人类

当 Claude Code 启动一个会话时，它会构建一个可用技能列表及其描述。Claude 扫描这个列表以决定"这个请求是否有对应的技能？"这意味着描述字段不是一个摘要，而是何时触发此技能的描述。

在技能描述中包含触发词（如"babysit"）会很有帮助。

### 帮助 Claude 记忆

这个文本日志文件帮助 Claude 记住过去的事件，比如审查 Sarah 的认证 PR。

某些技能可以通过在自身内部存储数据来包含一种记忆形式。您可以将数据存储在简单的仅追加文本日志文件或 JSON 文件中，也可以存储在复杂的 SQLite 数据库中。

例如，一个 `standup-post` 技能可能会保留一个 standups.log 文件，记录每次发布的帖子，这意味着下次您运行它时，Claude 会读取自己的历史记录，并能判断自昨天以来发生了什么变化。

您可以使用环境变量 `${CLAUDE_PLUGIN_DATA}` 来获取一个稳定的目录来存储数据，在此处阅读更多关于在技能中持久化数据的信息：<https://code.claude.com/docs/en/plugins-reference#persistent-data-directory>。

### 使用按需钩子

技能可以包含仅在技能被调用时激活的钩子，并且仅持续会话期间。将此用于那些您不想一直运行，但有时极其有用的更具意见性的钩子。

例如：

* `/`**`careful`** — 通过 Bash 上的 PreToolUse 匹配器阻止 rm -rf、DROP TABLE、force-push、kubectl delete。您只希望在知道自己在操作生产环境时使用它——一直开启会让您发疯。
* `/`**`freeze`** — 阻止任何不在特定目录中的 Edit/Write 操作。在调试期间很有用："我想添加日志，但我总是意外地'修复'不相关的代码。"

## 分发技能

技能的最大好处之一是您可以与团队其他成员分享它们。

有两种方式可以与他人分享技能：

* 将您的技能检入到您的仓库中（位于 `./.claude/skills` 下）
* 制作一个**插件**，并建立一个 Claude Code 插件市场，用户可以上传和安装插件（在此处阅读更多[文档](https://code.claude.com/docs/en/plugin-marketplaces)）

对于在相对较少的仓库中工作的小团队，将技能检入仓库效果很好。但每个检入的技能也会稍微增加模型的上下文。随着规模扩大，内部插件市场允许您分发技能，让您的团队决定安装哪些技能，并包含一个设置流程。

## 管理技能市场

如何决定哪些技能进入市场？人们如何提交它们？

在 Anthropic，我们没有集中式团队来做决定；相反，我们尝试有机地找到最有用的技能。如果有人有一个技能希望别人试用，他们可以将其上传到 GitHub 中的沙箱文件夹，并在 Slack 或其他论坛中分享链接。

一旦一个技能获得了关注（由技能所有者决定），他们可以提交一个 PR 将其移入市场。

## 组合技能

您可能希望拥有相互依赖的技能。例如，您可能有一个文件上传技能用于上传文件，以及一个 CSV 生成技能用于生成 CSV 并上传它。这种依赖管理尚未原生构建到市场或技能中，但您只需按名称引用其他技能，如果它们已安装，模型就会调用它们。

## 衡量技能

为了了解技能的表现，我们使用一个 PreToolUse 钩子，允许我们在公司内部记录技能使用情况（[示例代码在此](https://gist.github.com/ThariqS/24defad423d701746e23dc19aace4de5)）。这意味着我们可以找到哪些技能受欢迎，或者哪些技能与我们的预期相比触发不足。

## 开始使用

技能的最佳实践仍在不断发展。我们大多数最好的技能都是从几行代码和一个注意事项开始的，然后随着人们不断添加内容以应对 Claude 遇到的新边缘情况而变得更好。

理解技能的最佳方式是开始使用、实验，并看看什么对您有效。
