AI 编程工具缩短了从想法到工作原型的时间。CodeRabbit 是一家 AI 代码审查平台，它注意到与这种吞吐量并行的另一个趋势：代码能够编译并通过测试，但实际并未实现团队真正想要构建的功能。

CodeRabbit 的 AI 副总裁 David Loker 将原因定位在模型上游。经验丰富的开发者常常认为编程智能体理解与他们相同的上下文，因此不会写下那些对他们来说显而易见的需求。然后编程智能体就用自己认为合理的内容来填补这些空白。

为了弥合这一差距，CodeRabbit 使用 Claude 设计并构建了一个智能体编排系统，在生成任何代码之前先运行一个结构化的规划阶段。团队的工作假设是：规划质量决定输出质量，而代码生成越廉价，朝错误方向前进的代价就越高。

## **解决 AI 编程中的内部知识缺口**

CodeRabbit 团队在研究客户群中 AI 生成的 Pull Request 时发现，最常见的失败模式是代码虽然能够编译并通过测试，但仍然没有解决它本应解决的问题。

“随着我们作为开发者积累经验，我们会内化知识，”Loker 说。“所有这些都在我们脑子里，我们假设其他开发者也知道。但我们又对 AI 系统也做了同样的假设，认为它也能隐式理解。我们甚至没有意识到自己在做这些假设。”

模糊的提示会迫使底层系统用自己认为合理的内容来填补空白。而这种猜测往往与开发者的想法相左。

Loker 举了一个个人例子。在做一个副项目中的记忆系统时，他花了好几个小时与一个编程智能体迭代，直到一切都能运行。当他询问智能体如何使用该系统时，指令告诉他要传入一个用户令牌。但根本没有登录页面。他指定了系统需要用户，但从未说过用户需要一种登录方式。智能体填补了空白，结果数小时的工作产出了一个缺少前门的成品。

“最终的结果是，你在它之上构建了更多东西，然后很久之后才发现有问题，”Loker 说。“在 AI 工作流中，后期验证可能代价极其高昂。”

## **在 AI 编程解决方案之前运行的编排层**

CodeRabbit 的应对方式是在代码生成之前插入一个规划系统。该系统协调多个 Claude 模型，分析需求并揭示假设，然后生成一个结构化的执行计划，定义应该构建什么以及它需要满足哪些约束。

“这个规划系统并非旨在取代 Claude Code 的计划模式，”Loker 说。“它是一个更高层次的编排，发生在 Claude Code 之前，目的是将其指向一个非常狭窄且正确的方向，使所有需要明确的内容都变得明确，并且我们清楚所有正在做出的假设。”

输出是一份协作式的产品需求文档（PRD）：一个在完整上下文中创建、经团队相关方验证并在实现开始前审查的计划。Claude Code 接收该计划并基于它生成细粒度的实现计划。这份计划成为共享的工件，记录了决定的内容及其原因，这不仅帮助团队避免返工，并在后续验证输出是否与原始意图匹配，还能帮助新工程师快速上手。

## **在 Claude 模型家族中进行路由**

CodeRabbit 将每个模型层级与任务复杂度匹配，以优化成本和延迟。Opus 驱动编排循环以及更高级别的战略工作，即理解问题并设定整体方向。Sonnet 接收该输出并将其排序为结构化的规划步骤。Haiku 处理范围狭窄的操作，如上下文蒸馏和针对性工具使用，在这些操作中问题足够具体，小模型也能很好地回答。

“如果 Haiku 在某个任务上表现与 Sonnet 一样好，我们就用 Haiku，”Loker 说。“如果评估框架告诉我们，给 Opus 更多空间能提高规划质量，我们就给它更多空间。我们不做猜测。”

## **构建用于评估规划质量的评估框架**

CodeRabbit 拥有成熟的代码审查评估系统，但缺乏用于评估规划输出的系统。构建这一基础设施本身就成了一项独立项目。

该系统从手工调整的示例和人工检查开始。团队开发了一个 LLM 评判器库，对规划质量的特定维度进行打分。由于规划最终会产生代码，团队还可以衡量生成的代码是否有效、是否包含额外范围、以及花了多少 token 才达到目标。对同一任务分别运行有规划步骤和无规划步骤，可以隔离出规划本身的价值。

“我们当时并不知道规划需要达到什么样的详细程度，”Loker 说。过于细化的规划会随着代码库的变动而过时；过于宏观的规划又给智能体留下了填补假设的空间，而这正是规划层原本要解决的根本问题。找到合适的抽象层次需要迭代，而评估框架使这种迭代成为可能。

## **在编写任何代码之前捕获错误**

在 AI 原生的编程工作流中，许多原本在代码审查阶段出现的决策现在被提前到规划层完成。在代码生成之前构建一个团队可以审查并达成一致的计划，可以在早期捕获错误。

“我们利用 Claude 生态系统构建的是一个团队级的规划系统，”Loker 说。“规划本身成为一个质量门。如果我们能确保规划的质量从一开始就很好，那么下游的影响非常显著。你最终会得到好得多的代码。”
