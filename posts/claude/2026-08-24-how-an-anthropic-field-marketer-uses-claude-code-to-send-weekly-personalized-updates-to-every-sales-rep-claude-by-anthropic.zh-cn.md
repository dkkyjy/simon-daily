# 一位 Anthropic 区域市场人员如何用 Claude Code 为每位销售代表发送每周个性化更新 | Anthropic 出品的 Claude

**日期：** 2026-08-24 00:00 UTC
**链接：** https://claude.com/blog/how-an-anthropic-field-marketer-uses-claude-code-to-send-weekly-personalized-updates-to-every-sales-rep

---

作为市场人员，我面临的最大挑战之一，就是让销售团队随时掌握一线市场的最新动态。大多数市场人都听过那种走廊里的偶遇对话——销售代表随口说一句："哦，那个活动我完全没听说过"（或者那份新白皮书、那场网络研讨会），你这才意识到自己错过了向销售代表传递最新成果的机会，而销售代表本可以将这些传递给客户。

我最初的解决方案，很多市场人都能感同身受：每周一早上和销售团队开一个 15 分钟的晨会。我会在周日晚上把全公司各部门的更新汇总起来，整理成演示幻灯片，然后在会上现场讲解，再把幻灯片分享到 Slack 上。任务完成了，对吧？其实并没有：自从用上 Claude 之后，这一切都显得过于手动了；而且随着团队规模扩大，我开始同时支持多个销售团队，我原来的幻灯片流程已经跟不上了。这些更新也越来越缺乏针对性，因为我已没有时间去为每个团队筛选出真正适合他们的机会。

我希望让 Claude 来做这件事，为每位销售代表打造一份更好的"产品"：一份根据他们各自负责的客户定制、并与我们市场活动全面匹配的每周简报。

幸运的是，我们恰好组织了一场市场黑客松——专门拿出时间来用 Claude Code 重构可重复的流程和工作流。我和团队聚在一起，花了一个小时集中攻克这个问题，效果立竿见影。像黑客松这样轻松、通常由同行主导的学习机会，能让人去尝试和探索那些在日常工作中根本挤不出时间做的事，我们的团队也不例外。

## **你不需要会写代码，你需要的是把问题说清楚**

同行市场人问我最多的问题之一是："我该怎么开始用 AI？"我的方法，尤其是在使用 Claude Code 时，是先写一段提示词，告诉 Claude：虽然我本身不是技术人员，但我有一个具体的难题，请把我当作一位深刻理解业务问题的产品经理，一步一步地和我协作。我习惯边想边说，所以经常会把自己对问题的描述录下来，然后把文字稿交给 Claude；这样 Claude 就能获得完整的业务背景。

在我们团队的每周客户经理简报这个案例中，我首先向 Claude 阐明了目标：向每位销售代表发送一条每周 Slack 消息，告知他们市场端正在发生什么，以及这些如何帮助他们服务客户。然后我写了一封模拟的每周更新，给 Claude 一个可以参照的模板。我知道销售代表是行动导向的，所以我从"本周三件要事"入手，列出三个行动项，比如即将举办的活动或近期发布的内容，他们可以直接分享给客户。我还为经理单独写了一个汇总模板，因为经理通常希望看到团队的全面概览，而不仅仅是单个客户的情况。

接下来，我通过 MCP 将 Claude 连接到了 BigQuery；BigQuery 是我们市场团队的核心数据源，提供来自 HubSpot、Clay 和 Salesforce 的细粒度数据洞察。我想从简单开始，所以先接入了我们活动和网络研讨会的单一权威数据源。为了让每份更新实现个性化，我让 Claude 从我们的 CRM 中拉取每位销售代表负责的区域，以及 Slack 中沟通的相关客户动态。这样，Claude 就能将两者结合，生成一份个性化的每周更新。

随着时间推移，我与其他市场团队一起不断丰富数据源，所以简报现在已涵盖新发布的博客文章、电子书、客户案例、网络研讨会，甚至来自我们合作伙伴生态系统的活动。

## **用户反馈才是真正的提示词工程**

要把这套流程推向一线，我先从一个愿意充当测试组的销售团队开始。先发给 10 个人，万一出错心里也没那么慌，而且这个团队也承诺会积极提供反馈。第一次发送之后，我做了一些微调。

有些问题纯粹是错误。比如，当源数据表中某个活动没有填写 URL 时，Claude 会自行编造一个看起来合理但实际上无法访问的链接。我们立刻在提示词中加入了一条硬性规则：绝不编造 URL。现在，只有当链接地址与源数据表一字不差时，才会显示链接。后来某个版本干脆把没有链接的活动从简报中完全剔除，因为我们意识到，对于销售人员无法为客户注册的活动来说，这些信息只是噪音。

到第一周结束时，提示词中已包含九条内容规则，每一条都可以追溯到某位销售或经理的一条反馈。一位销售反馈说，某位工程副总裁被推荐参加了一场面向知识工作者的工作坊，所以我们现在会将联系人职位与活动的目标受众进行校验，不匹配的直接剔除，不做任何说明。我们还设置了一个行业筛选机制，确保零售客户不会出现在金融晚宴的邀请中；而还没有分配客户的新入职销售则会收到一条简短的欢迎语，而不是一条空白消息。

另一些问题则出在数据层面。市场领域的人都清楚，维护一个统一的权威数据源有多难。比如，我们的线下活动数据表在六周内就调整过三次列的顺序。为了应对这种情况，我们修改了提示词，让每次运行都先读取表头行、核对列映射关系，然后再开始生成内容。不再硬编码"查看 C 列"，而是改为类似"查看包含活动 URL 的那一列"这样的指令。

## **将简报推广到全公司**

经过这些初步运行后，我将简报扩展到我支持的所有团队，现在区域市场部门已为全公司销售团队运行这套流程。每个周一早上，来自 Anthropic 多个销售板块的客户经理打开 Slack，就会收到一条私信，其中列出了本周的三项优先行动、针对他们客户的线下活动、已注册即将举办的网络研讨会的联系人、可分享的营销内容，以及其他跟进建议。

每条消息都是根据收件人自己的客户列表生成的，所以没有两条消息是相同的。这套简报正在发挥作用：最近一周，仅因为正确的销售代表在周一早上就看到了正确的活动，一场高管晚宴的注册人数就翻了一番。

当 Anthropic 的业务拓展代表（BDR）也想拥有自己的版本时，我们只需复制提示词并修改一个字段即可，因为 BDR 在 CRM 中通过不同的关系映射到客户，与销售经理不同。提示词的结构和内容规则原封不动地沿用，BDR 团队在两天内就上线了。此后，我也为客户成功团队和联盟团队做了同样的配置，还为销售之外的其他跨职能合作伙伴提供了一份全部市场活动的概览。

无论业务节奏多快，我和我的团队在 Claude 的帮助下，都能确保销售代表在每周一开始时，清楚地知道本周正在发生什么，以及应该优先关注哪些客户和活动。每周一的发送内容都会被完整归档，所以我可以随时调出任何一位销售人员在任何日期收到的具体内容，经理也能在一个汇总视图中看到整个团队的推荐。我仍然会阅读发出去的内容，只不过系统不再等待我的审批了。几周前我休假时，周一的定时发送照常自动完成，一切顺利。

## **使用 Claude 上手的最佳实践**

以下是我根据自己使用 Claude Code 的经验总结的一些技巧和建议：

1. **从小处着手，从你已经在手动完成的事情开始。** 当周围充斥着各种关于 AI 应用的讨论时，要迈出第一步确实很难。我的建议是：挑出你投入手动时间最多的那个重复性任务，让 Claude 帮你重构它。这样你就能评判输出质量，因为你已经知道"好的结果"长什么样。如果问题仍然觉得太大，就把 Claude 当作思考伙伴，让它帮你把问题拆解成步骤。如果这件事涉及与其他人共享，先让早期运行结果发给你自己，这样你能在别人之前发现错误。
2. **用通俗易懂的语言编写指令，并为每个文档保留版本记录。** 就像你向一位新同事交代工作那样向 Claude 说明情况，剩下的交给 Claude 去做。让 Claude 将每次更新保存为一个带编号的版本，并附一行说明记录本次变更内容，这样你就有了每条提示词对应每次运行结果的完整记录。我们使用的是一个 Markdown 文件，同事们各自为自己的业务板块运行；我们最初从一份共享的 Google 文档开始，当需要编辑的人越来越多后，就迁移到了 GitHub。
3. **先在一个小型、 committed 的群体中试点。** 我们的首次测试选择了少数几位客户经理，我们知道他们愿意花时间提供反馈、持续改进报告，帮助我们发现错误或提出扩展和个性化覆盖范围的建议。
4. **用反馈来改进提示词，将每次纠正都转化为一条明确的规则。** 当收件人开始与我们分享反馈、每一次纠正都变成 Claude 的一条明确规则时，这份市场简报才真正变得实用起来。

2. **用通俗易懂的语言编写指令，并为每个文档保留版本记录。** 就像你向一位新同事交代工作那样向 Claude 说明情况，剩下的交给 Claude 去做。让 Claude 将每次更新保存为一个带编号的版本，并附一行说明记录本次变更内容，这样你就有了每条提示词对应每次运行结果的完整记录。我们使用的是一个 Markdown 文件，同事们各自为自己的业务板块运行；我们最初从一份共享的 Google 文档开始，当需要编辑的人越来越多后，就迁移到了 GitHub。
3. **先在一个小型、愿意配合的群体中试点。** 我们的首次测试选择了少数几位客户经理，我们知道他们愿意花时间提供反馈、持续改进报告，帮助我们发现错误或提出扩展和个性化覆盖范围的建议。
4. **用反馈来改进提示词，将每次纠正都转化为一条明确的规则。** 当收件人开始与我们分享反馈、每一次纠正都变成 Claude 的一条明确规则时，这份市场简报才真正变得实用起来。
