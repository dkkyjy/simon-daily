## 摘要

* **在任务之间运行 `/clear`。** 这可以防止先前不相关的上下文被发送回模型，从而减少 token 用量。
* **在开始之前设置好你的模型和努力级别。** 在对话中途更改其中任何一个都可能破坏你的提示缓存，从而增加 token 成本。
* **使用 @-提及文件，而不是直接命名它们。** 文件会直接附加到你的消息中，这可以节省一次读取调用，或者如果 Claude 必须去查找的话，节省一次搜索。
* **为嘈杂的命令添加静默标志，或在子代理中运行它们。** 命令输出会像文件一样被添加到对话中，并在会话的剩余时间内一直保留在那里。
* **在新会话中运行一次 `/context`。** 它会显示已加载的内容（`CLAUDE.md`、MCP 工具定义），这样你就可以删掉任何不必要的东西。
* **在离开键盘休息之前运行 `/compact`。** 提示缓存在一小时后过期，而在缓存仍然有效时总结对话要便宜得多。

## 最大化价值

直到不久之前，你用来编写代码的工具都是固定费用（或免费的）。无论你那天下午修复了一个测试还是五十个测试，你的编辑器成本都一样，所以单个任务本身并没有真正的价格。

对于像 Claude Code 这样的代理式编码工具，情况就不同了。同样的已完成任务，根据你使用它的方式，成本也可能不同。

在一次会话中，Claude 读取测试及其覆盖的文件，进行编辑，并在几轮对话内完成。在另一次会话中，它先在仓库中 grep 搜索，在到达同样的两个文件之前读取了十几个文件，而每一轮对话也会拖上自今天早上以来已读入对话的所有其他内容。

这是同样的修复，但你花费了不同数量的 token，而且整个过程中模型还不得不考虑十个它并不需要的文件。

高效使用 token 并不意味着总体上使用更少的 token。它意味着确保你使用的 token 确实用于你实际要求的事情上。

所以让我们先看看什么决定了 token 的价格，然后是什么决定了会话发送多少 token，并在此过程中，看看这对你如何运行会话意味着什么。

## **什么决定了 token 的价格**

你是按 token 计费的，但你实际支付的是推理费用：即 GPU（或 TPU，或模型恰好运行的任何硬件）在你的 token 上运行模型所需的时间。

有三件事决定了一个 token 需要多少这样的时间：你运行的模型、它是输入 token（进入）还是输出 token（输出），以及它是否被缓存。

### 模型

更大的模型在输入和输出 token 上都会做更多的工作。哪种模型适合哪种工作本身就是一个话题，我们在 [*在 Claude Code 中选择 Claude 模型和努力级别*](https://claude.com/blog/claude-model-and-effort-level-in-claude-code) 中已经介绍过。

对于这篇文章，你只需要知道，我们即将讨论的所有其他内容都会乘以模型的价格：当问题真正困难或模糊时使用更大的模型，当工作是常规性的时使用更小的模型。
