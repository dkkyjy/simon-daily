# 在生产环境中运行自动模式 | Claude by Anthropic

**日期：** 2026-08-07 00:00 UTC
**链接：** https://claude.com/blog/auto-mode-in-production

---

[自动模式现已成为](http://claude.com/blog/auto-mode-default-in-claude-code) Claude Code 中的默认设置。它不再要求你批准代理想要运行的每条命令，而是通过一个分类器评估每个操作，并阻止看起来可能有害的操作。

自动模式的设计解决了一个常见的代理编码权衡：速度与安全。审查每条命令能让人类保持在循环中，但一旦会话持续数小时或并行增加，这种监督就会成为瓶颈。完全跳过权限检查速度更快——但这也是提示注入、范围漂移以及偶尔删除生产资源得以发生的原因。

自动模式弥合了大部分差距。在内部评估中，分类器捕捉到的危险操作比开发人员手动点击权限提示时更多，并且其性能在第三方红队测试中依然保持稳定。而且由于会话暂停频率降低，Claude 在中断之间的工作时间比之前的默认设置长了 9 倍——覆盖所有 Claude Code 使用场景。

为了了解自动模式在生产环境中的表现，我们与 Nuro、Gusto 和 Garner Health 的团队进行了交流，了解他们如何以及为何将自动模式作为日常工具，在生产环境中平衡速度与安全。

### 为 Nuro 更长时间的自主代理提供动力

Nuro，这家开发通用 4 级自动驾驶技术的实体 AI 公司，于 2025 年底采用 Claude Code，到 3 月时它已成为公司最受欢迎的代理编码工具。

在自动模式发布之前，高级软件工程师 Kai Zhou 已经开始原型设计一个内部替代方案：一个钩子，将每个待处理操作发送给一个小型模型，自动批准常规的 90% 操作，并将任何敏感内容路由到 Slack 供人工审查。该原型回应了一个真实的矛盾：工程师讨厌盯着批准提示，但从公司安全和法律角度来看，完全跳过权限过于危险，无法批准。当自动模式发布时，Kai 搁置了这个副项目。

如今，Kai 在他编写的所有内容中都使用自动模式。

“我不想一直坐在那里点击批准，”Kai 说。“我 100% 的编码工作都使用自动模式。大多数时候，我会打开三四个并行运行自动模式的会话，需要时再查看一下。”

例外情况是涉及其他团队的工作。例如，当 Claude Code 代表他审查拉取请求时，Kai 会切换回交互模式，并在每个请求发出前逐一审查。

自动模式也不是无约束运行的。Nuro 大量依赖[技能](https://agentskills.io/home)，工程师们直接在其设置中拒绝最危险的命令，如递归删除。分类器在这些护栏内做出判断。

然而，自动模式更大的解锁能力在于，它能够启动在工程师结束一天工作后继续运行的任务。具体来说，Kai 的团队使用自动模式来驱动长期运行的研究代理，这些代理会爬升其自动驾驶栈背后的评估指标：这些任务具有清晰、可测量的信号，代理可以自行迭代。

在夜间，代理可以研究评估套件标记的假阴性，起草提案，运行实验，并持续迭代结果。这种方法适用于任何具有清晰评估方法的任务——Nuro 的另一个团队使用它来缩小特定二进制文件的内存占用——因为指标本身会告诉代理它是在改进还是退步。

“前几天，我在晚上 10 点启动了一个代理，它一直运行到凌晨 5 点——早上给了我三个拉取请求，”Kai 说。“我觉得这相当令人印象深刻。只有自动模式才能支持这种工作负载。”

### 在 Gusto 更快、更安全地交付拉取请求

在领先的中小企业技术公司 Gusto，转向自动模式始于一次主动的安全升级。

Martin Emde 在该公司的 AI 开发工具团队工作，他目睹了权限疲劳拖慢团队速度。自动模式在不牺牲控制或安全的情况下给了他们同样的速度，自从工程部门全面采用以来，整体权限负担明显下降。

自 12 月以来，Martin 已启动了 2,425 个 Claude Code 会话，自动模式是他的日常工具。过去因文件夹访问批准而停滞的跨仓库工作现在可以不间断运行，无人值守的任务（如从 GitHub、Slack 和 Jira 编译每日笔记）也能自主运行。根据他们团队自己的分析，自 2026 年 5 月中旬以来，大约 10% 的会话记录包含自动模式拒绝，这证明分类器在完成实际工作，同时不会拖累合法任务。

“自动模式在速度和控制之间给了我们更安全的平衡，”Martin 说。“我们能够移除重复提示，在不损害安全的情况下提高生产力。我们可以看到自动模式在正确的时间进行阻止，这给了我们快速行动的信心。”

Chad Kunsman 是 Gusto AIT 云工程团队的成员，他从另一个方向得出了同样的结论。他的工作——端点调查、日志审计、连接器管理、跨 MCP 服务器栈的文档摄取——以二十分钟的短时爆发运行，而非通宵马拉松。他寻求的不是更长的运行时间；他想要的是绕过权限的无人工干预节奏，同时避免糟糕提示或提示注入溜进来所带来的风险。

“考虑到对提示注入的保护，以及它检查你所做的事情是否与你要求的一致的方式，它比绕过权限更好，也比权限提示快得多，”Chad 说。

在分类器偶尔介入的情况下，Chad 说它判断准确。“当它阻止我时，它是有道理的，并解释了原因。它偏离了我最初的要求，然后它进行了检查。它完全没有偏离。”

Chad 仍然会在最敏感的工作中退出自动模式。当会话深入生产基础设施——Terraform、AWS、对实时 API 的直接 POST 调用——他会切换到接受编辑模式，并手动验证每个工具调用。“你必须权衡你节省的时间与它可能合理犯的错误，以及那会有多灾难性，”他说。“归根结底，你仍然要对发生的事情负责。”

这种判断在更广泛的纵深防御设置中运作：Gusto 将其 MCP 流量通过一个带有工具防护和提示检查的治理代理层路由，因此代理在自动模式介入之前就使用严格限定的权限工作。

### 在 Garner Health 加速软件开发生命周期（SDLC）

医疗保健技术公司 Garner Health 于 2 月向所有 550 名员工（涵盖各个职能部门）推出了 Claude Code。该工具已接入所有核心系统，包括 Salesforce、Zendesk 和 Snowflake，员工被鼓励每周花大约两小时自动化工作中最可重复的部分。

在自动模式之前，这种规模伴随着开销。Garner 的平台工程经理 Evan Magnussen 将权限管理描述为一个繁琐的循环：手工策划批准的命令列表，并看着管道命令被拒绝。

如今，Evan 和他的大多数同事在每个会话中都使用自动模式，从研究代码库到通过 MCP 管理外部集成。

“我们为整个工程组织构建了一个标准化的软件开发生命周期，这真的只有通过自动模式才能实现，”Evan 说。“员工们视它为卸下了肩上的重担。他们不再需要长时间监控他们的代理了。”

该生命周期作为标准化技能的插件运行。代理接收任务，探索其可访问的上下文，将上下文文件提交到仓库，运行 Evan 所称的“对抗性研究”来压力测试其自身假设，然后进入实施阶段——仅在需要无法自行找到的上下文时才暂停等待人工介入。Evan 指出，研究密集的阶段在自动模式之前是不可能实现的。

开箱即用，分类器几乎不需要调整。Evan 的唯一调整与 Nuro 的 Kai 类似：他配置自动模式不批准与他人通信的操作，如发送 Slack 消息或电子邮件。

“我个人不喜欢 Claude 在我与他人沟通时代表我行事，”他说。从事核心知识产权工作的团队——在自动模式之前最怀疑跳过权限的团队——学会了调整分类器的注入提示，使其在工作中更宽松或更严格。

他对其他正在推广该功能的企业有什么建议？积极投入并构建正确的控制措施，以便在确保安全部署的同时赋能工程师。“如果我们说，每个人都去构建自己的工作流，而我们没有遥测，那将非常危险，”Evan 说。“因为我们有遥测，因为我们构建了相对标准的工作流，我们有了更多的信心。”
