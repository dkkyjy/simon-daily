# 一句话总结

Opus 4.7 是 Anthropic 最强的编码模型，需调整提示词和努力级别以在 Claude Code 中发挥最佳性能。

# 主要观点

1. 在交互式编码中，Opus 4.7 在用户轮次后会更深入推理，但会消耗更多令牌。
2. 将 Claude 视为可委托的工程师，而非逐行指导的结对程序员。
3. 在首次交互中明确指定任务意图、约束、验收标准和文件位置。
4. 减少用户交互次数，因为每轮都会增加推理开销。
5. 对于可信任的长时间任务，使用自动模式以减少周期时间。
6. 默认努力级别为 xhigh，介于 high 和 max 之间。
7. Opus 4.7 不支持固定思考预算，而是采用自适应思考。
8. 响应长度根据任务复杂度自动校准，不再默认冗长。
9. 模型减少工具调用频率，增加推理，从而提升结果质量。
10. Opus 4.7 默认减少子代理的生成，需明确指示何时并行工作。

# 收获

1. 在 Claude Code 中，将 Opus 4.7 视为可自主工作的工程师，在首轮提供完整上下文。
2. 使用 xhigh 默认努力级别处理大多数编码任务，仅在极端复杂任务时切换到 max。
3. 通过提示词直接控制思考深度，例如要求“仔细思考”或“优先快速响应”。
4. 明确指定期望的响应长度和工具使用频率，因为新模型默认行为已改变。
5. 对于多文件更改和模糊调试等长时间任务，Opus 4.7 表现优于前代模型。
