# Claude Code 现支持工件

**日期：** 2026-06-18 00:00 UTC
**链接：** https://claude.com/blog/artifacts-in-claude-code

---

从今天开始，Claude Code 可以将工作进度捕获为工件，从而将 Claude Code 的工作转化为实时、可共享的可视化页面——包括 PR 演练、系统解释器、仪表板和发布检查清单——这些页面会随着您会话的进行自动更新。

一个 Claude Code 会话可以涵盖从调查事件到重构服务，再到分析数月数据的各种工作。工件将工作转化为任何人都可以打开和探索的网页，例如拉取请求演练、可以筛选和排序的仪表板，甚至是随着工作完成而自动填写的发布检查清单。工件使协作处理共享工作变得更加容易，因此团队可以花更多时间构建，减少沟通状态更新的时间。

## **基于您会话的上下文构建**

Claude Code 使用您会话的完整上下文来构建工件，包括您的代码库、连接器以及对话本身。一个单一的事件页面可以汇集来自代码的失败测试及其背后的函数、来自连接监控工具的错误峰值，以及来自您刚刚运行的会话的根本原因推理。使用工件，您无需连接数据源或搭建基础设施。您只需请求一个页面，Claude Code 就会基于现有内容构建它。

## **实时页面，原地更新**

当 Claude Code 更新工件时，打开的页面会原地刷新，团队成员在发布后立即就能看到更新。每次发布都是同一链接下的一个新版本，并带有版本历史记录，以便您可以随时恢复；图库功能让您可以浏览和管理您创建的所有工件。

根据我们的内部测试，最常见的用例之一是调试。典型情况如下：工程师在站会前开始调查事件。Claude Code 处理日志并发布一个工件：时间线、可疑提交和错误率图表。她从页面标题处与团队分享链接。到站会开始时，Claude 已随着调查进展重新发布了两次工件，纳入了最新信息。借助工件，团队成员和利益相关者无需"向我们介绍代理发现了什么"，因为他们都在查看同一个视图，拥有相同的上下文。

## **对您的组织私有**

默认情况下，每个工件仅对其作者私有。当您准备好时，可以直接从页面与您的团队成员和组织共享。工件仅可由您组织中经过身份验证的成员查看，并且不能公开。管理员通过组织级开关和基于角色的范围来管理访问权限，设置保留策略，并通过合规性 API 获得组织范围的可见性。

## **开始使用**

向您的会话请求一个工件——或者只需请求一些可视化内容，*以下是一些按角色划分的想法：*

* **法律/开源**：对每个依赖项进行许可证审计，直接从仓库中标记 copyleft 许可证。*"构建一个列出每个第三方依赖项及其许可证的工件，标记任何 copyleft 许可证。"*
* **隐私**：一份数据流图，显示个人数据在代码中的收集、存储和记录位置。*"追踪我们在代码库中处理个人数据的位置，形成隐私审查用的工件。"*
* **安全**：链接到确切代码行的发现，使修复明确无误。*"构建一个包含此次审查中身份验证发现的工件，每个发现都链接到代码。"*
* **财务运营/平台财务**：从您的基础设施即代码中映射的云资源和成本驱动因素。*"从 Terraform 中将我们的云资源映射到工件中，按服务分组，并标注主要成本驱动因素。"*
* **软件工程师**：审阅者可以实际跟随的 PR 或错误演练，从差异和周围代码中提取。*"制作一个演练此 PR 的工件——差异、推理以及我测试过的内容。"*
* **设计师和前端工程师**：一个屏幕的多种 UX 方向，每种都基于您的实际组件构建，以便您选择的那个可以直接发布。*"给我一个包含此注册表单 5 种 UX 变体的工件，基于我们的组件库构建。"*
* **高级工程师和架构师**：服务实际如何组合的映射图，从真实的导入图而非白板绘制。*"从代码中将支付服务如何组合映射成一个工件。"*
* **SRE 和值班人员**：随着您调查而增长并最终成为事后分析报告的事件页面。*"将此事件转化为工件——时间线、可疑提交、来自监控的错误峰值——并在处理过程中重新发布。"*
* **工程经理**：实际发布内容的页面，基于合并的 PR 构建。*"根据 PR 构建一个关于我团队本周合并内容的工件，按项目分组。"*

Claude Code 构建页面并为您提供一个链接。在浏览器或桌面应用中打开它，从标题处共享——更新会自动发布到相同的 URL。

## **可用性**

工件目前以测试版形式提供给 Claude Team 和企业组织，可通过 Claude Code CLI 和桌面应用使用，页面可在任何浏览器中查看。
