今天，我们推出代码审查功能，它会在每个拉取请求（PR）上派遣一组代理，以捕获快速浏览遗漏的缺陷——专为深度而非速度而设计。这是我们在 Anthropic 内部几乎所有 PR 上运行的系统。现已面向团队版和企业版提供研究预览。

## **管理审查瓶颈**

在过去一年中，每位 Anthropic 工程师的代码输出量增长了 200%。代码审查已成为瓶颈，我们每周都会从客户那里听到同样的反馈。他们告诉我们，开发人员不堪重负，许多 PR 只是被快速扫过而非深入阅读。

我们需要一个能在每个 PR 上都信任的审查者。代码审查便是成果：深度、多代理的审查，能够捕获人类审查者自己也经常遗漏的缺陷。这是一个比我们现有的 [Claude Code GitHub Action](https://code.claude.com/docs/en/github-actions) 更彻底（也更昂贵）的选项，后者仍保持开源并可供使用。

我们在 Anthropic 内部几乎所有 PR 上都运行代码审查。此前，16% 的 PR 获得了实质性的审查评论。现在这一比例达到了 54%。它不会批准 PR——这仍需人类决策——但它缩小了差距，使审查者能够真正覆盖即将发布的内容。

## **工作原理**

当 PR 被打开时，代码审查会派遣一组代理。这些代理并行查找缺陷，验证缺陷以过滤误报，并按严重程度对缺陷进行排序。结果以一条高信号量的概览评论加上针对具体缺陷的内联评论形式呈现在 PR 上。

审查规模随 PR 大小调整。大型或复杂的变更会获得更多代理和更深入的阅读；小修小改则进行轻量级处理。根据我们的测试，平均每次审查耗时约 20 分钟。

## **代码审查的实际效果**

我们已经在内部运行代码审查数月：在大型 PR（修改超过 1000 行）上，84% 的审查都有发现，平均每项发现 7.5 个问题。在少于 50 行的小型 PR 上，这一比例降至 31%，平均发现 0.5 个问题。工程师们基本上认同它发现的内容：只有不到 1% 的发现被标记为错误。

有一个案例：一个生产服务的一行变更看起来平平无奇，属于通常会被快速批准的那种差异。但代码审查将其标记为严重问题。该变更会破坏该服务的身份验证——这种失败模式在差异中很容易被忽略，但一经指出便一目了然。在合并前该问题被修复，工程师后来分享说，他们自己不会发现这个问题。

早期访问客户也看到了类似的模式。在 TrueNAS 开源中间件中的 [ZFS 加密重构](https://github.com/truenas/middleware/pull/18291) 上，代码审查发现了相邻代码中一个预先存在的缺陷：一个类型不匹配问题，导致每次同步时静默清除加密密钥缓存。这是 PR 恰好触及的代码中的一个潜在问题，人类审查者在扫描变更集时不会立即去查找这类问题。

## **成本与控制**

代码审查追求深度，比轻量级解决方案（如 [Claude Code GitHub Action](https://code.claude.com/docs/en/github-actions)）更昂贵。审查按 token 用量计费，通常平均为 15–25 美元，费用随 PR 大小和复杂度变化。

管理员有多种方式控制支出和使用量：

* **月度组织上限**：设定所有审查的总月度支出上限
* **仓库级别控制**：仅在你选择的仓库上启用审查
* **分析仪表板**：追踪已审查的 PR、接受率和总审查成本

## **开始使用**

代码审查现已作为研究预览版在 beta 阶段面向团队版和企业版计划提供。

* **对于管理员**：在 [Claude Code 设置](http://claude.com/admin-settings/claude-code) 中启用代码审查，安装 GitHub 应用，并选择你要运行审查的仓库。
* **对于开发者**：启用后，新 PR 会自动运行审查。无需额外配置。

[查阅文档](http://code.claude.com/docs/en/code-review) 以了解更多信息。
