# 提示工程最佳实践

**日期：** 2025-11-10 00:00 UTC
**链接：** https://claude.com/blog/best-practices-for-prompt-engineering

---

[上下文工程](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)已成为与LLM协作中日益重要的组成部分，而提示工程则是其基本构建块。

[提示工程](https://docs.claude.com/en/docs/build-with-claude/prompt-engineering/claude-4-best-practices)是一门构建指令以从AI模型获得更优输出的技艺。它涉及如何表述查询、指定风格、提供上下文以及引导模型行为来实现你的目标。

模糊指令与精心设计的提示之间的差异，可能意味着泛泛输出与精准所需之间的鸿沟。结构不良的提示可能需要多次来回交流才能澄清意图，而精心设计的提示则能一次到位。

为帮助你入门，我们整理了一些团队最佳实践，包括旨在立即改善结果的实际方法。我们将从今天即可使用的简单习惯开始，然后逐步扩展到适用于复杂项目的高级方法。

## 如何使用提示工程

在最基本的层面上，提示工程就是修改你传递给LLM的查询。通常只是在提出实际请求之前向查询中添加信息——但知道*哪些*信息是*正确*的信息，才是设计出优秀有效提示的秘诀。

### 核心技巧

这些提示工程技巧构成了有效AI交互的基础。持续使用它们，你将立即看到响应质量的提升。

#### 明确且清晰

现代AI模型对清晰、明确的指令响应极佳。不要假设模型能推断出你想要什么——直接说明。使用简单的语言，准确无误地说明你想要什么。

**关键原则**：准确告诉模型你想要看到什么。如果你想要全面的输出，就明确要求。如果你想要特定功能，就列出它们。像Claude这样的现代模型尤其受益于明确的指示。

**示例：创建分析仪表板**

**模糊**："创建一个分析仪表板"

**明确**："创建一个分析仪表板。尽可能包含所有相关功能和交互。超越基础，打造一个功能完备的实现。"

第二个版本明确要求全面功能，并表明你希望模型超越最低要求。

**最佳实践**：

* 以直接动作动词开头："编写"、"分析"、"生成"、"创建"
* 跳过开场白，直接提出请求
* 说明你希望输出包含什么，而不仅仅是处理什么
* 对质量和深度期望要具体

#### 提供上下文和动机

解释*为什么*某件事很重要，有助于AI模型更好地理解你的目标，并提供更具针对性的响应。这对于能够推理你潜在目标的新型模型尤其有效。

**示例：格式偏好**

**效果较差**："永远不要使用项目符号"

**效果更好**："我更喜欢自然段落形式的回复，而不是项目符号，因为我觉得流畅的散文更容易阅读，也更适合对话。项目符号对于我随意的学习风格来说显得过于正式和列表化。"

第二个版本帮助模型理解规则背后的原因，使其能够对相关的格式选择做出更好的决策。

**何时提供上下文**：

* 解释输出的目的或受众
* 阐明为何存在某些约束
* 描述输出将如何使用
* 指出你试图解决什么问题

#### 具体明确

提示工程中的具体性意味着用明确的指导方针和要求来构建指令。你对想要的内容越具体，结果就越好。

**示例：膳食计划**

**模糊**："为地中海饮食创建一个膳食计划"

**具体**："设计一份针对糖尿病前期管理的地中海饮食膳食计划。每日1800卡路里，重点选择低升糖食物。列出早餐、午餐、晚餐和一份零食，并附上完整的营养分析。"

**什么使提示足够具体？**

包括：

* 明确的约束条件（字数、格式、时间线）
* 相关上下文（受众是谁、目标是什么）
* 期望的输出结构（表格、列表、段落）
* 任何要求或限制（饮食需求、预算限制、技术约束）

#### 使用示例

示例并非总是必要，但在解释概念或演示特定格式时效果显著。也称为一次性或少量示例提示，示例通过展示而非告知来阐明难以用描述表达的细微要求。

**现代模型重要提示**：Claude 4.x及类似高级模型会非常关注示例中的细节。确保你的示例与你希望鼓励的行为一致，并尽量减少你希望避免的模式。

**示例：文章摘要**

**无示例**："总结这篇文章"

```
以下是我想要的摘要风格示例：

文章：[关于AI监管的文章链接]
摘要：欧盟通过全面的AI法案，针对高风险系统。关键条款包括透明度要求和人类监督授权。将于2026年生效。

现在以相同风格总结这篇文章：[你的新文章链接]
```

**何时使用示例**：

* 期望的格式更容易通过展示而非描述来表达
* 你需要特定的语气或风格
* 任务涉及微妙的模式或惯例
* 简单的指令未能产生一致的结果

**专业提示**：从一个示例开始（一次性）。仅在输出仍不符合你的需求时，再添加更多示例（少量示例）。

#### 允许Claude表达不确定性

给予AI明确许可，让其表达不确定性而非猜测。这能减少幻觉并提高可靠性。

**示例**："分析这些财务数据并识别趋势。如果数据不足以得出结论，请说明，而非进行推测。"

这个简单的补充通过允许模型承认局限性，使响应更加可信。

## 高级提示工程技巧

这些核心习惯能让你走得很远，但你仍可能遇到需要更复杂方法的情况。高级提示工程技巧在你构建智能体解决方案、处理复杂数据结构或需要分解多阶段问题时尤为出色。

### 预填充AI的响应

预填充允许你为AI启动响应，引导格式、语气或结构。这种技巧在强制输出格式或跳过开场白时特别强大。

**何时使用预填充**：

* 你需要AI输出JSON、XML或其他结构化格式
* 你想跳过对话式开场白，直接进入内容
* 你需要保持特定的语气或角色
* 你想控制AI如何开始其响应

**示例：强制JSON输出**

无预填充时，Claude可能会说："这是你请求的JSON：{...}"

带预填充（API使用）：

```
messages=[
    {"role": "user", "content": "从该产品描述中提取名称和价格，输出为JSON。"},
    {"role": "assistant", "content": "{"}
]
```

AI将从左大括号继续，仅输出有效的JSON。

**注意**：在聊天界面中，你可以通过非常明确的方式近似实现："仅输出有效的JSON，无需开场白。以左大括号开始你的响应。"

### 思维链提示

思维链提示涉及在回答之前请求逐步推理。这种技巧有助于处理需要结构化思维的复杂分析任务。

**现代方法**：Claude提供[扩展思考](https://www.anthropic.com/news/visible-extended-thinking)功能，可自动进行结构化推理。当可用时，扩展思考通常优于手动思维链提示。然而，理解手动思维链在扩展思考不可用或你需要可审查的透明推理时仍然很有价值。

**何时使用思维链**：

* 扩展思考不可用（即免费的[Claude.ai](http://claude.ai)计划）
* 你需要可审查的透明推理
* 任务需要多个分析步骤
* 你想确保AI考虑特定因素

思维链有三种常见实现方式：

**基本思维链**

只需在指令中添加"逐步思考"。

```
为今年"关爱儿童"项目起草个性化募捐邮件，向捐赠者请求捐款。

项目信息：
<program>
{{PROGRAM_DETAILS}}
</program>

捐赠者信息：
<donor>
{{DONOR_DETAILS}}
</donor>

在撰写邮件前，请逐步思考。
```

**引导式思维链**

构建你的提示，提供特定的推理阶段。

```
在撰写邮件前先思考。首先，思考哪些信息可能吸引这位捐赠者，考虑其捐赠历史。然后，考虑"关爱儿童"项目的哪些方面会引起他们的共鸣。最后，根据你的分析撰写个性化捐赠邮件。
```

**结构化思维链**

使用标签将推理与最终答案分开。

```
在<thinking>标签内思考后再撰写邮件。首先，分析哪些信息会吸引这位捐赠者。然后，识别相关的项目方面。最后，在<email>标签内撰写个性化捐赠邮件，使用你的分析。
```

**注意**：即使扩展思考可用，明确的CoT提示对复杂任务仍然有益。这两种方法是互补的，而非互斥的。

### 控制输出格式

对于现代AI模型，有几种有效的方法来控制响应格式：

**1. 告诉AI该做什么，而不是不该做什么**

不要："不要在响应中使用markdown"  
尝试："你的响应应由流畅的散文段落组成"

**2. 使你的提示风格与期望输出匹配**

提示中使用的格式风格可能会影响AI的响应风格。如果你希望尽量减少markdown，就减少提示中的markdown。

**3. 明确说明格式偏好**

对于格式的详细控制：

```
在撰写报告或分析时，使用完整段落以清晰、流畅的散文写作。使用标准段落分隔进行组织。仅在内联代码、代码块和简单标题中使用markdown。

除非你呈现的是真正离散的项目且列表格式是最佳选择，或用户明确要求列表，否则不要使用有序列表或无序列表。

不要用项目符号列出项目，而是将它们自然地融入句子中。你的目标是可读、流畅的文本，引导读者自然地理解思想。
```

### 提示链

与之前的技巧不同，提示链无法在单个提示中实现。链式操作将复杂任务分解为多个顺序步骤，每个步骤使用单独的提示。每个提示处理一个阶段，输出馈入下一个指令。

这种方法通过使每个单独任务更简单，以延迟换取更高的准确性。通常，这种技巧会通过工作流或编程方式实现，但你也可以在收到响应后手动提供提示。

**示例：研究摘要**

1. **第一个提示**："总结这篇医学论文，涵盖方法论、发现和临床意义。"

2. **第二个提示**："审查上述摘要的准确性、清晰度和完整性。提供分级反馈。"

3. **第三个提示**："根据此反馈改进摘要：[步骤2的反馈]"

每个阶段通过聚焦的指令增加精炼。

**何时使用提示链**：

* 你有一个需要分解为步骤的复杂请求
* 你需要迭代精炼
* 你正在进行多阶段分析
* 中间验证能增加价值
* 单个提示产生不一致的结果

**权衡**：链式操作会增加延迟（多次API调用），但通常能显著提高复杂任务的准确性和可靠性。

## 你可能听说过的技巧

一些在早期AI模型中流行的提示工程技巧，对于像Claude这样的模型已不那么必要。然而，你仍可能在旧文档中遇到它们，或在特定情况下发现它们有用。

### XML标签用于结构化

XML标签曾一度是增加提示结构和清晰度的推荐方式，尤其是在整合大量数据时。虽然现代模型在不使用XML标签的情况下能更好地理解结构，但在特定情况下它们仍然有用。

**示例**：

```
<athlete_information>
- 身高：6英尺2英寸
- 体重：180磅
- 目标：增肌
- 饮食限制：素食
</athlete_information>

根据上述运动员信息生成一份膳食计划。
```

**XML标签何时仍可能有帮助**：

* 你正在处理极其复杂的提示，混合多种类型的内容
* 你需要绝对确定内容的边界
* 你正在使用较旧版本的模型

**现代替代方案**：对于大多数用例，清晰的标题、空白和明确的语言（"使用以下运动员信息..."）效果同样好，且开销更少。

### 角色提示

角色提示在查询措辞中定义专家角色和视角。虽然这可能有效，但现代模型足够复杂，过度强化的角色提示通常是不必要的。

**示例**："你是一名财务顾问。分析这个投资组合..."

**重要注意事项**：不要过度约束角色。"你是一个有用的助手"通常比"你是一位世界知名的专家，只说技术术语，从不犯错"更好。过于具体的角色可能会限制AI的有用性。

**角色提示何时可能有帮助**：

* 你需要在多个输出中保持一致的语气
* 你正在构建需要特定角色的应用程序
* 你希望为复杂主题设置领域专业知识框架

**现代替代方案**：通常，明确说明你想要什么视角更有效："分析这个投资组合，重点关注风险承受能力和长期增长潜力"，而不是分配角色。

[在Claude中尝试](https://preview.claude.ai/new)。

## 综合运用

你现在已经看到了单独使用的技巧，但它们真正的力量在于战略性组合。提示工程的艺术不是使用所有可用技巧，而是为你的特定需求选择正确的组合。

**结合多种技巧的示例**：

```
从这份季度报告中提取关键财务指标，并以JSON格式呈现。

我需要这些数据进行自动化处理，因此你的响应必须仅包含有效的JSON，不得有开场白或解释。

使用此结构：
{
  "收入": "带单位的值",
  "利润率": "百分比",
  "增长率": "百分比"
}

如果任何指标在报告中未明确说明，请使用null而非猜测。

以左大括号开始你的响应：{
```

此提示结合了：

* 明确的指令（具体提取什么）
* 上下文（格式为何重要）
* 示例结构（展示格式）
* 表达不确定性的许可（如果不确定则使用null）
* 格式控制（以左大括号开始）

## 选择正确的技巧

并非每个提示都需要所有技巧。以下是一个决策框架：

**从这里开始：**

1. 你的请求是否清晰明确？如果不是，先解决清晰度问题
2. 任务是否简单？仅使用核心技巧（具体、清晰、提供上下文）
3. 任务是否需要特定格式？使用示例或预填充
4. 任务是否复杂？考虑分解（链式操作）
5. 是否需要推理？使用扩展思考（如果可用）或思维链

**技巧选择指南**：

| 如果你需要... | 使用... |
| --- | --- |
| 特定的输出格式 | 示例、预填充或明确的格式指令 |
| 逐步推理 | 扩展思考（Claude 4.x）或思维链 |
| 复杂的多阶段任务 | 提示链 |
| 透明的推理 | 带结构化输出的思维链 |
| 防止幻觉 | 允许说"我不知道" |

## 常见提示问题故障排除

即使是精心设计的提示也可能产生意外结果。以下是常见问题及解决方法：

* **问题：响应过于泛泛** → 解决方案：增加具体性、示例或明确要求全面输出。要求AI"超越基础"。
* **问题：响应偏离主题或未抓住要点** → 解决方案：更明确地说明你的实际目标。提供你提问的原因上下文。
* **问题：响应格式不一致** → 解决方案：添加示例（少量示例）或使用预填充控制响应的开始。
* **问题：任务过于复杂，结果不可靠** → 解决方案：分解为多个提示（链式操作）。每个提示应做好一件事。
* **问题：AI包含不必要的开场白** → 解决方案：使用预填充或明确要求："跳过开场白，直接给出答案。"
* **问题：AI编造信息** → 解决方案：明确允许在不确定时说"我不知道"。
* **问题：AI在你想要实现时却建议更改** → 解决方案：明确行动："更改此函数"，而不是"你能建议更改吗？"

**专业提示**：从简单开始，仅在需要时增加复杂性。测试每个添加项，看它是否真正改善了结果。

## 应避免的常见错误

从这些常见陷阱中学习，以节省时间并改进你的提示：

* **不要过度设计**：更长、更复杂的提示并不总是更好。
* **不要忽视基础**：如果你的核心提示不清晰或模糊，高级技巧也无济于事。
* **不要假设AI能读心**：具体说明你想要什么。含糊不清会让AI有误解的空间。
* **不要同时使用所有技巧**：选择针对你特定挑战的技巧。
* **不要忘记迭代**：第一个提示很少能完美工作。测试并改进。
* **不要依赖过时的技巧**：XML标签和强角色提示对于现代模型已不那么必要。从明确、清晰的指令开始。

## 提示工程注意事项

### 处理长内容

实施高级提示工程的挑战之一是通过额外的token使用增加上下文开销。示例、多个提示、详细指令——它们都会消耗token，而上下文管理本身就是一项技能。

记住，在合理且证明其使用价值时使用提示工程技巧。关于有效管理上下文的全面指导，请查看我们关于[上下文工程](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)的博客文章。

**上下文感知改进**：包括Claude 4.x在内的现代AI模型具有显著改进的上下文感知能力，有助于解决历史上的"中间丢失"问题，即模型难以平等关注长上下文的所有部分。

**为什么任务拆分仍然有帮助**：即使有这些改进，将大任务分解为更小、离散的块仍然是一种有价值的技巧——不是因为上下文限制，而是因为它帮助模型专注于在非常具体的要求和范围内做到最好。一个有明确边界的聚焦任务始终比试图在单个提示中完成多个目标产生更高质量的结果。

**策略**：处理长上下文时，清晰组织信息，将最关键细节放在开头或结尾。处理复杂任务时，考虑将其分解为聚焦的子任务是否能提高每个组件的质量和可靠性。

### 好的提示是什么样的？

提示工程是一项技能，需要多次尝试才能掌握。判断是否做对的唯一方法是测试并观察。第一步就是自己尝试。你会立即看到使用和未使用我们介绍的提示技巧的查询之间的差异。

要真正磨练你的提示工程技能，你需要客观衡量提示的有效性。好消息是，这正是我们在[anthropic.skilljar.com](https://anthropic.skilljar.com/claude-with-the-anthropic-api)的提示工程课程中所涵盖的内容。

**快速评估技巧**：

* 输出是否符合你的特定要求？
* 你是通过一次尝试就获得结果，还是需要多次迭代？
* 格式在多次尝试中是否一致？
* 你是否避免了上面列出的常见错误？

## 最后的建议

提示工程归根结底是关于沟通：使用最能帮助AI清晰理解你意图的语言。从本指南早期介绍的核心技巧开始。持续使用它们，直到它们成为第二天性。仅在解决特定问题时才引入高级技巧。

记住：最好的提示不是最长或最复杂的。而是那个以最少必要结构可靠实现你目标的提示。随着练习，你会培养出对哪些技巧适合哪些情况的直觉。

向上下文工程的转变并不会削弱提示工程的重要性。事实上，提示工程是上下文工程中的基本构建块。每个精心设计的提示都成为塑造AI行为的更大上下文的一部分，与对话历史、附加文件和系统指令协同工作，创造更好的结果。
