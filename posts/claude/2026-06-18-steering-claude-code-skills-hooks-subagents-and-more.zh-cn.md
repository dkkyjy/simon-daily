# 引导 Claude Code：技能、子代理、钩子等

            **日期：** 2026-06-18 00:00 UTC
            **链接：** https://claude.com/blog/steering-claude-code-skills-hooks-rules-subagents-and-more

            ---

            Claude 旨在按照您的工作方式工作，而在 Claude Code 中，您可以对其进行自定义。

有七种方法可以指导 Claude 的行为：CLAUDE.md 文件、规则、[**技能**](https://code.claude.com/docs/en/skills)、[**子代理**](https://code.claude.com/docs/en/sub-agents)、[**钩子**](https://code.claude.com/docs/en/hooks-guide)、输出样式以及附加系统提示。

每种方法控制：

* 指令何时加载到上下文中；
* 它是否在长会话中持续存在（压缩行为）；以及
* 它承载多大的权威性。

下表提供了每种方法关键差异的快速总结，而文章正文则提供了更多细节和决策框架，用于确定您的每条 Claude 指令应归属于何处。

| 方法 | 加载时机 | 压缩行为 | 上下文成本 | 使用时机 |
| --- | --- | --- | --- | --- |
| CLAUDE.md（根目录） | 会话开始；在整个会话期间保持在上下文中 | 记忆化。读取一次并在会话期间缓存；压缩后清除缓存并重新读取 | 高。无论是否相关，每一行都消耗令牌 | 构建命令、目录布局、单体仓库结构、编码约定、团队规范 |
| CLAUDE.md（子目录） | 按需加载，当 Claude 读取该子目录下的文件时 | 丢失，直到再次触及该子目录 | 低。仅在处理相关子目录时消耗上下文 | 特定于子目录的约定 |
| 规则 | 会话开始（用户级规则）或仅当匹配的文件被触及（路径限定） | 压缩时重新注入 | 中等。始终开启，除非是路径限定 | 特定约束或约定（例如，所有 API 处理器必须使用 Zod 验证输入） |
| 技能 | 会话开始时加载名称和描述；调用技能时加载完整正文 | 已调用的技能重新注入，直至共享预算上限；最旧的优先丢弃 | 低。仅在调用时加载完整正文；受限于已调用技能的共享令牌预算 | 程序化工作流（部署或发布检查清单） |
| 子代理 | 会话开始时加载名称、描述和工具列表；仅通过代理工具调用时加载正文 | 仅最终消息（摘要加元数据）返回主会话 | 低。在调用前主上下文中成本为零；在自身独立的上下文窗口中运行 | 并行运行工作或应隔离运行并仅返回摘要的辅助任务（深度搜索、日志分析、依赖审计） |
| 钩子 | 在生命周期事件触发时触发 | 完全绕过压缩 | 低。配置位于主上下文之外；某些输出可能返回（例如，阻塞错误） | 确定性自动化：运行 linter、完成后发布到 Slack、阻止命令、在 PreCompact 时备份聊天历史 |
| 输出样式 | 会话开始；注入到系统提示中 | 永不压缩 | 高。占用上下文窗口，但覆盖默认系统提示 | 重大角色变更（代码助手变为通用助手） |
| 附加系统提示 | 会话开始；作为 CLI 标志传递 | 永不压缩；仅适用于该次调用 | 中等。在会话中首次请求后缓存 | 语气、回复长度、格式偏好 |

## 传递指令的七种方法

### CLAUDE.md 文件

CLAUDE.md 是项目根目录下的一个 Markdown 文件。它在会话开始时加载到上下文中，并在整个会话期间保持。

构建命令、目录布局、单体仓库结构、编码约定和团队规范都自然地适合放在这里。

有两种类型，它们的加载方式不同：

* **始终加载**：第一种是根目录 CLAUDE.md 文件，可以位于共享仓库中和/或本地保存，用于您个人对特定项目的偏好。所有这些文件在会话开始时加载，并且在长会话中不会丢失或降级。当 Claude Code 压缩对话时，它会重新读取这些文件。
* **按需加载**：位于您初始化会话的文件夹下方的子目录中的 CLAUDE.md 文件。例如，`app/api/CLAUDE.md` 在 Claude 读取 `app/api` 下的文件时加载，而不是在会话开始时。它与路径限定规则共享压缩行为：消失，直到再次触及该子目录。

当 Claude 读取该目录内的文件时，当前工作目录下的所有子目录 CLAUDE.md 文件都会加载。

在共享仓库中，CLAUDE.md 会像任何无主的配置文件一样增长：每个团队都会追加自己的指令，而没有任何内容被删除。成本会随着规模扩大而增加。

每一行都会加载到仓库中每位工程师的每个会话中，无论是否与其任务相关。这会消耗令牌并削弱对实际重要指令的遵循度。随着文件增长，应将团队特定的约定推送到路径限定规则中，将程序推送到技能中，这样它们只会在相关时加载。

**提示：** 保持 CLAUDE.md 在 200 行以内，为其指定所有者，并像审查代码一样审查对其的更改。将此文件视为向 Claude 提供代码库概览，或作为指向其他文件的索引，Claude 可在需要时从中查找更多信息。

在单体仓库中，为每个团队的目录提供其自己的子目录 CLAUDE.md，这样团队只加载自己的约定，并且开发人员可以使用 `claudeMdExcludes` 设置来跳过他们从不接触其代码的团队的文件。

对于必须适用于组织中每个仓库的标准——安全策略、合规要求——可以通过 MDM 或配置管理将集中管理的 CLAUDE.md 部署到开发人员的机器上，并且无法通过个人设置排除。

在我们的博文 [CLAUDE.md 文件：为您的代码库自定义 Claude Code](https://claude.com/blog/using-claude-md-files) 中了解更多关于设置 CLAUDE.md 的信息。

### 规则

[**规则**](https://code.claude.com/docs/en/memory#organize-rules-with-claude/rules/) 是 `.claude/rules/` 中的 Markdown 文件，为 Claude 提供特定的约束或约定。

无范围规则的行为类似于 CLAUDE.md，它们在会话开始时始终加载，并在压缩时重新注入。这可能会因为加载了与当前任务无关的上下文而浪费令牌。

路径限定规则允许您仅在相关时加载规则指令，通过添加控制加载时机的 `paths` 字段来实现。

例如：一个限定在 `src/api/**` 的规则在纯文档会话期间会保持在上下文之外。只有当 Claude 读取 `src/api/` 目录内的文件时，它才会被加载。

示例如下：

```
---
paths:
  - "src/api/**"
  - "**/*.handler.ts"
---
所有 API 处理器在处理之前必须使用 Zod 验证输入。
```

**提示**：文件特定的约束，例如"迁移只能追加"，最适合作为**规则**放置在您的 `paths` 前置元数据中。当指令涉及跨领域关注点或出现在代码库多个（但非全部）位置的文件时，应优先选择路径限定规则，而非嵌套的 CLAUDE.md 文件。

### 技能

[**技能**](https://code.claude.com/docs/en/skills) 位于 `.claude/skills/` 中，作为指令、脚本和资源的文件夹，由 Claude 动态加载。每个技能都有一个 `SKILL.md` 文件，包含名称、描述和正文。

只有名称和描述在会话开始时加载；当 Claude 调用该技能时（通过斜杠命令 `/code-review` 或自动匹配任务），完整正文才会加载。

技能通过您的系统提示触发。

例如，`/code-review` 是一个内置技能，用于审查您当前的差异并报告其发现，而无需编辑文件。该技能定义了操作手册，因此每次调用时 Claude 都会遵循相同的结构化方法。

在压缩时，Claude Code 会重新注入已调用的技能，直至所有已调用技能的总预算上限。如果您在会话期间调用了许多技能，最旧的会优先被丢弃。

**提示：** 程序化的指令，如部署工作流、发布检查清单或审查流程，应归属于技能，而非 CLAUDE.md。

Claude Code 自带技能，但您也可以编写自己的自定义技能。我们的 [为 Claude 构建技能的完整指南](https://claude.com/blog/complete-guide-to-building-skills-for-claude) 向您展示了如何操作。

### 子代理

[**子代理**](https://code.claude.com/docs/en/sub-agents) 是 `.claude/agents/` 中的 Markdown 文件，用于定义用于特定辅助任务的隔离助手。每个文件使用 YAML 前置元数据（名称、描述，以及模型和工具访问的可选字段），后跟成为该子代理系统提示的正文。

子代理与技能类似，名称、描述和工具列表在会话开始时加载，但代理正文中的较大上下文不会自动调用。Claude 通过代理工具调用它们，并传入一个提示字符串。

Claude Code 的上下文窗口保存了 Claude 了解的有关您会话的所有信息。此处的 [交互式时间线](https://code.claude.com/docs/en/context-window) 逐步说明了加载的内容和时机。

子代理正文中较大的指令上下文不仅不会自动调用，而且根本不会进入父对话。

然后，子代理在其自己的全新上下文窗口中运行，唯一返回主会话的是子代理的最终消息（通常是许多子任务聚合的结果）加上元数据。

这种模式具有可扩展性：子代理可以嵌套多达五层，并且 [动态工作流](https://claude.com/blog/a-harness-for-every-task-dynamic-workflows-in-claude-code) 可以编排数十到数百个后台代理，而无需您指定子代理架构的每个细节。编排计划和中间结果存在于脚本变量中，而不是 Claude 的上下文窗口中，这使得在不损失指令保真度的情况下实现扩展成为可能。

**提示：** 这种隔离是选择子代理而非技能的主要原因之一。当辅助任务（如深度搜索、日志分析或依赖审计）会以您不会再引用的中间结果弄乱主对话时，请使用子代理。当您希望程序在主线程内执行以便查看和引导每一步时，请使用技能。

### 钩子

[**钩子**](https://code.claude.com/docs/en/hooks-guide) 是用户定义的命令、HTTP 端点或 LLM 提示，通过在 [Claude 生命周期中的特定事件](https://code.claude.com/docs/en/hooks#hook-lifecycle)（如文件编辑、工具调用或会话开始）触发，提供对 Claude 行为的更确定性控制。

Claude Code 会话中可触发钩子的事件映射。

您在 `settings.json`、托管策略设置或技能/代理前置元数据中注册钩子。

有几种类型的钩子：命令、HTTP、mcp_tool、提示和代理。所有钩子都是确定性触发的。前三种确定性执行，而后两种（提示和代理）使用 Claude 的判断而非一组规则来确定输出。

钩子具有较低的上下文成本，因为配置或指令位于主上下文窗口之外。根据钩子类型，执行程序运行处理程序（命令、http、mcp_tool）或使用单独的窗口进行模型调用（提示、代理）。

某些钩子的输出可能保存到主上下文窗口。例如，阻塞钩子的标准错误会保存在上下文中，以便 Claude 知道调用被拒绝的原因。

但大多数钩子的输出不会保存到主窗口，除非配置明确返回它。如果您在压缩之前使用 `PreCompact` 事件将聊天历史备份到另一个文件以供以后参考，Claude 不会知道哪个文件保存了聊天历史。

这使得这些钩子类型与 CLAUDE.md、规则和技能有根本性的不同。您可以在我们的文章 [如何配置钩子](https://claude.com/blog/how-to-configure-hooks) 中了解更多信息。

**提示：** 将钩子用于任何应确定性发生的事情：编辑后运行 linter、完成后发布到 Slack，或在特定命令执行前阻止它们。`PreToolUse` 钩子可以检查任何工具调用并以退出码 2 拒绝它。

它们具有较低的上下文成本，因为它们是执行程序运行的代码，而不是加载到上下文中的 Claude 指令。

### 输出样式

[**输出样式**](https://code.claude.com/docs/en/output-styles) 是 `.claude/output-styles/` 中的文件，用于将指令注入系统提示。它们永不压缩，在每个会话开始时加载，并在会话内首次请求后缓存，这意味着它们具有中等上下文成本。

由于它们位于系统提示中，输出样式具有我们目前所介绍的任何方法中最高的指令遵循权重，应谨慎使用。

**对输出样式的更改将替换默认输出样式**（除非您在样式的前置元数据中设置了 `keep-coding-instructions: true`）。

在 Claude Code 中，这将移除告诉 Claude 它正在帮助用户处理软件工程任务的指令，以及其他关键的默认指令，例如：

* 如何限定更改范围；
* 何时添加或省略代码注释；
* 如何处理安全问题；以及
* 验证习惯，如在宣布工作完成前运行测试。

默认情况下，自定义输出样式会丢弃所有这些内容，Claude Code 会变得更像一个通用助手，而不是软件工程助手。

**提示**：在编写自定义输出样式之前，请检查内置样式。**主动**、**解释性**和**学习**涵盖了最常见的需求（自主性、教学模式、协作编码），而您无需维护样式文件。

### 附加系统提示

修改输出样式的一种替代方法是 `append-system-prompt` 标志。修改输出样式文件可能会对 Claude 的行为产生巨大、意外的更改，而附加标志仅对原始系统提示进行附加。它不会修改 Claude 的角色；只是向其默认角色添加指令。

它也是在调用时传递的，并且仅适用于该次调用，而不是作为文件在会话间持久化。

与其他传递指令的方法相比，附加系统提示可能具有更高的上下文成本。它会增加输入令牌，尽管提示缓存会在会话中首次请求后降低此成本。指示 Claude 使用更冗长或更长的样式也会增加输出令牌。

**提示：** 附加系统提示最适合添加特定的编码标准、输出格式或领域特定知识。请记住，使用此方法附加系统提示在遵循度方面存在收益递减。通常，您使用此方法提供的指令越多，Claude 遵循它们的严格程度就越低，尤其是在存在任何矛盾的情况下。

## Claude Code 自定义快速提示

如果您发现自己正在做以下事情之一，您可能需要考虑将指令放在替代位置：

**在 CLAUDE.md 中写"每次 X，总是做 Y"。** 如果行为应该可靠地发生，例如每次编辑后运行 prettier 或完成后发布到 Slack，请改用 `settings.json` 中的钩子。模型选择运行格式化程序与格式化程序自动运行是不同的。

**在 CLAUDE.md 中写"永远不要这样做"。** 当有绝对不应发生的事情时，指令是错误的工具。Claude 大部分时间会遵循指令，但在压力下、在长会话或模棱两可的情况下，或者由于作为任务一部分访问的文件中存在提示注入，模型可能无法遵循提示规则。真正的防护栏需要是确定性的，而强制执行方法是 [钩子](https://code.claude.com/docs/en/hooks) 和 [权限](https://code.claude.com/docs/en/permissions)。`PreToolUse` 钩子可以检查调用并以退出码 2 退出以阻止它。[**托管设置**](https://code.claude.com/docs/en/settings#managed-settings) 更进一步：它们由管理员部署，不能被用户的本地配置覆盖，并且是强制执行确定性、组织级防护栏的唯一方法。

**在 CLAUDE.md 中写一个 30 行的程序。** 程序应归属于技能。CLAUDE.md 用于 Claude 应始终掌握的事实：构建命令、单体仓库布局、团队约定。部署运行手册或安全审查清单应位于 `.claude/skills/` 中，其正文仅在调用时加载。

**没有路径的 API 特定规则。** 如果规则仅适用于 `src/api/**`，使用 `paths:` 限定它可使其在不相关的工作期间保持在上下文之外。无范围规则在机制上与将内容放入 CLAUDE.md 相同：始终加载，始终消耗令牌。

**将个人偏好写入项目级 CLAUDE.md 文件。** 所有基于文件的方法都有一个用户级对应项，无论您在哪个仓库中，都会为每个 Claude Code 会话加载。使用本地文件存储个人偏好（始终使用语义化提交消息）。将项目级文件用于团队范围但特定于给定代码库的偏好。
