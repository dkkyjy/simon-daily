**日期：** 2026-06-18 00:00 UTC

Claude 旨在以您的工作方式工作，而在 Claude Code 中，您可以对其进行自定义。

有七种方法可以指示 Claude 的行为：CLAUDE.md 文件、规则、[**技能**](https://code.claude.com/docs/en/skills)、[**子代理**](https://code.claude.com/docs/en/sub-agents)、[**钩子**](https://code.claude.com/docs/en/hooks-guide)、输出样式以及追加系统提示词。

每种方法控制：

* 指令何时加载到上下文中；
* 它是否在长会话中持续存在（压缩行为）；以及
* 它承载多大的权威性。

下表提供了每种方法之间关键差异的快速摘要，而本文则提供了更多细节和决策框架，用于确定您的每条 Claude 指令应归属于何处。

| 方法 | 加载时机 | 压缩行为 | 上下文成本 | 使用场景 |
| --- | --- | --- | --- | --- |
| CLAUDE.md（根目录） | 会话开始时；在整个会话期间保持在上下文中 | 记忆化。读取一次并在会话期间缓存；压缩后清除缓存并重新读取 | 高。每一行都会消耗令牌，无论是否相关 | 构建命令、目录布局、monorepo 结构、编码约定、团队规范 |
| CLAUDE.md（子目录） | 按需加载，当 Claude 读取该子目录下的文件时 | 丢失，直到再次触及该子目录 | 低。仅在处理相关子目录时消耗上下文 | 特定于子目录的约定 |
| 规则 | 会话开始时（用户级规则）或仅在触及匹配文件时（路径限定） | 压缩时重新注入 | 中等。始终开启，除非是路径限定 | 特定约束或约定（例如，所有 API 处理器必须使用 Zod 验证输入） |
| 技能 | 会话开始时加载名称和描述；调用技能时加载完整内容 | 已调用的技能在共享预算内重新注入；最旧的优先丢弃 | 低。仅在调用时加载完整内容；受已调用技能之间的共享令牌预算约束 | 程序化工作流（部署或发布检查清单） |
| 子代理 | 会话开始时加载名称、描述和工具列表；仅通过 Agent 工具调用时加载主体 | 只有最终消息（摘要加元数据）返回主会话 | 低。在调用前主上下文零成本；在自身隔离的上下文窗口中运行 | 并行运行工作，或应在隔离环境中运行并仅返回摘要的侧任务（深度搜索、日志分析、依赖审计） |
| 钩子 | 在生命周期事件时触发 | 完全绕过压缩 | 低。配置位于主上下文之外；某些输出可能返回（例如，阻止性错误） | 确定性自动化：运行 linter、完成时发布到 Slack、阻止命令、在 PreCompact 时备份聊天历史 |
| 输出样式 | 会话开始时；注入系统提示词 | 永不压缩 | 高。占据上下文窗口，但覆盖默认系统提示词 | 重大角色变更（从代码助手变为通用助手） |
| 追加系统提示词 | 会话开始时；作为 CLI 标志传入 | 永不压缩；仅适用于该次调用 | 中等。会话中首次请求后缓存 | 语气、响应长度、格式偏好 |

## 传递指令的七种方法

有七种方式可以自定义 Claude Code 的行为：CLAUDE.md 文件用于始终开启的项目上下文，规则用于硬性约束，技能用于可复用的程序，子代理用于委派工作，钩子用于确定性自动化，以及输出样式或系统提示词追加用于全局更改。

每种方法都在上下文成本和权威性之间进行权衡。这些方法影响 Claude 的行为，而两个独立的调节旋钮——[您选择的模型和努力级别](https://claude.com/blog/claude-model-and-effort-level-in-claude-code)——控制它的能力有多强以及它工作的努力程度。

### CLAUDE.md 文件

CLAUDE.md 是位于项目根目录的 Markdown 文件。它在会话开始时加载到上下文中，并在整个会话期间保持存在。

构建命令、目录布局、monorepo 结构、编码约定和团队规范都自然适合放在这里。

有两种类型，它们的加载方式不同：

* **始终加载**：第一种是根目录 CLAUDE.md 文件，可以位于共享仓库中和/或本地保存，用于您针对特定项目的个人偏好。所有这些文件在会话开始时加载，并且不会在长会话中丢失或降级。当 Claude Code 压缩对话时，它会重新读取这些文件。
* **按需加载**：位于您初始化会话的文件夹下方子目录中的 CLAUDE.md 文件。例如，当 Claude 读取 `app/api` 下的文件时，`app/api/CLAUDE.md` 才会加载，而不是在会话开始时。它与路径限定规则共享压缩行为：直到再次触及该子目录才会重新加载。

当 Claude 读取某个目录内的文件时，cwd 下方所有子目录的 CLAUDE.md 文件都会加载。

在共享仓库中，CLAUDE.md 会像任何无人管理的配置文件一样增长：每个团队都会追加自己的指令，而没有任何内容被删除。这种成本在规模扩大时会不断累积。

每一行都会加载到仓库中每位工程师的每个会话中，无论与其任务是否相关。这会消耗令牌并稀释对真正重要指令的遵循度。随着文件增长，应将团队特定的约定推入路径限定规则，将程序推入技能中，这样它们只在相关时才加载。

**提示：** 将 CLAUDE.md 保持在 200 行以内，为其指定负责人，并像审查代码一样审查对其的更改。内容本身应遵循与任何提示词相同的规则：[编写有效的提示词](https://claude.com/blog/best-practices-for-prompt-engineering)意味着明确具体、解释约束背后的原因，并展示示例。

将此文件视为向 Claude 提供代码库概览，或作为指向其他文件的索引，Claude 可以在需要时从中查找更多信息。

在 monorepo 中，为每个团队的目录配置各自的子目录 CLAUDE.md，这样团队只加载自己的约定，开发人员也可以使用 claudeMdExcludes 设置来跳过他们从不接触的团队的代码文件。

对于必须适用于组织中每个仓库的标准——安全策略、合规要求——可以通过 MDM 或配置管理将集中管理的 CLAUDE.md 部署到开发人员的机器上，并且无法通过个人设置将其排除。

更多关于设置 CLAUDE.md 的内容，请参阅我们的博客文章：[CLAUDE.md 文件：为您的代码库自定义 Claude Code](https://claude.com/blog/using-claude-md-files)。
