# Claude Code 代码审查

**日期：** 2026-03-09 00:00 UTC  
**链接：** https://claude.com/blog/code-review  

---  

今天我们推出代码审查功能，该功能会在每个PR上派遣一组代理，捕捉粗略审查遗漏的错误，专为深度而非速度而构建。这是我们在Anthropic几乎所有PR上运行的系统。现面向团队版和企业版提供研究预览。

## **管理审查瓶颈**

过去一年中，每位Anthropic工程师的代码输出量增长了200%。代码审查已成为瓶颈，我们每周都会从客户那里听到同样的反馈。他们告诉我们，开发人员捉襟见肘，许多PR只得到粗略浏览而非深入审阅。

我们需要一个在每个PR上都能信赖的审查者。代码审查正是为此而生：深度、多代理的审查，能够捕捉人类审查者自身常常遗漏的错误。相比我们现有的[Claude Code GitHub Action](https://code.claude.com/docs/en/github-actions)（仍保持开源且可用），这是一个更彻底（也更昂贵）的选项。

我们在Anthropic几乎每个PR上都运行代码审查。此前，16%的PR获得了实质性审查评论。现在这一比例达到了54%。它不会批准PR——这仍是人类决策——但它缩小了差距，使审查者能够真正覆盖正在交付的内容。

## **工作原理**

当PR被创建时，代码审查会派遣一组代理。这些代理并行查找错误，验证错误以过滤误报，并按严重程度对错误进行排序。结果以单个高信号概览评论的形式呈现在PR上，同时附带针对特定错误的行内评论。

审查规模随PR大小调整。大型或复杂变更会获得更多代理和更深入的审阅；琐碎变更则进行轻量级检查。根据我们的测试，平均每次审查耗时约20分钟。

## **代码审查实战**

我们已在内部运行代码审查数月：对于大型PR（超过1000行变更），84%会发现问题，平均7.5个问题。对于50行以下的小型PR，这一比例降至31%，平均0.5个问题。工程师们大体认同其发现：不到1%的发现被标记为错误。

在一个案例中，生产服务的一行变更看似常规，属于通常会被快速批准的差异类型。但代码审查将其标记为严重问题。该变更会破坏服务的身份验证功能，这种故障模式在差异中容易被忽略，但一经指出便显而易见。该问题在合并前被修复，工程师事后表示，他们自己本不会发现这个问题。

早期接入客户也看到了类似模式。在TrueNAS开源中间件的[ZFS加密重构](https://github.com/truenas/middleware/pull/18291)中，代码审查发现了相邻代码中一个预先存在的错误：一个类型不匹配问题，每次同步都会静默清除加密密钥缓存。这是PR恰好触及的代码中一个潜在问题，属于人类审查者扫描变更集时不会立即寻找的那种问题。

## **成本与控制**

代码审查优化深度，比[Claude Code GitHub Action](https://code.claude.com/docs/en/github-actions)等轻量级解决方案更昂贵。审查按令牌使用量计费，通常平均为15-25美元，随PR大小和复杂度调整。

管理员有多种方式控制支出和使用量：

* **月度组织上限**：定义所有审查的总月度支出
* **仓库级别控制**：仅在你选择的仓库上启用审查
* **分析仪表板**：追踪已审查的PR、接受率和总审查成本

## **开始使用**

代码审查现作为研究预览版，面向团队版和企业版计划提供。

* **对于管理员**：在你的[Claude Code设置](http://claude.ai/admin-settings/claude-code)中启用代码审查，安装GitHub应用，并选择你希望运行审查的仓库。
* **对于开发者**：启用后，审查会自动在新PR上运行。无需额外配置。

请访问[文档](http://code.claude.com/docs/en/code-review)了解更多信息。
