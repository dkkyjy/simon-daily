**日期：** 2026-04-28 00:00 UTC
**链接：** https://claude.com/blog/onboarding-claude-code-like-a-new-developer-lessons-from-17-years-of-development

---

[Skyline](https://skyline.ms/home/software/Skyline/wiki-page.view?name=team) 是一款开源蛋白质分析软件，由华盛顿大学 MacCoss 实验室的首席开发者 Brendan MacLean 维护，自 2008 年以来一直处于活跃开发状态。Skyline 帮助研究人员检测和定量血浆、组织等样本中的蛋白质，这对生物标志物发现、疾病研究和药物开发至关重要。MacCoss 实验室的代码库包含超过 70 万行 C# 代码，由一个小团队维护了 17 年，并运行着超过 20 万项自动化夜间测试。

*一幅用 Blender 制作的西雅图天际线 3D 插图，代表华盛顿大学 MacCoss 实验室所在地。自 2008 年以来，Brendan MacLean 和他的团队一直在那里开发和维护 Skyline。Claude 帮助 Brendan 在背景中添加了 Claude 标志。图片由 MacCoss 实验室提供。*

近三十年来，Brendan 一直是 Skyline 的“连接组织”，为实验室引入了数十名本科生、研究生和博士后。*

随着开发者不断加入和离开，代码库吸收了他们的贡献。到 2024 年，它已经承载了一个长寿项目常见的负担。随着开发者的更替，某些领域已经变得无人敢碰。

经过数十年培训实验室成员的经验，Brendan 知道如何让研究人员快速上手实验室庞大的代码库。他没有预料到的是，同样的方法应用于 AI 工具，竟然能让 Skyline 的代码库重新变得可控。

## 同样的入职问题，不同类型的开发者

Brendan 曾怀疑现代 AI 编码工具能否像专门为 C# 语言和环境打造的工具那样理解 C# 代码。

早期在浏览器中使用 Claude.ai 的实验证实了他的猜测。他描述一个问题，得到一个回复，然后将整个 C# 文件复制回项目中，将范围限制在他可以在不参考项目代码的情况下描述的独立问题上。

“当变更变得更加渐进时，整个过程变得非常费力，”Brendan 说。

每次与 Claude.ai 的会话都感觉像从零开始，因为它不了解 Skyline 是什么、其组件之间如何关联，也不知道 17 年的开发建立了什么。

这正是 Brendan 在引导新开发者时面临的相同体验，这给了他一个想法。

“我可以像引导实习开发者一样，通过 Claude Code 将我的大型项目介绍给 Claude：先解释足够的信息以完成一个有限的成功项目，并为下一次迭代产生更好的上下文，”Brendan 说。

他将所有 AI 上下文移入了一个独立的仓库 [pwiz-ai](https://github.com/ProteoWizard/pwiz-ai)，与代码库分开保存，以便适用于所有分支和时间点。根目录下的 `CLAUDE.md` 文件负责环境设置，并引导 Claude 查阅相关文档：可以把它看作“地形概览”，而非专业知识本身。

专业知识存放在 [skills](https://agentskills.io/home) 中，这是一种为代理提供能力和专业知识的开放格式。例如，他的 `debugging` 技能旨在将 Claude 从他所谓的“猜测和测试”模式中拉出来，推动其在尝试任何修复之前进行根因分析。技能可以手动触发，也可以自动触发；Brendan 为最关键的一些技能设置了明确的触发条件——`debugging` 技能描述写道“在调查 bug、故障或意外行为时始终加载”。

*pwiz-ai 仓库结构，展示了上下文、技能和 MCP 集成如何连接到 Skyline 的代码库。图片由 MacCoss 实验室提供。*

有了上下文基础，教 Claude 调试代码库的细节所需的工作量就大大降低了。Claude 已经知道代码的功能。交互从理解开始，而不是从零开始。

“一个看似重大的担忧——‘Claude 无法真正了解我的大型项目’——变得越来越清晰：上下文只是另一个需要维护和发展的工件，”Brendan 说。

## 减少技术债务，加速开发

一个为期一年的项目——在 Skyline 中构建 Files View 面板（一个显示所有文档相关文件的新界面，支持文件系统监控和拖放组织）——在负责的开发者离开后一直未完成。Brendan 用 Claude Code 接手了这个项目。

两周后项目完成了，所有最终提交都由 Claude 共同署名。

“以前以这种状态遗留的工作通常最终会被丢弃，”Brendan 说。在学术实验室中，开发者流动频繁——研究生完成学位，博士后继续前进，实习生夏天结束时离开。过去，任何进行中的工作都会永远搁置。

三年前，在失去维护 Skyline 夜间测试管理模块的开发者后，Brendan 停止为该模块添加新功能。该模块是用 Java 编写的，是 LabKey Server 科学数据门户的一部分。最近，在让一位熟练的 LabKey 开发者使用 Claude Code 创建设置文档后，Brendan 花了不到一天时间就添加了他多年来一直想要的功能，并用他过去只雇设计师来制作的 CSS 更新了页面布局。

新的基础设施也随之而来。

Skyline 的 2,000 多张教程图片的截图复现现已完全自动化，几乎 100% 可复现，并通过 Claude Code 扩展了仅显示差异的视图和像素变化放大功能，以及一个由 Claude 用 C# 编写的 MCP 服务器，使其能够“看到”这些差异。Claude Code 每天早上生成一份每日摘要，显示从 Skyline 夜间测试基础设施中提取的测试失败、异常和未解决的支持线程，在 Brendan 坐下来工作之前就发送到他的收件箱。

Claude 还编写了 Python 版本的 MCP 服务器来实现这一功能，从 LabKey Server 上的三个独立关系数据流、团队电子邮件以及 GitHub 上带有发布标签的代码中提取数据。

*一封由 Claude Code 自动生成的每日摘要邮件，从 Skyline 的夜间测试基础设施中提取数据。图片由 MacCoss 实验室提供。*

Brendan 的开发者现在几乎不再自己编写代码，主要是指导 Claude Code，并使用该工具自主生成自动化脚本和 MCP 实现。例如，实验室中一位曾对代理式编码工具持怀疑态度的开发者，构建并发布了新的绘图扩展——一个用于可视化离子迁移率数据的 mobilogram 面板——并将功劳归于 Claude Code。

*mobilogram 面板使用 Claude Code 构建，将离子迁移率数据与质谱结果一起可视化。图片由 MacCoss 实验室提供。*

“我看到几乎每个人都在尝试有趣的新功能，而这些功能在过去可能会因为忙于其他工作而无法尝试，”Brendan 说。

## 给在遗留代码库上工作的开发者的建议

基于 17 年的开发者入职经验以及一年多将同样的方法应用于 Claude Code 的经验，以下是 Brendan 想对在遗留代码库上工作的开发者说的话。

**上下文是你最好的朋友**

Claude 生成的待办事项列表和计划不会跨会话保留。[上下文](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)才是会保留的东西，而且必须有意识地维护。这是大多数开发者跳过的一步，也是大多数开发者成功遇到瓶颈的原因。

“要明白，如果你不记录‘上下文’，Claude 就无法学习。不要指望魔法，”Brendan 说。“投入精力构建和维护你的上下文层。并像对待任何其他项目工件一样对待它：进行版本控制、不断扩展、持续维护。”

Brendan 将 AI 上下文放在一个单独的仓库中，因为它的增长速度与代码不同，并且适用于所有分支和时间点——将其放在代码仓库内变得越来越受限。将上下文放在同一仓库中也是一个可行的替代方案；重要的是它被版本化、维护，并在需要时可用。

**投入构建你的技能库**

使用 [skills](https://claude.ai/skills) 来编码任何 Claude 实例都可以加载的领域知识。Brendan 的技能遵循“引用而非嵌入”的原则：每个技能指向中央文档知识库，而不是复制内容，使其保持轻量且易于维护。

他最常用的技能包括：一个 `skyline-development` 技能，让 Claude 了解项目及其文档；一个 `version-control` 技能，编码项目特定的提交和 PR 约定；以及一个 `debugging` 技能，旨在将 Claude 从“猜测和测试”模式中拉出来，推动其在尝试任何修复之前进行根因分析。

**当数据访问是关键时，使用 MCP 集成**
在 Claude 需要访问真实数据的地方构建 [MCP 集成](https://anthropic.com/engineering/mcp)：测试结果、异常报告、支持线程。

对于开源项目，构建和维护上下文层具有特殊的重要性。没有入职预算，没有超越书面记录的机构记忆，也无法保证任何贡献者明年还会在这里。上下文一旦构建，就可以供每位贡献者使用，并在项目的整个生命周期中持续存在，这是人类机构知识永远无法做到的。`pwiz-ai` 仓库本身就是一个开源工件——上下文属于项目，而非任何单个贡献者，并且比所有构建它的人更持久。

## 十七年的入职经验，一个结论

你不会把一个 70 万行的代码库交给新员工并期望第一天就出成果。你会给他们找一个独立的小项目，带他们逐步了解，随着他们理解的加深再扩大范围。

正如 Brendan 所学到的，你与 Claude 建立的上下文以同样的方式运作。

一旦工程师对代码库有了足够的了解，他们就可以跨分支和时间点工作。Claude 在获得足够的上下文和指导后，也能做到同样的事情。
