2024 年，我们有了一个聊天窗口中的 Claude。你提一个问题，得到一个答案，但需要你自己把这个答案变成有用的东西。2025 年，Claude Code 让工程师们以令我们其余人有些羡慕的速度交付产品。

今年，我们都可以借助 [Claude Cowork](https://claude.com/product/cowork) 迎头赶上。

我从去年开始使用 Claude Code 处理聊天无法胜任的较长、多步骤任务。一周之内，我从不知道终端是什么，到构建出 [能在 30 秒内完成 30 分钟任务的 Claude Code 工作流](https://claude.com/blog/how-anthropic-uses-claude-marketing)。我当时用 Claude Code 做非技术工作，因为那时 Claude Cowork 还不存在。

现在，我 90% 的工作都在 [Claude Cowork](https://claude.com/product/cowork) 中完成。在这篇文章中，我将向你展示如何判断你的哪些任务适合放在那里，通过我自己工作中的真实案例来讲解，并让你在大约十分钟内完成你的第一个可交付成果。

## 使用 Chat vs Claude Cowork vs Claude Code

如果你的工作是非技术性的知识工作——邮件、演示文稿、电子表格、文档、会议，以及“你能把这总结一下吗”——那么 Claude Cowork 就是为你准备的。你不需要会写代码。你不需要知道什么是“代理”或如何构建一个。

如果你过去两年一直在其他 100 个标签页和文件之间打开一个 AI 聊天标签页，把提示或问题复制粘贴进去，再把答案复制粘贴出来，那么你已经知道如何使用 Claude Cowork 了。就是那样，只是少了复制粘贴。

同样的 Claude 模型驱动着聊天、Claude Cowork、Claude Code、Claude Design 以及 Claude 出现的一切地方。这些是不同的工作区，用于不同类型的工作，但内部运行着同样的模型。以下是一个关于何时使用哪个的思考框架：

*   **Chat** 通常是知识工作者开始接触 Claude 的方式。你把你的东西带给 Claude：上传一个文件，粘贴一些文本，描述情况，然后得到一个答案。Chat 用于回答问题、头脑风暴和边思考边表达。
*   Claude 桌面应用中的 **Claude Cowork** 把这一点颠倒过来。你不是把工作带给 Claude，而是把 Claude 带到你的工作中。你把它指向电脑上的一个文件夹，连接到你已经使用的应用，告诉它你想要完成什么。通过 Claude Cowork，你描述一个结果，然后走开，回来时工作已经完成了。  
*   **Claude Code** 是为构建和交付软件的开发者准备的。如果你的工作存在于代码中，就从那里开始。

很多人不知道 Claude Cowork 和 Claude Code 在底层运行着相同的[引擎](https://code.claude.com/docs/en/how-claude-code-works)。

### 什么时候应该使用 Claude Cowork？

理解什么时候用 Claude Cowork 而不是聊天，是大多数人卡住的地方，所以这是我的经验法则：

*   如果你想要的东西适合几次交互，比如一个问题、一个解释、一个头脑风暴或一个快速检查，那就**用聊天**。
*   如果你需要的是可交付的成果，比如别人会打开的文件、别人会展示的演示文稿、或者需要排序的电子表格，那就**用 Claude Cowork**。用它来处理任何多步骤的、涉及多个文件/文件类型或多个应用的事情，或者你会把它描述为任务而不是问题的事情。通过 Claude Cowork，你是在把工作*委托*给 Claude。

以下是一些界限的例子：

| 示例问题或任务 | 使用 |
| --- | --- |
| 我们的业务评审会议应该涵盖什么？ | Chat |
| 读取这个 Google Drive 文件夹中过去三个月的会议记录，用我们的模板生成一个 QBR 演示文稿。 | Claude Cowork |
| 怎么用 VLOOKUP？ | Chat |
| 浏览我的电子表格，把所有的 VLOOKUP 改成 INDEX MATCH。 | Claude Cowork |
| 为这个页面建议更好的标题标签和元描述。 | Chat |
| 用这张表里新的标题标签和元描述，通过 CMS 连接器更新这 30 个页面。 | Claude Cowork |

最常见的错误是凡事都用聊天，从未感受到 Claude Cowork 能带来的不同。相反的错误是把 Claude Cowork 当作一次性问题来用，然后等着聊天本来五秒就能回答的事情。

### Claude Cowork 式任务的五个要素

如果你在刚开始时不确定该把哪些项目委托给 Claude Cowork，就用这个清单来检验。你不需要满足所有五个条件，但一个好的候选任务会符合其中几项：

1.  **有多个输入。** 多个文件、整个文件夹，或者一个文件加上一些连接器。如果只有一个输入，聊天通常就能处理得很好（不过还是建议你试试）。
2.  **有文件输出。** 你需要一个可以附加、展示、分享或重复利用的交付物：文档、演示文稿、电子表格或 CSV。
3.  **你会再次做这件事。** 一次性任务也行，但重复性任务才是最佳选择。你可以安排它们在你坐到桌前之前就运行好。
4.  **你心里已经有“好”的标准。** 你熟悉输出的形式，所以能在 15 秒内判断结果是正确、错误，还是完成了 70%。  
5.  **中间部分是最无聊的。** 思考发生在开始（决定你想要什么）和结束（决定它是否正确）。中间的一切（提取、编译、核对、重新格式化）就是你要交出去的部分。

## 我在 Anthropic 如何使用 Claude Cowork

我负责 Anthropic 的增长营销，所以我的例子都带有营销色彩。不要为了找一个可以直接复制的工作流来读这些——长期来看那没什么帮助。看看每个例子是如何符合上面清单中的几项的，因为那才是你为自己的 Claude Cowork 工作流寻找的模式。

### 每日简报

营销人员每天收到的 Slack 频道和邮件数量可能令人难以招架。我有一个“每日简报”任务，每天早上 6 点运行。Claude Cowork 连接到我的 Slack 和 Gmail，我的提示告诉它检查我的未读邮件和我关心的频道，将它们分类，并生成一份简短报告。

这份报告给我一个 TLDR，告诉我需要关注什么，按类型分组的标记邮件，频道摘要，以及任何可能影响营销的隔夜产品相关事件。任何被 Slack 和邮件淹没的人都可以运行这个工作流的某个版本。

### 预算节奏

我的部分工作包括绩效营销的预算节奏。这是一种没人想做的工作，因为它无聊又繁琐。许多绩效营销团队在 Google Sheets 中追踪每日支出和消耗率，以估算达到目标的节奏。你要么手动从每个渠道导出每日支出并粘贴到表格中，要么付费使用第三方工具来提取、转换和加载数据。

通过 Claude Cowork，我连接到 Google Ads 和 Meta Ads，在桌面应用中创建一个实时工件（基本上是一个 HTML 仪表盘），它会自动拉取我的每日支出并为我计算节奏。我还可以直接用通俗的英语告诉 Claude 如何过滤我的广告系列以及要注意什么。

对照上面的清单：多个来源输入（每个渠道的支出），有文件输出（这里是仪表盘），我经常重新运行它，而中间部分就是我不想自己做的、毫无灵魂的下载复制粘贴苦差事。由于广告平台通过我的连接器集成在一起，我可以随时更新这个仪表盘。

### 报告

我不再需要导出一堆 CSV、建立数据透视表或手动合并文件。我让 Claude Cowork 连接到 Google Search Console。它会拉取我关心的数据（查询、国家、页面），并将其整合到一个表格中，而不是像 Google 手工导出数据时默认每个维度一个 CSV 文件那样。

我还给 Claude 提供要关注什么的背景信息，比如对比最近七天与之前七天，只过滤特定国家，标记任何有显著变化的数据，并按照我想要的模板写出报告。之后我可以调整任何内容或向 Claude 提出后续问题。

通过 Claude Cowork 的定时功能，这个任务每周自动运行。以前报告每次大约需要 30 分钟；现在只需要 5 分钟，而且我把这 5 分钟花在需要我判断的部分上：补充缺失的背景信息和推敲重点内容。

这些只是我使用 Claude Cowork 的一些例子，但仅仅是冰山一角。查看我写的另一篇文章，其中详细介绍了[另一个复杂用例的逐步讲解](https://www.linkedin.com/feed/update/urn:li:activity:7448056387772833795/)，涉及插件、技能、本地 MCP 和 [Dispatch](https://support.claude.com/en/articles/13947068-assign-tasks-from-anywhere-in-claude-cowork)，了解更多最佳实践。

## 你在 Claude Cowork 中的前 10 分钟

第一次打开应用？以下是如何开始：

1.  打开 Claude 桌面应用，切换到 Claude Cowork 标签页。
2.  给 Claude 一些可以处理的东西。放入几个文件，指向电脑上的一个文件夹，或者连接一个你经常使用的应用（Slack、Gmail、Notion、CRM 等）。平庸的 Claude Cowork 输出和出色的输出之间的区别几乎从来不是你的提示，而是你是否提供了足够丰富的上下文让 Claude 去处理。
3.  告诉 Claude 你想要的结果。描述你最终想要的可交付成果，并提供必要的背景信息。
4.  从一个你很熟悉的实际任务开始。你会立刻看到它的强项在哪里，哪里需要你提供上下文，而且你已经知道“好”的标准是什么。
5.  让 Claude 在开始之前先问你问题。这是我养成的唯一最有用的习惯。把它作为你提示的一部分：*在我们开始之前，把你的要求复述给我听，以确保我们理解一致，然后尽可能多地向我提出澄清性问题。*

这能揭示出你没想到要指定的东西，比如我们看哪个时间段，这里“好”是什么意思，或者你知道但 Claude 不知道的边缘情况。陷阱是以为 Claude 已经知道对你来说显而易见的东西。提前回答五个问题只花你 30 秒。但事后发现同样的差距会浪费你时间和 token，而且很难修正。

还是不确定该交出什么？问 Claude。Claude 有记忆能力，可以搜索你过去的对话，所以你可以问它你最常做哪些任务，以及哪些任务适合在 Claude Cowork 中尝试。

### 我什么时候仍然会使用聊天

我仍然大量使用聊天来讨论定位问题、在做出决定之前测试一个想法，或者问一些随机问题，比如为什么我的狗老舔床。

关键不在于聊天是“旧”事物。聊天适用于当输出是你头脑中的一个想法时；而 Claude Cowork 适用于当输出是你将交给别人的东西时。

## 去创造点什么吧

选一个你每周都会做的重复性任务，尝试用 [Claude Cowork](https://claude.com/product/cowork) 来做，看看会得到什么结果。最初几个任务可能会感觉有点别扭，但尝试几次后，你会很快从“我该怎么用这个”变成“下一个我该交给它什么”。
