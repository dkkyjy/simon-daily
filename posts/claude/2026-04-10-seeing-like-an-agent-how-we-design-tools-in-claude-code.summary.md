# 中文摘要

## 一句话总结
设计AI代理工具需像代理一样思考，通过实验和观察来平衡通用工具与专用工具的选择。

## 主要观点
1. 构建代理工具是设计代理系统最困难的部分之一。
2. 工具设计应匹配模型自身能力，而非人类偏好。
3. AskUserQuestion工具通过结构化调用提升用户与代理的沟通效率。
4. TodoWrite工具随模型能力提升反而限制代理灵活性。
5. Task工具替代TodoWrite，支持子代理间任务协调与更新。
6. 让代理自主搜索代码库比被动接收RAG上下文更有效。
7. 渐进式信息暴露允许代理通过探索逐步构建上下文。
8. Claude Code目前约20个工具，新增工具门槛很高。
9. 子代理（Guide Agent）可处理文档搜索而不污染主代理上下文。
10. 工具设计是艺术与科学的结合，需持续实验和调整。

## 核心启示
1. 定期重新评估工具必要性，避免过时工具限制模型能力。
2. 优先采用渐进式信息暴露而非一次性注入大量上下文。
3. 让代理自主构建上下文比被动接收检索结果更智能。
4. 工具设计应随模型能力提升而演进，而非一成不变。
5. 通过子代理分离关注点，保持主代理上下文精简高效。
