## 何时使用提示缓存

在您希望一次性发送大量提示上下文并在后续请求中重复引用该信息的情况下，提示缓存可以发挥有效作用，包括：

* **对话代理：** 降低长时间对话（尤其是带有长指令或上传文档的对话）的成本和延迟。
* **编码助手：** 通过在提示中保留代码库的摘要版本来改进自动补全和代码库问答。
* **大型文档处理：** 在提示中嵌入完整的长篇材料（包括图像），而不会增加响应延迟。
* **详细指令集：** 共享广泛的指令、流程和示例列表，以微调Claude的响应。开发者通常会在提示中包含几个示例，但通过提示缓存，您可以包含数十个高质量输出的多样化示例，从而获得更好的性能。
* **代理搜索和工具使用：** 提升涉及多轮工具调用和迭代更改场景的性能，其中每一步通常都需要新的API调用。
* **与书籍、论文、文档、播客文稿和其他长篇内容对话：** 通过将整个文档嵌入提示中，让用户向其提问，从而激活任何知识库。

早期客户已经在各种用例中看到了提示缓存的显著速度和成本改进——从包含完整知识库到100次示例，再到在提示中包含对话的每一轮。

| **用例** | **无缓存延迟（首个令牌时间）** | **有缓存延迟（首个令牌时间）** | **成本降低** |
| --- | --- | --- | --- |
| 与书籍对话（100,000令牌缓存提示）[1] | 11.5秒 | 2.4秒（-79%） | -90% |
| 多示例提示（10,000令牌提示）[1] | 1.6秒 | 1.1秒（-31%） | -86% |
| 多轮对话（10轮对话，带长系统提示）[2] | ~10秒 | ~2.5秒（-75%） | -53% |

### 我们如何为缓存提示定价

缓存提示的定价基于您缓存的输入令牌数量以及您使用该内容的频率。写入缓存的成本比任何给定模型的基础输入令牌价格高出25%，而使用缓存内容的成本则显著降低，仅为基础输入令牌价格的10%。

|  |  |  |  |
| --- | --- | --- | --- |
| **Claude 3.5 Sonnet**  * 我们迄今为止最智能的模型 * 200K上下文窗口 | **输入**  * $3 / 百万令牌 | **提示缓存**  * $3.75 / 百万令牌 -   缓存写入 * $0.30 / 百万令牌 - 缓存读取 | **输出**   * $15 / 百万令牌 |
| **Claude 3 Opus**  * 适用于复杂任务的强大模型 * 200K上下文窗口 | **输入**  * $15 / 百万令牌 | **提示缓存**  * $18.75 / 百万令牌 -   缓存写入 * $1.50 / 百万令牌 - 缓存读取 | **输出**  * $75 / 百万令牌 |
| **Claude 3 Haiku**  * 最快、最具成本效益的模型 * 200K上下文窗口 | **输入**  * $0.25 / 百万令牌 | **提示缓存**  * $0.30 / 百万令牌   -   缓存写入 * $0.03 / 百万令牌 - 缓存读取 | **输出**  * $1.25 / 百万令牌 |
