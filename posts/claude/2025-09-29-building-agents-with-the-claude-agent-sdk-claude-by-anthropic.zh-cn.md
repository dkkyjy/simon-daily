去年，我们与客户分享了[构建高效智能体](https://www.anthropic.com/engineering/building-effective-agents)的经验。自那时起，我们发布了 [Claude Code](https://claude.com/product/claude-code)，这是一个最初为支持 Anthropic 内部开发者生产力而构建的智能编码解决方案。

在过去的几个月里，Claude Code 已远不止是一个编码工具。在 Anthropic，我们一直在[使用它](https://www.anthropic.com/news/how-anthropic-teams-use-claude-code)进行深度研究、视频创作和笔记记录，以及无数其他非编码应用。事实上，它已经开始驱动我们几乎所有主要的智能体循环。

换句话说，[驱动 Claude Code 的智能体框架](https://claude.com/blog/harnessing-claudes-intelligence)（即 Claude Code SDK）也可以驱动许多其他类型的智能体。为了体现这一更广阔的愿景，我们将 Claude Code SDK 更名为 Claude Agent SDK。

在这篇文章中，我们将重点说明为什么我们要构建 Claude Agent SDK，如何使用它构建你自己的智能体，并分享我们团队在自身部署中总结出的最佳实践。

## 给 Claude 一台计算机

[Claude Code 的关键设计原则](https://www.youtube.com/watch?v=vLIDHi-1PVU)是 Claude 需要程序员日常使用的相同工具。它需要能够在代码库中找到合适的文件、编写和编辑文件、检查代码、运行代码、调试、编辑，有时需要迭代执行这些操作直到代码成功。

我们发现，通过允许 Claude 访问用户的计算机（通过终端），它具备了像程序员一样编写代码所需的全部条件。

但这同时也让 Claude Code 中的 Claude 在*非*编码任务上表现出色。通过为其提供运行 bash 命令、编辑文件、创建文件和搜索文件的工具，Claude 可以读取 CSV 文件、搜索网络、构建可视化图表、解读指标以及执行各种其他数字工作——简而言之，用一台计算机创建通用型智能体。Claude Agent SDK 背后的关键设计原则就是给你的智能体一台计算机，让它们像人类一样工作。

## 创建新型智能体

我们相信，给 Claude 一台计算机，就能解锁构建比以前更高效的智能体的能力。例如，使用我们的 SDK，开发者可以构建：

* **金融智能体**：构建能够理解你的投资组合和目标，并通过访问外部 API、存储数据和运行代码进行计算来帮助你评估投资的智能体。
* **个人助理智能体**：构建能够帮你预订旅行、管理日历、预约、整理简报等任务的智能体，通过连接到你的内部数据源并跨应用追踪上下文。
* **客户支持智能体**：构建能够处理高度模糊用户请求（如客服工单）的智能体，通过收集和审查用户数据、连接到外部 API、回复用户消息以及在必要时升级给人工处理。
* **深度研究智能体**：构建能够通过搜索文件系统、分析和综合来自多个来源的信息、跨文件交叉引用数据以及生成详细报告，对大量文档集合进行全面研究的智能体。

以及更多。其核心是，SDK 为你提供了构建智能体的基本组件，用于任何你想要自动化的工作流程。

## 构建你的智能体循环

在 Claude Code 中，Claude 通常在一个特定的反馈循环中运作：收集上下文 → 采取行动 → 验证工作 → 重复。

智能体通常在一个特定的反馈循环中运作：收集上下文 → 采取行动 → 验证工作 → 重复。

这为我们思考其他智能体以及它们应该具备的能力提供了一个有用的方法。为了说明这一点，我们将以在 Claude Agent SDK 中构建一个邮件智能体为例进行讲解。

## 收集上下文

在开发智能体时，你不仅需要给它一个提示词：它还需要能够获取和更新自己的上下文。以下是 SDK 中的功能如何提供帮助。

### **智能搜索与文件系统**

文件系统代表了*可以*被拉入模型上下文的信息。

当 Claude 遇到大文件（如日志或用户上传的文件）时，它会决定使用哪种方式将这些文件加载到上下文中，例如使用 `grep` 和 `tail` 等 bash 脚本。实质上，智能体的文件夹和文件结构成为了一种[上下文工程](http://anthropic.com/news/context-management)的形式。

我们的邮件智能体可能会将之前的对话存储在一个名为“Conversations”的文件夹中。这样，当被问及这些对话时，它就可以搜索这些内容以获取上下文。

### **语义搜索**

[语义搜索](https://www.anthropic.com/news/contextual-retrieval)通常比智能搜索更快，但准确性较低、维护更困难且透明度较低。它涉及对相关上下文进行分块，将这些块作为向量嵌入，然后通过查询这些向量来搜索概念。考虑到其局限性，我们建议从智能搜索开始，仅在你需要更快的结果或更多变化时才添加语义搜索。

### **子智能体**

Claude Agent SDK 默认支持子智能体。[子智能体](https://docs.claude.com/en/api/agent-sdk/subagents)在两方面很有用。首先，它们支持并行化：你可以启动多个子智能体同时处理不同的任务。其次，它们有助于管理上下文：子智能体使用自己独立的上下文窗口，只将相关信息发送回编排器，而不是它们的全部上下文。这使得它们非常适合处理需要筛选大量信息而其中大部分信息无用的任务。

在设计我们的邮件智能体时，我们可以给它一个“搜索子智能体”的能力。邮件智能体可以并行启动多个搜索子智能体——每个子智能体对你的邮件历史执行不同的查询——并让它们只返回相关摘录，而不是完整的邮件线程。

### **压缩**

当智能体长时间运行时，上下文维护变得至关重要。Claude Agent SDK 的压缩功能会在上下文限制接近时自动总结之前的消息，这样你的智能体就不会用尽上下文。这建立在 Claude Code 的[压缩斜杠命令](https://docs.claude.com/en/docs/claude-code/sdk/sdk-slash-commands#%2Fcompact-compact-conversation-history)之上。

## 采取行动

一旦收集了上下文，你就需要给你的智能体灵活的行动方式。

### **工具**

[工具](https://www.anthropic.com/engineering/writing-tools-for-agents)是智能体执行的主要构建块。工具在 Claude 的上下文窗口中非常显眼，因此 Claude 在决定如何完成任务时会优先考虑这些工具。这意味着你应该有意识地设计工具以最大化上下文效率。你可以在我们的博客文章[《编写高效的工具供智能体使用——借助智能体》](https://www.anthropic.com/engineering/writing-tools-for-agents)中看到更多最佳实践。

因此，你的工具应该是你希望智能体执行的主要操作。了解如何在 Claude Agent SDK 中制作[自定义工具](https://docs.claude.com/en/api/agent-sdk/custom-tools)。

对于我们的邮件智能体，我们可以将“`fetchInbox`”或“`searchEmails`”等工具定义为智能体的主要、最频繁的操作。

### **代码生成**

Claude Agent SDK 擅长代码生成——这是有充分理由的。代码是精确、可组合且无限可重用的，使其成为需要可靠执行复杂操作的智能体的理想输出。

### **MCP**

[模型上下文协议](https://modelcontextprotocol.io/)（MCP）提供了标准化的外部服务集成，自动处理认证和 API 调用。这意味着你可以将智能体连接到 Slack、GitHub、Google Drive 或 Asana 等工具，而无需编写自定义集成代码或自行管理 OAuth 流程。

对于我们的邮件智能体，我们可能想要`搜索 Slack 消息`以了解团队上下文，或者`检查 Asana 任务`以查看是否已经有人被分配处理客户请求。借助 MCP 服务器，这些集成开箱即用——你的智能体只需调用类似 search_slack_messages 或 get_asana_tasks 的工具，MCP 就会处理其余工作。

不断增长的 [MCP 生态系统](https://github.com/modelcontextprotocol/servers)意味着你可以快速为智能体添加新功能，因为预构建的集成不断变得可用，让你可以专注于智能体的行为。

## 验证你的工作

Claude Code SDK 通过评估自身工作来完成智能体循环。能够检查并改进自身输出的智能体从根本上更加可靠——它们在错误累积之前发现错误，在偏离时自我纠正，并在迭代中不断进步。

关键在于给予 Claude 具体的评估工作方式。以下是三种我们觉得有效的方法：

### **定义规则**

最好的反馈形式是为输出提供明确定义的规则，然后解释哪些规则失败以及原因。

[代码检查](https://stackoverflow.com/questions/8503559/what-is-linting)是一种优秀的基于规则的反馈形式。反馈越深入越好。例如，生成 TypeScript 并进行检查通常比生成纯 JavaScript 更好，因为它为你提供了多个额外的反馈层。

在生成邮件时，你可能希望 Claude 检查邮件地址是否有效（如果无效则抛出错误），以及用户之前是否曾向该地址发送过邮件（如果是，则抛出警告）。

### **视觉反馈**

当使用智能体完成视觉任务（如 UI 生成或测试）时，视觉反馈（以截图或渲染形式）会很有帮助。例如，如果发送带有 HTML 格式的邮件，你可以截取生成的邮件的截图，并将其提供给模型进行视觉验证和迭代优化。模型随后会检查视觉输出是否与要求匹配。

例如：

* **布局** - 元素位置是否正确？间距是否合适？
* **样式** - 颜色、字体和格式是否按预期呈现？
* **内容层次** - 信息是否以正确的顺序和适当的强调呈现？
* **响应式** - 看起来是否破损或拥挤？（不过单张截图提供的视口信息有限）

使用像 Playwright 这样的 MCP 服务器，你可以自动化这个视觉反馈循环——截取渲染后的 HTML 截图、捕捉不同视口大小，甚至测试交互元素——所有这些都在你的智能体工作流程中完成。

来自大语言模型（LLM）的视觉反馈可以为你的智能体提供有用的指导。

### **LLM 作为评判者**

你也可以让另一个语言模型基于模糊规则“评判”你的智能体的输出。这通常不是一个非常健壮的方法，并且可能有较大的延迟权衡，但对于任何性能提升都值得付出成本的应用场景，它可能会有帮助。

我们的邮件智能体可能会有一个单独的子智能体来评判其草稿的语气，看是否适合用户之前的消息风格。

## 测试和改进你的智能体

在经历了智能体循环几次之后，我们建议测试你的智能体，并确保它已经充分准备好完成其任务。改进智能体的最佳方法是仔细查看其输出，特别是它失败的情况，并设身处地思考：它是否拥有完成工作所需的[正确工具](https://www.anthropic.com/engineering/writing-tools-for-agents)？

以下是一些在评估你的智能体是否具备完成工作的能力时可以考虑的问题：

* 如果你的智能体误解了任务，可能是缺少关键信息。你能改变搜索 API 的结构，使其更容易找到需要了解的内容吗？
* 如果你的智能体反复失败，你能在工具调用中添加一个正式的规则来识别并修复该失败吗？
* 如果你的智能体无法修正错误，你能给它更多有用或创造性的工具，以便用不同的方式处理问题吗？
* 如果你的智能体性能随着添加功能而变化，请基于客户使用情况构建一个代表性的测试集用于程序化评估（或叫 evals）。

## 开始使用

Claude Agent SDK 通过让 Claude 能够访问一台计算机（可以在上面编写文件、运行命令并迭代工作），使得构建自主智能体变得更加容易。

牢记智能体循环（收集上下文、采取行动、验证工作），你可以构建易于部署和迭代的可靠智能体。

你今天就可以[开始使用](https://docs.claude.com/en/api/agent-sdk/overview) Claude Agent SDK。对于已经在基于 SDK 进行构建的开发者，我们建议按照[本指南](https://docs.claude.com/en/docs/claude-code/sdk/migration-guide)迁移到最新版本。
