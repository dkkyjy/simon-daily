# 使用 Claude Agent SDK 构建智能体

**日期：** 2025-09-29 00:00 UTC
**链接：** https://claude.com/blog/building-agents-with-the-claude-agent-sdk

---

去年，我们与客户分享了[构建有效智能体](https://www.anthropic.com/engineering/building-effective-agents)的经验教训。自那以后，我们发布了 [Claude Code](https://claude.com/product/claude-code)，这是一款我们最初为提升 Anthropic 内部开发者生产力而构建的智能编码解决方案。

在过去的几个月里，Claude Code 已经远不止是一个编码工具。在 Anthropic，我们一直在[使用它](https://www.anthropic.com/news/how-anthropic-teams-use-claude-code)进行深度研究、视频创作和笔记记录，以及无数其他非编码应用。事实上，它已经开始驱动我们几乎所有主要的智能体循环。

换句话说，[驱动 Claude Code 的智能体框架](https://claude.com/blog/harnessing-claudes-intelligence)（即 Claude Code SDK）同样可以驱动许多其他类型的智能体。为了体现这一更广阔的愿景，我们将 Claude Code SDK 更名为 Claude Agent SDK。

在这篇文章中，我们将重点介绍我们构建 Claude Agent SDK 的原因，如何用它构建你自己的智能体，并分享从我们团队自身部署中总结出的最佳实践。

## 给 Claude 一台计算机

[Claude Code 的关键设计原则](https://www.youtube.com/watch?v=vLIDHi-1PVU)是，Claude 需要程序员每天使用的相同工具。它需要能够在代码库中找到合适的文件、编写和编辑文件、检查代码、运行代码、调试、编辑，有时还需要迭代执行这些操作，直到代码成功运行。

我们发现，通过让 Claude 访问用户的计算机（通过终端），它便拥有了像程序员一样编写代码所需的一切。

但这同时也让 Claude Code 中的 Claude 在*非*编码任务上变得高效。通过赋予它运行 bash 命令、编辑文件、创建文件和搜索文件的工具，Claude 可以读取 CSV 文件、搜索网络、构建可视化图表、解读指标，以及执行各种其他数字化工作——简而言之，就是利用计算机创建通用型智能体。Claude Agent SDK 的关键设计原则就是给你的智能体一台计算机，让它们像人类一样工作。

## 创建新型智能体

我们相信，给 Claude 一台计算机能够解锁构建比以往更高效智能体的能力。例如，使用我们的 SDK，开发者可以构建：

* **金融智能体**：构建能够理解你的投资组合和目标，并通过访问外部 API、存储数据和运行代码进行计算来帮助你评估投资的智能体。
* **个人助理智能体**：构建能够帮助你预订旅行和管理日历，以及安排预约、整理简报等事务的智能体，通过连接到你的内部数据源并跨应用追踪上下文来实现。
* **客户支持智能体**：构建能够处理高模糊度用户请求（如客户服务工单）的智能体，通过收集和审查用户数据、连接到外部 API、给用户回复消息以及在必要时升级给人工处理。
* **深度研究智能体**：构建能够通过搜索文件系统、分析和综合多个来源的信息、跨文件交叉引用数据以及生成详细报告，对大量文档集合进行全面研究的智能体。

还有更多可能性。其核心在于，SDK 为你提供了构建智能体的基本元素，适用于任何你想要自动化的流程。

## 构建你的智能体循环

在 Claude Code 中，Claude 通常在一个特定的反馈循环中运行：收集上下文 -> 采取行动 -> 验证工作 -> 重复。

智能体通常在一个特定的反馈循环中运行：收集上下文 -> 采取行动 -> 验证工作 -> 重复。

这提供了一种有用的方式来思考其他智能体以及它们应被赋予的能力。为了说明这一点，我们将通过一个示例来演示如何在 Claude Agent SDK 中构建一个邮件智能体。

## 收集上下文

在开发智能体时，你希望赋予它的不仅仅是一个提示词：它需要能够获取并更新自己的上下文。以下是 SDK 中的功能如何提供帮助。

### **智能搜索与文件系统**

文件系统代表了*可能*被拉入模型上下文的信息。

当 Claude 遇到大文件（如日志或用户上传的文件）时，它会决定使用 bash 脚本（如 `grep` 和 `tail`）将这些文件加载到其上下文中。本质上，智能体的文件夹和文件结构成为一种[上下文工程](http://anthropic.com/news/context-management)的形式。

我们的邮件智能体可能会将之前的对话存储在一个名为"对话"的文件夹中。当被问及相关问题时，这将允许它搜索这些之前的对话以获取上下文。

### **语义搜索**

[语义搜索](https://www.anthropic.com/news/contextual-retrieval)通常比智能搜索更快，但准确性较低，更难维护，且透明度较低。它涉及将相关上下文"分块"，将这些块嵌入为向量，然后通过查询这些向量来搜索概念。考虑到其局限性，我们建议从智能搜索开始，只有在你需要更快的结果或更多变体时才添加语义搜索。

### **子智能体**

Claude Agent SDK 默认支持子智能体。[子智能体](https://docs.claude.com/en/api/agent-sdk/subagents)在两个方面很有用。首先，它们支持并行化：你可以启动多个子智能体同时处理不同的任务。其次，它们有助于管理上下文：子智能体使用自己独立的上下文窗口，只将相关信息发送回编排器，而不是它们的完整上下文。这使得它们非常适合需要筛选大量信息而其中大部分信息无用的任务。

在设计我们的邮件智能体时，我们可能会赋予它一个"搜索子智能体"的能力。然后，邮件智能体可以并行启动多个搜索子智能体——每个子智能体对你的邮件历史运行不同的查询——并让它们只返回相关的摘录，而不是完整的邮件线程。

### **压缩**

当智能体长时间运行时，上下文维护变得至关重要。Claude Agent SDK 的压缩功能会在上下文限制接近时自动总结之前的消息，这样你的智能体就不会耗尽上下文。这建立在 Claude Code 的[压缩斜杠命令](https://docs.claude.com/en/docs/claude-code/sdk/sdk-slash-commands#%2Fcompact-compact-conversation-history)之上。

## 采取行动

一旦你收集了上下文，你就需要给你的智能体灵活的行动方式。

### **工具**

[工具](https://www.anthropic.com/engineering/writing-tools-for-agents)是智能体执行的主要构建模块。工具在 Claude 的上下文窗口中非常突出，这使得它们成为 Claude 在决定如何完成任务时首要考虑的行动。这意味着你应该有意识地设计你的工具，以最大化上下文效率。你可以在我们的博客文章[为智能体编写有效工具——与智能体合作](https://www.anthropic.com/engineering/writing-tools-for-agents)中查看更多最佳实践。

因此，你的工具应该是你希望智能体采取的主要行动。了解如何在 Claude Agent SDK 中制作[自定义工具](https://docs.claude.com/en/api/agent-sdk/custom-tools)。

对于我们的邮件智能体，我们可能会将"`fetchInbox`"或"`searchEmails`"等工具定义为智能体的主要、最频繁的行动。

Claude Agent SDK 擅长代码生成——这是有充分理由的。代码是精确的、可组合的且无限可重用的，这使得它成为需要可靠执行复杂操作的智能体的理想输出。

### **MCP**

[模型上下文协议](https://modelcontextprotocol.io/)（MCP）提供了与外部服务的标准化集成，自动处理身份验证和 API 调用。这意味着你可以将智能体连接到 Slack、GitHub、Google Drive 或 Asana 等工具，而无需编写自定义集成代码或自行管理 OAuth 流程。

对于我们的邮件智能体，我们可能希望`搜索 Slack 消息`以了解团队上下文，或`检查 Asana 任务`以查看是否已有人被分配处理客户请求。使用 MCP 服务器，这些集成开箱即用——你的智能体只需调用诸如 search_slack_messages 或 get_asana_tasks 之类的工具，MCP 就会处理其余工作。

不断增长的 [MCP 生态系统](https://github.com/modelcontextprotocol/servers)意味着随着预构建集成的可用，你可以快速为智能体添加新功能，让你专注于智能体行为。

## 验证你的工作

Claude Code SDK 通过评估其工作来完成智能体循环。能够检查和改进自身输出的智能体从根本上来说更可靠——它们在错误叠加之前捕捉错误，在偏离时自我纠正，并在迭代中不断改进。

关键在于给 Claude 提供评估其工作的具体方法。以下是三种我们觉得有效的方法：

### **定义规则**

最好的反馈形式是为输出提供明确定义的规则，然后解释哪些规则失败以及原因。

[代码检查](https://stackoverflow.com/questions/8503559/what-is-linting)是一种极好的基于规则的反馈形式。反馈越深入越好。例如，生成 TypeScript 并对其进行检查通常比生成纯 JavaScript 更好，因为它为你提供了多个额外的反馈层。

在生成邮件时，你可能希望 Claude 检查邮件地址是否有效（如果无效则抛出错误），以及用户之前是否曾向该地址发送过邮件（如果是则抛出警告）。

### **视觉反馈**

当使用智能体完成视觉任务（如 UI 生成或测试）时，视觉反馈（以截图或渲染的形式）可能很有帮助。例如，如果发送带有 HTML 格式的邮件，你可以截取生成的邮件截图并将其提供给模型进行视觉验证和迭代优化。然后模型会检查视觉输出是否与请求相符。

例如：

* **布局** - 元素定位是否正确？间距是否合适？
* **样式** - 颜色、字体和格式是否如预期显示？
* **内容层次** - 信息是否以正确的顺序呈现并带有适当的强调？
* **响应式** - 看起来是否破损或拥挤？（尽管单张截图的视口信息有限）

使用像 Playwright 这样的 MCP 服务器，你可以自动化这个视觉反馈循环——截取渲染后的 HTML 截图、捕捉不同视口大小，甚至测试交互元素——所有这些都在智能体的工作流程内完成。

来自大语言模型（LLM）的视觉反馈可以为你的智能体提供有用的指导。

### **LLM 作为评判者**

你也可以让另一个语言模型基于模糊规则来"评判"智能体的输出。这通常不是一个非常稳健的方法，并且可能有较大的延迟权衡，但对于任何性能提升都值得付出成本的应用来说，它可能是有帮助的。

我们的邮件智能体可能会有一个单独的子智能体来评判其草稿的语气，看是否与用户之前的消息相匹配。

## 测试和改进你的智能体

在经历了几次智能体循环之后，我们建议测试你的智能体，并确保它已为任务做好了充分准备。改进智能体的最佳方法是仔细查看其输出，特别是失败的情况，并设身处地思考：它是否拥有完成工作所需的[正确工具](https://www.anthropic.com/engineering/writing-tools-for-agents)？

以下是一些在评估你的智能体是否胜任其工作时可以问的问题：

* 如果你的智能体误解了任务，可能缺少关键信息。你能改变搜索 API 的结构，使其更容易找到需要的信息吗？
* 如果你的智能体反复在某个任务上失败，你能在工具调用中添加一个正式规则来识别和修复失败吗？
* 如果你的智能体无法修复错误，你能给它更有用或更有创意的工具来以不同方式解决问题吗？
* 如果你的智能体的性能随着你添加功能而变化，请基于客户使用情况构建一个代表性的测试集用于程序化评估（或评估）。

## 开始使用

Claude Agent SDK 通过让 Claude 访问一台可以编写文件、运行命令和迭代工作的计算机，使得构建自主智能体变得更加容易。

牢记智能体循环（收集上下文、采取行动和验证工作），你可以构建易于部署和迭代的可靠智能体。

你可以立即[开始使用](https://docs.claude.com/en/api/agent-sdk/overview) Claude Agent SDK。对于已经在基于 SDK 进行构建的开发者，我们建议按照[本指南](https://docs.claude.com/en/docs/claude-code/sdk/migration-guide)迁移到最新版本。
