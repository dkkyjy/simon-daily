让一个代理投入生产不仅仅需要一个好的提示。代理需要运行它所编写的代码的地方、访问你数据的凭据、可观测的会话，以及能够随使用量扩展的基础设施。在应用 AI 团队，我们工作在产品、研究和基于 Claude 构建的客户的交汇点——我们反复看到同样的模式：基础设施是区分原型和生产代理的关键所在。团队常常在安全、状态管理、权限管理和 harness 调优上耗费开发周期。

[Claude 托管代理](https://platform.claude.com/docs/en/managed-agents/overview)，我们用于构建和部署生产级代理的可组合 API 套件，将针对性能调优的代理 harness 与生产基础设施配对，使团队能够在数天内而非数月内从原型走向发布。在这篇文章中，我们将介绍 Anthropic 代理构建模块的演进、我们为什么构建 Claude 托管代理，以及团队如今如何在生产中使用它。

## **演进中的代理架构**

当我们在 2023 年向开发者开放 Claude 时，API 有意设计得简单：令牌进，令牌出。你发送一个提示，Claude 返回一个补全，然后你构建 harness 和底层基础设施。

多年来，API 逐渐丰富，但底层的约定从未改变：一次请求，一次模型轮次，你的应用程序决定下一步发生什么。在很长一段时间里，这就足够了。总结一份文档、分类一个支持工单、重写一段文本——这些工作适合在单个轮次内完成。

然而，随着时间的推移，人们想要交办的任务不再适合这样的模式。他们希望 Claude 全程完成一个任务，查询某项内容，对其采取行动，观察变化，然后决定下一步做什么。他们希望它在他们工作所依赖的系统 *内部* 运行，比如代码库、内部维基或工单系统。

使用 API，将 Claude 变成一个代理意味着构建你自己的循环：询问模型要做什么，运行工具，将结果反馈回去，然后重复。你负责构建和部署代理脚手架，随着模型的演进，这可能需要进行调优。对于需要完全自定义的代理，这种方法是合理的。对于更可预测且复杂度较低的代理工作负载，随着模型和产品的演进而优化 harness 变得乏味。

[Claude Code](https://code.claude.com/docs/en/overview)（我们于 2025 年推出的代理编码工具，允许 Claude 直接与你的代码库交互）包含了我们自己版本的 harness：循环、工具执行、子代理、上下文管理以及使其成为有效代理的丰富能力。开发者自然希望在其不同领域的代理中也拥有类似的 harness 机制。

为了使团队能够基于 Claude Code harness 构建代理，我们发布了 [Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview)。Claude Agent SDK 为开发者提供了工具，让他们能够基于与 Claude Code 相同的机制构建自己的代理，而无需维护自制的循环。对于许多团队来说，这正是代理变得实用的时候：harness 已经为 Claude 调优过，附带基础设施原语，并且随着 Claude Code 的改进而不断优化。

然而，即使有了 harness，在生产环境中部署代理仍然可能因为以下几个原因而具有挑战性：

*   **托管与扩展。** 代理在哪里运行？对于一个需要数小时的任务，进程可以保持活跃多长时间？当使用量增长时，是什么对它进行扩展？
*   **会话管理。** 代理的历史记录和进度存储在哪里？一次运行能否在中断后恢复而不受影响？你能回溯并检查之前会话中发生了什么吗？
*   **文件系统管理。** 做实际工作意味着产生工件：编辑代码、编写文件、构建输出。代理在哪里获得一个工作区来操作？在不同的运行之间，该工作区会怎样？
*   **执行隔离。** Claude 编写的代码必须在某处执行。如果出错了，影响范围有多大？你在生产环境中真正信任的边界是什么？
*   **凭据。** 代理需要访问你的系统。它如何在不向所生成的代码暴露专有信息的情况下获得这种访问？
*   **可观测性。** 当一个代理自主工作一小时并做出一些令人惊讶的事情时，你能重建它采取的每一个步骤吗？

借助 Agent SDK，上述生产基础设施的许多元素都是通过 Claude Code 的机制提供的。代理获得了一个真实的工作文件系统，会话状态持久化在本地或外部存储中，可观测性通过 OpenTelemetry 导出到你已有的任何监控栈中。

然而，随着团队越来越多地构建从本地开发转向生产的代理，他们需要一种能够以托管基础设施大规模部署它们的方法。同时，随着模型及其周围的 harness 变得更加先进——运行更长时间、执行更多代码、触及更多系统、采取更多行动——扩展、安全和沙箱化变得更具挑战性。

其中几个障碍源于一个共同的架构选择：代理 harness 通常与它操作的文件系统 *运行在同一个容器中*。一个容器必须先启动（付出启动成本），Claude 才能思考；代理以及代码执行紧邻你的凭据；当容器终止时，运行也随之终止。

托管代理通过[将大脑与双手解耦](https://www.anthropic.com/engineering/managed-agents)解决了这些问题。调用 Claude 的 harness 与执行代码的沙箱分开运行，而会话——一个只追加的日志，记录所有模型调用、工具调用和结果——将两者连接起来。Claude 可以在任何容器存在之前开始推理，沙箱远离你的凭据，并且整个运行可以在任何时候从会话中重建。

## **何时以及为何使用 Claude 托管代理**

使用托管代理构建时，用户定义任务、工具和护栏，Anthropic 在我们的基础设施上运行代理，并处理底层的代理循环：如何为代理提供执行环境来调用工具、出错时如何恢复、多代理编排等等。

当 harness 没有随着模型智能一起演进时，[代理就会崩溃](https://www.anthropic.com/engineering/harness-design-long-running-apps)。在 Claude Sonnet 4.5 上，代理会在接近上下文末尾时急于完成任务，提前结束工作，而不是利用剩余的空间——这种模式称为“上下文焦虑”。我们的修复方法是在 harness 中添加上下文重置，预设 Claude 在接近限制时需要帮助保持连贯性。但这个预设没有延续到下一个模型。在 Claude Opus 4.5 上，这种表现消失了，我们添加的重置变成了纯粹的负担。

对于大多数组织来说，维护一个 harness 是无法使其产品差异化的额外开销。Harness 需要针对特定模型行为进行调优；像压缩、工具执行和缓存这样的原语在 Claude 上的工作方式与其他模型不同。借助 Claude 托管代理，harness 与模型一同演进，使团队能够专注于那些能够让他们的代理差异化的东西：**上下文管理和领域专业知识。**

为了允许开发者配置构建有效代理所需的上下文和工具，托管代理围绕三个主要资源构建：代理、环境和会话。一个 *代理* 是一个配置：模型、提示、一组工具以及围绕它们的护栏。一个 *环境* 是代理运行的执行上下文：沙箱容器、其网络规则以及其中预装的包，托管在我们的云上或你控制的基础设施上。每次运行是一个 *会话*，它将代理与环境配对，并获得自己独立的沙箱实例。会话在服务器端持久保存其完整的事件历史、沙箱状态和输出，因此长时间运行的工作可以暂停、干净地恢复，并在事后逐步追溯。使用托管代理，你可以定义一次代理和环境，然后随着工作负载增长，针对同一配置运行多次会话。

## **在托管代理上为生产和规模构建**

在应用 AI 团队内部，我们观察到代理从原型走向生产——既在 Anthropic 内部，也在我们客户的系统中——覆盖编码、金融、支持、法律以及十几个其他领域。这让我们清楚地看到，什么区分了演示版和生产就绪的代理，以及团队经常在什么地方卡住。

下面，我们分享在像 Claude 托管代理这样的托管服务上构建的最常见原因：

**1. 凭据被保留在沙箱之外。** 当所有内容运行在一个容器中时，Claude 生成的代码紧邻你的凭据，因此提示注入可能导致模型通过诱使其读取自身环境而泄露令牌。我们可以通过在同一容器内设置健壮的护栏来防范这一点，但解耦架构通过将凭据完全保留在沙箱之外，实现了更安全的方法。用于 MCP、CLI 和 GitHub 仓库等工具的令牌存储在一个单独的保险库中，一个代理仅在需要时获取并解密它们。托管代理提供了[保险库](https://platform.claude.com/docs/en/managed-agents/vaults)，可以开箱即用地处理凭据，因此你无需运行自己的密钥存储、在每次调用时传输令牌，或忘记代理代表哪个终端用户执行操作。保险库凭证在存储前经过信封加密保护，检索需要签名的请求令牌进行验证。

**2. 消除沙箱开销带来的更低延迟。** 延迟是许多企业团队最为关注的指标，因为用户能敏锐地感觉到他们在等待 Claude 响应。没有托管代理架构，每个会话都必须启动一个容器，即使是那些代理只需要思考而从不运行工具的会话。这种启动时间被浪费了，用户会感觉到在第一个响应之前有延迟。使用托管代理，Claude 立即开始推理，同时环境并行启动，而从不运行工具的会话完全跳过容器。这意味着用户在无需等待容器启动的情况下看到第一个令牌，并且当代理需要运行某些东西时，环境已经就绪。在我们的测试中，这在中位数情况下（p50）将首令牌时间缩短了约 60%，在最慢的情况下（p95）缩短了超过 90%。

**3. 可靠、持久的会话，支持会话管理、可观测性和记忆。** 不同于请求/响应，托管代理以 *事件* 为单位思考。会话是一个持续的事件流：每个模型调用、工具调用和结果，都会被追加到一个独立于运行代理进程的日志中。通过这种架构，你可以在代理工作时实时获取事件流更新，并且可以稍后恢复任何会话，无需管理数据库或保存点。除非你删除会话，否则历史记录会在交互之间保留；当一个会话空闲时，其容器会被检查点保存，以便你可以从暂停的地方干净地继续。由于整个运行已经是事件记录，可观测性和记忆随之而来：Claude 开发者控制台为你的代理会话提供了原生可视化时间线视图，以及允许你深入检查任何对话记录的调试体验。托管代理还附带了诸如记忆和梦境等功能，这些功能也利用了会话的持久性。[梦境](https://platform.claude.com/docs/en/managed-agents/dreams) 是一个定时进程，它会审查你的代理会话和记忆存储，提取模式，并整理记忆，使你的代理随着时间的推移不断改进。梦境在会话之间优化记忆，通过读取持久的会话日志，从反复出现的错误和用户偏好中学习。

**4. Anthropic 托管或自托管云容器的灵活性。** 默认情况下，使用托管代理，你可以将编排和工具执行都委托给 Anthropic 托管的云容器。这使得托管和扩展变得简单易行，提供了更快的生产路径。由于在托管代理中大脑与双手解耦，双手可以位于任何地方，包括你的虚拟私有云 (VPC) 内部。因此，我们还为希望控制工具执行的团队提供了[自托管沙箱](https://platform.claude.com/docs/en/managed-agents/self-hosted-sandboxes)，这样代理的代码、文件系统和网络出口永远不会离开他们的环境。我们还提供了 [MCP 隧道](https://platform.claude.com/docs/en/agents-and-tools/mcp-tunnels/overview)，让你能够将 Claude 连接到在你的私有网络内运行的模型上下文协议 (MCP) 服务器。因此，自托管沙箱控制 *代理代码在哪里执行*，而 MCP 隧道控制 *Anthropic 如何连接到你网络中的 MCP 服务器*，使你能够精确控制哪些内容留在你的边界内。

*内置的 Claude 托管代理可观测性控制台记录每一个事件，因此你可以擦洗时间线、打开任何步骤并读取其原始负载。*

除了这些功能之外，还包括结果（允许代理根据评分标准评估自己的工作）、多代理编排、权限策略和 webhook 等功能。了解更多信息，请访问[此处](https://platform.claude.com/docs/en/managed-agents/overview)。

### **客户如今如何在托管代理上构建**

跨行业，客户已经使用 Claude 托管代理在生产中部署代理。以下是一些示例：

*   [Notion](https://claude.com/customers/notion) 在托管代理上运行其自定义代理：团队直接从任务板上将工作分配给 Claude，Claude 获取每个任务相关的文档、会议记录和连接数据，完成的代码、演示文稿和网站被放回工作区以供审查。数十个任务并行运行，他们的团队描述早期原型将大约十二小时的工作转变为二十分钟。
*   [Rakuten](https://claude.com/customers/rakuten) 使用托管代理在产品、销售、市场和财务领域部署了专家代理，每个代理大约在一周内上线。
*   [Sentry](https://claude.com/customers/sentry) 将其 Seer 调试代理与一个编写补丁并开启 PR 的 Claude 代理配对，由一名工程师在数周而非数月内完成。
*   [Asana](https://claude.com/blog/claude-managed-agents) 构建了能够接手项目内任务的人工智能队友，而 [Atlassian](https://claude.com/blog/claude-managed-agents) 则将开发者代理放入 Jira 工作流中。

## **开始使用 Claude 托管代理**

我们构建托管代理的目的是让通过 Claude Code 和 Claude 开发者控制台（位于 [platform.claude.com](http://platform.claude.com)）启动代理变得尽可能简单。例如，控制台的快速入门允许你从一个代理模板开始，或用自然语言描述一个代理，然后将其转化为一个生产就绪的代理，你可以在几分钟内进行安全配置和部署。

*platform.claude.com 上的代理快速入门：从模板开始或描述你想要构建的内容。*

*几步之后：代理已创建，环境已配置，会话已激活。控制台实时流式传输运行过程。*

在 Claude Code 中，默认提供 [/claude-api 技能](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/claude-api-skill)，为 Claude 提供关于如何使用 Claude 托管代理构建应用程序的详细、最新的参考材料。我们强烈建议你利用它来获取设置托管代理应用程序的最佳实践。通过运行 `/claude-api managed-agents-onboard` 开始，它将引导你完成从零开始设置新托管代理的交互式向导。

## **构建托管代理的未来**

随着团队分享他们使用托管代理构建的内容，我们看到他们过去花在生产基础设施上的时间现在用于区分其代理的工作：管理上下文和为用户定制体验。现在，当新模型发布时，你只需更新代理以使用它，重新运行评估，并部署改进，而无需改动底层架构。
