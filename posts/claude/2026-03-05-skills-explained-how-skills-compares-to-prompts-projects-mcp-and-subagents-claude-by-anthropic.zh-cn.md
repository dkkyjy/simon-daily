## **了解您的代理构建模块**

### **什么是技能？**

技能是包含指令、脚本和资源的文件夹，当与任务相关时，Claude 会动态发现并加载它们。可以将它们视为专业培训手册，为 Claude 提供特定领域的专业知识——从处理 Excel 电子表格到遵循您组织的品牌指南。

**技能的工作原理：** 当 Claude 遇到任务时，它会扫描可用的技能以找到相关匹配。技能采用渐进式披露：首先加载元数据（约 100 个 token），仅提供足够的信息让 Claude 判断技能是否相关。完整指令在需要时加载（少于 5k 个 token），捆绑的文件或脚本仅在需要时加载。

**何时使用技能：** 当您需要 Claude 一致且高效地执行专业任务时，请选择技能。它们非常适合：

* **组织工作流：** 品牌指南、合规流程、文档模板
* **领域专业知识：** Excel 公式、PDF 处理、数据分析
* **个人偏好：** 笔记系统、编码模式、研究方法

**示例：** 创建一个[品牌指南技能](https://github.com/anthropics/skills/tree/main/skills/brand-guidelines)，其中包含您公司的调色板、排版规则和布局规范。当 Claude 创建演示文稿或文档时，它会自动应用这些标准，而无需您每次都进行解释。

[了解更多](https://support.claude.com/en/articles/12512176-what-are-skills)关于技能的信息，并查看[我们不断增长的技能库](https://github.com/anthropics/skills)。

### **什么是提示词？**

[提示词](https://docs.claude.com/en/prompt-library/library)是您在对话中以自然语言提供给 Claude 的指令。它们是临时的、对话式的且反应式的——您在当下提供上下文和方向。

**何时使用提示词：** 在以下情况下使用提示词：

* 一次性请求：“总结这篇文章”
* 对话式优化：“让语气更专业一些”
* 即时上下文：“分析这些数据并识别趋势”
* 临时指令：“将其格式化为项目符号列表”

**示例：**

*请对这段代码进行全面的安全审查。我希望您关注：*

*1. 常见漏洞，包括：*

* *注入缺陷（SQL、命令、XSS 等）*
* *身份验证和授权问题*
* *敏感数据泄露*
* *安全配置错误*
* *失效的访问控制*
* *加密失败*
* *输入验证问题*
* *错误处理和日志记录问题*

*2. 对于您发现的每个问题，请提供：*

* *严重级别（严重/高/中/低）*
* *代码中的位置（行号或函数名称）*
* *解释为什么存在安全风险以及如何被利用*
* *具体的修复建议，尽可能提供代码示例*
* *防止类似问题的最佳实践指南*

*3. 代码上下文：[描述代码的功能、语言/框架及其运行环境——例如，“这是一个处理用户身份验证和处理支付数据的 Node.js REST API”]*

*4. 其他考虑因素：*

* *是否存在任何 OWASP Top 10 漏洞？*
* *代码是否遵循 [特定框架/语言] 的安全最佳实践？*
* *是否存在任何具有已知漏洞的依赖项？*

*请按严重性和潜在影响对发现结果进行优先级排序。*

**专业提示：** 提示词是与 Claude 交互的主要方式，但它们不会跨对话持久保存。对于重复的工作流或专业知识，请考虑将提示词捕获为技能或项目指令。

**何时改用技能：** 如果您发现自己多次在不同对话中输入相同的提示词，那么是时候创建一个技能了。将重复出现的指令（如“使用 OWASP 标准审查此代码是否存在安全漏洞”或“将此分析格式化为包含执行摘要、关键发现和建议”）转化为技能。这可以避免您每次都重新解释流程，并确保执行的一致性。

查看我们的[提示词库](https://docs.claude.com/en/prompt-library/library)、[提示词最佳实践](http://claude.com/blog/prompt-engineering-best-practices)或[智能提示词生成器](https://claude.ai/public/artifacts/3796db7e-4ef1-4cab-b70c-d045778f23ec)以开始使用。

### **什么是项目？**

所有付费 Claude 套餐均提供[项目](https://support.claude.com/en/articles/9517075-what-are-projects)功能，它是自包含的工作区，拥有自己的聊天记录和知识库。每个项目包含一个 200K 的上下文窗口，您可以在其中上传文档、提供上下文，并设置适用于该项目内所有对话的自定义指令。

**项目的工作原理：** 您上传到项目知识库的所有内容在该项目的所有聊天中均可用。Claude 会自动使用此上下文来提供更明智、更相关的响应。当您的项目知识接近上下文限制时，Claude 会无缝启用检索增强生成（RAG）模式，将容量扩展至最多 10 倍。

**何时使用项目：** 在以下情况下选择项目：

* **持久上下文：** 应为每次对话提供信息的背景知识
* **工作区组织：** 为不同计划提供独立的上下文
* **团队协作：** 共享知识和对话历史（适用于 Team 和 Enterprise 套餐）
* **自定义指令：** 项目特定的语气、视角或方法

**示例：** 创建一个“Q4 产品发布”项目，包含市场研究、竞争对手分析和产品规格。该项目中的每次聊天都可以访问这些知识，而无需您重新上传或重新解释上下文。

**何时改用技能：** 项目为 Claude 提供特定工作内容的持久上下文——您公司的代码库、研究计划或持续的客户合作。技能则教 Claude 如何做某事。项目可能包含产品发布的所有背景信息，而技能可以教 Claude 您团队的写作标准或代码审查流程。如果您发现自己需要在多个项目中复制相同的指令，这就是创建技能而不是项目的信号。

[了解更多](https://support.claude.com/en/articles/9517075-what-are-projects)关于项目的信息。

### **什么是子代理？**

[子代理](https://docs.claude.com/en/docs/claude-code/sub-agents)是专门的 AI 助手，拥有自己的上下文窗口、自定义系统提示词和特定的工具权限。子代理可在 Claude Code 和 Claude Agent SDK 中使用，它们独立处理离散任务并将结果返回给主代理。

**子代理的工作原理：** 每个子代理都使用自己的配置运行——您定义它做什么、如何处理问题以及可以访问哪些工具。Claude 会根据描述自动将任务委派给适当的子代理，或者您可以明确请求特定的子代理。

**何时使用子代理：** 在以下情况下使用子代理：

* **任务专业化：** 代码审查、测试生成、安全审计
* **上下文管理：** 保持主对话专注，同时将专业工作外包
* **并行处理：** 多个子代理可以同时处理不同方面
* **工具限制：** 将特定子代理限制为安全操作（例如，只读访问）

**示例：**

```
创建一个代码审查子代理，具有 Read、Grep 和 Glob 工具的访问权限，但没有 Write 或 Edit 权限。当您修改代码时，Claude 会自动将此子代理委派给质量和安全审查，而不会冒意外代码更改的风险。
```

**何时改用技能：** 如果多个代理或对话需要相同的专业知识——如安全审查流程或数据分析方法——请创建技能，而不是将该知识构建到各个子代理中。技能是可移植和可重用的，而子代理是为特定工作流而专门构建的。使用技能来传授任何代理都可以应用的专业知识；当您需要具有特定工具权限和上下文隔离的独立任务执行时，请使用子代理。

[了解更多](https://code.claude.com/docs/en/sub-agents)关于子代理的信息。

### **什么是 MCP？**

MCP 在 AI 应用程序与您现有的工具和数据源之间创建了通用连接层。

模型上下文协议（MCP）是一种开放标准，用于将 AI 助手连接到数据所在的外部系统——内容存储库、业务工具、数据库和开发环境。

**MCP 的工作原理：** MCP 提供了一种标准化方式，将 Claude 连接到您的工具和数据源。无需为每个数据源构建自定义集成，您可以针对单一协议进行构建。MCP 服务器公开数据和功能；MCP 客户端（如 Claude）连接到这些服务器。

**何时使用 MCP：** 在以下情况下选择 MCP：

* 访问外部数据：Google Drive、Slack、GitHub、数据库
* 使用业务工具：CRM 系统、项目管理平台
* 连接到开发环境：本地文件、IDE、版本控制
* 与自定义系统集成：您的专有工具和数据源

**示例：** 通过 MCP 将 Claude 连接到您公司的 Google Drive。现在 Claude 可以搜索文档、读取文件并引用内部知识，而无需手动上传——连接会持续存在并自动更新。

**何时改用技能：** MCP 将 Claude 连接到数据；技能教 Claude 如何处理这些数据。如果您在解释*如何*使用工具或遵循流程——如“查询我们的数据库时，始终先按日期范围过滤”或“使用这些特定公式格式化 Excel 报告”——那就是技能。如果您需要 Claude 首先*访问*数据库或 Excel 文件，那就是 MCP。将两者结合使用：MCP 用于连接，技能用于流程知识。

[了解更多](https://www.anthropic.com/news/model-context-protocol)关于 MCP 的信息，并查看[文档](https://modelcontextprotocol.io/docs/develop/build-server)了解如何构建 MCP 服务器。

## **它们如何协同工作**

真正的力量在于将这些构建模块组合起来。每个模块都有其独特用途，而它们共同作用时，便能构建出复杂的智能体工作流。

### **对比：选择合适的工具**

| 特性 | 技能 | 提示词 | 项目 | 子智能体 | MCP |
| --- | --- | --- | --- | --- | --- |
| **提供内容** | 程序性知识 | 即时指令 | 背景知识 | 任务委派 | 工具连接 |
| **持久性** | 跨对话 | 单次对话 | 项目内 | 跨会话 | 持续连接 |
| **包含内容** | 指令 + 代码 + 资源 | 自然语言 | 文档 + 上下文 | 完整智能体逻辑 | 工具定义 |
| **加载时机** | 按需动态加载 | 每轮对话 | 始终在项目中 | 调用时 | 始终可用 |
| **可包含代码** | 是 | 否 | 否 | 是 | 是 |
| **最适合** | 专业专长 | 快速请求 | 集中式上下文 | 专项任务 | 数据访问 |

### **示例智能体工作流：研究智能体**

让我们构建一个综合性的研究智能体，组合多个构建模块。此示例展示如何组装并激活一个用于竞争分析的智能体。

**步骤 1：设置您的项目**

创建一个“竞争情报”项目，并上传：

* 行业报告与市场分析
* 竞品产品文档
* 来自 CRM 的客户反馈
* 以往的研究摘要

添加项目指令：

*从我们产品战略的角度分析竞争对手。重点关注差异化机会和新兴市场趋势。呈现结论时需附上具体证据和可操作的建议。*

**步骤 2：通过 MCP 连接数据源**

为以下内容启用 MCP 服务器：

* Google Drive（用于访问共享研究文档）
* GitHub（用于查看竞品开源代码库）
* 网络搜索（用于获取实时市场信息）

**步骤 3：创建专项技能**

创建一个“竞争分析”技能：

# 我的公司 GDrive 导航技能

## 概述
针对 Meridian Tech 的 Google Drive 结构优化的搜索与检索策略。使用此技能可高效定位内部文档、研究资料和战略材料。

## Drive 组织结构

**顶层结构：**
- `/Strategy & Planning/` - OKR、季度计划、董事会演示文稿
- `/Product/` - PRD、路线图、技术规格
- `/Research/` - 市场研究、竞争情报、用户研究
- `/Sales & Marketing/` - 案例研究、推介演示文稿、营销材料
- `/Customer Success/` - 实施指南、成功指标
- `/Company Ops/` - 政策、组织架构图、团队目录

**命名约定：**
- 格式：`YYYY-MM-DD_文档名称_vX`
- 最终版本标记为 `_FINAL`
- 草稿包含 `_DRAFT` 或 `_WIP`

## 搜索最佳实践

1. **先宽泛，再筛选** - 使用文件夹上下文 + 关键词
2. **定位文档所有者** - 销售材料从 Sales/ 中查找，而非根目录
3. **检查时效性** - 当前战略优先考虑最近 6 个月的文档
4. **寻找“权威来源”** - 带有 `_FINAL`、`_APPROVED` 标记的文件，或位于 `/Archives/Official/` 中的文件

## 研究代理工作流程

1. 确定主题类别（产品、市场、客户）
2. 使用针对性关键词搜索相关文件夹
3. 检索 3-5 份最新/最相关的文档
4. 与 `/Strategy & Planning/` 交叉参考以获取上下文
5. 引用来源时注明文件名和日期
```

**第 4 步：配置子代理（仅限 Claude Code/SDK）**

创建专门的子代理：

`market-researcher` 子代理：

```

2. 收集定量数据（市场份额、增长率、融资情况）
3. 分析定性洞察（分析师观点、客户评价）

呈现结论时附上引用来源和置信度。
```

`technical-analyst` 子代理：

```

---
你是一名分析竞争对手技术选择的技术架构师。

分析时：
1. 审查公开代码仓库和技术文档
2. 评估架构模式和技术栈
3. 评估可扩展性和性能方案
4. 识别技术优势和局限性

```

**第 5 步：激活你的研究代理**

现在当你询问 Claude：“分析我们排名前三的竞争对手如何定位他们的新 AI 功能，并找出我们可以利用的差距”

以下是发生的过程：

1. **项目上下文加载**：Claude 访问你上传的研究文档并遵循项目指令
2. **MCP 连接激活**：Claude 搜索你的 Google Drive 获取最近的竞争对手简报，并拉取 GitHub 数据
3. **技能启用**：竞争分析技能提供分析框架
4. **子代理执行**（在 Claude Code 中）：market-researcher 收集行业数据，而 technical-analyst 审查技术实现
5. **提示词优化**：你提供对话式指导：“特别关注医疗保健领域的企业客户”

**结果：** 一份全面的竞争分析，从多个数据源提取信息，遵循你的分析框架，利用专业知识，并在整个研究项目中保持上下文。

## **常见问题**

#### **技能如何工作？**

技能使用[渐进式披露](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)来保持 Claude 的高效性。处理任务时，Claude 首先扫描技能元数据（描述和摘要）以识别相关匹配。如果技能匹配，Claude 加载完整指令。最后，如果技能包含可执行代码或参考文件，这些仅在需要时加载。

这种架构意味着你可以拥有许多技能而不会压垮 Claude 的上下文窗口。Claude 在需要时精确访问所需内容。

#### **技能与子代理：何时使用什么**

**使用技能的场景：** 当你需要任何 Claude 实例都能加载和使用的能力时。技能就像培训材料——它们让 Claude 在特定任务上表现更好，适用于所有对话。

**使用子代理的场景：** 当你需要完整的、自包含的代理，专门用于特定目的，能独立处理工作流时。子代理就像拥有自己的上下文和工具权限的专业员工。

**同时使用的场景：** 当你需要具有专业知识的子代理时。例如，代码审查子代理可以使用特定语言最佳实践的技能，将子代理的独立性与技能的可移植专业知识相结合。

#### **技能与提示词：何时使用什么**

**使用提示词的场景：** 当你给出一次性指令、提供即时上下文或进行对话式交流时。提示词是响应式的、短暂的。

**使用技能的场景：** 当你拥有需要反复使用的程序或专业知识时。技能是主动式的——Claude 知道何时应用它们——并且在对话之间持续存在。

**同时使用：** 提示词和技能自然互补。使用技能提供基础专业知识，然后使用提示词为每个任务提供特定上下文和细化。

#### **技能与项目：何时使用什么**

**使用项目的场景：** 当你需要背景知识和上下文，这些应告知关于特定倡议的所有对话时。项目提供始终加载的静态参考材料。

**使用技能的场景：** 当你需要仅在相关时激活的程序知识和可执行代码时。技能提供按需加载的动态专业知识，节省你的上下文窗口。

**同时使用的场景：** 当你既需要持久上下文又需要专业能力时。例如，一个包含产品规格和用户研究的“产品开发”项目，结合用于创建技术文档和分析用户反馈数据的技能。

**关键区别：** 项目说“这是你需要知道的”。技能说“这是做事的方法”。项目提供你工作的知识库。技能提供在任何地方都能工作的能力——任何对话、任何项目。

#### **子代理可以使用技能吗？**

可以。在 Claude Code 和 Agent SDK 中，子代理可以像主代理一样访问和使用技能。这创造了强大的组合，让专业子代理利用可移植的专业知识。

例如，你的 python-developer 子代理可以使用 pandas-analysis 技能按照你团队的约定执行数据转换，而你的 documentation-writer 子代理使用技术写作技能来一致地格式化 API 文档。
