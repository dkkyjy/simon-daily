# Anthropic 网络安全团队如何借助 Claude Code 构建威胁检测平台

            **日期：** 2026-05-12 00:00 UTC
            **链接：** https://claude.com/blog/how-anthropic-uses-claude-cybersecurity

            ---

            在她的整个职业生涯中，Jackie Bow 一直梦想着能构建这样的工具：它们可以获取真正重要的上下文——不仅仅是日志和警报，还包括 Slack 对话、内部文档和机构知识，这些信息能告诉你某个事件是真正的威胁还是噪音——而无需人工承担手动梳理数据的负担。

当她加入 Anthropic 时，她终于有机会与 Claude 合作构建这些工具。Jackie 领导 Anthropic 的检测平台工程团队，该团队专注于防御性网络安全：检测威胁并响应潜在的入侵，而不是探测漏洞。这项工作涉及监控系统中的可疑活动、对安全警报进行分类，以及在异常事件演变为安全事故之前进行调查。

对于一家构建日益强大 AI 模型的公司来说，这项工作是基础性的。[Anthropic 的责任扩展政策](https://www.anthropic.com/news/anthropics-responsible-scaling-policy) 将产品发布直接与安全承诺挂钩，这意味着 Bow 的团队有助于决定公司可以安全发布哪些产品。

"我感觉这是安全工程师的黄金时代，"担任 Anthropic 检测平台工程团队技术负责人的 Bow 说道。"我终于可以构建我一直梦寐以求的工具了。"

## **问题：淹没在数据和警报中**

安全负责人对这一模式再熟悉不过了。

警报触发。分析师打开终端，开始熟悉的例行操作：在五六个不同的工具之间来回切换，每个工具都需要自己的查询语言和思维模式。他们必须在多个平台上保持专业能力，同时不断在不同界面和查询语法之间进行上下文切换。

每次调查都变成了一次数据考古，将分散在互不关联系统中的碎片信息拼凑起来。对于大多数团队来说，简单的调查需要耗费数小时，而复杂的调查可能持续数天。

"一个人一天能处理的警报数量是有限的，超过这个限度，他们深入调查的细致程度就会开始下降，"Jackie 解释道。

她的团队决定对此采取行动。他们问自己：什么在消耗我们的精力？什么工作感觉重复？什么阻碍了我们从事有影响力的工作？

答案很明确。警报分类可能会耗费数小时，然后分析师才能确定威胁是否真实。跨互不关联系统的手动关联拖慢了所有工作。而不同查询语言和界面之间的持续上下文切换造成了认知负担，这种负担会随着一天的工作而不断累积。

随着公司的发展，攻击面也在扩大，对安全团队的要求也在增加。

"如果不借助像 Claude 这样的工具来增强能力，我们就无法扩展以满足 Anthropic 的需求，"Jackie 说。

## **解决方案：Claude 查找证据（CLUE）**

在几个月的时间里，Bow 的团队构建了 CLUE，这是一个检测和响应平台，重新构想了安全团队调查威胁的方式。CLUE 并非在现有工具栈中增加另一个仪表板，而是提供了一个由 Claude 驱动的自然语言界面，通过工具使用直接连接到 Anthropic 的内部系统。

使用 Claude Code 构建 CLUE 将传统的软件开发时间线呈指数级压缩，使他们能够在处理日常工作的同时构建这个系统。Bow 的团队在一天内就完成了概念验证。设计文档、开发步骤和实现在一周内完成。

"我们构建的大部分内容都是通过与 Claude Code 对话完成的，"Jackie 回忆道。"它既是设计伙伴，也是协作者。"

改变她看法的时刻发生在她要求 Claude Code 在 CLUE 界面中添加一个按钮时。她本以为会经历 JavaScript 框架和 CSS 调试的繁琐过程。Claude Code 立即实现了这个功能，而且做得比她本人还要好。

"那时我意识到，我不再受自身技术局限的束缚了。我能构建任何我能想到的东西，"她说。

### **CLUE 分类**

当警报涌入时，CLUE 分类会在人类分析师看到它们之前执行初步分类。Claude 使用工具从 Anthropic 的各个系统中获取额外上下文来丰富每个警报，这些系统包括 Slack 消息、内部文档、代码仓库和数据仓库。它会分配处置结果：误报、真阳性、恶意或预期行为。每个警报都会获得一个置信度分数，以便分析师知道应该将注意力集中在哪里。

这个信息丰富步骤解决了一个任何安全分析师都认识的问题：警报作为孤立的信号到达。一次失败的登录尝试。一次异常的 API 调用。一次配置变更。没有上下文，这些事件只是噪音。有了上下文（用户是谁、他们在做什么、这是否符合他们团队的模式），清晰的信号就会浮现出来。

"内部上下文是缺失的那一块拼图，它确实有助于根据你的环境来对警报进行上下文化，"Jackie 解释道。

### **CLUE 调查**

借助 CLUE，安全分析师现在可以使用自然语言查询所有安全关键日志。想知道"过去一天内该系统所有失败的登录尝试有哪些？"只需询问 CLUE，Claude 就会执行必要的 SQL 查询。

"Claude 在编写精确查询方面比人类强得多，"Jackie 说。该工具运行一个代理循环：一个编排器向子代理发出命令，这些子代理并行执行查询、收集发现，并将结果综合成连贯的调查摘要。原本需要数小时手动关联工作的事情，现在在三到四分钟内就能完成。

数据证实了这一点。在调查过程中，CLUE 平均每次会话进行 25 次工具调用和近 11 次查询——远远超过分析师能够合理手动执行的次数，而且精度更高。这些工具调用中的每一次，否则都需要打开单独的控制台或切换到不同的界面。

然而，真正的差异化因素在于内部上下文。CLUE 通过工具直接连接到 Anthropic 的系统，使 Claude 能够访问外部安全平台永远无法获取的机构知识。当警报触发时，Claude 可以检查 Slack 以了解团队是否讨论过计划内的维护。它可以查询数据仓库以了解基线行为。它可以检查代码仓库以了解某个服务实际是做什么的。

### **数据治理审查**

该团队通过一个常见的数据治理场景展示了 CLUE 的能力：检查在过去两个月内，是否有三名合同工访问了他们不应该访问的任何文档。

据 Bow 称，这类调查通常需要至少半天的手动工作，包括查询访问日志、交叉引用权限以及审查文档分类。借助 CLUE，Claude 读取请求，制定计划，并生成详细的查询，从而抽象掉技术复杂性。调查在几分钟内完成，生成一份摘要和建议，并且所运行的每个查询都完全透明。

## **衡量影响**

当团队着手构建 CLUE 时，他们不仅想了解它是否感觉更快，还想知道他们能否量化结果。

**更少的误报**：在 CLUE 分类之前，大约三分之一的警报最终被证明是误报。这一比率已降至 7%，这意味着分析师将时间花在重要的信号上。*

**更广的覆盖范围**：也许比速度更重要的是团队现在能够检查的内容。在 CLUE 之前，低置信度信号因为时间不够而未被检查。现在，CLUE 分类会处理每一个传入的警报并进行信息丰富，而批量处理则处理数千个以前在仪表板中只是噪音的信号。

**规模化的时间节省**：基于 30 天的使用数据，CLUE 自动化了大约 12,000 次查询和 27,000 次工具调用——这些工作如果手动完成，估计需要 1,870 小时（234 人天）。这相当于相比手动分类节省了 5-10 倍的时间。*

**他们仍在学习衡量的内容**：准确性比速度更难量化。团队会审查 CLUE 的处置结果并跟踪分歧，但他们仍在构建反馈循环，以了解 Claude 捕捉到分析师可能会遗漏的内容的频率——反之亦然。记录文本对此有所帮助：每次调查都可以被审计，以了解 Claude 究竟检查了什么以及它是如何得出结论的。

## **未来方向：让 Claude 像 Claude 一样进行调查**

在 AI 研究中有一个概念叫做"[苦涩的教训](http://www.incompleteideas.net/IncIdeas/BitterLesson.html)"——这个观察结果是，将人类特定的推理编码到模型中，其表现始终不如赋予模型通用能力并让它们自己找到方法。Bow 和她的团队一直在思考这对检测和响应意味着什么。

"在 CLUE 开发的早期，团队曾就应在多大程度上限制 Claude 的调查路径进行过辩论，"Bow 说。"SOAR 时代的本能反应是：构建剧本，定义每一步，使过程具有确定性。但我们不断注意到一些事情。当我们给 Claude 探索的自由度——访问工具和一个目标，而不是一套僵化的流程——它常常会走我们不会预设的调查路径。有时这些路径会揭示我们可能会错过的上下文。"

关键在于给 Claude 设定边界（它可以使用的工具，它可以访问的数据），同时保持策略的开放性。这一见解塑造了他们下一步将 CLUE 带向何方。

**从被动到主动**：今天，CLUE 响应警报。事件触发，Claude 进行调查。但该架构支持更雄心勃勃的目标：持续探索。与其等待检测规则触发，Claude 代理可以主动寻找可疑模式——与团队编写的任何规则都不匹配的异常，单独看起来正常但整体来看不寻常的行为。

**从自身学习**：团队存储每一次调查的记录文本。这个语料库正在成为一个知识库，Claude 可以查询它以了解过去调查是如何展开的模式。随着时间的推移，CLUE 会发展出任何人类分析师都无法维持的组织记忆。

**拥抱非确定性**：传统安全工具将不一致视为错误。CLUE 将其视为一个特性。同一个警报可能在不同的日子以不同的方式被调查，这没问题——有时第二条路径会发现第一条路径遗漏的东西。该团队正在试验并行运行多种调查策略并比较结果。

"安全运营的苦涩教训是什么？我们花了多年时间构建编码了人类如何调查的系统。下一代工具应该赋予模型调查的能力，并让它们找到比我们可能预设的更好的方法，"Bow 补充道。
