# ONE SENTENCE SUMMARY:
从单智能体协作转向多智能体编排，通过子代理、代理团队和质量门控实现异步并行编码，将开发者从指挥者转变为工厂管理者。

# MAIN POINTS:
1. 开发者正从与单一AI配对转向管理整个智能体团队。
2. 单一智能体面临上下文过载、无专长和无协调三大限制。
3. 多智能体通过并行性、专长化、隔离和复合学习实现乘法效应。
4. 子代理模式是最简单的多智能体入门方式，需手动管理依赖图。
5. 代理团队提供共享任务列表、对等消息和文件锁定等协调原语。
6. 3-5名团队成员是并行协作的最佳规模。
7. 计划审批、钩子检查和AGENTS.md是三大关键质量门控。
8. 验证已成为瓶颈，而非代码生成。
9. Ralph Loop模式通过小原子任务和上下文重置实现持续交付。
10. 高质量规格说明是编排五十个并行代理的最大杠杆。

# TAKEAWAYS:
1. 从子代理开始，逐步升级到代理团队，最后叠加质量门控。
2. 使用计划审批在代码存在前发现架构问题，比修复坏代码成本更低。
3. 仅使用人工编写的AGENTS.md文件，AI生成的规则会降低成功率。
4. 设置WIP限制，不要运行超过你能够有效审查的代理数量。
5. 将判断权留给自己，只将可评估的明确任务委托给代理。
