# ONE SENTENCE SUMMARY
智能体的表现取决于模型与围绕其构建的“脚手架”（Harness）的协同设计，而非仅依赖模型本身。

# MAIN POINTS
1. 编码智能体 = AI模型 + 脚手架（Harness）。
2. 优秀的模型配合优秀的脚手架胜过优秀的模型配合糟糕的脚手架。
3. 每次智能体犯错都应成为永久性规则，防止同类错误再次发生。
4. 上下文腐烂会降低模型推理能力，需通过压缩和卸载来缓解。
5. 文件系统和Git是智能体持久化状态与协作的基础。
6. 钩子（Hooks）是强制执行层，确保系统而非提示词来约束行为。
7. 规划器/生成器/评估器分离模式优于模型自我评估。
8. 沙箱为智能体提供隔离执行环境，支持并行与安全操作。
9. AGENTS.md文件是最高杠杆率的配置点，每条规则需源自实际失败。
10. 随着模型改进，脚手架空间不会缩小，而是向更复杂任务移动。

# TAKEAWAYS
1. 将智能体每次失败视为永久性信号，持续迭代优化脚手架配置。
2. 优先设计工具、提示词和反馈循环，而非等待更强模型发布。
3. 保持AGENTS.md简短精炼，每条规则必须追溯至具体失败案例。
4. 使用钩子实现静默成功、详细失败，自动注入错误信息供模型修正。
5. 选择脚手架框架而非从零构建，聚焦领域特定提示词和工具设计。
