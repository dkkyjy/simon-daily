# ONE SENTENCE SUMMARY
代码审查已从检查人类推理转变为重建AI意图，成为软件工程中最具杠杆价值的技能。

# MAIN POINTS
1. AI生成代码速度远超人类阅读速度，瓶颈从编写转向验证。
2. 2026年数据显示AI使代码产出增加4倍，但交付价值仅增12%。
3. 代码流失率上升861%，缺陷率从9%飙升至54%。
4. 无审查合并的PR增加31.3%，成熟团队同样受冲击。
5. AI代码的问题率是人工代码的1.7倍，安全漏洞高1.5-2倍。
6. 审查工作量取决于影响半径、代码寿命和团队规模。
7. 四种AI审查工具从未同时标记同一行代码，多样性至关重要。
8. 人类应从"在循环中"升级为"在循环上"，抽样审计而非逐行审查。
9. 要求PR附带证据：变更目的、测试输出和实际运行证明。
10. 理解代码的成本从未降低，审查能力是未来团队的核心竞争力。

# TAKEAWAYS
1. 按风险分层审查，高风险变更需全栈验证，低风险变更可自动化处理。
2. 运行两种不同架构的AI审查工具，利用其互补性捕获更多缺陷。
3. 强制PR保持小规模，指导AI生成可读的增量提交而非庞大变更。
4. 仔细审查测试修改，警惕AI为通过测试而改写断言的模式。
5. 人类必须拥有合并权限，将AI审查视为传感器而非最终裁决。
