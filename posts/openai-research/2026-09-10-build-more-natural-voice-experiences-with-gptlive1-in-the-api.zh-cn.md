# 通过 API 中的 GPT‑Live‑1 打造更自然的语音体验

**日期：** 2026-09-10 00:00 UTC
**链接：** https://openai.com/zh-Hans-CN/index/introducing-gpt-live-1-in-the-api/

GPT‑Live‑1 将自然的全双工语音对话带入 API，具备更强的指令遵循能力、自定义语音和电话支持。"

GPT‑Live‑1 将 ChatGPT 自然的全双工对话能力带入 API，让开发者对语音智能体的表达和行为拥有更多控制权。"

Vimeo 上 Yelp 用户证言 1225436485 的当前封面图。"

我们正通过 API 推出 GPT‑Live‑1，为开发者提供一个强大而自然的语音模型，用于构建语音应用和企业工作流。

在 GPT‑Live‑1 的 API 版本中，我们聚焦于让开发者能够围绕用户、工作流和目标来引导和定制语音体验的全新能力。

GPT‑Live‑1 的一项核心优势——流畅的打断处理——已在早期评估中展现出业务价值：Speak 发现，GPT‑Live‑1 为学习者提供了更多思考时间，语言导师的回应更加从容，与以往的基于轮次的系统相比，打断率降低了近 80%。"

通过单一模型对输入和输出音频进行联合推理来改善打断处理，避免了级联 STT–LLM–TTS 架构带来的延迟和脆弱的交接问题。"

GPT‑Live‑1 可将推理和工具调用委托给 GPT‑6 Astra 等后端文本模型或第三方模型。"

让开发者通过系统提示词来塑造智能体的语气、语速和对话风格。"

更好地处理背景噪声和静默，不会打断对话，也不会将每个步骤都大声叙述出来。"

在长时间交互中提升上下文保持能力和对话质量。"

支持将全双工语音智能体部署到电话场景中，从餐厅预订到客户支持均可覆盖。"

Yelp Host 借助 GPT-Live-1 无缝完成预订，同时处理背景噪声、旁侧对话和打断。"

传统语音智能体将语音转文本、推理模型和文本转语音拼接在一起。

每次交接都会增加延迟，并带来更多丢失时序、上下文或对话自然节奏的风险。

GPT‑Live‑1 在单一模型中同时处理聆听和说话，简化了语音层。

这使得对话可以继续进行，而后台工作同步完成。"

与我们的级联架构相比，GPT-Live-1 将代码库精简了 80%，减少了 23,000 行代码。

这让我们实现了自然、实时的患者对话，也让团队得以从预约到护理流程的全链路优化体验。"

开发者可以选择对话背后的模型、工具和智能体框架。

例如，他们可以将 GPT‑Live‑1 与 Luna 等模型搭配用于日程安排或订单更新等高并发任务，并使用 Astra 等模型处理需要推理能力的复杂客户问题。

这种灵活性让开发者能够根据每项任务匹配推理深度、速度和成本。"

GPT‑Live‑1 原生提供 ASR 转写文本和回复文本。

它还具备强大的字母数字识别能力，并支持关键词偏置。

虽然 GPT‑Live‑1 并非基于轮次的模型，但它原生支持轮次检测，因此开发者仍可围绕明确的轮次边界进行构建。"

在我们的各项评估中，GPT‑Live‑1 将全双工基准测试（Full Duplex Bench）性能较 GPT‑Realtime‑2 提升了 30 个百分点。

搭配 GPT‑6 Astra 在中等推理强度下，它在 Tau3 上排名榜首，该基准衡量的是端到端任务中的前沿语音智能体智能水平。"
