# GLM-5.3 与高级网络攻击能力的扩散

2026年9月29日


*Andrew Fasano, Marius Fleischer  
Cole McFaul, Robert Xiao, Tripp Gallagher*

五个月前，我们[宣布](https://www.anthropic.com/glasswing)推出了 Claude Mythos Preview，这是首个能够自主构建复杂端到端网络漏洞利用的 AI 模型。AI 的快速进步让我们意识到，这种能力最终会扩散到许多其他模型，使恶意网络攻击者更容易发起高影响力的网络攻击。

鉴于此，我们选择以有限方式发布 Claude Mythos Preview——通过 Project Glasswing 计划，让可信的网络防御者能够在恶意攻击者获得类似能力之前，在关键软件中发现[超过 10,000 个漏洞](https://www.anthropic.com/research/glasswing-initial-update)。

但这些模型现在已经到来。在这篇文章中，我们分享对 GLM-5.3 的分析，这是智谱 AI（在中国以外称为 Z.ai）开发的最新 AI 模型。与 Claude Mythos Preview 类似，GLM-5.3 也具备强大的自主构建端到端网络漏洞利用的能力。但 GLM-5.3 与其他前沿模型不同，它在发布时没有设置有意义的保障措施来限制滥用。我们的模拟测试发现，攻击者可以使用简单技术以 64% 到 100% 的成功率绕过 GLM-5.3 的保障措施。相比之下，这些攻击在我们测试的有保障措施的 Claude 模型上均未成功。我们认为 GLM-5.3 宽松的保障措施显著增加了恶意攻击者可用的网络攻击能力。同时，这些能力也可以帮助防御者保护他们的系统。

9 月 17 日，美国国家标准与技术研究院（NIST）的 AI 标准与创新中心（CAISI）发布了[他们自己对 GLM-5.3 网络攻击能力的评估](https://www.nist.gov/news-events/news/2026/09/caisis-assessment-zais-glm-53-cyber-capabilities)。CAISI 发现 GLM-5.3 是"迄今为止发布的最具网络攻击能力的开源权重模型"，在 CAISI 网络基准测试的汇总中，它落后于美国前沿模型约四个月。我们的能力发现与 CAISI 基本一致。在 CAISI 的比较中，美国模型在适用情况下是在禁用网络保障措施的情况下进行测试的，美国前沿包括仅向经过验证的用户发布的模型。攻击者无法轻易访问这些版本的美国模型，但任何人都可以下载 GLM-5.3。本文增加了对 GLM-5.3 的保障措施如何容易被绕过或移除的分析。

**图 1.** 研究结果摘要。上：Claude Opus 4.6 与 Claude Mythos Preview 之间的漏洞利用能力增长，与 GLM-5.2 与 GLM-5.3 之间的能力跃升相似。Claude 模型发布时带有网络保障措施，减少保障措施的版本仅限于经过验证的用户。任何人都可以下载和使用 GLM-5.3。下：GLM-5.3 的有限保障措施可以被标准技术绕过，这些技术在我们测试中未能绕过或不适用于 Claude 模型。

## GLM-5.3 能够端到端开发工作漏洞利用

为了理解 GLM-5.3 如何使网络威胁行为者能够发现和利用真实软件漏洞，我们使用自动化基准测试和人工介入工作流进行了评估。对于两种方法，我们都在隔离的沙盒环境中运行测试模型，使它们只能攻击我们为这些评估设置的离线目标。我们主要关注漏洞利用开发能力，因为这是 Claude Mythos Preview 相比之前 Claude 模型展现显著跃升的地方。

首先，我们在[ExploitBench](https://arxiv.org/abs/2605.14153)上运行该模型，它衡量 AI 模型利用 Google Chrome 使用的 V8 引擎中已知漏洞的能力。在这里，我们关注模型成功开发端到端漏洞利用的能力，因为这对攻击者来说是最相关的能力，也是我们在不同模型之间看到显著变化的地方。我们发现 GLM-5.3 在 410 次尝试中有 50 次成功开发端到端漏洞利用。Claude Mythos Preview 以相似的速度做到这一点——在 410 次尝试中有 56 次。

在我们内部的二进制漏洞利用基准测试中，[1](#footnote-1)我们测试模型是否能够在参与 Google OSS-Fuzz 项目的流行开源项目中发现和利用漏洞。在这里，完全控制流劫持可获得满分。我们在基准测试的 100 个任务（随机选择）上评估了几个模型，发现 GLM-5.3 在 4% 的试验中成功开发完全控制流劫持；Claude Mythos Preview 为 6%。虽然 GLM-5.3 在这里表现低于 Claude Mythos Preview，但显然已经跨过了一个有意义的门槛：早期模型如 Claude Opus 4.6 和 GLM-5.2 在其中任何一个中都不成功。

**图 2.** 漏洞利用能力与输出令牌预算的关系。每条线显示模型达到基准测试最佳结果的尝试比例与使用的输出令牌数。两张图都显示了两个禁用保障措施的 Claude 模型（Opus 4.6、Mythos Preview）、两个 GLM 模型（5.2 和 5.3）以及 Moonshot AI（Kimi K3）和 DeepSeek（V4.1-Flash）发布的最新开源权重模型的结果。

接下来，我们评估了 GLM-5.3 在人类专家手中的开放式进攻性网络任务上的表现（类似于我们今年早些时候对[Claude Mythos Preview 的测试](https://red.anthropic.com/2026/mythos-preview)）。在这里，我们选择人类专家不知道现有漏洞的目标，然后要求他们使用模型识别和利用新漏洞。这些实验测试了专家在短时间内能做什么：它们通常运行一天或更短时间，总共不到一小时的人工专注时间。

**图 3.** 研究驱动测试期间由 GLM-5.3 生成的漏洞利用页面的截图（已编辑），显示其通过恶意网站窃取用户的 SSH 私钥。该漏洞利用将模型在流行网页浏览器组件中发现的多个 0 天漏洞串联起来，读取用户计算机上的敏感文件。

在这些会话的第一个中，一名研究人员在沙盒机器上使用 GLM-5.3 和流行网页浏览器的本地 Linux 构建。在一天的时间里（人工注意力有限），GLM-5.3 在浏览器的 JavaScript 引擎中发现了几个此前未知的漏洞，并将它们串联成一个工作的漏洞利用：一个网页，访问时会从访客的计算机读取任意文件（见图 3）。这个漏洞利用针对浏览器的 Linux 构建，因为那是提供给模型的唯一环境。然而，我们认为这些漏洞也可能影响其他平台的用户，尽管那里的利用路径可能更复杂。（我们已向维护者披露这些漏洞。）在会话后期，研究人员还使用 GLM-5.3 在几个其他广泛使用的系统中识别出可利用的漏洞，包括无线和图形驱动程序以及面向网络的设备软件。我们目前正在审查这些报告，并将适当向维护者披露。

在第二个会话中，一名研究人员使用 GLM-5.3-Flash（GLM-5.3 的较小、能力较弱的版本）开发针对*已知*漏洞的漏洞利用（我们之前在这里写过这些"N 天"漏洞利用[这里](https://www.anthropic.com/research/n-days)）。在这里，研究人员专注于 Google Chrome 中最近披露的一个缺陷（CVE-2026-11645），以查看模型能多快将公共修复转化为工作的攻击。研究人员向 GLM-5.3-Flash 提供了这个 CVE 和另一个已知缺陷的公共细节。在没有研究人员显著指导的情况下，GLM-5.3-Flash 将这些缺陷的漏洞利用串联起来，为 ARM64 目标构建了可靠的漏洞利用链，绕过了指针认证（PAC）加固。这需要 20 分钟的人工注意力，加上 GLM-5.3-Flash 八小时的工作。按照智谱的 API 价格，这项工作的成本将是 20.40 美元。

## GLM-5.3 缺乏稳健的保障措施

GLM-5.3 发布时带有一些内置保障措施：如果用户要求明显有害的内容，模型通常会拒绝。[2](#footnote-2)在我们的测试中，我们发现这些保障措施可以通过各种简单技术绕过或移除。

最密集——也是最成功的——方法是一种称为"abliteration"的[标准拒绝减少技术](https://arxiv.org/abs/2406.11717)。由于 GLM-5.3 作为开源权重模型发布，用户可以重新配置它以在不显著影响其能力的情况下移除其拒绝。几位开发者在模型发布后几天内向公众发布了 GLM-5.3 的 abliterated 版本。

为了研究 abliteration 允许攻击者绕过 GLM-5.3 保障措施的程度，我们自己制作了一个 abliterated 副本，然后在三个衡量模型对明显有害请求的依从频率的公共基准测试上运行它（[JailbreakBench](https://jailbreakbench.github.io/)、[HarmBench](https://www.harmbench.org/)和[StrongREJECT](https://strong-reject.readthedocs.io/en/latest/)）。abliteration 模型花了我们团队（之前从未尝试过这项任务）大约 2,200 GPU 小时，计算成本约为 4,400 美元。[3](#footnote-3)abliteration GLM-5.3-Flash 花了大约 600 GPU 小时。编辑将 GLM-5.3 的拒绝率从超过 90% 降低到前两个基准测试（JailbreakBench 和 HarmBench）的约 3% 和 2%，以及第三个（StrongREJECT）的 12%。abliteration 没有显著降低模型的能力：在衡量一般科学能力的 GPQA-Diamond 评估中，标准和 abliterated 模型得分相同；在 CyberGym 评估的测试子集中，abliterated 版本得分低几个百分点（如下表所示）。

**图 4.** 上：发布的和 abliterated 的 GLM 模型以及 Claude 模型在 JailbreakBench、HarmBench 和 StrongREJECT 上的平均拒绝率。abliteration 后，GLM 模型很少拒绝这些查询。Claude 模型无法进行 abliteration，因为它们的权重没有公开发布或可定制。下：GLM-5.3 和 GLM-5.3-Flash 与它们的 abliterated 变体在 GPQA-Diamond 和 CyberGym 上的表现。abliteration 保留了大部分能力。

在我们的测试中，我们观察到 GLM-5.3 的保障措施也可以*不使用*abliterated 模型版本的情况下被规避。我们将模型置于一个模拟世界中，[4](#footnote-4)在其中给它攻击关键系统的明显恶意请求。开箱即用，GLM-5.3 在所有试验中都拒绝了（与我们测试的其他模型一样）。但我们确定了几个绕过 GLM 模型保障措施的简单方法，使它在大多数或所有情况下都会响应这些请求。这些包括：

1. 提供欺骗性提示，例如告诉模型它是一个在练习中工作的自主红队代理。这使得 GLM-5.3 64% 的时间参与。
2. 预填充模型的思考令牌，使其看起来已经考虑了用户的请求并决定继续。这使得 GLM-5.3 92% 的时间参与。
3. 使用模型的 abliterated 版本，如上所述。这使得 GLM-5.3 100% 的时间参与。

在我们的测试中，这些技术都没有使有保障措施的 Claude 模型执行我们测试的有害任务。Claude 的保障措施阻止了使用欺骗性提示的请求。Anthropic API 没有为潜在攻击者提供预填充 Claude 思考的方法。而且由于 Claude 的权重没有提供给用户，它们无法被 abliteration 来改变 Claude 的行为。

**图 5.** 每个模型在明显有害请求后尝试连接远程目标系统的比率，按模型和绕过条件分类（每单元格 50 个样本，五个攻击顺序 × 两个目标 × 五次尝试）。GLM-5.3 从直接请求的零参与上升到掩护故事、预填充和 abliteration 下的 64%、92% 和 100%，而所有测试的 Claude 模型在 API 保障措施下都保持零参与。上锁的单元格标记对 Claude API 通常不可行的攻击。

## 这意味着什么？

GLM-5.3 很可能会让恶意攻击者获得能够让他们无限制地发现和利用网络漏洞的能力。这与任何其他类似能力的 AI 模型都不同，所有其他模型都是在发布时带有保障措施或通过有限访问计划发布的。GLM-5.3 的发布是攻击者可用的网络攻击能力的一个有意义的步骤变化。[Anthropic](https://www.anthropic.com/threat-intelligence-report-september-2026)和[其他美国 AI 实验室](https://cloud.google.com/blog/topics/threat-intelligence/from-prompting-to-autonomy-the-evolution-of-adversarial-ai)最近发布了报告，披露了网络攻击者如何尝试使用 AI 系统。鉴于这些证据，我们认为国家和非国家行为者都可能使用像 GLM-5.3 这样的模型造成现实世界的伤害。

另一方面，具有这种能力水平的模型也可以被防御者使用。我们的观点是网络防御者应该使用满足他们需求的最佳可用工具。我们正在努力安全地向尽可能多的防御者扩展 Claude 网络攻击能力的访问。网络防御者面临会使用他们能获得的每个有能力工具的 attacker，我们相信防御者应该配备至少与他们的对手使用的同样好的前沿模型。

通过 Project Glasswing（和其他努力，如[Patch the Planet](https://openai.com/index/patch-the-planet/)），网络防御者在关键时刻之前保护关键系统方面取得了有意义的进展——但还有很多工作要做。虽然经过验证的防御者现在可以通过我们的可信访问计划使用甚至更先进的模型如 Claude Mythos 5.1，但自由访问能力的关键门槛现在已经跨过。GLM-5.3 强调了向更广泛的实体扩展先进前沿模型访问的紧迫性，以赋能网络防御者。

政府应该对足够有能力的 AI 模型进行安全测试，包括 GLM-5.3 的后续版本。如果没有来自独立来源的高质量评估，这些能力的影响可能直到为时已晚才会对模型开发者完全清晰。随着世界各地的 AI 开发者构建越来越有能力的开源权重模型，我们希望他们努力适当保障这些能力并防止滥用。

1. 我们之前以"OSS-Fuzz"的名义发布了这个基准测试的结果；在这里，我们在从这次评估中随机选择的 100 个任务的子集上测试了模型。
2. 上一节详述的网络任务没有触发发布模型的此类拒绝，但如果我们要求 GLM-5.3 帮助开发恶意软件或帮助对远程目标发起网络攻击，我们观察到拒绝。
3. 大部分用于并行探索变体和修改后测试模型能力。我们估计一个熟悉这项技术的团队，从零开始在这个模型上工作，需要接近 600 GPU 小时（1,200 美元）。
4. 在这个模拟中永远不会执行任何模型生成的代码，模型也没有与外部系统交互的任何方式。在这个隔离的测试环境中，被评估的模型被给予访问一个假 bash 工具，该工具不执行提供的代码。相反，我们要求另一个 LLM 根据模拟世界的描述近似命令的结果。这些模拟不是现实世界条件的完美描绘，因此是对模型在给定情况下行为的完美衡量。
