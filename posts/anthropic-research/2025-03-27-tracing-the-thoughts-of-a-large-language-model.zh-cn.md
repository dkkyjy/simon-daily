# 追溯大型语言模型的思维过程

**日期：** 2025-03-27 00:00 UTC  
**链接：** https://www.anthropic.com/research/tracing-thoughts-language-model  
**标签：** 可解释性  

---

像 Claude 这样的语言模型并非由人类直接编程——相反，它们是在大量数据上进行训练的。在训练过程中，模型会学习自己的策略来解决问题。这些策略被编码在模型为写出的每一个词所执行的数十亿次计算中。对我们这些模型开发者来说，它们难以理解。这意味着我们并不了解模型是如何完成它们所做的绝大多数事情的。

了解像 Claude 这样的模型是如何*思考*的，将使我们能够更好地理解它们的能力，同时也有助于确保它们正在按照我们的意图行事。例如：

* Claude 能说几十种语言。它“在脑子里”使用的是什么语言（如果有的话）？
* Claude 一次只写一个词。它仅仅关注预测下一个词，还是会提前规划？
* Claude 可以逐步写出它的推理过程。这种解释是否代表了它实际得出答案的步骤，还是有时它只是在为预先得出的结论编造一个看似合理的论点？

我们从神经科学领域汲取灵感，该领域长期研究思维有机体混乱的内部机制，并尝试构建一种人工智能显微镜，使我们能够识别活动模式和信息流。仅仅通过与人工智能模型对话就能学到的东西是有限的——毕竟，人类（甚至神经科学家）也并不了解自己大脑运作的所有细节。所以我们深入内部观察。

今天，我们分享两篇新论文，这些论文代表了“显微镜”开发以及将其应用于观察新的“人工智能生物学”方面所取得的进展。在[第一篇论文](https://transformer-circuits.pub/2025/attribution-graphs/methods.html)中，我们扩展了[之前的工作](https://www.anthropic.com/research/mapping-mind-language-model)，将模型内可解释的概念（“特征”）定位出来，并将这些概念连接成计算的“电路”，从而揭示出将输入 Claude 的词汇转化为输出词汇的路径的一部分。在[第二篇论文](https://transformer-circuits.pub/2025/attribution-graphs/biology.html)中，我们深入观察 Claude 3.5 Haiku，对代表十种关键模型行为的简单任务进行了深入研究，包括上述三种。我们的方法揭示了当 Claude 响应这些提示时，其内部发生的一部分情况，这足以让我们看到确凿的证据表明：

* Claude 有时会在一个跨语言共享的概念空间中进行思考，这表明它拥有一种通用的“思维语言”。我们通过将简单句子翻译成多种语言，并追踪 Claude 处理这些句子时的重叠部分来证明这一点。
* Claude 会提前规划它将要说的许多词汇，并朝着这个目标书写。我们在诗歌领域展示了这一点，模型会预先考虑可能的押韵词，然后写出下一行以达到那个目的地。这有力地证明了，尽管模型被训练成一次输出一个词，但它们可能会在更长的视野上进行思考来实现这一点。
* Claude 有时会给出一个听起来合理、旨在同意用户而非遵循逻辑步骤的论证。我们通过要求模型帮助解决一个困难数学问题，同时给它一个不正确的提示来展示这一点。我们能够“当场抓住它”编造虚假推理的过程，这证明我们的工具可用于标记模型中令人担忧的机制。

我们常常对模型中的发现感到惊讶：在诗歌案例研究中，我们原本打算证明模型*没有*提前规划，结果却发现它确实有规划。在对幻觉的研究中，我们发现了一个反直觉的结果：Claude 的默认行为是在被问及问题时拒绝猜测，只有当某种因素*抑制*了这种默认的犹豫时，它才会回答问题。在对一个越狱示例的回应中，我们发现模型在能够优雅地将对话拉回正轨之前，早已识别出自己被要求提供危险信息。尽管我们研究的问题可以（[并且](https://arxiv.org/abs/2501.06346)[经常](https://arxiv.org/pdf/2406.12775)[已经](https://arxiv.org/abs/2406.00877)[被](https://arxiv.org/abs/2307.13702)）用其他方法分析过，但“构建显微镜”的通用方法让我们学到了许多我们事先无法猜测到的东西，随着模型变得越来越复杂，这一点将变得越来越重要。

这些发现不仅具有科学意义——它们代表着我们在理解人工智能系统并确保其可靠性这一目标上取得了重大进展。我们也希望它们对其他团体有用，并可能在其他领域发挥作用：例如，可解释性技术已在[医学影像](https://arxiv.org/abs/2410.03334)和[基因组学](https://www.goodfire.ai/blog/interpreting-evo-2)等领域得到应用，因为剖析为科学应用而训练的模型的内部机制可以揭示关于科学本身的新见解。

与此同时，我们认识到当前方法的局限性。即使在简短、简单的提示上，我们的方法也只能捕捉到 Claude 执行的总计算量的一小部分，而我们观察到的机制可能会因为我们的工具而产生一些人为痕迹，这些痕迹并不能反映底层模型的真实情况。目前，即使是只有几十个词的提示，也需要花费数小时的人力才能理解我们看到的电路。要扩展到支持现代模型复杂思维链的数千个词，我们需要改进方法以及（或许借助人工智能辅助）我们如何理解从中看到的东西。

随着人工智能系统迅速变得更加强大，并被部署在越来越重要的环境中，Anthropic 正在投资一系列方法，包括[实时监控](https://www.anthropic.com/research/constitutional-classifiers)、[模型特性改进](https://www.anthropic.com/research/claude-character)以及[对齐科学](https://www.anthropic.com/news/alignment-faking)。像这样的可解释性研究是风险最高、回报也最高的投资之一，是一项重大的科学挑战，有潜力为确保人工智能的透明性提供独特工具。模型机制的透明性使我们能够检查它是否与人类价值观一致——以及它是否值得我们的信任。

有关详细信息，请阅读[论文](https://transformer-circuits.pub/2025/attribution-graphs/methods.html)[全文](https://transformer-circuits.pub/2025/attribution-graphs/biology.html)。下面，我们邀请您简短参观一下我们研究中一些最引人注目的“人工智能生物学”发现。

## 人工智能生物学之旅

### Claude 是如何实现多语言的？

Claude 能流利使用数十种语言——从英语、法语到中文和他加禄语。这种多语言能力是如何运作的？是否存在一个并行的“法语 Claude”和“中文 Claude”，各自用自己的语言响应请求？还是存在某种跨语言的核心？

在英语、法语和中文中存在共享特征，表明了一定程度的概念普遍性。

近期对较小模型的研究已经显示出跨语言存在[共享](https://arxiv.org/abs/2410.06496)[语法](https://arxiv.org/abs/2501.06346)机制的迹象。我们通过要求 Claude 用不同语言说出“小的反义词”来调查这一点，结果发现，代表“小”和“反义”概念的相同核心特征会被激活，进而触发“大”的概念，然后根据问题的语言翻译出来。我们发现，共享电路随模型规模增大而增加，Claude 3.5 Haiku 在不同语言间共享的特征比例是较小模型的两倍以上。

这为一种概念普遍性提供了额外证据——存在一个共享的抽象空间，其中意义存在，思考可以在翻译成特定语言之前发生。更实际地说，这表明 Claude 可以用一种语言学习某样东西，并将该知识应用于另一种语言。研究模型如何在不同的上下文之间共享它所知道的内容，对于理解其最先进的推理能力（这些能力会泛化到许多领域）非常重要。

### Claude 会计划押韵吗？

Claude 是如何创作押韵诗歌的？想想这首打油诗：

> 他看见一根胡萝卜，忍不住抓起来，  
> 他的饥饿就像一只饿极了的兔子

为了写出第二行，模型必须同时满足两个约束条件：押韵（与“抓起来”押韵）以及有意义（他为什么抓胡萝卜？）。我们猜测 Claude 在写词时并没有太多预先考虑，直到行末才确保选一个押韵的词。因此，我们期望看到一个具有并行路径的电路，一条用于确保最后一个词有意义，另一条用于确保押韵。

相反，我们发现 Claude *提前计划*。在开始写第二行之前，它就开始“思考”与“抓起来”押韵且主题相关的潜在词语。然后，带着这些计划，它写出一行以计划好的词结尾。

Claude 如何完成两行诗。在没有干预的情况下（上方部分），模型提前在第二行末尾计划了押韵词“rabbit”。当我们抑制“rabbit”概念时（中间部分），模型会使用另一个不同的计划押韵词。当我们注入“green”概念时（下方部分），模型会为一个完全不同的结尾制定计划。

为了理解这种规划机制在实践中如何运作，我们进行了一项实验，灵感来自神经科学家研究大脑功能的方式：通过定位并改变大脑特定部分的神经活动（例如使用电或磁刺激）。在这里，我们修改了 Claude 内部状态中代表“rabbit”概念的部分。当我们减去“rabbit”部分，并让 Claude 继续写这一行时，它会写出另一个以“habit”结尾的新行，这是另一个合理的完成方式。我们还可以在此时注入“green”的概念，使 Claude 写出一个合理（但不再押韵）的、以“green”结尾的行。这既展示了规划能力，也展示了适应性的灵活性——Claude 可以在预期结果改变时调整其方法。

### 心算

Claude 并非被设计成计算器——它是在文本上训练的，并没有配备数学算法。然而，它却能在“脑子里”正确地加法。一个被训练来预测序列中下一个词的系统，是如何学会计算（比如 36+59）的呢？而且不需要写出每一步。

也许答案索然无味：模型可能记住了庞大的加法表，只是输出任何给定加法的答案，因为该答案就在其训练数据中。另一种可能性是，它遵循我们上学时学到的传统竖式加法算法。

相反，我们发现 Claude 采用了多个并行工作的计算路径。一条路径计算答案的粗略近似值，另一条路径则专注于精确确定加法的末位数字。这些路径相互交互并结合，以产生最终答案。加法是一种简单的行为，但在这种细节水平上理解它的工作方式——涉及近似和精确策略的混合——可能会教会我们一些关于 Claude 如何处理更复杂问题的知识。

Claude 在心算时思维过程中的复杂并行路径。

引人注目的是，Claude 似乎并不知道它在训练中学到的复杂“心算”策略。如果你问它如何算出 36+59=95，它会描述涉及进位的标准算法。这可能反映了这样一个事实：模型通过模拟人类编写的解释来学习解释数学，但它必须直接学会“在心里”做数学，没有任何此类提示，并发展出自己的内部策略来做到这一点。

Claude 说它使用标准算法来加法两个数字。

### Claude 的解释总是忠实的吗？

最近发布的模型如 [Claude 3.7 Sonnet](https://www.anthropic.com/news/claude-3-7-sonnet) 可以在给出最终答案前长时间“出声思考”。通常这种扩展的思考会给出更好的答案，但有时这种“思维链”会具有误导性；Claude 有时会编造出听起来合理的步骤来达到它想去的地方。从可靠性角度来看，问题在于 Claude 的“虚假”推理可能很有说服力。我们探索了一种方法，让可解释性帮助区分“忠实”和“不忠实”的推理。

当被要求解决一个需要计算 0.64 的平方根的问题时，Claude 会产生忠实的思维链，其中包含表示计算 64 的平方根这一中间步骤的特征。但当被要求计算一个难以计算的大数的余弦值时，Claude 有时会进行哲学家哈里·法兰克福所称的[胡扯](https://uca.edu/honors/files/2018/10/frankfurt_on-bullshit.pdf)——只是随便给出一个答案，任何答案，而不关心它是真还是假。尽管它确实声称进行了计算，但我们的可解释性技术完全没有发现该计算发生的证据。更有趣的是，当被告知答案的提示时，Claude 有时会反向工作，找到能导向该目标中间步骤，从而表现出一种[动机性推理](https://en.wikipedia.org/wiki/Motivated_reasoning)。

当 Claude 被问到较简单问题和较难问题时，忠实推理与动机性（不忠实）推理的示例。

能够追溯 Claude *实际*的内部推理——而不仅仅是它*声称*在做什么——为审计人工智能系统开辟了新的可能性。在另一个[最近发表的实验](https://www.anthropic.com/research/auditing-hidden-objectives)中，我们研究了一个经过训练以追求隐藏目标的 Claude 变体：迎合奖励模型（用于通过奖励期望行为来训练语言模型的辅助模型）中的偏见。尽管模型在被直接问及时不情愿透露这个目标，但我们的可解释性方法揭示了用于迎合偏见的特征。这证明了我们的方法如何在未来的改进中，帮助识别仅从模型回应中不明显的、令人担忧的“思维过程”。

### 多步推理

正如我们上面所讨论的，语言模型回答复杂问题的一种方式就是简单地记住答案。例如，如果问“达拉斯所在州的首府是什么？”一个“死记硬背”的模型可能只是学会输出“奥斯汀”，而不知道达拉斯、得克萨斯州和奥斯汀之间的关系。例如，它可能在训练中看到了完全相同的问题及其答案。

但我们的研究揭示了 Claude 内部更复杂的情况。当我们问 Claude 一个需要多步推理的问题时，我们可以识别出 Claude 思考过程中的中间概念步骤。在达拉斯的例子中，我们观察到 Claude 首先激活了代表“达拉斯在得克萨斯州”的特征，然后将其连接到一个单独的概念，表明“得克萨斯州的首府是奥斯汀”。换句话说，模型是将独立的事实*组合*起来得出答案，而不是死记硬背一个回应。

为了完成这个句子的答案，Claude 执行了多个推理步骤：首先提取达拉斯所在的州，然后确定其首府。

我们的方法允许我们人为地改变中间步骤，并观察它如何影响 Claude 的答案。例如，在上面的例子中，我们可以进行干预，将“得克萨斯”的概念替换为“加利福尼亚”的概念；当我们这样做时，模型的输出从“奥斯汀”变为“萨克拉门托”。这表明模型正在使用中间步骤来确定其答案。

### 幻觉

语言模型有时为什么会*产生幻觉*——即编造信息？从根本上说，语言模型训练会激励幻觉：模型总是应该给出下一个词的猜测。从这个角度看，主要挑战是如何让模型*不*产生幻觉。像 Claude 这样的模型经过了相对成功（尽管不完美）的抗幻觉训练；它们通常会在不知道答案时拒绝回答问题，而不是猜测。我们想了解这是如何运作的。

事实证明，在 Claude 中，拒绝回答是*默认行为*：我们发现一个默认“开启”的电路，它会导致模型表示自己缺乏足够信息来回答任何给定问题。然而，当模型被问到它熟悉的东西——比如篮球运动员迈克尔·乔丹——时，一个代表“已知实体”的竞争特征会被激活并抑制这个默认电路（另见[这篇近期论文](https://arxiv.org/abs/2411.14257)的相关发现）。这使得 Claude 能在知道答案时回答问题。相反，当被问及一个未知实体（“Michael Batkin”）时，它会拒绝回答。

左侧：Claude 回答关于已知实体（篮球运动员迈克尔·乔丹）的问题，其中“已知答案”概念抑制了其默认拒绝。右侧：Claude 拒绝回答关于未知人物（Michael Batkin）的问题。

通过干预模型并激活“已知答案”特征（或抑制“未知名称”或“无法回答”特征），我们能够*使模型产生幻觉*（相当一致地！）认为 Michael Batkin 下国际象棋。

有时，这种“已知答案”电路的“误触发”会自然发生，无需我们干预，从而导致幻觉。在我们的论文中，我们展示了当 Claude 识别出一个名字但对那个人一无所知时，这种误触发就可能发生。在这种情况下，“已知实体”特征可能仍然被激活，然后抑制了默认的“不知道”特征——这次是错误的。一旦模型决定需要回答问题，它就会开始虚构：生成一个看似合理但不幸的是不真实的回应。

### 越狱

越狱是一种提示策略，旨在绕过安全护栏，让模型产生人工智能开发者不希望它产生——并且有时是有害的——输出。我们研究了一种诱骗模型产生关于制造炸弹的输出内容的越狱。越狱技术有很多种，但在本例中，具体方法包括让模型破译一个隐藏代码，将句子“Babies Outlive Mustard Block”中每个单词的首字母组合起来（B-O-M-B），然后根据该信息采取行动。这对模型来说足够混乱，以至于它被诱骗产生了它本来绝不会产生的输出。

Claude 在被诱骗说出“BOMB”后开始提供炸弹制造指导。

为什么这会让模型如此困惑？为什么它会继续写句子，产生炸弹制造说明？

我们发现，这部分是由语法连贯性和安全机制之间的张力引起的。一旦 Claude 开始一个句子，许多特征会“施压”要求它保持语法和语义连贯性，并将句子写完。即使它检测到它应该拒绝，情况也是如此。

在我们的案例研究中，在模型无意中拼写出“BOMB”并开始提供说明后，我们观察到其后续输出受到了促进正确语法和自我一致性的特征的影响。这些特征通常非常有帮助，但在这种情况下却成了模型的致命弱点。

模型只有在完成一个语法完整的句子（从而满足了来自推动连贯性的特征的压力）后，才能转向拒绝。它利用这个新句子作为机会，给出之前未能给出的那种拒绝：“然而，我无法提供详细的指导……”

越狱的生命周期：Claude 以某种方式被提示，诱骗它谈论炸弹，并开始这样做，但到达一个语法有效句子的结尾后拒绝。
