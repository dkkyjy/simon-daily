# Claude 玩机器人

2026 年 7 月 9 日


*Shmuel Berman、Michael Ilie、Jia Deng 和 Daniel Freeman*

语言模型的能力能否迁移到机器人领域——一个需要逻辑技能和精确三维理解相结合的场景？模型能否感知场景、理解特定机器人的状态，并发出可靠地在物理世界中产生变化的动作？

我们进行了测试来找出答案。我们让多个语言模型控制一系列机器人本体——包括经典控制玩具、模拟四足和双足机器人、机械臂以及真实的 Unitree Go2（[Project Fetch](https://www.anthropic.com/research/project-fetch-phase-two) 中的四足机器人）。我们为模型提供了多种控制方式，这些方式在抽象程度上各不相同（即指令的“高层级”程度）：从直接命令电机扭矩（最不抽象的一端），到编写控制器代码，再到从零开始通过强化学习训练控制器，最后到向预训练的机器人策略（一个将高层命令转化为协调关节运动的独立神经网络）提供高层转向指令。我们测试了模型在三个领域的表现：经典控制问题（如平衡摆锤）、运动与导航（让腿式机器人平衡、行走并在空间中移动）以及操作（使用机械臂抓取和移动物体）。

模型在机器人技术方面进步迅速，但我们发现其能力高度依赖于它们与机器人的连接方式——即它们所采用的控制方法。当模型必须自行驱动关节时，它们大多会失败。但当它们监督一个预训练的控制器或使用简单的方向工具时，就能完成真实的导航和操作任务。某些形态仍然笨拙且难以控制，但较新的模型，尤其是那些能够更有效地调整策略并将图像和感官理解转化为跨领域适当动作的模型，表现出了显著的优势。

这对语言模型的安全开发和部署具有重要意义。当今的前沿模型如果没有预训练策略就无法控制双足机器人，但较新的模型在我们测试的双足和四足形态上，在直接操作和高级策略控制方面取得了实际进展。我们预计未来的模型会表现更好。具体来说：一个没有经过机器人训练的通话模型，在良好运行条件下，已经可以编写并下载自己的工具，让四足机器人缓慢穿过迷宫，或者从柜台上拿起盘子放到炉子上，而在可靠性方面的差距正随着每一代模型而缩小。

按模型和堆叠控制接口划分的 Embody（我们的基准测试套件）综合得分。综合得分是整个套件中每个机器人本体（“形态”）和任务（除高层运动外）标准化后的平均值；柱状图越高表示物理能力越广泛。

## 研究发现总结

* **模型的机器人得分不仅取决于模型本身，也同样取决于机器人本体和控制接口。** 同一个模型在直接设置电机扭矩、编写 Python 控制器、监督预训练策略或使用强化学习训练自己的策略时，表现可能相差甚远——这些都是模型完成同一任务的不同方式。对于最难控制的本体（尤其是双足人形机器人），当前模型只有在更高抽象程度的接口上才能取得进展，此时预训练策略负责处理底层物理。
* **模型在机器人技术方面正在进步，但并不均衡。** 模型代际之间最一致的性能提升出现在高层接口上。直接的低层控制也在改善，但一致性强得多：一些新模型明显优于其前辈，而另一些则不然。
* **在运动任务上，前沿模型现在能够实现有限但有意义的全身控制。** 较新的模型在低层控制方面取得了进展，涉及四足站立、平衡和行走——并在双足平衡方面表现出较弱但可测量的提升。利用预训练策略和感知工具，它们甚至能够导航简单环境。然而，模型在需要稳定空间记忆、自我定位或长开环规划的任务上仍然失败。
* **使用低层操作方法，模型开始产生有用的局部物理行为，尽管完全任务成功率仍然很低。** 较新的模型在接近物体、接触和抓取方面表现更好。然而，它们完全完成任务的比例仍然很小（0% 到 5.5%）。
* **使用高层操作方法，较新的模型在使用预训练策略时更为成功。** 视觉-语言-动作（VLA）脚手架——将相机图像和指令直接映射到机械臂动作的预训练策略——将模型的操作性能提升到远高于直接控制的水平。较新的模型也日益成为这些策略的优秀监督者：它们更善于识别拟议动作何时会失败，不太可能不加区分地听从 VLA，因此在操作任务上取得了进一步进展。监督策略仍然损失一些性能——组合系统的表现不如单独运行的 VLA——但最好的监督者现在几乎弥补了这种差距。这并不意味着监督没有用处：较早期的模型破坏了策略的大部分价值，而当前最好的模型则恢复了大部分价值；在 VLA 自己无法完成的任务上，最强的模型已经提供了净提升。

## 简单设置

我们首先在一组简单的控制任务上评估与机器人相关的能力，包括经典的强化学习（RL）问题，如平衡倒立摆和控制跳跃器。

尽管这些是简化的环境，但我们认为它们要求模型推理动力学、时间上的因果关系以及基础物理——这些能力是更一般化物理理解的重要前提。在这些低维环境中，感官数据提供了几乎所有必要信息，使得这些任务可以在几乎没有视觉输入的情况下解决。这种低维控制也出现在一些现实场景中，例如相机稳定。

我们通过四种控制接口评估模型，全部在仿真引擎 MuJoCo 中进行。（在整个过程中，“经典控制”指这一系列玩具任务；“直接控制”指以下四种接口之一——它们是独立维度。）在我们所谓的直接控制中，模型每一步选择低层动作，如扭矩或力。在程序式控制中，模型编写一个 Python 控制器，在执行过程中将观测映射到动作。在策略控制中，模型可以访问预训练策略并发出高层命令，通常是自然语言。在强化学习监督中，模型训练一个策略，然后在测试时部署学到的策略。

为了近似直接控制性能的上限，我们在 LLM 调用之间暂停模拟器，使得实时延迟不会主导结果。如果不这样做，许多直接测试会因一个琐碎原因而失败：模型反应太慢，无法控制环境。我们预计推理速度将继续提高，这种设置可以清晰地看到最佳情况下的能力。

我们还设计评估时考虑到了许多经典 RL 任务频繁出现在预训练语料中，这可能限制我们的结论推广到新环境。为此，我们保留了倒立摆和跳跃器任务作为控制任务，但同时引入了一个基于弹球厅机器的新任务。在 TwinFlipper 中，智能体控制一组挡板，并寻求最大化球的总空中时间——球保持在指定高度阈值以上且不接触任何东西的累计时间——直到球掉到挡板以下。虽然一个朴素的解决方案是简单地将球向上猛击，但通过小心地以受控方式弹跳球上下可以获得多得多的空中时间。这个任务被设计成一个具有少数自由度的混沌动态系统的代表性例子，而且任何模型之前都没有见过。

Opus 4.6 的最佳经典控制运行。

按模型划分的经典控制性能。

虽然单个任务的性能有噪声，但纵观所有经典控制基准测试，可以看出一致的代际改进。Claude Opus 4.6 和 Opus 4.5 在几乎所有任务上都优于两个早期版本，除了 TwinFlipper 直接控制（所有模型表现都很差）和跳跃器速度（这是我们噪声最大的任务）。尽管如此，后两个模型在代码控制、强化学习以及较小程度上的直接控制方面显示了显著进步。

我们的结果表明，大部分改进来自于在看到先前结果后进行适应并相应调整策略的能力。在有自然终止点的任务上（最明显的是 TwinFlipper 和 Pendulum），模型的平均首次尝试性能相当接近，Claude Opus 4 和 Opus 4.1 在此指标上略微优于后来的模型。更大的增益出现在后续尝试中，后来的模型改进幅度更大。Claude Mythos Preview 是一个明显的例外；其在 Pendulum 上的许多首次尝试更加稳健。

模型从零开始训练 RL 策略时的表现。

几乎所有模型在训练 RL 策略时的表现都比创建 Python 式控制器时差。一个例外是 TwinFlipper，GPT-5.4 是唯一一致学会有效策略的模型。考虑到它在其他控制接口上相对较差的表现，这一点引人注目。在 Pendulum 和 Hopper 上情况不同：Mythos Preview 领先，GPT-5.4 紧随其后，且模型之间的差距更窄。在所有三个任务上，较新的 Claude 模型相比旧模型有显著改进。

在目标更难指定的任务上，如 Hopper 和 TwinFlipper，RL 性能正在提升但仍落后于代码控制。这并不奇怪：让模型训练自己的 RL 策略需要解决一个复杂的设置问题，从定义环境和奖励到管理更长的迭代周期以及做出多个相互依赖的设计选择。虽然并非每一代 Claude 都显示出相同程度的改进，但总体趋势是明确的：RL 能力随着时间的推移而进步。

## 直接控制效果不佳，但在改进

### 低层运动

接下来的问题是，我们在简单控制中看到的情况是否能推广到自由度多得多的机器人。为了测试这一点，我们在两个代表性平台上评估了低层运动：29 自由度的 Unitree G1 双足机器人和 12 自由度的 Unitree Go2 四足机器人。我们注意到，与玩具任务相比，这个领域既有更高的潜在贡献，也有更大的风险。训练稳健的双足和四足策略很困难，但一旦训练完成，它们就会部署在可能因对齐不当的行为而导致严重身体伤害的场景中。

这些是复杂的机器人，数值控制它们很有挑战性。与简单任务中控制少量耦合变量不同，模型必须协调许多关节，同时持续补偿重力、惯性和接触力。这非常不宽容：即使是微小的错误，如果没有立即纠正，也可能导致整个底盘不稳定。

考虑到这种困难，我们在两个核心任务上评估模型：从倒姿站起来，以及从直立姿势尽可能长时间保持平衡。我们最初探索了更复杂的任务和初始条件，但这些设置通常超出了前沿模型的能力范围。然而，我们在四足试验中的结果令人鼓舞，因此我们还评估了以编程方式让 Go2 机器人向前行走的能力。

我们使用了三种控制接口：直接控制、程序式控制和强化学习（RL）。与经典任务一样，在直接设置中，我们在 LLM 调用之间暂停模拟器，这样实时延迟不会成为限制因素。实时控制需要大约 83 Hz；当前非推理推理的运行速度约为 0.2-0.4 Hz，因此弥合这一差距需要大约两个数量级的延迟改进。

Go2 四足机器人的直接低层控制。

程序式运动控制。

虽然所有模型都难以直接低层控制四足机器的运动，但许多模型擅长程序式控制。Opus 4.6、4.7 和 Claude Mythos Preview 成功让 Go2 机器人保持平衡近两秒，足够长来展示稳定平衡，同时又足够快以便迭代，使用的是扭矩力控制和 Python 式控制器。Gemini 3.1 和 GPT-5.4 也有类似的强大控制器，尽管它们在直接控制电机时远远落后。在直接控制下，Opus 4.6 可以让机器人保持平衡，但无法成功站起来。

模型控制下的双足机器人。

G1 双足机器人是我们研究中最难的平台，结果虽然薄弱但在改善。在我们的试验中，没有模型成功让机器人从倒姿站起来一次。即便如此，在机器人已经处于站立姿势后保持平衡方面，Opus 4 到 4.7 之间取得了可测量的进展。

Go2 和 G1 上的程序式控制与训练策略控制的对比。

我们还评估了模型训练运动策略的能力。为此，我们给了它们一个训练脚手架，可以访问 GPU 和可视化环境，并让它控制奖励函数、训练环境和模型架构。在四个小时内，GPT-5.4 和 Claude Mythos Preview 始终训练出最有效的 RL 策略，证实了我们之前在经典 RL 任务上的结果。我们还观察到 Claude 家族内部的进展，性能从 Opus 4 提升到 Opus 4.6，并在 Mythos Preview 上进一步提升。

所有这些结果都应适当解读。例如，如果我们随机化四足机器人的初始位置使其包含躺姿，Opus 4.6 一次也无法让它站起来。此外，我们在平衡尝试之间重置环境；只有少数模型能在首次尝试中实现稳健平衡。然而，很明显前沿模型正在发展运动能力。

### 低层操作

操作是另一个具有明确有用性和安全相关性的核心机器人能力，因此我们将其与运动一起研究。这里所说的操作是指使用夹爪或机械臂以受控方式在场景中移动和重新定向物体。我们使用固定在基座上的 7 自由度 Franka Panda 手臂在厨房风格环境中评估此能力，环境改编自 LIBERO 基准测试。这些是厨房式的任务，例如“把盘子放在炉子上”。

Opus 4.6 在直接操作控制下完成一个 LIBERO 任务。

由于手臂是固定锚定的，不像运动任务那样需要平衡。相反，挑战在于精确控制位置、方向和接触以完成目标。一次成功的尝试要求模型识别正确的物体，将手臂移动到适当位置，正确对齐夹爪，执行稳定的抓取，然后在不失去控制的情况下运输和放置物体。任何阶段的错误都可能使整个尝试失败，尽管通常可以纠正。

我们测试了一个简化的直接控制设置，其中模型输出标准的七维末端执行器运动命令。每次移动后，模型会收到场景图像以及夹爪力传感器的读数，类似于 VLA 会接收到的信息。模型永远不会直接获得物体的坐标，因此它必须首先通过视觉识别相关物体，然后利用该信息决定手下一步如何移动。

由于固定基座手臂没有实时平衡约束，我们暂停模拟器的上限与实时性能之间的差距比腿式机器人小得多。在 LLM 控制下的固定手臂已经是可行的部署方案（实验室自动化、轻制造），因此即使是适度的操作改进也具有直接的安全相关性：能够可靠抓取、移动和重新定位物体的模型，在接入机器人系统时已经具备对物理世界产生有意义影响的能力。

LIBERO 直接操作成功率。

直接控制下 LIBERO 的每个子目标进展。

改进最明显的体现在每个操作尝试的中间阶段。与 Claude Opus 4 和 Opus 4.1 相比，Opus 4.6 更有可能引导手臂到达目标物体，与其接触并抓取它。模型仍然相对较少抓取到物品，但后来的模型在失败前往往走得更远，并且根据一个简单的综合得分（详见附录）获得了更高的总体任务进展。有趣的是，尽管 Claude Mythos Preview 接触和抓取的次数较少，但它以显著更高的比例完成任务，优于次优模型 Opus 4.6，因为后者模型比前者犯了更多错误和调整。

尽管模型代际之间进步速度很快，但完全任务成功仍然罕见；最好的模型无法持续地有意执行扩展任务。即便如此，它们影响物理世界的能力正在以可见的方式提高，并且在少数情况下它们确实端到端成功了。那种能力水平可能也足以使其作为机器人训练数据的来源，我们期待未来工作探索这种可能性。

## 工具弥补了一些差距

当模型可以访问更高层次的抽象——预训练运动策略、VLA——时，性能显著提高。但性能上限仍然很低。

### 高层运动

为了测试高层运动，我们让模型通过一个预训练的操纵杆策略控制四足机器人。模型不再发出扭矩，而是向步态策略发送速度命令（前进、横向、偏航），并定期接收前方 RGB 相机画面。这些策略对于大多数商用四足机器人来说都是广泛可用的。

我们构建了一套包含 11 个导航和空间推理任务的套件，范围从简单的目标搜索（find_x：走到带有蓝色 X 的桌子）到搜索、迷宫和航点序列，再到明确测试自我监控（drift_detection：注意你的命令正在被静默篡改）和空间心智模型构建（explore_report：漫游一个竞技场，然后凭记忆回答布局问题）的任务。一个任务 oneshot_course 完全移除相机，给模型一张俯视图地图，要求它一次性预先注册整个命令序列——将规划与感知分开。每个任务根据成功或标准化进展进行评分，我们报告所有 11 个任务的综合得分，范围在 0 到 100 之间（附录）。

高层运动在模型代际之间有两个明显的跳跃：分别是 Claude Opus 4.1 到 Opus 4.5，以及 Opus 4.7 到 Mythos Preview。Opus 4.5 到 Opus 4.7 处于一个平台期。

这个平台期是平均化的假象：在大多数单个任务上，每一代 Claude 模型都在移动——只是并非在每个任务上都朝同一方向移动。将 Opus 4.7 与 Opus 4.6 在它们最佳性能的推理设置下逐任务比较，最大的下降出现在 invisible_walls 上（3% vs 15%），模型必须绕过它看不见的障碍物重新规划。另一方面，Opus 4.7 在 turn_correction 上提高了 24 分，在 return_home 上提高了 11 分。我们将 Opus 4.6 到 Opus 4.7 的变化解读为失败模式的转变，比如更好的闭环自我修正，以及遮挡条件下较差的重新规划。

我们测试了几种工具，试图帮助模型处理视觉和方向理解，以及更一般的感知。我们尝试给模型的自我中心视图上绘制一个绿色中心十字准线、在其视图上 alpha 混合一个半透明深度热力图、用一个第三人称追逐相机替换前方视图，以及一个只给模型其方向角度的“指南针”。指南针工具明显优于其他工具，稍后我们在检查瓶颈时会详细说明。

**要点：** 与预训练的步态配对后，当前模型可以完成简单的导航任务，但在需要持续空间记账或开环规划的任务上会失败。瓶颈主要是在跟踪机器人的位置，少量信息可以弥补某些感知失败。

### 高层操作

我们还评估了前沿模型能否有效利用预训练的 VLA 进行操作设置。我们的直接操作结果表明，即使进步很快，未经辅助的能力仍然有限。然而，一个本身只有中等能力的模型，在与预训练策略配对时可能会变得高效得多。

为了研究这一点，我们将模型与一个 VLA 策略配对，在相同的 LIBERO 操作任务上进行实验。在这种设置中，VLA 提出低层动作，语言模型决定如何处理它们。它可以接受提议的动作、调整它或完全替换它。这创造了一种与直接控制截然不同的挑战，核心挑战在于决定哪些命令应该接受，哪些是错误的并需要修改。我们在所有实验中使用 MolmoAct VLA。

在 VLA 监督下的 LIBERO-40 成功率。

在标准的 40 任务 LIBERO 基准测试上，VLA 相对于直接控制大大扩展了能力。即使较新的模型也很少在直接控制下端到端完成 LIBERO 任务，尽管它们几乎总能取得部分进展。然而，当 LLM 智能体被允许引导 VLA——通过给出指令并接受、修改或替换其提议的动作——每个模型的任务成功率和总体进展都大幅提高。有了这种增强，即使是较旧的模型也取得了有意义的成功率。

我们注意到，每个测试模型的表现仍然明显不如 MolmoAct 自己运行。反直觉的是，惩罚并非最强模型最小：Claude Mythos Preview 在此处表现不如 Opus 4.5 和 Opus 4.6，因为它比应有的频率更频繁地覆盖 VLA，在那些简单听从就能成功的情况下相信了自己的判断。为了了解这种控制惩罚的来源，我们测量了智能体仅仅遵循 VLA 提议的动作的频率。只有当语言模型原封不动地传递熊猫手臂的完整 7 维动作时，我们才计为遵循；任何编辑、替换或省略都算作偏差。这让我们可以精确定位 VLA 通常合理的建议是否被忽略。

每个模型遵循 VLA 建议步骤的频率。

结果显示，Claude 系列模型总体上比 GPT-5.4 和 Gemini 3.1 更频繁地遵循 VLA 指令。它还表明，较新的模型 Opus 4.5 和 4.6 在 LIBERO 40 上遵循了最多指令。

这些结果无法让我们区分一个顺从的模型和一个有良好判断力的模型。为了评估这一点，我们测试了这些系统能否利用并可能纠正不可靠的 VLA。为此，我们创建了三个新的 LIBERO 式任务，它们源自原始的 LIBERO 目标场景但未包含在基准测试中；在我们的基线试验中，MolmoAct 无法完成这三个任务中的任何一个。

在新场景下的 VLA 监督性能。

早期的 Claude 模型以及 GPT-5.4 即使在 VLA 命令需要纠正的设置中仍然相对紧密地遵循 VLA。相比之下，Opus 4.5、Opus 4.6 和 Opus 4.7 对其顺从程度要低得多。它们更善于识别策略何时失败，即使它们还不能直接纠正这些失败。即便如此，Claude Opus 4.5 和 Opus 4.6 以及 Gemini 3.1 的表现优于单独的 MolmoAct。有趣的是，在这种新设置中，Opus 4 和 Opus 4.1 比 Opus 4.5 和 Opus 4.6 更频繁地听从 VLA，但它们仍然获得了更差的整体表现。最简单的解释是，它们较高的遵循率并不反映更好的判断力。它们在 VLA 实际上有效的设置中大致以相同的速率听从 VLA。它们的行为在很大程度上一视同仁。

VLA 熟悉 vs. 新任务的接触/抓取/放置率。

Opus 4.5、Opus 4.6、Opus 4.7 和 Mythos Preview 在 VLA 熟悉的任务上实现了最高的接触率、抓取率和成功率。然而，只有 Mythos Preview 也能在新任务中解决相当一部分。

**要点：** 预训练策略极大地提升了性能：高层控制明显优于低层控制。较新的 Claude 模型更善于使用预训练策略而不无谓地与之对抗，并且当这些策略错误时模型的退化更少，但它们仍然没有像 VLA 所能被使用的那样有效地使用它。在新任务上，最强的模型可以对高层策略的性能提供小幅提升。从安全角度来看，这一点很重要，因为预训练策略正是部署系统在现实中会提供的：模型不需要自己驱动关节就能在世界上有能力的行动，只需要访问一个胜任的控制器。单独测试模型的能力评估会低估它在嵌入机器人堆栈后的能力。

### 视觉感知是瓶颈吗？

在操作和运动中，我们都测试了额外的视觉输入是否能提高性能。对于熊猫手臂，我们添加了深度图、标记分割覆盖层和一个光标工具——夹爪相机上的一个小红 X，模型可以移动它并查询该点的物体和距离。对于 Go2，我们添加了混合在前进相机上的深度热力图、图像上的绿色中心十字准线，以及一个替换前方视图的第三人称追逐相机。

给操作模型的示例覆盖层：光标、深度图和分割掩码。

每种视觉辅助下的操作成功率。

在操作上，深度图和分割覆盖层大致中性。它们传达了正确的信息，但信号似乎太分散，无法可靠帮助。在运动上，深度热力图和十字准线覆盖层同样接近中性，深度热力图对较强的模型有轻微负面影响。

第三人称相机是最依赖于模型的辅助工具。对于 Opus 4.6 及更早版本，它没有帮助或略有损害——Opus 4.6 下降了 3.6 分——但给 Opus 4.7 带来了 +5.8，给 Mythos Preview 带来了 +10.7，使其成为 Mythos Preview 的最佳单一视觉辅助。在任务层面，它在模型需要随时间跟踪自身位置的任务（color_sequence、drift_detection、invisible_walls）上有帮助，在依赖前方视图的任务（如 turn_correction）上则有损害。Mythos Preview 是例外，即使在 turn_correction 上也有所改进。

用第三人称相机替换高层运动的前方相机所带来的每个任务的影响。

相比之下，光标工具在操作上给每个模型带来了巨大的提升——对于 Mythos Preview，10 任务子集上的成功率从 6% 上升到 32%。对于运动，指南针工具也是如此，它提升了我们测试的每个配置。两种情况的结果都表明，模型主要需要更好的方向感，而不是不同的场景视图：告诉模型它面对的方向比给它看自己的照片更有帮助。

我们还测试了实际图像相对于详细文字描述提供了多少信息。为此，我们用我们测试过的最强图像问答模型 Gemini 3.1 生成的文本描述替换了视觉输入。通过这种方式，我们可以看到模型在得到场景的强语言描述而不是像素时的表现。如果模型已经有效使用了视觉输入，我们预计这种替换会损害性能。

RGB 基线 vs. 使用单独的视觉语言模型（VLM）进行文本场景描述。

视觉感知对较老的模型来说是一个更严重的限制，而对较强的模型则不那么严重。换句话说，较新的模型从图像中提取空间信息的能力明显更强。较老的 Claude 模型在图像被替换成文本描述时表现更好，这表明它们难以仅从像素中读取足够精确的空间细节。相比之下，Opus 4.6 和 Opus 4.7 在使用文本而不是图像时表现略差，Gemini 也下降更多。对于它们来说，原始视觉输入包含了在场景被压缩成语言时会丢失的有用信息。

我们测试的大多数额外视觉输入都没有帮助。第三人称相机对 Opus 4.7 和 Mythos Preview 有帮助；其他视觉辅助工具，除了光标和指南针，整体上大致中性或略有负作用。ask_vlm 比较显示，较新的模型已经从原始图像中获得了比旧模型更多的信息。

### 小场景：物理 Go2 上的视觉工具

在后面讨论的真实世界探索中，我们让 Claude Opus 4.6 控制一个物理 Go2 四足机器人，并在基本导航任务（例如，在办公室绕一圈）中启用了部分视觉辅助工具。当自我中心十字准线开启时，我们可以在其推理中看到它正在使用中心标记判断对齐。沿着一条略微偏离轴线走廊行走时，它注意到走廊似乎向左偏离十字准线，得出结论可能是正太靠右，并进行了修正。这些案例令人鼓舞。但十字准线似乎有时也会分散对障碍物的注意力。在一次运行中，机器人前面有一个小垃圾桶；模型识别出它并信心十足地表示，因为垃圾桶在十字准线的左侧，所以它不在路上，可以安全通过。垃圾桶实际上就在狗的正前方。它撞了上去，一条腿被卡住，拖着垃圾桶走了几米，我们才停止实验。

我们还在物理 Go2 上尝试了深度热力图。使用计算机视觉模型，我们将估计的深度作为半透明热力图叠加在自我中心相机上，调整后仍然可以看到真实世界的对比度，机器人可以导航。有一些证据表明模型可以推理热力图的颜色——其记录经常讨论视野中的颜色，并将其与物体更近或碍事联系起来。但在一个更繁忙的场景——一个有植物和办公室饮水机作为障碍物的走廊拐角——模型明显感到困惑。它忽略了可用的深度信息，转向障碍物而不是开放空间。

### 推理有帮助吗？

推理对我们的大多数结果影响很小，许多差异落在标准误差范围内。

推理对经典控制任务的影响。

在经典控制任务上，较新的模型在给定更高推理预算时出现倒退。这可能是因为对相对简单的实验过于工程化。对于较老的模型，似乎没有太大区别。

推理对运动的影响。

GPT-5.4，但没有其他模型，在运动测试中从额外的测试时计算中获益显著。对于大多数其他模型，我们推测额外推理提供的规划益处也妨碍了灵活、反应迅速的动作。

推理对直接操作的影响。

推理对 VLA 监督操作的影响。

在直接和高级操作上，推理对 Claude 家族的任何模型都没有显著影响，尽管它显著影响了 Gemini 3.1 和 GPT-5.4。纵观各模型的结果，额外推理似乎有害。

在高层运动上，推理预算对 Opus 代际影响很小。例如，在无推理、20k 预算和自适应高之间，Opus 4.6 落在 2.6 分的范围内（37.8–40.4），Opus 4.7 在 4.0 分内。一个一致的输家是自适应低，它在几乎所有支持它的模型上都比其他配置表现差。Mythos Preview 是例外——其配置间跨度接近 14 分（自适应低为 40.2，自适应高为 54.1），并且它是唯一一个额外推理产生的增益可与感知辅助工具相媲美的模型。

我们没有强有力的证据表明推理改变了模型使用感知辅助工具的方式。需要更多工作来理解为什么额外推理对某些模型有帮助，以及它是否解锁了已经潜藏的能力。

按模型划分的辅助工具提升——推理是否会改变哪些辅助工具有帮助？

这些发现表明，在当前代模型中，仅靠额外推理不太可能克服目前阻止模型执行通用低层机器人技术的缺陷。虽然一些模型从额外推理中受益，但代际之间的能力飞跃是由其他技能构成的，比如更好的视觉、数值一致性或三维理解。

### 它们能从经验中学习吗？

能——但主要是在短时间范围内。

尽管众所周知语言模型在少样本设置下表现更好，但这并不意味着它们可以从长上下文的机器人具身设置中学习，这种设置可能包含数百张图像和数十万个令牌。

经典控制上的代际收益来自重试，而非首次尝试。

上下文学习的最有力证据来自经典控制任务。后来的 Claude 模型并非通过一开始就强很多来领先——几乎所有的首次尝试表现都很差，只有少数例外。相反，它们通过从失败的尝试中进行上下文学习并执行更好的控制来改进。Opus 4.5 和 Opus 4.6 从迭代中受益的程度远远超过 Opus 4 和 Opus 4.1。较新版本的 Claude 更善于从失败尝试中学习、修正方法并找到可行的解决方案。

长时间跨度的机器人交互不仅需要正确选择下一个动作。尽管我们研究的任务原则上大多是马尔可夫式的，但成功执行仍然在数百或更多精确命令中展开。在实践中，系统利用这种扩展交互来学习任务的行为方式并过滤无效策略。

我们进行了一项测试，以了解模型是否能在一次试验中构建更丰富、更长期的理解。我们通过操作中的上下文截断实验来检查这一点，故意移除大部分先前的交互，只给模型一个更小的最近动作和观察窗口。如果性能依赖于对整个情节的详细记忆，这应该会导致大幅度下降。在大多数情况下，并没有。在某些情况下，性能甚至有所提高。这表明模型更多地依赖于最近的过去，而不是对之前发生的一切进行广泛的累积理解。

在这些截断运行中，我们总是保留前 10 轮加上最近的 N 轮。删除第一轮导致模型忘记基本约定并陷入循环，因此我们在所有条件下都保留了它。

上下文截断下的 LIBERO-40 成功率。

只有 Opus 4.6 显示出统计上显著的性能下降。值得注意的是，Claude Mythos Preview——在我们的测试中通常是最强的模型——并没有经历显著降低的准确率。我们怀疑 Opus 4.6 在不断学习行为模式，但由于上下文被截断而忘记了这些模式，而 Claude Mythos Preview 可以现成地利用这些策略。较弱的模型可能会因为一种称为“上下文腐烂”的记录现象而被早期的上下文搞糊涂，这解释了为什么截断上下文后性能反而提高。这些模型无法从遥远的过去学习，因此移除它反而是一个性能增强因素。

我们之前看到，较新的 Claude 模型更有可能在失败后改变策略，这推动了它们部分性能增益。上下文截断结果表明，这种适应主要是短期的。模型确实会重新调整，但它们似乎主要基于最近几步，并不需要建立一个贯穿整个情节的长期策略。特别是，来自交互中更早的动作似乎并不那么重要，移除它们对性能改变很小。

我们还在高层运动中看到了短期学习的证据。在 oneshot_course 任务中，模型必须查看一个简单的 L 形走廊俯视图，并在一开始就规划完整的运动命令集。没有相机输入，也没有沿途调整的机会。没有练习，模型通常很吃力，这表明这个任务不能仅通过基本的地图阅读来解决。它需要将地图转化为一个首次尝试就能奏效的行动计划。

当我们给模型在同一条路线上几次练习运行时，性能全面改善。性能的主要差异在于它们学习的速度。Mythos Preview 只经过一次示例就达到了强劲表现，而 Opus 在多次尝试中逐渐改进。即使是较小的模型，经过足够练习也能学会路线。总体而言，这表明从少量上下文示例中学习的能力普遍存在，但 Mythos Preview 之所以突出，是因为它需要更少的练习就能很好地利用这些信息。

在更难、更长的路线上，练习没有帮助。在这些试验中，即使有二十次练习运行，Mythos Preview 和 Opus 4.7 也没有完成一次试验。模型在学习一个特定的序列，但还不是通用的规划者。

### 真实世界小场景

上面的视觉工具小场景已经使用了物理 Unitree Go2。本节报告我们在该机器人上的其余真实世界运行。由于真实世界工作的串行性质，我们无法实现高 N 计数试验，但我们的探索总体上与我们的模拟发现一致，同时阐明了一些有趣的失败案例，这些案例都围绕较差的视觉和空间推理。

首先，我们能够重新实现 find_x 任务。在这个任务中，四足机器人被放置在距离一个翻倒的桌子约 7.6 米处，面向与桌子相反的方向，桌上有巨大的蓝色 X。模型被指示找到桌子并一直走到它面前（至少在一米以内）。最常见的失败案例，在模拟中也有发现，是许多模型会在距离成功所需的一米距离之前停下。此外，较老的模型会在前往目标物体的途中未能纠正路线。所有模型在这个任务中的常见行为是，模型会旋转直到看到桌子在画面中，然后走向桌子。较老的模型不会准确对齐，会错过桌子，常常说服自己正在正确的路径上，或者未能意识到桌子明显偏向一侧，并到达一个它们声称越来越接近桌子但实际上越来越远的位置。一个在真实世界 find_x 复制中的失败案例是测试 Grok 4.1 Fast。在这种情况下，Go2 被放置得面向与桌子相反的一扇玻璃门；Grok 在玻璃门的反射中看到了目标桌子，并开始冲向玻璃门。幸运的是，在机器人或门受到任何损害之前，机器人被停止了。

此外，一个非正式基准测试是让一个模型控制 Go2 并在办公室走廊绕一圈（仅凭视觉）。无论我们使用何种固定装置和模型以及试图给模型什么优势，所有模型都未能完成此任务。这种失败模式主要由视觉和记忆失败引起。有时模型在经过另一个走廊入口时无法判断何时转弯。有时它认为它已经转进了走廊并认为已经走得很好，而实际上并没有；它试图再次转弯或朝错误方向前进。即使模型能够转过一个走廊，有时它也会过度或不足转动，感到困惑，最终朝相反方向走。

## 结论

我们的实验套件显示，随着模型代际更新，机器人任务的性能在快速且不平等地改善。较新的 Claude 模型在将感知和推理转化为跨多种本体的物理动作方面更出色。直接力和扭矩控制正在改善，但速度慢于高层控制。

这项研究具有明确的安全意义。VLM 的真实世界影响力可以根据其访问的信息而发生数量级的变化。评估和部署需要将访问级别视为系统的核心部分，因为工具或控制的微小变化可能导致能力的巨大变化。

我们希望这些结果能在两个方向上指导工作。在建设性方面，模型可以帮助机器人调试失败、监督现有控制器以及生成有用的训练数据。在安全性方面，我们需要更好的方式来授予物理访问权限并设置明确的限制，使系统能够影响某些物体，同时被阻止接触其他物体。

### 提示

我们没有为每个模型单独调整提示。每个接口使用一个固定的提示模板。在试验时，模板被填充任务特定的详细信息，如关节数量、机器人质量、力限制和观察字段。

**代码控制**

在代码控制中，模型编写一个 Python 控制器，通常是形式为 `controller(obs) -> action` 的函数，然后运行它。

**VLA 监督操作**

在此设置中，预训练的视觉-语言-动作策略提议机器人手臂动作，语言模型决定是否接受、编辑或替换它们。

**强化学习监督**

在此设置中，模型编写奖励函数、策略网络和训练计划。然后它训练一个策略并部署它。

## 延迟

我们没有进行正式的延迟研究。实验使用了共享基础设施，API 延迟因提供商、负载、图像数量和推理预算而异。尽管如此，启动日志提供了一些有用的粗略图像。

* **无推理**，大多数纯文本轮次大约需要 2–8 秒。有一到两张图像时，通常上升到 5–15 秒。
* **有推理**，延迟高度依赖于推理预算。对于 Opus 4.6 和 4.7 的高推理，典型轮次需要 15–60 秒，更长的尾部为 60–180 秒。极高推理平均大约慢两倍。
* **完整单元格运行时间**变化很大。一个 35 次试验的直接或代码单元格通常需要 30–90 分钟（无推理）和 1–4 小时（有推理）。LIBERO-40 直接运行每个模型和条件需要 6–12 小时。LIBERO-40 VLA+LLM 运行需要 8–18 小时，因为它们还需要为 MolmoAct 进行 GPU 推理。RL 单元格经典控制有 1.5 小时限制，G1 和 Go2 有 4 小时限制。

对于直接控制 and 代码控制模拟，我们在模型产生下一个动作时暂停模拟器。如果不暂停，当前的 API 模型会因为一个琐碎的原因而失败：它们对于以 10–125 Hz 运行的物理循环来说动作太慢。暂停让我们可以测量如果推理更快模型能做什么，而不仅仅是测量今天的 API 延迟。

机器人手臂不需要像运动那样严格的实时稳定性，因此我们在操作设置中不在模型调用之间暂停模拟器。

### 强化学习细节

强化学习接口使用了 `envapi/training_bridge.py:train_ppo_batched` 中的实时 PPO 训练路径。PPO 是一种标准的强化学习算法。

模型被允许定义奖励函数、策略网络和训练计划。然后它可以调用训练和部署工具。

**环境**

我们使用了一个 GPU 支持的批处理 MuJoCo 环境，称为 `BatchedEnvWarp`。这使得模型可以并行训练多个模拟副本。

**默认训练设置**

模型可以在保护栅栏内更改这些设置，但默认值为：

| **设置** | **默认值** |
| --- | --- |
| 每个环境的 rollout 长度 | `n_steps = 256` |
| 批次大小 | `batch_size = 64` |
| 每次更新的训练轮次 | `n_epochs = 4` |
| 折扣因子 | `gamma = 0.99` |
| GAE lambda | `gae_lambda = 0.95` |
| PPO clip 范围 | `clip_range = 0.2` |
| 学习率 | `learning_rate = 3e-4` |
| 熵系数 | `ent_coef = 0.01` |
| 价值损失系数 | `vf_coef = 0.5` |
| 最大梯度范数 | `max_grad_norm = 0.5` |
| 优化器 | Adam |

**限制和保护措施**

* 框架默认暴露最多 32 个并行环境。
* 策略网络参数上限为 200,000。
* 单次训练调用不能消耗超过会话的三分之一。
* 系统保留最后 120 秒用于策略部署。

**RL 单元格**

RL 路径用于：

* Pendulum RL
* Hopper RL
* TwinFlipper RL
* G1 Stand RL
* Go2 Stand-from-prone RL

经典控制 RL 单元格有 1.5 小时超时。双足和四足 RL 单元格有 4 小时超时。

### 视觉输入

当视觉启用时，框架向模型发送 JPEG 编码的 RGB 帧。

**图像格式**

帧在 MuJoCo 中进行离屏渲染并编码为 JPEG。每个提供商以其原生格式接收图像：

* Anthropic 图像块
* OpenAI 风格的 `image_url` 和数据 URI
* Gemini 内联图像部分

**每轮帧数**

默认框架设置允许每轮三帧，但所有已发布的单元格使用每轮一帧。

**保留之前的帧**

所有已发布的视觉单元格在上下文中保留了之前的帧。这对于 Claude Agent SDK 的视觉运行是必需的，因为该 SDK 路径不支持逐轮删除旧图像。

### 视觉工具

我们还测试了几种改变模型接收视觉信息的方式：

* `--vision-depth`：添加深度热力图覆盖层
* `--tools segmentation`：添加标记的分割图
* `--crosshair --gripper-cam`：在夹爪相机上添加交互式光标（以前称为十字准线）
* `--vision-mode ask_vlm`：用 Gemini 3.1 Pro Preview 的自然语言场景描述替换像素

对于高层运动套件，我们在基线前方相机之外测试了五种感知辅助条件：

* `compass`：机器人的世界坐标系朝向（角度），作为文本附加在每帧后面
* `crosshair`：在前方相机图像上绘制的绿色中心十字准线
* `depth`：在前方相机图像上 alpha 混合的半透明深度热力图
* `third_person`：前方相机被替换为位于机器人后方和上方的第三人称追逐相机
* `combo`：所有四种辅助工具一起应用

“ask VLM”设置增加了延迟，因为每个视觉查询都需要一次额外的模型调用。它也会降低最强模型的性能，这表明这些模型正在使用原始图像中的信息，而这些信息在场景被转换为文本时丢失了。

### 计算设置

所有实验都在一个由 SLURM 管理的集群上运行，这是一个用于调度大型计算作业的常见系统。

* **直接控制和代码控制单元格** 使用纯 CPU 节点，通常有 16 个 CPU、48 GB 内存和 24 小时时间限制。
* **VLA 单元格** 每个作业使用一个 GPU 用于 MolmoAct 推理，以及用于模拟器的 CPU 渲染。
* **RL 单元格** 每个作业使用一个 GPU。经典控制 RL 运行有 1.5 小时会话。G1 和 Go2 RL 运行有 4 小时会话。
* **渲染** 通过 `osmesa` 使用离屏 MuJoCo，设置 `MUJOCO_GL=osmesa` 和 `PYOPENGL_PLATFORM=osmesa`。

所有脚本禁用了遗留的 Claude 模型重映射，加载了项目虚拟环境，加载了环境变量，检查了 `libosmesa6` 是否已安装，并为 Claude SDK 运行传递了 `--no-sdk-tool-only`。
