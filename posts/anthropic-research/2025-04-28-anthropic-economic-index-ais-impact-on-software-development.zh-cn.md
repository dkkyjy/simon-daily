# Anthropic 经济指数：人工智能对软件开发的影响

**日期：** 2025-04-28 00:00 UTC  
**链接：** https://www.anthropic.com/research/impact-software-development  
**标签：** 社会影响，经济研究  

---

涉及计算机编程的工作在现代经济中只占一小部分，但却具有影响力。过去几年里，人工智能系统的引入极大改变了这些工作——这些系统能够协助并自动化大量的编码工作。

在我们[之前的经济指数研究](https://www.anthropic.com/news/the-anthropic-economic-index)中，我们发现美国从事计算机相关职业的工人对 Claude 的使用比例极不均衡：也就是说，与计算机相关的任务中与 Claude 的对话数量远远超出从相关工作岗位人数上所能预测的数量。在[教育领域](https://www.anthropic.com/news/anthropic-education-report-how-university-students-use-claude)也是如此：计算机科学学位（涉及大量编码）显示出极高的 AI 使用比例。

为了更详细地了解这些变化，我们对 [Claude.ai](http://claude.ai/redirect/website.v1.64624b22-8692-4809-bb7a-1fd1e2ecdee6)（大多数人默认与 Claude 交互的方式）和 [Claude Code](https://docs.anthropic.com/en/docs/agents-and-tools/claude-code/overview)（我们新的专业化编码“智能体”，能够使用多种数字工具独立完成一系列复杂任务）上的 50 万次编码相关交互进行了分析。

我们发现了三个关键模式：

1. **编码智能体更多地用于自动化。** Claude Code 上 79% 的对话被识别为“自动化”——即 AI 直接执行任务——而非“增强”（AI 与人类协作并增强人类能力，占 21%）。相比之下，Claude.ai 上只有 49% 的对话被归类为自动化。*这可能意味着，随着 AI 智能体变得越来越普遍，并且更多具有智能体能力的 AI 产品被构建出来，我们应当预期任务自动化程度会更高。*
2. **程序员普遍使用 AI 构建面向用户的应用程序。** JavaScript 和 HTML 等 Web 开发语言是我们数据集中最常用的编程语言，用户界面和用户体验任务位列编码用途的前列。*这表明，专注于简单应用程序和用户界面的工作可能比纯后端工作更早面临 AI 系统的颠覆。*
3. **初创公司是 Claude Code 的主要早期采用者，而企业则落后。** 在一项初步分析中，我们估计 Claude Code 上 33% 的对话服务于初创公司相关工作，而只有 13% 被识别为与企业相关的应用。*采用差距表明，使用尖端 AI 工具的灵活组织与传统企业之间存在分化。*

### 我们如何分析 Claude Code 和 Claude.ai 上的对话

我们使用我们的[隐私保护分析工具](https://www.anthropic.com/research/clio)分析了总计 50 万次 Claude 交互（分布在 Claude Code 和 Claude.ai 之间），该工具将用户对话提炼为更高级、匿名的洞察。在此，我们用它来识别对话的主题（例如“UI/UX 组件开发”），或者——正如我们将在下面解释的——将对话归类为侧重于“增强”还是“自动化”。

### 开发者如何与 Claude 交互？

在我们之前的经济指数报告中，我们将“自动化”（AI 直接执行任务）与“增强”（AI 与用户协作执行任务）区分开来。在此，我们发现 Claude Code 显示出极高的自动化率——79% 的对话涉及某种形式的自动化，而 Claude.ai 上这一比例为 49%。

我们还将自动化和增强进一步划分为若干子类型（如我们在[之前的工作](https://www.anthropic.com/news/the-anthropic-economic-index)中所讨论的）。“反馈循环”模式（Claude 自主完成任务，但借助人工验证——例如，用户将任何错误发送回给 Claude）在 Claude Code 上（占交互的 35.8%）几乎是 Claude.ai（21.3%）的两倍。“指令性”对话（Claude 以最少的用户交互完成任务）在 Claude Code 上也更高（43.8%，而 Claude.ai 为 27.5%）。所有增强模式——包括“学习”（用户从 AI 模型获取知识）——在 Claude Code 上的比例均显著低于 Claude.ai。

子类型定义如下：指令性：以最少的交互完全委托任务；反馈循环：通过环境反馈引导任务完成；任务迭代：协作完善过程；学习：知识获取与理解；验证：工作核实与改进。

这些结果说明了专业化、编码为中心的智能体（本例中为 Claude Code）与用户与大型语言模型交互的“标准”方式（即通过 Claude.ai 这样的聊天界面）之间的差异。随着更多具有智能体能力的产品发布，我们可能会看到 AI 融入人们工作方式上的差异。至少在编码领域，这可能意味着更多的任务自动化。

这就提出了一个问题：随着 AI 使用越来越普遍，开发者在其中的参与程度将如何？重要的是，我们的结果确实表明，即使在自动化中，人类仍然频繁参与：“反馈循环”交互仍需要用户输入（即使该输入只是将错误信息粘贴回给 Claude）。但这种情况能否持续下去仍不确定——未来更强大的智能体系统可能会逐渐需要越来越少的用户输入。

### 开发者用 Claude 构建什么？

总体而言，我们发现开发者普遍使用 Claude 来构建网站和移动应用程序的用户界面及交互元素。虽然没有单一语言占主导地位，但主要面向 Web 的开发语言 JavaScript 和 TypeScript 合计占所有查询的 31%，而 HTML 和 CSS（其他面向用户的代码语言）合计又增加了 28%。

百分比代表两个平台上编码相关任务的总百分比。由于 Claude Code 和 Claude.ai 权重相同，每个平台对应的条形部分代表该平台使用量的一半。

后端开发语言（用于幕后逻辑、数据库和基础设施，以及 API 和 AI 开发）也有体现：值得注意的是，Python 占查询的 14%。然而，Python 具有双重用途——既用于后端开发，也用于数据分析。结合 SQL（另一种以数据为重点的语言，占查询的 6%），这些语言可能包含了大量数据科学和分析应用，超越了传统的后端开发。

编程语言使用百分比代表两个平台的总百分比。由于 Claude Code 和 Claude.ai 权重相同，每个平台对应的条形部分代表该平台使用量的一半。

这些模式进一步延伸到涉及 Claude 的常见编码任务类型。排名前五的任务中有两个专注于面向用户的应用程序开发：“UI/UX 组件开发”和“Web 与移动应用开发”分别占对话的 12% 和 8%。这类任务越来越适合一种称为“氛围编码”的现象——不同经验水平的开发者用自然语言描述他们期望的结果，然后让 AI 负责实现细节。

与更通用用途相关的对话，例如“软件架构与代码设计”和“调试与性能优化”，在 Claude.ai 和 Claude Code 中也占有很高比例。

推测而言，这些发现表明，如果不断增长的能力导致“氛围编码”更多地成为主流工作流程，那么专注于简单应用程序和用户界面的工作可能会更早面临 AI 系统的颠覆。随着 AI 越来越多地处理组件创建和样式设计任务，这些开发者可能会转向更高层级的设计和用户体验工作。

### 谁在使用 Claude 进行编码？

我们还分析了哪些开发者群体可能在使用 Claude。我们使用分析系统来识别最能描述用户编码相关交互的项目类型（例如，个人项目 vs. 为初创公司做的项目）。由于我们不知道 Claude 的回复被用于的真实世界背景，这些分析依赖于不完整数据的不确定推断。因此，我们将这些发现视为比上述发现更具初步性。

点之间的距离表示每种项目类型在 Claude.ai（蓝色）和 Claude Code（橙色）上的流行程度差异。

初创公司似乎是 Claude Code 的主要早期采用者，而企业采用则滞后。初创公司工作占 Claude Code 对话的 32.9%（比在 Claude.ai 上的使用高出近 20%），而企业工作仅占 Claude Code 对话的 23.8%（略低于其在 Claude.ai 上 25.9% 的份额）。

此外，涉及学生、学者、个人项目构建者和教程/学习用户的用途合计占两个平台交互的一半。换句话说，个人——而不仅仅是企业——是编码辅助工具的重要采用者。

这些采用模式反映了过去的技术转变：初创公司利用新工具获取竞争优势，而成熟组织行动更为谨慎，并且通常在公司范围内采用新工具之前会进行详细的安全检查。AI 的通用性可能会加速这种动态：如果 AI 智能体带来显著的生产力提升，早期采用者与晚期采用者之间的差距可能会转化为显著的竞争优势。

### 局限性

我们的分析基于现实世界中的 AI 使用——开发者实际上如何在他们的工作流程中使用 Claude。尽管这种方法使我们的发现具有实际意义，但它也带来了固有的局限性。这些局限性包括：

* 我们只分析了来自 Claude.ai 和 Claude Code 的数据。我们排除了可能显示不同模式的团队版、企业版和 API 使用情况，尤其是在专业环境中；
* 自动化与增强之间的界限随着 Claude Code 等智能体工具的出现变得越来越模糊。例如，“反馈循环”模式在质量上不同于传统的自动化，因为它仍然需要用户的监督和输入。我们可能需要扩展自动化/增强框架以涵盖新的智能体能力；
* 我们对谁在使用 Claude 进行编码的归类依赖于有限上下文的推断。当将对话归类为“初创公司”与“企业”工作，或“个人”与“学术”项目时，我们的分析工具基于不完整的信息做出了有根据的猜测。因此，某些分类可能是错误的。此外，我们包含了一个“无法分类”选项，Claude 在 5% 的 Claude.ai 对话和 2% 的 Claude Code 对话中选择了该选项。我们将此类别从分析中排除并重新归一化了结果；
* 我们的数据集可能捕捉到了早期采用者。这些用户可能不代表更广泛的开发者群体，这种自我选择可能会使使用模式偏向于更有经验或技术上更冒险的用户；
* 出于隐私考虑，我们只分析了特定保留窗口内的数据，可能错过了软件开发中的周期性模式（如冲刺周期或发布计划）；
* Claude 使用的代表性尚不清楚，相对于整体 AI 编码辅助工具的采用情况。许多开发者使用多种 AI 工具，而不仅仅是 Claude，这意味着我们只呈现了他们 AI 参与模式的部分视图；
* 我们只研究了开发者委托给 AI 的任务——而不是他们最终如何在代码库中使用 AI 输出、生成代码的质量，或者这些交互是否有效提高了生产力或代码质量。

### 展望未来

AI 正在从根本上改变开发者的工作方式。我们的分析表明，在使用像 Claude Code 这样的专业智能体系统时尤其如此，在面向用户的应用程序开发工作中尤为突出，并且可能为初创公司相对于更成熟的企业带来特定优势。

我们的发现提出了许多问题。“反馈循环”（人类仍然参与过程）的普遍性会随着 AI 能力的进步而持续存在，还是会转向更完全的自动化？随着 AI 系统能够构建更大规模的软件，开发者是否会转向主要管理和指导这些系统，而不是自己编写代码？哪些软件开发角色变化最大，哪些可能会完全消失？

AI 不断增强的编码能力也可能对 AI 开发本身产生特别深远的影响。由于如此多的 AI 研究和开发依赖于软件，AI 辅助编码的进步可能有助于加速突破，形成一个正反馈循环，进一步加速 AI 的进步。

从宏观角度来看，AI 系统非常新。但相对而言，编码是 AI 在经济中发展最成熟的用途之一。这使得它值得关注。尽管我们不能假设从软件开发中得出的结论会直接适用于其他类型的职业，但软件开发可能是一个领先指标，告诉我们未来随着越来越强大的 AI 模型的推出，其他职业可能会如何变化。
