对终端用户而言，开源软件的理由之一始终是拥有检查和修改该软件工作方式的自由。

对大多数人（甚至包括专业程序员）来说，现实情况是，这种自由更多时候意味着能够依赖*其他人*来做这件事。大多数人无法为阅读并修改自己经常使用的工具代码所需投入的时间找到一个合理的理由。

我认为大语言模型（LLM）已经改变了这个等式，让最初的梦想变得切实可行得多。

我每天会有好几次让普通的 Claude 聊天会话"从 GitHub 克隆 x/y，并告诉我 Z 是如何工作的"。

过去，为了让软件能够编译以开始动手研究它，所需要的摩擦成本足以让我常常懒得去尝试。现在，我把它视为一个零时间投入的挑战：让 Codex 或 Claude Code 检出并构建 X，然后十分钟后再回来看进展如何。

我还没有习惯性地*修改*所用软件，但我已经看到了一条通往那种状态的道路，而这条路在大约一年前还不存在。
