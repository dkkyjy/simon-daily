[Release](/elsewhere/release/)
[datasette 1.0a38](https://github.com/simonw/datasette/releases/tag/1.0a38)
— An open source multi-tool for exploring and publishing data

> This release fixes a **SQL injection** security issue that affects Datasette instances that serve a **mixture of public and private tables** in the same database, with access configured using the [Datasette permissions system](https://docs.datasette.io/en/latest/authentication.html).
>
> Site administrators who serve private tables in this way are advised to disable the [execute-sql permission](https://docs.datasette.io/en/latest/authentication.html#execute-sql) ` on that database to prevent users from accessing private tables using raw SQL queries. The bug that has been fixed would have allowed users with access to any public table to execute SQL injection attacks despite that restriction, giving them read-only access to data in private tables in the same database.
>
> This fix is also available in [Datasette 0.65.3](https://simonwillison.net/2026/Aug/6/datasette-2/).

Thankfully this particular configuration - private tables and public tables exposed for the same database within the same instance - is likely to be rare. I've not encountered an instance like that myself.
