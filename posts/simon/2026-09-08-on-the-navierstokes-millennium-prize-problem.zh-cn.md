2026年9月8日 - 链接博客

**[关于纳维-斯托克斯千禧年大奖难题](https://openai.com/index/navier-stokes-solution/)**（[转引自](https://news.ycombinator.com/item?id=49613262 "Hacker News")）OpenAI 取得了一项令人瞩目的成果——他们使用一个尚未发布的模型，对[纳维-斯托克斯方程的存在性与光滑性问题](https://en.wikipedia.org/wiki/Navier–Stokes_existence_and_smoothness)给出了解决方案。该问题是自2000年5月24日起悬赏一百万美元的七项[千禧年大奖难题](https://en.wikipedia.org/wiki/Millennium_Prize_Problems)之一。

这一发现在一定程度上被来自特里斯坦·巴克马斯特（Tristan Buckmaster）的指控所掩盖。他是纽约大学的一位数学教授，当时正与莱文特·阿尔珀格（Levent Alpöge）合作研究相关问题。阿尔珀格是一位才华横溢的数学家，目前在 Anthropic 工作。

特里斯坦的投诉附带了[一份仓促发布的版本](https://mastodon.social/@tristanbuckmaster/117233413705701198)，是他们自己的研究成果。[这里是描述事情经过的 PDF 文件](https://cims.nyu.edu/~tristanb/statement.pdf)。*极其*简短的版本是这样的：特里斯坦和莱文特在这道题上工作了将近一年，大量使用了 Claude 和 Codex（主要是 GPT-5.6 Sol），然后在8月15日取得了突破。数学圈的谣言机器随即开始运转，特里斯坦和莱文特得知 OpenAI 听说 Anthropic 已经解决了"一个重大未解决问题"，于是他们主动联系 OpenAI，了解到 OpenAI 有一个团队正在用类似的方法研究一个相关问题。引用特里斯坦的原话：

> 我询问他们第一次发送提示词是什么时候。这个问题 OpenAI 在相当长一段时间内没有直接回答。最终大家达成一致：提示词是在过去几天内发送的，而那时关于我们工作的信息已经传到了 OpenAI。
>
> 我询问该模型是否在训练中使用了、或能否访问我们在 Codex 中的会话记录——我们在整个项目期间一直把所有草稿都输入其中。我得到的回复是模型不会查阅用户数据。我又追问了关于训练的问题，但没有得到回答。

事情从这里开始变得更加复杂。OpenAI 团队提出可以等特里斯坦先发表，或者请他撰写一篇关于他们成果的文章，但明确表态莱文特*不会*被邀请作为共同作者，因为 OpenAI 与莱文特所在的雇主存在竞争关系。

以下是 OpenAI 对其工作的描述：

> 9月1日（周二），我们听说有传闻称两道千禧年大奖难题已被解决。受这些传闻以及我们内部模型性能跃升的启发，我们启动了一项工作，对该模型在所有未解决的千禧年大奖难题以及少数其他高影响力问题上进行评估。[...]
>
> 智能体于9月5日（周六）得出了最终解决方案，距首批智能体启动约88小时。Lean 形式化与验证又额外花费了17小时，由 GPT‑6 Astra 完成。
>
> 在所有尝试的问题中，智能体共发送了490万条消息，使用了约3000亿个输出 token。在解决纳维-斯托克斯问题的过程中，智能体发送了270万条消息，使用了约1300亿个输出 token。

（我们不清楚他们所用内部模型的成本结构，但按照 GPT-6 Astra 的公开 API 价格，3000亿个输出 token 的费用将达到[1500万美元](https://www.llm-prices.com/#ot=300000000000&sel=gpt-6-astra)。）

以下是他们阐述对特里斯坦和莱文特工作看法的部分（加粗为本人所加）：

> 我们的工作始于9月1日，起因是听到一则传闻，后来我们意识到这涉及 Anthropic 员工莱文特·阿尔珀格和纽约大学数学教授特里斯坦·巴克马斯特。在我们完成全部项目和 Lean 验证（9月6日）之后，根据传闻我们认为他们同样拥有纳维-斯托克斯方程的解，于是我们主动联系他们，提议同步发布我们的成果，并在联合公告中承认他们的优先权。[...]
>
> 我们（研究人员和智能体）在他们公开发表之前，通过任何途径都未见过他们的任何工作——尤其没有任何特定用户数据被调取用于解决此问题。**虽然可能性不大，但我们无法排除这样一种情况：从他们使用我们产品的数据中派生出的去标识化数据，有助于[提升我们的模型性能](https://openai.com/policies/how-your-data-is-used-to-improve-model-performance/)。** 然而，我们的证明在方法上有显著不同，即使在欧拉方程的情形下，所证明的具体结果也不同（有外力驱动与无外力驱动）。

我对这里发生的事情的理解是：OpenAI 听说有人用大语言模型解决了某些千禧年大奖难题，便将其视为展示其最新模型实力的机会，却几乎没有认真考虑抢发一支团队成果在观感上的影响——而这支团队在将近一年的时间里一直在使用 OpenAI 自己的模型来攻克这道难题。

这一局面似乎与当前计算机安全领域正在发生的事情如出一辙。阿尼尔·马达瓦帕蒂（Anil Madhavapeddy）最近指出，[如今仅仅一个漏洞的传闻就足以找到安全利用方法](https://anil.recoil.org/notes/rumour-is-the-exploit)，因为如果有人知道某款软件存在未修补的漏洞，他们就可以让智能体去找到它。数学领域现在是否也是如此？仅仅知道某个问题存在一份未发表的解，就可能触发数百万美元的大语言模型开销，只为抢先一步。

这也凸显了我一直以来的一个持续困扰：这一切的运作方式到底是怎么回事。当一个 AI 实验室说我的数据被"用于提升模型性能"时，*这到底意味着什么*？

我曾经最钟爱的两个假设性问题是这样的：

* 如果我在运行 Codex 时，其中一个 API 密钥意外被包含在上下文中，那么将来别人请求一个 API 密钥时，拿到我的那个的概率有多大？（我曾经问过 OpenAI 的人，他们把这叫做"回吐"问题，并向我保证他们非常努力地防止这种情况发生……但不会说明具体怎么做的。）
* 如果我用 ChatGPT 头脑风暴，探讨公司可能的新方向，那么六个月后某个竞争对手问"X 公司接下来可能会做什么"时，我的信息被暴露给对方的概率有多大？

我现在最钟爱的假设性问题变成了：

* 如果我用 ChatGPT 帮助我部分解决一道千禧年大奖难题，那么我的工作影响训练、以至于后来某个模型帮助*别人*抢先解出这道题的概率有多大？
