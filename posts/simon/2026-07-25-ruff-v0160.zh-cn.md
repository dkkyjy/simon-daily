**[Ruff v0.16.0](https://astral.sh/blog/ruff-v0.16.0)**。Astral 在几天前（7月23日）发布了其 Ruff Python 代码检查工具的一个重要新版本。我今天注意到这一点，是因为我的多个 CI 任务由于新的默认 Ruff 检查规则和未固定版本的 `"ruff"` 开发依赖而开始失败。

来自 Brent Westbrook 的公告文章：

> Ruff 现在默认启用 413 条规则，而之前的版本只有 59 条。
>
> 自从 Ruff 的默认规则集在 [v0.1.0](https://github.com/astral-sh/ruff/blob/main/changelogs/0.1.x.md#breaking-changes) 中最后一次修改以来，Ruff 中的规则数量已从 708 条增加到 968 条。其中许多规则能捕获严重问题，包括[语法错误](https://docs.astral.sh/ruff/rules/load-before-global-declaration)和[即时运行时错误](https://docs.astral.sh/ruff/rules/yield-in-init/)，但之前并未默认启用。借助新的规则集，Ruff 无需任何配置就能让您注意到这些问题以及许多其他问题。

以下是一行命令，可用于任何 Python 项目进行尝试：

```
uvx ruff@latest check .
```

我对最新的 Ruff 运行了我的三个最大项目——[Datasette](https://datasette.io/)、[sqlite-utils](https://sqlite-utils.datasette.io/) 和 [LLM](https://llm.datasette.io/)——它发现了*数百个*因违反新默认规则而产生的小问题。

这三个项目都具有非常全面的测试套件，在 CI 中针对 Python 3.10 到 Python 3.14 执行，因此此类升级相当安全。以下命令完成了大部分升级工作：

```
uvx ruff@latest check . --fix --unsafe-fixes
```

针对 `sqlite-utils`，该命令报告：

```
Found 1618 errors (1538 fixed, 80 remaining).
```
