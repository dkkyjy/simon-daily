# First run the tests

自动化测试在使用编码代理时已不再是可选项。

过去不编写测试的借口——即测试耗时且成本高昂，在代码库快速迭代时需要不断重写——当代理能在几分钟内将其整理成型时已不再成立。

测试对于确保AI生成的代码能按预期运行也至关重要。如果代码从未被执行过，那么它部署到生产环境后能实际正常运行纯粹是运气使然。

测试同样是帮助代理快速熟悉现有代码库的绝佳工具。当你向Claude Code或类似工具询问某个现有功能时，它们极有可能找到并读取相关的测试。

代理本身已倾向于测试，但现有测试套件的存在几乎必然能促使代理对其所做的新变更进行测试。

每当我针对现有项目启动与代理的新会话时，我都会首先提示以下变体：先运行测试

对于我的Python项目，我已将`pyproject.toml`配置为可以这样提示：运行"uv run pytest"

这四个词的提示具有多重目的：

* 它告知代理存在测试套件，并迫使其弄清楚如何运行测试。这几乎能确保代理将来会运行测试以确认没有破坏任何功能。

* 大多数测试框架会向代理粗略显示测试的数量。这可以作为项目规模和复杂度的参考，同时也暗示代理若想了解更多信息应自行搜索测试。

* 它让代理进入测试思维模式。运行测试后，代理自然会考虑后续用自己的测试来扩展它们。

类似于"使用红/绿TDD"，"先运行测试"提供了一个四词提示，涵盖了已内置于模型中的大量软件工程规范。
