# Interactive explanations

当我们无法追踪代理编写的代码如何工作时，我们就会背上认知债务。

对于很多事情来说，这并不重要：如果代码从数据库获取一些数据并以 JSON 格式输出，那么实现细节很可能足够简单，我们无需在意。我们可以尝试新功能，对其工作原理做出相当可靠的猜测，然后快速浏览代码以确认。

然而，细节往往确实很重要。如果我们应用程序的核心变成了一个我们不完全理解的黑箱，我们就无法再自信地对其进行推理，这使得规划新功能变得更加困难，并最终像累积的技术债务一样拖慢我们的进度。

我们如何偿还认知债务？通过加深对代码工作原理的理解。

我最喜欢的方法之一是构建交互式解释。

## 理解词云

在《一位 AI 代理编码怀疑论者尝试 AI 代理编码，极其详细》一文中，Max Woolf 提到用提示词测试 LLM 的 Rust 能力：创建一个 Rust 应用，能够根据长输入文本生成“词云”数据可视化。

这激发了我的想象力：我一直想知道词云是如何工作的，于是我启动了一个异步研究项目——此处是初始提示词，代码和报告在此——来探索这个想法。

效果非常好：Claude Code for Web 为我构建了一个 Rust CLI 工具，能够生成像这样的图像：

但它实际上是如何工作的呢？

Claude 的报告称它使用了“阿基米德螺旋放置，每个词带有随机角度偏移，以实现自然外观的布局”。这对我帮助不大！

我请求对代码库进行线性遍历，这帮助我更详细地理解了 Rust 代码——这是遍历结果（以及提示词）。这帮助我理解了 Rust 代码的结构，但我仍然没有直观地理解“阿基米德螺旋放置”部分实际是如何工作的。

于是我请求一个动画解释。我通过将现有 walkthrough.md 文档的链接粘贴到 Claude Code 会话中，并附上以下内容来实现：

使用 curl 将 <https://raw.githubusercontent.com/simonw/research/refs/heads/main/rust-wordcloud/walkthrough.md> 获取到 /tmp，以便你能阅读全文

受此启发，构建 animated-word-cloud.html——一个页面，接受粘贴的文本（将其持久化在 URL 的 `#fragment` 中，这样加载时如果 `#` 有内容，页面将使用该文本作为输入并自动提交），当你提交文本时，它会使用该文档中描述的算法构建词云，但以动画方式呈现，使算法清晰易懂。包含一个动画滑块，可以暂停、调整速度，甚至在暂停时逐帧步进。在任何阶段，可见的进行中的词云都可以下载为 PNG。你可以在此处体验结果。这是一个动画 GIF 演示：

这使用了 Claude Opus 4.6，事实证明它在构建解释性动画方面品味相当不错。

如果你仔细观察动画，可以看到对于每个词，它尝试通过显示一个框将其放置在页面上的某个位置，运行检查以确定该框是否与现有词相交。如果相交，它会继续尝试寻找合适的位置，从中心向外螺旋移动。

我发现这个动画确实帮助我理解了算法的工作原理。

我一直是动画和交互式界面的爱好者，它们有助于解释不同的概念。一个好的编码代理可以按需生成这些内容，以帮助解释代码——无论是它自己的代码还是他人编写的代码。
