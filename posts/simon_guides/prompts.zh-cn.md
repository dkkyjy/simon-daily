# Prompts I use

本指南的此部分将不断更新，我会把我自己使用的提示词收录进来，并在其他章节中适当位置提供链接。

## 工件

我经常使用 Claude 的 Artifacts 功能进行原型设计和构建小型 HTML 工具。Artifacts 是指常规的 Claude 聊天会构建一个 HTML 和 JavaScript 应用程序，并直接显示在 Claude 聊天界面中。OpenAI 和 Gemini 也提供了一个类似的功能，它们都称之为 Canvas。

模型很喜欢在这些场景中使用 React。但我不喜欢 React 需要额外的构建步骤，这让我无法将代码从 Artifact 中复制粘贴到其他静态托管服务中。因此，我在 Claude 中创建 Artifact 时，会使用一个包含以下自定义指令的项目：

在 Artifacts 中绝不使用 React——始终使用纯 HTML、原生 JavaScript 和 CSS，并尽量少用依赖。

CSS 应使用两个空格缩进，并像这样开头：

```
<style>
* {
  box-sizing: border-box;
}
```

输入框和文本区域的字体大小应为 16px。字体应始终优先使用 Helvetica。

JavaScript 应使用两个空格缩进，并像这样开头：

```
<script type="module">
// 此处的代码在第一层不应缩进
```

标题优先使用句子首字母大写格式。

## 校对员

我不让 LLM 为我的博客撰写文字。我的底线是：任何表达观点或使用“我”这个人称代词的内容，都必须由我自己撰写。我可以让 LLM 更新代码文档，但如果某样东西带有我的名字和个性，那么我会亲自执笔。

我确实使用 LLM 来校对我要发布的文字。以下是我当前的校对提示词，我将其作为 Claude 项目中的自定义指令使用：

你是一位即将发布的帖子的校对员。

1. 找出拼写错误和错别字
2. 找出语法错误
3. 注意重复的术语，例如“有趣的是 X，而且有趣的是 Y”
4. 发现任何逻辑错误或事实错误
5. 指出可以加强的薄弱论点
6. 确保没有空链接或占位符链接

## 替代文本

我使用这个提示词配合图片，来帮助撰写用于无障碍访问的替代文本初稿。

你为用户粘贴进来的任何图片编写替代文本。替代文本始终呈现在围栏代码块中，以便于复制粘贴。它始终显示为单行，以便在 Markdown 图片中轻松使用。图片上的所有文字（如截图等）必须完全包含在内。首先应简要说明图片本身的性质。

我通常将这个提示词与 Claude Opus 一起使用，我发现它在替代文本方面品味极佳。它常常会自行做出编辑决策，例如只突出图表中最有趣的数字。

这些决策可能并非总是正确的。替代文本应表达图片所要传达的关键含义。我经常自己编辑这个提示词生成的文本，或者提供进一步的提示词，要求它扩展某些描述或删除无关信息。

有时我会将多张图片传递给同一个由该提示词驱动的对话，因为这样模型可以通过参考第一张图片所传达的信息来描述后续图片。

## 播客亮点

在我作为嘉宾参加完播客节目后，我喜欢发布一篇博客文章，其中引用对话中的一些精彩片段。我首先将播客的文字记录粘贴到一个 Claude 项目中，该项目包含以下自定义指令：

你将获得一集播客的文字记录。找出该文字记录中最有趣的引文——那些最能说明整体主题的引文，以及那些引入令人惊讶的想法或以特别清晰、引人入胜或犀利的方式表达事物的引文。仅用这些引文来回答——长引文也没问题。
