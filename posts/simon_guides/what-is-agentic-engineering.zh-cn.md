# What is agentic engineering?

我使用术语**智能体工程**来描述在编码智能体的辅助下开发软件这一实践。

什么是**编码智能体**？它们是既能编写又能执行代码的智能体。常见的例子包括 Claude Code、OpenAI Codex 和 Gemini CLI。

什么是**智能体**？明确定义这个术语是一个挑战，至少从 1990 年代起就让 AI 研究人员感到困惑，但在我所接受的、至少是在像 GPT-5、Gemini 和 Claude 这样的大型语言模型（LLM）领域中，这个定义是这样的：

**智能体通过循环运行工具来实现一个目标**

“智能体”是一种软件，它调用一个 LLM 并传入你的提示词和一组工具定义，然后调用 LLM 请求的任何工具，并将结果反馈回 LLM。

对于编码智能体来说，这些工具包括一个可以执行代码的工具。

你提示编码智能体定义一个目标。然后，智能体在一个循环中生成并执行代码，直到该目标达成。

代码执行是使智能体工程成为可能的关键能力。如果没有直接运行代码的能力，LLM 输出的任何内容价值都有限。有了代码执行，这些智能体就可以开始迭代，朝着确实能工作的软件前进。

## 智能体工程

既然我们现在有了能编写可工作代码的软件，那么留给我们人类做的事情还有什么？

答案是：**非常多的事情**。

编写代码从来都不是软件工程师的唯一活动。这门手艺一直在于弄清楚**要编写什么代码**。任何给定的软件问题都有数十种潜在的解决方案，每种方案都有各自的权衡。我们的工作是导航这些选项，并找到最适合我们独特情况和需求的那个。

从编码智能体中获得出色结果本身就是一个深奥的课题，尤其是在这个领域正以令人眼花缭乱的速度发展的当下。

我们需要为我们的编码智能体提供解决问题所需的工具，以适当的详细程度说明这些问题，并验证和迭代结果，直到我们确信它们能够以稳健且可信的方式解决我们的问题。

LLM 不会从过去的错误中学习，但编码智能体可以——只要我们有意地更新我们的指令和工具框架，以考虑到我们在此过程中学到的东西。

如果使用得当，编码智能体可以帮助我们对我们承担的项目更有雄心。智能体工程应该帮助我们产出更多、质量更高的代码，以解决更具影响力的难题。

## 这不就是“氛围编码”吗？

“氛围编码”这个术语是由 **Andrej Karpathy** 在 2025 年 2 月创造的——巧合的是，就在 Claude Code 原始版本发布前三周——用来描述在“忘记代码甚至存在”的情况下提示 LLM 编写代码。

有些人将这个定义扩展到涵盖任何使用 LLM 生成代码的情况，但我认为这是个错误。氛围编码在其原始定义中更有用——我们需要一个术语来描述未经审查、原型质量的 LLM 生成代码，以区别于作者已将其提升到生产就绪标准的代码。

## 关于本指南

就像它试图涵盖的领域一样，**《智能体工程模式》** 本身就是一个进行中的作品。我的目标是识别并描述使用这些工具的模式，这些模式已被证明能取得成果，并且不太可能随着工具的进步而过时。

随着新技术出现，我会继续添加更多章节。没有哪一章应该被认为是完成的。随着我们对这些模式的理解不断演变，我会更新现有的章节。
