* 扩展思维更新

  2025年12月15日

  自初次发布以来，扩展思维能力已得到改进，因此在大多数情况下，我们建议使用该功能，而非专门的思考工具。扩展思维提供了类似的优势——为Claude提供推理复杂问题的空间——同时集成度更高、性能更优。有关实现细节，请参阅我们的扩展思维文档。

在持续增强Claude复杂问题解决能力的过程中，我们发现了一种特别有效的方法：一个“思考”工具，能在复杂任务期间为结构化思考创建专用空间。

这种简单而强大的技术——如下文所述，它与Claude新的“[扩展思维](https://www.anthropic.com/research/visible-extended-thinking)”能力（参见[扩展思维实现细节](https://platform.claude.com/docs/en/build-with-claude/extended-thinking)）不同——显著提升了Claude的智能体工具使用能力。这包括遵循策略、做出一致的决策、处理多步骤问题，同时实现开销最小化。

在这篇文章中，我们将探讨如何在不同应用中实现“思考”工具，并为开发者提供基于已验证基准测试结果的实用指南。

### 什么是“思考”工具？

通过“思考”工具，我们赋予Claude在得出最终答案的过程中加入一个额外的思考步骤的能力——该步骤拥有自己专属的空间。

虽然这听起来类似于扩展思维，但它们是不同的概念。扩展思维是Claude在开始生成响应之前所做的事情。通过扩展思维，Claude在采取行动之前会深入考虑并迭代其计划。而“思考”工具则是在Claude开始生成响应后，添加一个步骤来停下来思考它是否拥有继续前进所需的全部信息。这在执行长链工具调用或与用户进行多步骤长对话时尤其有用。

这使得“思考”工具更适用于以下情况：Claude仅凭用户查询无法获得制定响应所需的全部信息，并且需要处理外部信息（例如工具调用结果中的信息）。Claude使用“思考”工具进行的推理不如扩展思维全面，而是更侧重于模型发现的新信息。

我们建议在更简单的工具使用场景中使用扩展思维，例如非顺序工具调用或直接的指令遵循。扩展思维也适用于不需要Claude调用工具的用例，如编程、数学和物理。而“思考”工具更适合于Claude需要调用复杂工具、在长链工具调用中仔细分析工具输出、在具有详细指导原则的策略密集型环境中导航、或做出顺序决策（每一步都基于前一步且错误代价高昂）的场景。

以下是一个使用来自[τ-Bench](https://arxiv.org/abs/2406.12045)的标准工具规范格式的示例实现：

```
{
  "name": "think",
  "description": "使用该工具进行思考。它不会获取新信息或更改数据库，只会将想法追加到日志中。当需要复杂推理或某些缓存记忆时使用。",
  "input_schema": {
    "type": "object",
    "properties": {
      "thought": {
        "type": "string",
        "description": "要思考的想法。"
      }
    },
    "required": ["thought"]
  }
}
```

### 在τ-Bench上的性能

我们使用τ-bench（tau-bench）评估了“思考”工具，这是一个全面的基准测试，旨在测试模型在真实客户服务场景中使用工具的能力，其中“思考”工具是评估标准环境的一部分。

τ-bench评估Claude的能力：

* 与模拟用户进行真实对话
* 持续遵循复杂的客户服务代理策略指南
* 使用各种工具访问和操作环境数据库

τ-bench使用的主要评估指标是pass^*k*，它衡量在给定任务中所有*k*个独立任务试验都成功的概率，并在所有任务上取平均值。与LLM评估中常见的pass@*k*指标（衡量*k*次试验中至少一次成功的概率）不同，pass^*k*评估的是一致性和可靠性——这是客户服务应用中至关重要的品质，因为持续遵守策略是核心要求。

#### 性能分析

我们的评估比较了几种不同的配置：

1. 基线（无“思考”工具，无扩展思维模式）
2. 仅扩展思维模式
3. 仅“思考”工具
4. “思考”工具 + 优化提示（针对航空领域）

结果显示，当Claude 3.7在基准测试的“航空”和“零售”客户服务领域中有效使用“思考”工具时，性能提升显著：

* **航空领域**：带有优化提示的“思考”工具在pass^1指标上达到0.570，而基线仅为0.370——相对提升54%；
* **零售领域**：仅使用“思考”工具达到0.812，而基线为0.783。

特别有趣的是不同方法之间的比较。使用带有优化提示的“思考”工具取得了明显优于扩展思维模式（其性能与无提示的“思考”工具相似）的结果。仅使用“思考”工具（无提示）相比基线有所提升，但仍不及优化方法。

“思考”工具与优化提示的组合以显著优势取得了最强性能，这很可能是因为基准测试中[航空政策](https://github.com/sierra-research/tau-bench/blob/main/tau_bench/envs/airline/wiki.md)部分的高度复杂性，模型从获得如何“思考”的示例中受益最大。

#### τ-Bench分析的关键见解

我们的详细分析揭示了几种模式，可以帮助你有效实现“思考”工具：

1. **在困难领域，提示至关重要**。仅让“思考”工具可用可能会在一定程度上提升性能，但在困难领域，将其与优化提示结合使用可以带来显著更好的结果。然而，在较容易的领域，仅提供“思考”工具访问权可能就足够了。
2. **跨试验的一致性提升**。使用“思考”带来的改进在pass^k直到k=5时仍然保持，表明该工具有助于Claude更有效地处理边缘情况和异常场景。

### 何时使用“思考”工具

基于这些评估结果，我们确定了Claude最受益于“思考”工具的特定场景：

1. **工具输出分析**。当Claude在行动前需要仔细处理先前工具调用的输出，并且可能需要回溯其方法时；
2. **策略密集型环境**。当Claude需要遵循详细指南并验证合规性时；以及
3. **顺序决策制定**。当每个行动都基于前一个行动，且错误代价高昂时（常见于多步骤领域）。

## 实现最佳实践

为了充分利用Claude的“思考”工具，我们根据τ-bench实验推荐以下实现实践。

#### 1. 带有领域特定示例的策略性提示

最有效的方法是提供关于何时以及如何使用“思考”工具的清晰指令，例如τ-bench航空领域中使用的那种。提供针对你特定用例的示例，可以显著提高模型使用“思考”工具的效果：

* 推理过程中预期的详细程度；
* 如何将复杂指令分解为可操作的步骤；
* 处理常见场景的决策树；以及
* 如何检查是否已收集所有必要信息。

#### 2. 将复杂指南放入系统提示中

我们发现，当指南较长或复杂时，将关于“思考”工具的指令放在系统提示中，比将其放入工具描述本身更有效。这种方法提供了更广泛的上下文，有助于模型将思考过程更好地整合到其整体行为中。

### 何时*不*使用“思考”工具

尽管“思考”工具可以带来显著的改进，但它并不适用于所有工具使用用例，并且会带来提示长度和输出令牌的增加。具体来说，我们发现“思考”工具在以下用例中不会带来任何改进：

1. **非顺序工具调用**。如果Claude只需要执行一次工具调用或多次并行调用来完成任务，那么添加“思考”不太可能带来任何改进。
2. **简单的指令遵循**。当没有太多约束需要Claude遵守，且其默认行为已经足够好时，额外的“思考”不太可能带来收益。

### 开始使用

“思考”工具是你可以轻松添加到Claude实现中的一个功能，只需几个步骤即可获得有意义的改进：

1. **在智能体工具使用场景中测试**。从具有挑战性的用例开始——例如Claude在长链工具调用中在策略合规性或复杂推理方面遇到困难的情况。
2. **添加工具定义**。实现一个针对你领域定制的“思考”工具。它只需要最少的代码，但能实现更结构化的推理。同时考虑在系统提示中包含关于何时以及如何使用该工具的指令，并附上与你领域相关的示例。
3. **监控并优化**。观察Claude在实践中如何使用该工具，并调整你的提示以鼓励更有效的思考模式。

最棒的是，添加这个工具对性能结果的下行风险极小。除非Claude决定使用它，否则它不会改变外部行为，也不会干扰你现有的工具或工作流程。

### 结论

我们的研究表明，“思考”工具可以显著提升Claude 3.7 Sonnet在复杂任务上的性能¹，这些任务需要策略遵守和在长链工具调用中进行推理。“思考”并非一刀切的解决方案，但对于正确的用例，它能以最小的实现复杂度带来实质性的好处。

我们期待看到你将如何使用“思考”工具，与Claude一起构建更强大、更可靠、更透明的AI系统。

1. 虽然我们的τ-Bench结果集中于Claude 3.7 Sonnet在使用“思考”工具时的改进，但我们的实验表明，Claude 3.5 Sonnet（新）在与3.7 Sonnet相同的配置下也能获得性能提升，这表明这种改进也适用于其他Claude模型。
