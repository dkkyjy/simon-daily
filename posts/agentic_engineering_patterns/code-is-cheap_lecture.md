# 讲座摘要：智能体工程模式

**SUMMARY**
智能体极大降低了代码生成成本，但好代码的标准未变。工程师需建立新习惯，利用智能体优势，同时确保代码质量、可维护性与正确性。

**TOPICS & TIMESTAMPS**

00:00:00 **指南：智能体工程模式**
00:00:05 **核心挑战：适应代码成本降低的现实**
*   传统软件开发的宏观与微观习惯都基于“代码昂贵”这一核心约束。
*   宏观：大量时间用于设计、评估和规划，以确保昂贵的编码时间被高效利用。
*   微观：每日数百个决策都基于时间与收益的权衡（如重构、写文档、加测试）。

00:01:10 **编码智能体带来的颠覆**
*   将代码输入计算机的成本被极大降低。
*   并行运行智能体的能力使评估更复杂，一名工程师可同时在多处实现、重构、测试和编写文档。

00:01:45 **好代码的成本依然存在**
*   交付新代码的成本近乎免费，但交付“好代码”的成本仍然很高。
*   **“好代码”的定义包括：**
    *   功能正确，无错误。
    *   经过验证，确认符合用途。
    *   解决了正确的问题。
    *   优雅且可预测地处理错误情况。
    *   简单、最小化，便于理解和维护。
    *   有测试保护，防止未来回归。
    *   文档适当且保持更新。
    *   设计为未来变更留有余地（平衡YAGNI原则与可扩展性）。
    *   满足所有相关的非功能性质量指标（如安全性、可靠性、可观测性等）。

00:03:20 **工程师的新责任**
*   编码智能体工具可在多方面提供帮助，但**驱动工具的开发者**仍负有确保生成代码质量的重大责任。

00:03:35 **建立新习惯的必要性**
*   需要培养新的个人与组织习惯，以应对智能体工程带来的便利和机遇。
*   行业仍在探索最佳实践。
*   **当前建议：** 当直觉认为“不值得花时间构建”时，仍可发送提示让异步智能体尝试。最坏情况仅是消耗一些令牌。

**TOOLS**
*   **编码智能体 (Coding Agents):** 能生成、重构、测试和编写代码文档的AI工具，显著降低代码输入成本。
*   **异步智能体会话 (Asynchronous Agent Sessions):** 可并行运行的智能体任务，允许工程师同时推进多项工作。

**ONE-SENTENCE TAKEAWAY**
利用智能体应对代码成本下降的机遇，但工程师必须建立新习惯，确保生成代码的质量与可维护性。
