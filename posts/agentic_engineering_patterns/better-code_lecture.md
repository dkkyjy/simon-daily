**DEFINITIONS & KEY CONCEPTS**

### **智能体工程模式**
*   **核心主张**：AI 智能体应被用来帮助开发者产出更优质的代码，而非接受质量下降。
*   **关键选择**：使用智能体产出更差的代码是一种选择；我们同样可以选择利用它们来产出更好的代码。

### **技术债务**
*   **定义**：因选择快速但非最优的解决方案（而非“正确的方式”）而引入的长期维护成本或代码质量妥协，是一种权衡取舍的结果。
*   **最佳缓解策略**：首先避免承担技术债务。
*   **常见类型**：
    *   **API设计缺陷**：初始设计未能涵盖重要用例，导致后续修复工作量大。
    *   **糟糕的命名选择**：早期概念命名不当，后期在代码库中全局清理成本过高。
    *   **功能重复**：系统演化出重复但略有差异的功能，需要合并重构。
    *   **巨型文件**：单个文件代码行数过多，需要拆分为模块。

### **编码智能体的应用**
*   **理想场景**：处理概念简单但耗时、重复的重构任务。
*   **典型工作流**：
    1.  启动一个**异步编码智能体**（如Gemini Jules, OpenAI Codex web, Claude Code）。
    2.  给出明确指令，让其在后台分支或工作树中运行。
    3.  在**Pull Request中评估结果**，决定合并、迭代提示或丢弃。
*   **效果**：将代码改进的成本降至极低，使得对代码异味可以采取“零容忍”态度。

### **AI辅助决策与探索**
*   **避免规划失误**：LLM可以建议其训练数据中常见的、可靠的“无聊技术”解决方案，帮助开发者避免错过明显选项。
*   **探索性原型设计**：智能体可以根据提示快速构建系统模拟或原型，用于验证技术选型（如Redis是否适合高并发场景），成本极低。
*   **并行实验**：低成本使得同时测试多种解决方案成为可能，从而做出更可靠的技术选择。

### **复合工程循环**
*   **定义**：由Every公司的Dan Shipper和Kieran Klaassen提出的一种方法论。指在每个编码项目结束后进行回顾（复合步骤），总结有效方法并记录下来，用于改进未来智能体运行的指令。
*   **核心理念**：智能体遵循指令，通过持续改进指令来获得随时间推移而不断优化的结果。
*   **最终目标**：实现质量与速度的兼得，让小的质量改进产生复合增长效应。

**TOOLS**
*   **Gemini Jules**：谷歌开发的异步编码智能体。
*   **OpenAI Codex web**：OpenAI提供的基于网页的代码生成模型。
*   **Claude Code on the web**：Anthropic公司Claude模型的网页编码版本。
*   **Pull Request**：代码协作与审查流程中的关键环节，用于评估智能体生成的代码变更。

**ONE-SENTENCE TAKEAWAY**
利用编码智能体处理重构任务、探索方案并实践复合工程，能以极低成本持续提升代码质量，实现速度与质量兼得。
