# 讲座摘要：智能体工程模式 - 子智能体

**SUMMARY**
讲座介绍了子智能体模式，用于解决LLM上下文长度限制，通过分派新副本来处理大任务，包含探索、并行和专家子智能体等类型。

**TOPICS AND TIMESTAMPS**

*   **00:00:00 引言：LLM的上下文限制**
    *   LLM的上下文长度（工作内存）存在上限，通常约1,000,000令牌，高质量结果常低于200,000令牌。
    *   管理上下文以适应这些限制对获得优异结果至关重要。

*   **00:01:15 子智能体核心概念**
    *   **定义**：一种处理更大任务的方法，避免消耗主智能体（编码智能体）宝贵的高层上下文资源。
    *   **工作原理**：主智能体分派一个自身的新副本去实现特定目标，该副本拥有一个以全新提示开始的新上下文窗口。

*   **00:02:30 示例：Claude Code的探索子智能体**
    *   Claude Code在开始新任务时，使用子智能体探索代码库以了解结构和找到相关信息。
    *   **流程演示**：主智能体构建提示并分派“探索”子智能体，子智能体返回其发现的描述（如定位模板、Python代码、JavaScript、CSS样式等），供主智能体开始编辑。

*   **00:04:50 并行子智能体**
    *   **优势**：主智能体可同时运行多个子智能体，可能使用更快、更便宜的模型（如Claude Haiku），以显著提升性能。
    *   **应用提示示例**：“使用子智能体查找并更新受此更改影响的所有模板。”，适用于编辑多个独立文件的任务。

*   **00:06:10 专家子智能体**
    *   **定义**：通过自定义系统提示或工具进行进一步定制的子智能体，使其能承担不同专业角色。
    *   **专业角色类型**：
        *   **代码审查智能体**：审查代码，识别错误、功能缺失或设计弱点。
        *   **测试运行智能体**：运行测试，向主智能体隐藏详细输出，仅报告失败详情。
        *   **调试智能体**：专门负责调试，推理代码库并运行代码片段以定位问题根源。
    *   **核心价值提醒**：子智能体的主要价值在于保护主上下文和管理令牌密集型操作，而非过度分解任务。

*   **00:08:00 官方文档资源**
    *   列出了支持子智能体的流行编码智能体及其文档链接：
        *   OpenAI Codex 子智能体
        *   Claude 子智能体
        *   Gemini CLI 子智能体
        *   Mistral Vibe 子智能体
        *   OpenCode 智能体
        *   Visual Studio Code 中的子智能体
        *   Cursor 子智能体

**TOOLS**
*   **Claude Code**：使用探索子智能体来理解和导航代码库的编码智能体。
*   **Claude Haiku**：被提及为可用于并行子智能体的更快、更便宜的模型。
*   **difflib (Python库)**：在示例中被Claude Code子智能体发现用于生成代码差异。

**ONE-SENTENCE TAKEAWAY**
子智能体模式通过分派独立副本来处理大任务，有效管理LLM的上下文限制并提升效率。
