# 编码智能体工程模式：工作原理详解

**SUMMARY**
本讲座解释了编码智能体的核心组件：LLM、提示、工具调用和推理机制，并概述了其工作原理与优化策略。

**TOOLS**
*   **OpenAI 分词器**：用于可视化文本如何被转换为标记序列的在线工具。
*   **Bash() 工具**：允许智能体在环境中执行终端命令的工具。
*   **Python() 工具**：允许智能体运行 Python 代码的工具。
*   **天气查询工具 (示例)**：一个演示性的工具，用于展示智能体如何调用外部函数获取信息。

**ONE-SENTENCE TAKEAWAY**
编码智能体是通过系统提示和工具调用循环来驾驭 LLM 的软件，其核心在于理解标记、提示和工具交互机制。

### 讲座主题与时间戳

00:00:00 **指南与智能体工程模式**
00:00:05 **编码智能体如何工作**
00:00:15 **大型语言模型 (LLM)**
*   **定义**：一种可以补全文本句子的机器学习模型，是任何编码智能体的核心。
*   **示例模型**：GPT-5.4, Claude Opus 4.6, Gemini 3.1 Pro, Qwen3.5-35B-A3B。
*   **标记 (Token)**：LLM 实际处理的基本单位，文本被转换为整数标记序列。理解标记对成本（按处理量计费）和上下文长度（一次能考虑的标记数有限制）至关重要。
*   **多模态 LLM**：可以接受图像等非文本输入，这些输入同样被转换为标记进行处理，而非通过独立的 OCR 流程。

00:02:30 **提示与补全**
*   **提示 (Prompt)**：输入到 LLM 的内容。
*   **补全/响应 (Completion/Response)**：LLM 返回的文本。

00:03:00 **聊天模板化提示**
*   **定义**：一种将模型通信模拟为对话的特殊格式提示（如 `user:` 和 `assistant:` 的交替），提升了用户友好度。
*   **无状态性**：LLM 本身没有记忆，每次提示都从头开始。维持对话需要软件自行管理状态并重放整个历史，这会导致随着对话增长，提示成本增加。
*   **标记缓存**：提供商通过缓存已处理的常见标记前缀来提供更低费率，从而优化成本。编码智能体的设计会尽量避免修改早期对话内容以利用此优化。

00:05:20 **调用工具**
*   **定义**：工具是智能体“驾驭器”提供给 LLM 调用的函数，是智能体的定义性特征。
*   **工作原理**：
    1.  系统提示中声明可用工具及其调用格式（例如 `<tool>get_weather(city_name)</tool>`）。
    2.  LLM 在需要时生成工具调用请求文本。
    3.  智能体软件解析并执行该工具。
    4.  将工具执行结果作为新的消息内容返回给 LLM，LLM 据此生成最终回答。
*   **强大工具示例**：`Bash()`（执行终端命令）和 `Python()`（运行 Python 代码）等允许代码执行的工具。

00:07:10 **系统提示**
*   **定义**：在每次对话开始时提供给 LLM 的隐藏指令，用于设定模型的行为准则、可用工具等信息。
*   **特点**：通常非常冗长（可达数百行），包含了使编码智能体有效工作的关键指示。

00:08:00 **推理**
*   **定义**：模型在生成最终回复前，花费额外时间和标记生成内部“思考”文本的过程，类似于人类的大声思考。
*   **作用**：允许模型更深入地处理复杂问题，尤其有助于调试代码，使其能够追溯函数调用并探索复杂的解决路径。
*   **可调节性**：许多编码智能体允许调整“推理努力”级别，为更难的问题分配更多“思考”资源。

00:09:30 **LLM + 系统提示 + 工具循环**
*   **核心总结**：结合大型语言模型、精心设计的系统提示以及工具调用循环，就构成了编码智能体的主要部分。
*   **简易实现**：其基本机制出奇简单，可以在现有 LLM API 基础上用几十行代码实现一个基础的工具循环。
