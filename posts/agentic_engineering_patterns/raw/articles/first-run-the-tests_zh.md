首先运行测试

在使用编码智能体工作时，自动化测试不再是可选项。
那些过去不编写测试的借口——在代码库快速演进时，持续重写测试既耗时又昂贵——当智能体能在几分钟内完成测试时，就不再成立了。
它们对于确保 AI 生成的代码能实现其声称的功能也至关重要。如果代码从未被执行过，那么部署到生产环境后能实际运行纯属侥幸。
测试也是帮助智能体快速熟悉现有代码库的优秀工具。观察当你向 Claude Code 或类似工具询问现有功能时会发生什么——它们很可能会找到并阅读相关的测试。
智能体本身已有偏向测试的倾向，但现有测试套件的存在几乎肯定会推动智能体对其所做的新更改进行测试。
每当我针对现有项目开启新的智能体会话时，我都会先给出类似以下的提示：
首先运行测试
对于我的 Python 项目，我设置了 pyproject.toml，以便可以改用这个提示：
运行 "uv run pytest"
这四个字的提示有几个作用：

它告诉智能体存在测试套件，并迫使其找出运行测试的方法。这几乎确保了智能体未来会运行测试，以确保自己没有破坏任何功能。
大多数测试框架会给智能体一个关于测试数量的大致概念。这可以作为项目规模和复杂性的参考，也暗示智能体如果想了解更多，应该搜索测试本身。
它让智能体进入测试思维模式。运行测试后，智能体很自然地会在后续添加自己的测试。

类似于“使用红/绿测试驱动开发”，“首先运行测试”这个四字提示包含了大量已内置于模型中的软件工程规范。
