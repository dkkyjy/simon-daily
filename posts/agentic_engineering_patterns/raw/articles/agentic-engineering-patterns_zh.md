撰写智能体工程模式
2026年2月23日
我启动了一个新项目，旨在收集和记录智能体工程模式——这些编码实践和模式有助于我们在正步入的编码智能体开发新时代中获得最佳成果。
我使用“智能体工程”来指代使用编码智能体构建软件——例如 Claude Code 和 OpenAI Codex 这类工具，其定义性特征是它们既能生成也能执行代码，这使得它们能够独立于人类监督者的逐步指导，测试代码并迭代改进。
我认为“氛围编码”应沿用其最初定义，即完全不在意代码本身，如今这常与非程序员使用大语言模型编写代码相关联。
智能体工程则代表了尺度的另一端：专业软件工程师利用编码智能体，通过放大其现有专业知识来改进和加速工作。
关于这门新学科，有太多需要学习和探索的内容！我已经在我的 ai-assisted-programming 标签下发表了很多文章（345篇且仍在增加），但相对缺乏结构。我的新目标是创作一个能帮助回答“如何从这些东西中获得好结果”的内容，并集中在一处呈现。
我将在我的博客上以一系列章节式模式的形式来发展和推进这个项目，其格式松散地借鉴了1994年《设计模式：可复用面向对象软件的基础》一书所推广的风格。
我今天发布了前两章：
《现在编写代码成本低廉》探讨了智能体工程的核心挑战：产出初始可用代码的成本已降至几乎为零，这如何影响我们现有的、关于个人及团队工作方式的直觉？
《红/绿测试驱动开发》描述了测试优先开发如何帮助智能体以最少的额外提示，编写更简洁可靠的代码。
我希望能以每周1-2章的速度添加更多内容。我不确定何时会停止，因为要涵盖的内容实在太多了！
由我本人撰写，非大语言模型生成
我有一项严格的个人原则：不以自己的名义发布人工智能生成的文字。这项原则同样适用于《智能体工程模式》。我会使用大语言模型进行校对、充实示例代码以及处理各类其他辅助任务，但你在这里读到的文字将是我自己的。
章节与指南
《智能体工程模式》并非严格意义上的书，但具有类似书的形态。我将在我的网站上使用一种我称之为“指南”的新内容形式来发布它。指南是章节的集合，其中每个章节本质上都是一篇博客文章，但日期显示较不突出，其设计初衷是随时间推移而更新，而非在首次发布时冻结。
指南和章节是我应对在博客上发布“常青”内容这一挑战的答案。我一直在寻找实现这一点的方法。这感觉像是一种可能持续下去的格式。
如果你对实现细节感兴趣，可以在 Guide、Chapter 和 ChapterChange 模型以及相关的 Django 视图中找到代码，其中几乎全部是由 Claude Opus 4.6 在 Claude Code 中运行，并通过我的 iPhone 访问网络而编写的。
