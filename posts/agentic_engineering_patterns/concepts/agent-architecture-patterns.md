# 智能体架构模式

## 概述

智能体工程领域已收敛于几个关键的架构模式，用于构建可靠的生产级 AI 智能体。每种模式在复杂度、灵活性和可靠性上有不同的权衡。

## 架构演进

| 模式 | 时代 | 描述 |
|---|---|---|
| 链式 | ~2023-2024 | 线性提示链；简单但在生产中脆弱 |
| 有向图 | ~2025+ | 有状态的有向无环图（DAG），含显式节点/边；主导生产环境 |
| 分层 | ~2025+ | 多级别规划智能体，含子智能体 |
| ReAct | 持续 | 单智能体决策中的推理-行动循环 |

## 核心模式

### 有向无环图（DAG）

- 智能体建模为节点（操作）通过边（转换）连接
- 步骤间显式状态管理
- 参考实现：[[langgraph]]、[[graph-orchestration]]
- 适用场景：需要精确控制流和调试的复杂工作流

### 基于角色的多智能体

- 智能体（"团队"）承担分配的角色并通过交接协作
- 更容易推理单个智能体的行为
- 参考实现：[[crewai]]、[[microsoft-autogen]]
- 适用场景：基于团队的工作流和快速原型开发

### ReAct 循环

- 单智能体在推理和行动之间交替
- 简单但若无护栏可能无限循环
- 更复杂单智能体模式的基础
- 配合 [[tool-use]] 实现外部动作

## 趋势

- 基于图的编排正在取代链式模式（据 [[stackone-ai-agent-landscape-2026]]）
- [[multi-agent-systems]] 正成为生产环境标准而非单智能体
- [[agent-protocols]]（MCP、A2A、AG-UI）实现不同模式间的互操作性
- [[agent-architecture-patterns]] 正演变为混合方法，结合图 + 规划
